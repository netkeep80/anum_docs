# Метатеория связей (МТС)

**Метатеория связей (МТС)** исследует системы, в которых единственным первичным видом сущности является **связь**.

Главный постулат:

```text
всё есть связь
```

МТС начинается не с программного типа и не с графической стрелки. Её исходная наглядность — **остенсивная форма связи**: сама запись показывает, какие полюса различены, а какие самозамкнуты.

## Краткий словарь

Приставка **«а-»** в собственных терминах МТС означает **«ассоциативный»**. Она подчёркивает, что понятие определяется через связи и их ассоциативное окружение, а не через отдельную внешнюю структуру данных.

**Связь** — первичная сущность МТС. В направленной форме имеет начало и конец:

```text
A ⟼ B
```

При этом `A` и `B` сами являются связями, а не объектами другой онтологии.

**Асеть** — ассоциативная сеть связей. Связи могут быть полюсами других связей, поэтому отдельный первичный слой «узлов» не требуется:

```text
P = A ⟼ B
Q = P ⟼ C
```

**Акорень** — ассоциативный корень `∞`, единственная полностью самозамкнутая связь:

```text
∞ = ∞ ⟼ ∞
```

Акорень является исходной точкой корневых различений и не является пятым абитом.

**Абит** — одно из четырёх корневых различений, используемых как алфавит четверичного ачисла:

```text
[ ] 1 0
```

Их корневые значения задаются связями `O`, `C`, `L`, `U`.

**Ачисло** — конечная структурная запись через корневые различения. Ачисло описывает структуру; чтение само по себе не обязано материализовать описанные связи.

**Четверичное ачисло** состоит ровно из четырёх абитов:

```text
[ ] 1 0
```

Акорень `∞` не является пятым состоянием передачи: каждый новый контекст десериализации уже начинается относительно него.

**Апамять** — ассоциативная память: поиск, чтение, явная материализация и долговременное хранение конкретной асети. Физический адрес записи не является смысловым тождеством связи.

## 1. Остенсивный корень МТС

Акорень:

```text
∞ = ∞ ⟼ ∞
```

Для начала `b` и конца `e` в теоретической метанотации различаются четыре остенсивные формы:

```text
∞        оба полюса самозамкнуты
♂e       начало самозамкнуто, конец e различён
b♀       начало b различено, конец самозамкнут
b ⟼ e    оба полюса различены
```

Структурно:

```text
R = R ⟼ R      # ∞
S = S ⟼ e      # ♂e
E = b ⟼ E      # b♀
X = b ⟼ e      # b ⟼ e
```

`♂e` и `b♀` здесь — остенсивная теоретическая запись, а не команды получения полюсов. В принятом F1 MTS v0.9 знаки `♂` и `♀` не входят во внутренний минимальный реестр и остаются отложенными; соответствующая структура выражается самими связями.

Полностью самозамкнутая форма единственна:

```text
X = X ⟼ X
=> X = R = ∞
```

Нельзя получить второй акорень, просто выдав другой технический адрес или ID. Первичное различие возникает из рисунка самозамыкания, а затем распространяется через связанность с уже различёнными связями.

## 2. Пять корневых связей

Принятое MTS v0.9 основание сохраняет пятисвязное корневое ядро:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой четверичный словарь:

```text
[ → O
] → C
1 → L
0 → U
```

Остенсивно, в метаязыке теории:

```text
O = O ⟼ R   # ♂∞
C = R ⟼ C   # ∞♀
```

Поэтому необходимо различать:

```text
семантический корневой базис: R/O/C/L/U — 5 связей
транспортный алфавит:        [ ] 1 0   — 4 абита
```

Текущий минимальный внутренний F1-алфавит MTS v0.9 содержит ровно:

```text
∞ [ ] 1 0 ( ) ⟼ : =
```

Отложены как внутренние знаки:

```text
≡ ♂ ♀ ↑ { } ¬ ↛
```

А знаки:

```text
∧ ⇔ ⇒ ≠ →
```

используются только в метаязыке описания и доказательства.

## 3. Машинное представление вторично

После остенсивного определения связь можно представить машинной структурой:

```text
Link(start, end)
```

В самой связи нет обязательных полей «контекст», «теория», «правило», «смысл» или «тип». Если роль существенна, она выражается другими связями сети.

Техническая ссылка не является источником смыслового различия. Несамозамкнутый полюс должен быть уже различён самозамыканием или связанностью с ранее различёнными связями.

## 4. Тождество связи определяется началом и концом

Фундаментальное тождество для уже структурно различённых полюсов:

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Следовательно:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=> P1 = P2
```

В МТС не существует двух разных смысловых связей с одной и той же упорядоченной парой уже различённых полюсов.

Адрес памяти, номер записи, номер операции или позиция в последовательности могут различаться, но они не создают второе смысловое тождество связи.

F2/F3-исследование дополнительно вывело это тождество через конечные рекурсивно заземлённые формы, а не через технические ID среды исполнения.

## 5. Повтор связи и повтор позиции — разные вещи

Последовательность может несколько раз ссылаться на одну связь:

```text
[L, L, L, U]
```

Так представляется, например, ачисло:

```text
1110
```

Три позиции `1` различаются своим положением, но не создают три экземпляра `L`.

Если нужно различать события, акты, происхождение или историю, различие должно выражаться отдельной связевой структурой occurrence/provenance, а не техническим экземпляром одной semantic Link.

## 6. Контекст является частью сети связей

В MTS v0.9 контекст не определяется скрытым стеком среды исполнения. Структурная форма:

```text
P = parent ⟼ current
K = K ⟼ P
I ⟼ K
```

связывает текущий контекст с явным интерпретатором `I` и сохраняет лексическую вложенность через `K.parent`.

Открытие и закрытие Q/FORMAL-контекстов, а также возврат результата во внешний контекст оформляются явными структурными переходами. Временной порядок принадлежит Run/Act, а лексическая вложенность — `K.parent`.

Запись `current(K)` допустима здесь только как метанотация чтения структуры `K`; отдельный внутренний знак `↑` в F1 v0.9 не принят.

Если связевая форма двух состояний полностью совпадает, это одна и та же связь. Чтобы различать последовательные события перехода, их происхождение должно храниться самой историей актов.

## 7. Исходная запись, словарь и теория различаются

Одна последовательность байтов может участвовать во многих местах и актах чтения. Различаются:

```text
точное содержимое исходной записи
позиция или связевая история употребления
словарь D
грамматика G
теория T
интерпретатор I = D ⟼ (G ⟼ T)
контекст K
форма и результат
```

MTS v0.9 дополнительно фиксирует канонический STRING→QUATERNARY carrier: каждый физический byte кодируется одним `[8 bits]`-конвертом, без Unicode-normalization и без превращения runtime byte-id в semantic identity.

Если два объявления действительно должны различаться, различие выражается структурой истории и ролей, а не вторым экземпляром одной и той же пары полюсов.

## 8. Наблюдение отделено от изменения

Критическая граница апамяти:

```text
читать / искать / разрешать / проверять / воспроизводить
                    ≠
создавать / удалять / изменять
```

Поиск отсутствующей физической записи не создаёт её.

```text
не найдено ≠ не существует
find ≠ materialize
```

Явное получение связи с возможной материализацией должно вести себя канонически:

```text
ensureLink(A,B):
    если A ⟼ B уже записана -> вернуть её
    иначе -> материализовать её
```

Повторный вызов для той же пары возвращает ту же semantic Link.

## 9. Локальное равенство и правила вывода

Принятое в MTS v0.9 формальное равенство использует явное контекстно-локальное свидетельство представителя. В метанотации:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Это дополнительный контекстный механизм и он не переопределяет фундаментальное тождество связи по её полюсам.

Из локального отношения не следуют автоматически глобальная подстановка, транзитивное замыкание или переписывание всей сети.

Правило должно быть структурно объявлено и отдельно допущено теорией:

```text
Rule = DR ⟼ Body
T ⟼ Rule
```

Само наличие `Rule` как данных не означает автоматического исполнения.

## 10. Ачисла и пустой контекст

Ачисла используют ровно четыре корневых абита:

```text
[ ] 1 0
```

Каждый Q-контекст начинается от `R`, а empty/nonempty state в v0.9 представлен структурно, без скрытого `started:boolean` как semantic authority.

Поэтому:

```text
des(ε) = R
des([]) = R
```

Пустая группа `[]` допустима и является способом записать акорень внутри четверичного ачисла без пятого абита.

Для уже разрешённых значений сохраняется левоориентированная свёртка результата:

```text
des(a)     = a
des(a,b)   = a ⟼ b
des(a,b,c) = (a ⟼ b) ⟼ c
```

При этом там, где требуется сохранить явные позиции, включая значение `R`, v0.9 использует root-safe `ExactSequence`, чтобы не смешивать результат свёртки с тождеством последовательности.

Подробнее: [Ачисла и сериализация](docs/specs/Ачисла%20и%20сериализация.md).

## 11. Апамять

Апамять должна сохранять:

- тождество связи по упорядоченной паре различённых полюсов;
- единственность полностью самозамкнутого акорня;
- циклы и петли, укоренённо различимые относительно уже различённых связей;
- совместное использование одной связи несколькими структурами;
- повтор ссылок в последовательностях;
- различие чтения и изменения;
- независимость смыслового тождества от физического адреса.

Если внешний артефакт содержит две записи одной структурно неразличимой связи, они должны быть канонизированы в одну связь либо артефакт должен быть отклонён.

Подробнее: [Апамять и управление сетью связей](docs/specs/Апамять%20и%20управление%20сетью%20связей.md).

## 12. Производные теории не меняют корень

Завершённый F2–F6 цикл вывел поверх основания, не добавляя новые root sorts:

- конечную нормализацию и no-instance result;
- внутреннюю рекурсивную реверсию `J` отдельно от перестановки полюсов и navigation converse;
- connectivity-degree Count и производную Peano-структуру;
- конечные коллекции через explicit occurrence/provenance;
- конечные функции как декларативные данные;
- relative navigation/path algebra;
- application interpretations только под явной теорией/контекстом.

Эти конструкции являются производными слоями. Они не превращают Set, Function, Path, Count, application role или occurrence в новый примитив Link.

Текущий машинный выпуск:
[`mts-contract/v0.9`](contracts/mts-contract-v0.9.json) + [`mts-conformance/v0.9`](contracts/mts-conformance-v0.9.json).

Предыдущая неизменяемая пара свидетельств:
[`mts-contract/v0.8`](contracts/mts-contract-v0.8.json) + [`mts-conformance/v0.8`](contracts/mts-conformance-v0.8.json).

MTS v0.9 имеет `semanticBase = mts-contract/v0.8` и `observableSemanticDelta = true`: v0.9 — не только смена владельца реализации, а принятый F1 machine delta поверх v0.8.

Единственная текущая реализация написана на TypeScript и поставляется как пакет `@mts/core`; рекомендуемая граница потребителя — корневой экспорт пакета, собираемый из [`ts/src/public.ts`](ts/src/public.ts). Python runtime, Python oracle и compatibility runtime отсутствуют в активном дереве.

Методика изменения и принятия контрактов описана в [руководстве по вкладу](docs/CONTRIBUTING.md#разработка-мтс-через-контракты). История принятых ранее реализаций и исследований сохраняется Git, задачами и запросами на слияние; `main` хранит текущее состояние МТС, а не журнал пути к нему.

## Главный инвариант

```text
самозамыкание
→ первичное различение
→ акорень ∞
→ связанность с уже различёнными связями
→ связь, однозначная по структурно различённым полюсам
→ явный контекст и свидетельства
→ ассоциативный поиск
→ детерминированная проверка
→ явное изменение апамяти
```

В MTS v0.9 внутреннее F1-самовведение замкнуто на знаках:

```text
∞ [ ] 1 0 ( ) ⟼ : =
```

а остенсивная теория, машинный contract/conformance и TypeScript runtime должны оставаться согласованными, не подменяя друг друга.
