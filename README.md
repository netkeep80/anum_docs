# Метатеория связей (МТС)
<!-- версия документа МТС; mts-doc-version: v0.13 -->
> **Версия МТС: v0.13**

**Метатеория связей (МТС)** — формальная система, в которой единственным первичным видом сущности является **Связь**.

```text
всё есть Связь
Связь связывает Связи
различима только рекурсия
```

## Минимальный фундамент v0.13

Связь имеет начало и конец, которые сами являются Связями. Локальное самовхождение даёт четыре структурных аспекта:

```text
11  ROOT
10  START
01  END
00  PAIR
```

Из единственного акорня выводится корневой базис:

```text
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Канонический структурный алфавит ачисел MTS v0.13:

```text
8 = ROOT
9 = START
6 = END
1 = PAIR
```

Поэтому:

```text
R = 8
O = 98
C = 68
L = 19868
U = 16898
```

`U` — обычный `PAIR(C,O)`, а не пятый аспект и не пятый абит.

## Что уже определено в v0.13

Текущая система включает:

- структурное тождество и каноническое описание допустимых Связей;
- перенос между независимыми апамятями без опоры на локальные handles;
- композицию `FORMAL` через явные `Dictionary`, `Grammar`, `Theory` и допущенные `Rule`;
- явный Context и контекстную истину вида `K ⟼ A`;
- заземлённое исполнение через допущенные отношения `Theory`;
- ветви `ZERO` / `ONE` / `MANY` и остановку в `fixed point` / `quiescence`;
- семантику программы, выраженную Связями, в явно ограниченной области.

Полностью `self-hosted` система **не заявлена**: семантика программы существенно перенесена в Связи, но апамять и среда исполнения остаются внешней границей.

## Производный результат: рекурсивная инверсия

После принятия v0.13 отдельно доказана рекурсивная инволюция над принятой смысловой областью:

```text
J(A ⟼ B) = J(B) ⟼ J(A)
J² = Id
```

Она действует на аспекты так:

```text
ROOT      -> ROOT
START(X)  -> END(J(X))
END(X)    -> START(J(X))
PAIR(A,B) -> PAIR(J(B),J(A))
```

и на корневой базис:

```text
R -> R
O <-> C
L -> L
U -> U
```

Это сохраняет структурную **хиральность** `START/END`, но не вводит абсолютную привилегированную сторону. Проверенная структура МТС v0.13 классифицирована как `THEORY_DUALIZATION`: фундамент сохраняется, а ориентированные соглашения контекста, полномочий и исполнения переходят в согласованные зеркальные соглашения.

Это **производный результат, полученный после принятия v0.13**, а не новый смысловой закон принятого контракта. Машиночитаемый индекс: [реестр теорем](theorems/registry.json); итоговая проверка области: [аудит дуализации](theorems/v0.13/inversion/dualization-audit.json).

Каждый текущий документ описывает только МТС v0.13 и имеет явную версионную пометку. Рекомендуемый порядок:

5. [Апамять и управление сетью связей](docs/specs/Апамять%20и%20управление%20сетью%20связей.md) — память, эффекты, область исполнения и заземлённое исполнение.

## Источники истины

```text
нормативная теория
      ↓
принятый машинный контракт
      ↓
корпус соответствия
      ↓
исполняемые свидетельства и эталонная реализация
```

Реализация свидетельствует реализуемость, но не назначает смысл теории.

Отдельно:

```text
theorem registry = индекс доказательных результатов
!= нормативный источник семантики
```

Критические границы:

```text
смысловая Link != технический handle
описание Link != описываемая Link
representation != interpretation
read / search / verify / replay != materialize / write
NOT_FOUND != доказанное несуществование
Rule существует != Rule допущено Theory
```

## Разработка

Текущее ядро находится в `ts/` и поставляется как `@mts/core`.

Основные проверки:

```bash
npm --prefix ts test
npm --prefix ts run docs:check
npm --prefix ts run check
```

Изменения активного дерева проходят обязательные CI и repo-guard согласно `repo-policy.json`.
