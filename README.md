# Метатеория связей (МТС)

**Метатеория связей (МТС)** исследует системы, в которых единственным первичным видом сущности является **связь**.

Главный постулат:

```text
всё есть связь
```

МТС начинается не с программного типа и не с графической стрелки. Её исходная наглядность — **остенсивная форма связи**: сама запись показывает, какие полюса различены, а какие самозамкнуты.

## Краткий словарь

Приставка **«а-»** в собственных терминах МТС означает **«ассоциативный»**. Она подчёркивает, что понятие определяется через связи и их ассоциативное окружение, а не через отдельную внешнюю структуру данных.

**Связь** — первичная сущность МТС. В направленной форме имеет начало и конец:

```text
A ⟼ B
```

При этом `A` и `B` сами являются связями или различёнными формами связей, а не объектами другой онтологии.

**Асеть** — ассоциативная сеть связей. Связи могут быть полюсами других связей, поэтому асеть не требует отдельного первичного слоя «узлов». Например:

```text
P = A ⟼ B
Q = P ⟼ C
```

Здесь сама связь `P` является началом связи `Q`.

**Акорень** — ассоциативный корень `∞`, различённая полностью самозамкнутая связь:

```text
∞ = ∞ ⟼ ∞
```

Акорень является исходной точкой корневых различений, но не является абитом.

**Абит** — ассоциативный бит: одно из четырёх корневых различений, используемых как алфавит четверичного ачисла:

```text
[ ] 1 0
```

Их корневые значения задаются связями `O`, `C`, `L`, `U`.

**Ачисло** — ассоциативное число, то есть конечная структурная запись через корневые различения. Ачисло описывает структуру; его чтение само по себе не обязано материализовать описанные связи.

**Четверичное ачисло** — канонический носитель, состоящий только из четырёх абитов:

```text
[ ] 1 0
```

Например:

```text
[01]
```

является четверичной записью независимо от того, какую более высокую семантику ей назначает выбранный протокол.

**Строковое ачисло** — удобная исходная запись из имён, которые разрешаются **явным словарём** в четверичный носитель. Например:

```text
window position
```

при словаре:

```text
window   → []
position → ][
```

компилируется в:

```text
[]][
```

Строковый режим не вводит пятый вид абита и не кодирует неизвестное имя автоматически: неизвестное имя должно остаться ошибкой разрешения.

**Апамять** — ассоциативная память, то есть слой управления асетью: поиск, чтение, явная материализация, удаление и долговременное сохранение точных вхождений. Апамять не тождественна физическому адресу или конкретному способу хранения.

**Остенсивная форма** — запись, которая непосредственно показывает форму связи. Например:

```text
♂e
b♀
```

показывают самозамкнутое начало и самозамкнутый конец соответственно.

**Точное вхождение связи** — конкретное существование связи в асети. Два точных вхождения могут иметь одинаковые полюса и всё же оставаться различными:

```text
P1 = A ⟼ B
P2 = A ⟼ B
P1 ≠ P2
```

Поэтому форма связи и её конкретное существование — разные уровни описания.

## 1. Остенсивный корень МТС

Акорень обозначается знаком:

```text
∞
```

и является полностью самозамкнутой связью:

```text
∞ = ∞ ⟼ ∞
```

Акорень — различённая неподвижная точка, в которой смысл связывает смысл с самим смыслом. Отдельная сущность «смысл» для этого не требуется: смысл остаётся связью.

Из акорня видны четыре основные формы различённости бинарной связи:

```text
∞        оба полюса самозамкнуты
♂e       начало самозамкнуто, конец e различён
b♀       начало b различено, конец самозамкнут
b ⟼ e    оба полюса различены
```

Структурно:

```text
R = R ⟼ R      # ∞
S = S ⟼ e      # ♂e
E = b ⟼ E      # b♀
X = b ⟼ e      # b ⟼ e
```

Знаки `♂` и `♀` **не являются командами взять начало или конец**. Они остенсивно показывают самозамыкание соответствующего полюса:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

В конкретном акте интерпретации такая форма может участвовать в поиске, построении, проверке или разрешении недостающего полюса. Операция определяется актом и связями контекста, а не скрытым вторым значением знака.

Важно:

```text
самозамкнутая форма ≠ автоматически акорень
самозамкнутая форма ≠ автоматически незавершённая связь
```

## 2. Пять корневых связей

Текущий кандидат основания МТС использует пятисвязное корневое ядро:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

Первые различения вокруг акорня можно видеть непосредственно:

```text
[ → O = O ⟼ R ≡ ♂∞
] → C = R ⟼ C ≡ ∞♀
1 → L = O ⟼ C
0 → U = C ⟼ O
```

Поэтому `[ ] 1 0` — корневые абиты ачисел. Знаки `♂` и `♀` относятся уже к формальной записи форм самозамыкания. Эти уровни нельзя отождествлять.

## 3. Машинное представление идёт после остенсивного

После остенсивного определения связь можно представить нейтральной машинной структурой:

```text
Link(start, end)
```

Это представление для реализации, а не замена языка МТС.

В самой связи нет обязательных полей «контекст», «теория», «правило», «смысл» или «тип». Если роль существенна, она выражается другими связями сети.

## 4. Точное вхождение связи

Одинаковые полюса не означают тождество связей:

```text
P1 = A ⟼ B
P2 = A ⟼ B
P1 ≠ P2
```

То же относится к самозамкнутым формам:

```text
R = R ⟼ R
Q = Q ⟼ Q
R ≠ Q
```

Поэтому форма, положение в снимке памяти или физический адрес не заменяют тождество конкретного вхождения связи.

В эталонной реализации для этого используется `OccurrenceRef`; имя класса является технической деталью, а не понятием МТС.

## 5. Контекст является частью сети связей

Контекст не обязан существовать как скрытый стек среды исполнения:

```text
P = parent ⟼ current
K = K ⟼ P
```

`K` — конкретное вхождение состояния контекста.

Запись

```text
↑ = current(K)
```

означает получение текущей связи из явно указанного `K`, а не обращение к глобальной переменной.

Новое состояние создаётся новой связью; старое состояние не переписывается задним числом.

## 6. Исходная запись, словарь и теория различаются

Одна и та же последовательность байтов может встретиться несколько раз и получить разные значения в разных словарях. Поэтому различаются:

```text
содержимое исходной записи
конкретное вхождение исходной записи
выбранное разбиение
словарь D
форма F
допуск формы теорией T
```

Словарь также представляется сетью:

```text
D = D ⟼ (parentScope ⟼ localHistory)
```

Определение добавляет новое состояние словаря явно и сохраняет предыдущее состояние.

## 7. Наблюдение отделено от изменения

Критическая граница апамяти:

```text
читать / искать / разрешать / проверять
                    ≠
создавать / удалять / изменять
```

Поиск отсутствующей связи не создаёт её.

Материализация одной и той же пары может создать два разных вхождения:

```text
P1 = materialize(A,B)
P2 = materialize(A,B)
P1 ≠ P2
```

Индекс по паре полюсов служит поиску, но не определяет тождество связи.

## 8. Локальное равенство и правила вывода

Текущий кандидат локального равенства использует явного представителя в контексте:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Два элемента равны в `K`, когда их явно выбранные одношаговые представители являются одним и тем же точным вхождением.

Из этого **не следуют автоматически** глобальная подстановка, транзитивное замыкание, сравнение по форме всей сети или переписывание всех связанных выражений.

Дополнительное правило вывода должно быть отдельно допущено теорией:

```text
T ⟼ Rule
```

Поиск доказательства может быть сложным и эвристическим; доверенная часть только воспроизводит предъявленные точные связи и принимает либо отвергает результат.

## 9. Ачисла

Ачисла используют четыре корневых абита:

```text
[ ] 1 0
```

Акорень `∞` не является абитом: последовательность начинается относительно него.

Общая лестница получается такой:

```text
связь
→ акорень ∞
→ корневые различения [ ] 1 0
→ ачисла
→ строки
→ формальные знаки
→ словари и теории
→ интерпретация и вывод
```

При материализации последовательности:

```text
∞ A B C
```

создаются новые точные вхождения:

```text
A ⟼ B
B ⟼ C
```

Вложенная группа сначала строит внутреннюю связь и возвращает её как один элемент внешней последовательности.

Подробнее: [Ачисла и сериализация](docs/specs/Ачисла%20и%20сериализация.md).

## 10. Апамять

Апамять — контроллер сети связей. Она должна сохранять:

- множественность одинаковых пар полюсов;
- циклы;
- совместно используемые связи;
- различие чтения и изменения;
- тождество вхождений между сохранениями состояния.

Физический адрес записи в конкретном хранилище не является смыслом связи.

Подробнее: [Апамять и управление сетью связей](docs/specs/Апамять%20и%20управление%20сетью%20связей.md).

## Главный инвариант

```text
остенсивная форма
→ точное вхождение связи
→ явный контекст и свидетельства
→ ассоциативный поиск
→ детерминированная проверка
→ явное изменение памяти
```

`∞`, `♂`, `♀` и `⟼` — не украшение поверх машинной модели. Они делают фундаментальную структуру связи видимой в самой записи.
