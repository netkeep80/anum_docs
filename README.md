# Метатеория связей (МТС)

**Метатеория связей (МТС)** исследует системы, в которых единственным первичным видом сущности является **направленная связь**.

```text
всё есть связь
связь связывает связи
различима только рекурсия
```

## Остенсивное основание

Первичный теоретический слой МТС задаётся не конструктором языка реализации `Link(start,end)` и не буквенными уравнениями, а остенсивными формами связи:

```text
∞        полное самозамыкание
♂e       самозамыкание начала относительно уже различённого e
b♀       самозамыкание конца относительно уже различённого b
b ⟼ e    связь уже различённых полюсов
```

Структурные уравнения и технические имена являются вторичными точными проекциями этих форм:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R      # ♂∞
C = R ⟼ C      # ∞♀
L = O ⟼ C
U = C ⟼ O
```

Корневой четверичный словарь содержит ровно четыре абита:

```text
[ → O
] → C
1 → L
0 → U
```

`∞` — акорень, а не пятый абит. Машинное `Link(start,end)` — представление связи после определения её смысла, а не источник смыслового различия.

## Текущее состояние

**МТС v0.11** — текущий принятый выпуск.

**МТС v0.12** — непринятый кандидат. Ограниченная архитектурная сверка [#1167](https://github.com/netkeep80/anum_docs/issues/1167) завершена; её вывод сам по себе не является принятием v0.12. Уже слитое обязательное исполняемое свидетельство сохранения самозамыкания из [#1176](https://github.com/netkeep80/anum_docs/issues/1176) теперь перечисляется в кандидатном корпусе соответствия через [#1169](https://github.com/netkeep80/anum_docs/issues/1169). Жизненный цикл кандидата ведётся только в [#1134](https://github.com/netkeep80/anum_docs/issues/1134); `C7`, готовность и принятие остаются заблокированы до достаточного исполняемого свидетельства и последующего аудита жизненного цикла.

Файлы `mts-contract/v0.12` и `mts-conformance/v0.12` остаются машинными свидетельствами непринятого кандидата и не должны читаться как уже принятая теория. Текущая коррекция корпуса соответствия только перечисляет уже слитое обязательное исполняемое свидетельство; она не делает кандидат выбираемой средой, полным, готовым к принятию или принятым.

## Источники истины

```text
нормативная теория
      ↓
принятый машинный контракт
      ↓
корпус соответствия
      ↓
эталонная реализация
```

Реализация является свидетельством реализуемости, а не источником теории. Для непринятого кандидата его активная исследовательская задача или задача жизненного цикла может временно указывать, что машинные файлы кандидата требуют последующей коррекции; это не меняет принятое состояние.

Критические границы:

```text
смысловая Link != технический handle
source occurrence != resolved meaning
representation != interpretation
read / search / verify / replay != materialize / write
not found != does not exist
наличие Link T ⟼ Rule != независимое доверенное admission Rule
```

Текущее ядро находится в `ts/` и поставляется как `@mts/core`.

Основные проверки:

```bash
npm --prefix ts test
npm --prefix ts run docs:check
npm --prefix ts run check
```

Изменения активного дерева выполняются через запрос на слияние с обязательными CI и repo-guard согласно `repo-policy.json`.
