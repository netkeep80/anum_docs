# Натуральные числа, счёт и мера в МТС

> Статус: исследовательская глава. Accepted MTS v0.11 не изменяется этим текстом. Текущий Nat-кандидат должен быть отдельно доказан/фальсифицирован.

## 1. Почему натуральные числа требуют отдельного объяснения

В МТС нет скрытых типов, неявных единиц меры или математических сущностей, существующих «по умолчанию». Если различие важно, оно должно быть выражено фактической структурой Links и Anet.

Поэтому натуральное число нельзя вводить только как внешнюю метку `0,1,2,...`. Нужно объяснить, что именно структурно различается при счёте.

## 2. Нулевая граница и единица связи

Корневой базис содержит:

```text
L = O ⟼ C
U = C ⟼ O
```

В базовом чтении:

```text
L = linked / связь
U = unlinked / несвязь
```

Логические `true/false` являются контекстным чтением этих смыслов, а не обязательным определением.

Важно также не отождествлять автоматически:

```text
abit `1`
L
натуральное число 1
true
единицу измерения
```

Эти совпадения, если они нужны в конкретной теории, должны быть представлены и доказаны.

## 3. Протяжённость

Одна целая связь имеет начало и конец и потому задаёт единичную протяжённость. Несвязь задаёт нулевую границу — отсутствие протяжённости в данном различении.

Повторение отсутствия протяжённости не создаёт положительную протяжённость. Повторение же уже установленной единичной связи позволяет считать двойную, тройную и дальнейшую протяжённость.

Отсюда натуральное число разумно рассматривать не как точку координатной оси, а как меру протяжённости. Точка `n` на оси — лишь граница накопленной протяжённости от `0` до `n`.

## 4. Историческая connectivity-degree модель

Ранее исследовалась модель:

```text
0 = U
1 = L
2 = L ⟼ L
3 = (L ⟼ L) ⟼ L
...
```

Она естественно описывает степень связности и сохраняет предыдущую форму как структурный префикс. Но в ней `L` одновременно использовалась как сама единица связи и как натуральное число `1`. Кроме того, переход `0 -> 1` отличался от остальных successor-переходов, потому что:

```text
U ⟼ L != L
```

Поэтому единый successor требовал специального случая для нуля.

Эта модель остаётся важным historical/research evidence и не удаляется. Сейчас исследуется гипотеза, что она описывает скорее измеряемую connectivity-degree family, чем сам Nat carrier.

## 5. Новый Nat-кандидат

Главная гипотеза:

```text
N0 = U
N(n+1) = Nn ⟼ L
```

То есть:

```text
N0 = U
N1 = U ⟼ L
N2 = (U ⟼ L) ⟼ L
N3 = ((U ⟼ L) ⟼ L) ⟼ L
...
```

Здесь:

```text
U  = нулевая граница
L  = единица связной протяжённости
Nn = n единиц протяжённости, отсчитанных от нулевой границы
```

Это сразу даёт единый structural successor:

```text
Succ(N) = N ⟼ L
```

включая:

```text
Succ(N0) = U ⟼ L = N1
```

## 6. Почему L не обязана быть Nat(1)

`L` может быть тем, чем измеряется протяжённость, а `N1=U⟼L` — результатом одного применения этой меры от нулевой границы.

Аналогия:

```text
метр != 1 метр
```

В МТС различие не должно оставаться только словесным: оно отражается разными Link-формами.

## 7. Связь с аксиомами Пеано

Новая модель особенно интересна тем, что Peano-like конструкция возникает без специального zero-to-one перехода:

```text
Zero = U
Succ(N) = N ⟼ L
```

Но соответствие Пеано должно быть доказано, а не принято по сходству записи. Необходимы:

```text
closure
successor injectivity
zero is not successor
unique predecessor for non-zero Nat
no finite collapse/cycle
induction/minimality
initial 1+X algebra status
```

## 8. Степень связности как измеряемая величина

Старая последовательность:

```text
L
L ⟼ L
(L ⟼ L) ⟼ L
...
```

может быть сохранена как connectivity-degree structure.

Тогда вместо отождествления:

```text
Nat(n) = L-degree(n)
```

можно исследовать отношение:

```text
Degree(L-degree(n)) = Nn
```

Это разделяет объект измерения, единицу меры и результат измерения.

## 9. Кардинальное чтение

Для конечной Anet или последовательности различённых occurrences можно определить производное Count/Cardinality:

```text
Count(empty)     = N0
Count(singleton) = N1
Count(two)       = N2
...
```

При cardinal-like чтении конкретное содержание и допустимый порядок witness могут быть забыты, а количество сохранено.

Важно:

```text
semantic Link identity
!= occurrence identity
!= cardinal result
```

## 10. Ординальное чтение

Форма:

```text
N(n+1) = Nn ⟼ L
```

сохраняет предыдущий Nat как левый структурный префикс. Поэтому та же Nat-форма допускает ordinal-like чтение как достигнутая позиция после последовательных единичных продолжений.

МТС не обязана вводить primitive типы `Ordinal` и `Cardinal`. Более естественно хранить одну Nat-форму и различать её происхождение/роль связями окружающей Anet.

## 11. Арифметика

Если новый Nat carrier выдержит falsification, базовая рекурсивная арифметика должна быть перевыведена:

```text
Add(a,N0)=a
Add(a,Succ(b))=Succ(Add(a,b))

Mul(a,N0)=N0
Mul(a,Succ(b))=Add(Mul(a,b),a)
```

Порядок, Count, Degree и дальнейшие свойства также должны быть повторно проверены. Старые доказательства нельзя автоматически считать действующими только потому, что имена операций совпадают.

## 12. Граница accepted MTS и derived theory

На момент открытия исследования accepted MTS v0.11 фиксирует корневые Link identities и фундаментальные значения `L/U`, но Nat/Count/Peano arithmetic не обнаружены в accepted contract surface как самостоятельные semantic laws.

Поэтому текущий статус:

```text
accepted v0.11 = unchanged
active semantic candidate = NONE
new Nat model = derived-foundation hypothesis under falsification
```

После executable evidence необходимо отдельно определить:

```text
DERIVED_THEORY_CORRECTION_ONLY
```

или:

```text
OBSERVABLE_ACCEPTED_MTS_SEMANTIC_DELTA_REQUIRED
```

Только второй результат требует нового candidate lifecycle и решения о версии.

## 13. Принцип

Основной методологический вывод:

```text
в МТС нет умолчаний — только фактическая структура
```

Поэтому единица связи, натуральное число один, логическая истина, координата и единица измерения не должны сливаться только из-за привычной математической записи.

## 14. Nat как полигон для исчисления доказательств

Nat в МТС имеет двойную роль. С одной стороны, это фундаментальная производная математическая структура. С другой — это минимальный содержательный набор теорем, на котором удобно поэтапно строить proof calculus и математический аппарат aprover.

Поэтому программа развивается двумя связанными, но независимыми треками:

```text
TRACK N — структура и математическая истинность Nat (#1052)
TRACK P — proof Anet, replay, composition, reuse (#999)
SYNC    — theorem challenges (#1057)
```

Для каждой теоремы отдельно фиксируются три статуса:

```text
STRUCTURE = SUPPORTED | FALSIFIED | NOT TESTED
PROOF_ANET = SUPPORTED | GAP | NOT TESTED
REUSE = SUPPORTED | GAP | NOT TESTED
```

Это разделение принципиально. Если структурная теорема истинна, но текущий proof calculus не может выразить её доказательство, исправляется proof calculus, а не Nat. Если же структурный falsifier находит контрпример, нельзя усиливать prover ради сохранения неверной гипотезы.

Первая Peano-волна:

```text
T1 Zero / N0=U
T2 Succ closure
T3 Zero is not successor
T4 Successor injective
T5 Unique predecessor
```

T4 особенно важна как первый простой generic proof target:

```text
A ⟼ L = B ⟼ L
----------------
A = B
```

Она должна следовать из ordered-pole identity Links. После того как T4 будет не только структурно доказана, но и представлена как reusable proof Anet, T5 должна использовать именно это derived evidence, а не получать отдельное primitive admission.

Так Nat задаёт естественную лестницу развития конструктивного аппарата:

```text
Link identity
-> простое следствие
-> proof composition
-> reusable derived theorem
-> generic theorem/hypothesis
-> induction
-> recursive arithmetic
-> algebra
```

Индукция рассматривается только после появления первого reusable Peano proof suite. Она должна быть представима через общие MTS proof mechanisms, без trusted `InductionNode`, `forall`, `lambda`, `Predicate<T>` или Nat-specific opcode.

Текущая арифметическая лестница L0/L1/COMM остаётся на паузе до повторного входа через новую программу:

```text
W1 local Peano laws
W2 induction/minimality
W3 recursive Add
W4 elementary arithmetic
W5 addition commutativity
```

Таким образом proof calculus развивается под давлением реальных теорем МТС, а математическая теория Nat одновременно проверяется способностью строить явные proof Anets — без смешения двух видов авторитета.
