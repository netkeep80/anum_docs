# Система аксиом МТС

Статус: актуальное, нормативное.

Текущая машинная поверхность формул хранится в [`tests/mtc_formulas.mtc`](../../tests/mtc_formulas.mtc). Ниже приведены карточки **принятых определений/аксиом** корневого словаря; отдельный дублирующий свод формул не поддерживается.

Архитектурные уровни, L1-денотация и статусы утверждений задаются [Reference model МТС v0.1](../specs/Reference%20model%20МТС%20v0.1.md).

Важно различать:

```text
accepted axiom / definition
derived statement
conformance example
experimental hypothesis
```

Нахождение строки в `tests/mtc_formulas.mtc` само по себе не делает её новой аксиомой. Корневой fixture остаётся канонической машинной поверхностью текущей версии, но parser/interpreter/prover обязаны работать с явным логическим статусом утверждения.

Принятые взаимозависимые определения корневого словаря могут ссылаться друг на друга и рассматриваются совместно. Из этого не следует, что любой пример, равенство последовательностей или пучковая conformance-формула является отдельной аксиомой.

## A1. Акорень

Формула:

```text
∞ : [] = [] ⟼ []
[] = ∞
∞ = ∞ ⟼ ∞
```

Чтение:

```text
[] — минимальная завершённая форма одной связи
∞ — акорень
акорень несёт смысл смысла
```

Связь — единственная форма существования, поэтому акорень является связью полного самозамыкания. Reference model допускает конечный циклический carrier такой самоссылочной формы, но не превращает уравнение `∞ = ∞ ⟼ ∞` в неограниченное правило подстановки по всему языку.

## A2. Пустая круглая форма смысла

Формула:

```text
() : ♀() ⟼ ()♂
```

Чтение:

```text
() — минимальная формальная форма смысла
♀() — начало формальной формы смысла
()♂ — конец формальной формы смысла
```

Смысл не существует отдельно от связи: связь и есть смысл в своей различённой форме.

## A3. Смыслы квадратных абитов

Формулы:

```text
([) : (♀∞)
(]) : (∞♂)
```

Чтение:

```text
([) — смысл левого квадратного абита
(]) — смысл правого квадратного абита
```

В `([)` и `(])` квадратные скобки являются буквальными абитами внутри круглой формальной нотации.

## A4. Связь и несвязь

Формулы:

```text
(⟼) : (♀∞ ⟼ ∞♂)
(↛) : (∞♂ ⟼ ♀∞)
```

Чтение:

```text
(⟼) — смысл связи
(↛) — смысл несвязи
```

Несвязь не существует в натуре. Смысл несвязи выражается связью. Обратное направление связи не является отсутствием связи.

## A5. Квадратные формы абитов

Формулы:

```text
[1] : (⟼)
[0] : (↛)
```

Чтение:

```text
[1] — квадратная форма абита связи
[0] — квадратная форма абита несвязи
0 — абит связи, несущей смысл несвязи
```

Абит 0 не является отсутствием связи в натуре. Совпадение квадратных glyph в L2 и L3 не означает автоматического тождества: конкретное отображение формальной квадратной нотации в протокол ачисел относится к L3.

## A6. Начало и конец формы связи

Формулы:

```text
♀[] : ♀[] = ♀[] ⟼ []
[]♂ : []♂ = [] ⟼ []♂
```

Чтение:

```text
♀[] — начало формы связи
[]♂ — конец формы связи
```

Полюса формы связи записываются в актуальной ориентации: `♀F` — начало, `F♂` — конец. Старая ориентация `[]♀` и `♂[]` больше не является активной.

Для конкретной reference Link-структуры допустим конечный циклический carrier:

```text
start(F).start = start(F)
start(F).end = F

end(F).start = F
end(F).end = end(F)
```

Это инженерное представление самозамыкания и не определяет автоматически область подстановки оператора `=`.

## A7. Равенство

Формула:

```text
(=) : {♀[] = ♀[], []♂ = []♂}
(!=) : ¬(=)
```

Чтение:

Равенство вводится как формальный смысл сравнения соответствующих начал и концов формы. Повторные `♀[]` и `[]♂` являются позиционными вхождениями внутри локального шаблона; совпадение их текста не является само по себе глобальным binding.

**Полная метасемантика `=` пока не стабилизирована.** В частности, issue #79 должен формально определить:

```text
- когда повторные `[]` являются одним образцом после `:`;
- когда они являются разными позициями последовательности;
- чем отличаются form equality и denotational equality;
- когда `=` разрешает substitution;
- в какой области действует congruence конструктора `⟼`.
```

Поэтому текущая reference model не объявляет полный оператор `=` обычной бисимуляцией циклических Link-графов и не вводит неограниченную подстановку. Экспериментальный structural comparator конкретных уже материализованных Link-carriers может быть разработан отдельно, но он не тождественен L2-оператору `=` до решения #79.

`(!=)` вводится как инверсия смысла равенства `¬(=)` и используется в формулах различимости, например `{} != []`. Его полные proof/substitution-свойства также зависят от будущей формализации #79.
