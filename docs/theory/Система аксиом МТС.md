# 1. Почему остенсивность входит в основание

МТС нельзя свести к абстрактному API:

```text
Link(start,end)
```

так, чтобы потерять её собственную наглядную нотацию.

Foundation v2 исходит из того, что фундаментальные формы связи **показывают себя собственной записью**:

```text
∞
♂e
b♀
b ⟼ e
```

Machine carrier лишь реализует эту структуру.

Поэтому остенсивная форма находится в аксиоматическом изложении **до** программного представления.

---

# 2. A0 — онтологическая замкнутость

```text
всё есть связь
```

Любая семантически существенная сущность МТС должна быть представима связью или сетью связей.

Не вводятся как независимые обязательные примитивы:

```text
node
object
type
meaning
context
rule
stage
```

Если такое различение необходимо, оно выражается relations/evidence самой сети.

---

# 3. A1 — акорень

Существует **различённая** корневая occurrence — акорень:

```text
∞
```

Её остенсивная структура:

```text
∞ = ∞ ⟼ ∞
```

Акорень — полностью самозамкнутая связь.

Допустимое фундаментальное чтение:

> смысл смысла является связью смыслов; `∞` — различённая fixed point такого чтения.

Из A1 не следует существование внешнего primitive `Meaning(x)`.

Также A1 не утверждает, что любая occurrence формы:

```text
X = X ⟼ X
```

тождественна акорню.

---

# 4. A2 — четыре остенсивные формы различённости

Для полюсов `b` и `e` базовые формы:

```text
∞        оба внешних полюса не различены;
♂e       e различён, начало самозамкнуто;
b♀       b различён, конец самозамкнут;
b ⟼ e    оба полюса различены.
```

Структурно:

```text
R = R ⟼ R      # ∞
S = S ⟼ e      # ♂e
E = b ⟼ E      # b♀
X = b ⟼ e      # complete relation
```

Знаки `♂` и `♀` обозначают **самозамыкание**, а не host projection functions.

Следовательно, недопустимы фундаментальные определения:

```text
♂ = getStart
♀ = getEnd
♂ = constructor opcode
♀ = destructor opcode
```

Operational direction определяется explicit resolution act.

---

# 5. A3 — самозамыкание не является типом состояния

Самозамкнутая relation может быть:

- остенсивной partial form в одном resolution act;
- полностью известным payload в другом отношении;
- distinguished root occurrence, если это exact `∞`;
- другой exact self-cycle, не являющийся корнем.

Поэтому:

```text
shape(self-closed)
```

не создаёт host enum вроде:

```text
INCOMPLETE
ROOT
PLACEHOLDER
```

Роль следует из exact occurrence + explicit context/evidence.

---

# 6. A4 — бинарность и направленность

Каждая complete relation имеет два упорядоченных полюса:

```text
X = b ⟼ e
```

Направление существенно:

```text
b ⟼ e
```

и

```text
e ⟼ b
```

не отождествляются автоматически.

Partial forms сохраняют ту же ориентацию:

```text
♂e = S ⟼ e
b♀ = b ⟼ E
```

---

# 7. A5 — пятисвязный корневой bootstrap

Foundation v2 различает конечный root kernel:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Root vocabulary:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

Остенсивная связь между уровнями:

```text
O = O ⟼ R  ≡  ♂∞
C = R ⟼ C  ≡  ∞♀
```

`[ ] 1 0` — различённые root-derived bootstrap/serialization meanings. Они не являются host token types и не тождественны source glyphs `♂/♀`.

---

# 8. A6 — exact occurrence identity

Существование relation определяется exact occurrence, а не только формой.

```text
P1 = A ⟼ B
P2 = A ⟼ B

P1 ≠ P2
```

То же относится к partial forms:

```text
S1 = S1 ⟼ e
S2 = S2 ⟼ e

S1 ≠ S2
```

Обе могут соответствовать ostensive pattern `♂e`, но trusted evidence обязано выбирать конкретную occurrence.

Отсюда:

```text
ostensive form != occurrence identity
```

---

# 9. A7 — форма сети не задаёт универсальное тождество

Ни самозамкнутая shape, ни pair shape, ни graph isomorphism не заменяют exact identity.

```text
R = R ⟼ R
Q = Q ⟼ Q
```

не влечёт:

```text
R = Q
```

Аналогично одинаковая topology двух независимых persistent datasets не делает их occurrences одной identity.

---

# 10. A8 — structural declaration отделена от resolution

Остенсивная форма декларативна.

Например:

```text
♂e
```

сама по себе не диктует одну процедуру.

В зависимости от explicit bindings/evidence один act может:

```text
искать b⟼e;
проверять предъявленный b⟼e;
разрешать недостающий b;
использовать exact S=S⟼e как ordinary payload.
```

Поэтому:

```text
form != opcode
```

и constructor/destructor/check/search являются направлениями relation resolution, а не вторыми intrinsic meanings `♂/♀/⟼`.

---

# 11. A9 — контекст выражается сетью

Active context не требует hidden host stack:

```text
P = parent ⟼ current
K = K ⟼ P
```

`K` — exact occurrence снимка.

```text
↑ = current(K)
```

`current` может быть:

```text
∞
♂e
b♀
b⟼e
```

Переход создаёт новый `K_after`, не мутируя `K_before`.

---

# 12. A10 — source, ostensive form и semantic occurrence различны

Source glyph сам не является semantic authority.

```text
UTF-8 `♂`
```

должен пройти explicit chain:

```text
bytes
→ canonical content
→ source occurrence
→ segmentation
→ D resolution
→ G/T admission
→ exact self-closed form
```

Поэтому:

```text
source spelling != semantic occurrence
```

Аналогично `[ ] 1 0` как source characters не создают root kernel — bootstrap meanings логически предшествуют string notation.

---

# 13. A11 — словарь и теория explicit

Словарь `D` и теория `T` сами представлены networks.

Пример dictionary state:

```text
D = D ⟼ (parentScope ⟼ localHistory)
```

Пример theory admission:

```text
T ⟼ Form
T ⟼ Rule
```

Никакой host-global symbol map или theorem table не является семантической истиной сам по себе.

---

# 14. A12 — `:` является explicit persistent effect

Definition occurrence связывает source content с form через explicit state transition.

```text
Entry      = sourceContent ⟼ form
Occurrence = D_before ⟼ Entry
H_after    = H_before ⟼ Occurrence
D_after    = D_after ⟼ (sameParent ⟼ H_after)
```

`:` не эквивалентен:

```text
=
host assignment
theorem assertion
```

---

# 15. A13 — read/replay отделены от materialization

```text
read / find / resolve / replay
        ≠
materialize / define / persist transition
```

В частности ostensive query:

```text
♂e + binding b
```

не обязано материализовать `b⟼e`.

Search может вернуть существующие exact candidates; materialization требует отдельного explicit effect.

---

# 16. A14 — локальное равенство не уничтожает exact различённость

Foundation-v2 equality использует explicit representatives:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

```text
Equal_K(a,b)
⇔ rep_K(a) is rep_K(b)
```

Не выводятся автоматически:

```text
transitive closure
substitution
congruence
recursive shape equality
graph isomorphism equality
```

Отдельное inference rule требует explicit:

```text
T ⟼ Rule
```

---

# 17. A15 — actual act отличен от возможности действия

Нужно различать:

```text
I — interpreter / capability
A — actual occurrence конкретного interpretation act
```

`A` фиксирует exact source/form/D/G/T/K/binding/result evidence.

Таким образом процедура поиска может быть недоверенной, а selected act — независимо replayable.

---

# 18. A16 — последовательность acts имеет exact provenance

```text
Run_0     = R
Run_(i+1) = Run_i ⟼ A_i
```

Соседние acts требуют exact continuity:

```text
A_i.after is A_(i+1).before
```

Run хранит порядок/provenance, но не создаёт логическую транзитивность автоматически.

---

# 19. A17 — arbitrary networks остаются конечными native asets

Foundation v2 допускает:

```text
cycles
sharing
duplicate pairs
multiple self-closed occurrences
```

Recursive Anum является root-relative structural description на своей accepted occurrence-tree области, но не universal identity для arbitrary shared/cyclic network.

Exact revisit останавливает traversal; shape equality не используется как условие semantic identity.

---

# 20. A18 — persistent identity не является physical address

Persistent backend обязан различать:

```text
logical occurrence identity within dataset lineage
physical record/address
snapshot-local transport slot
runtime ref
```

Reopen того же dataset сохраняет logical occurrence identity.

Fresh import той же topology создаёт новый lineage, если отдельный replication contract не утверждает иное.

---

# 21. Историческая граница `♀F / F♂`

Historical accepted v0.2–v0.5 формальная нотация использовала projection-oriented spelling:

```text
♀F
F♂
```

Эта запись остаётся воспроизводимой в исторических contracts.

**Она не является Foundation-v2 определением self-closure.**

Foundation-v2 ostensive orientation:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

То есть перенос исторических projection glyph semantics в новую foundation запрещён.

---

# 22. Историческая корневая программа v0.2–v0.5

Десятиформульная historical root program и published contracts `mts-contract/v0.2` … `v0.5` сохраняются как принятая воспроизводимая линия.

Foundation v2 не переписывает её задним числом.

Но historical parser/typed AST/`ContextFrame`/projection semantics не должны подменять новую аксиоматическую основу.

В сжатом виде:

```text

A4  бинарность и направленность

A7  shape/isomorphism != identity
A8  declaration != resolution opcode
A9  explicit K / ↑

```

## Основной инвариант

Foundation v2 должна оставаться узнаваемой как МТС не только в storage topology, но и в способе изложения:

```text
∞
↓
∞ / ♂e / b♀ / b⟼e
↓
exact binary relation network
↓
explicit context/evidence
↓
resolution / replay / materialization
```

Если остенсивные `∞`, `♂`, `♀` исчезают и теория начинается только с `Link(start,end)`, теряется важная часть самого основания: **структура перестаёт быть показана и начинает только внешне описываться**.
