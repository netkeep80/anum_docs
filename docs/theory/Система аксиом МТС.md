# Система аксиом МТС

Этот документ фиксирует компактный нормативный набор обязательств принятого основания МТС. Текущий машинный выпуск — **MTS v0.9**; его `semanticBase` — MTS v0.8, а `observableSemanticDelta = true`. Мотивация и разъяснения находятся в [Основаниях МТС](Основания%20МТС.md).

Исторические версии сохраняются Git и не определяют текущую семантику автоматически; будущие расширения требуют отдельного решения.

## А0. Онтологическая замкнутость

```text
всё есть связь
```

Любое семантически существенное различие должно быть выражаемо связью или сетью связей.

**Несвязь не вводится как отдельный вид существующего**. Её смысл может быть представлен связью, но это не превращает отсутствие связности во вторую первичную сущность.

В корневом базисе:

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
0 ≠ DELETE_LINK
```

## А1. Самозамыкание является первичным источником различения

МТС не начинает с заранее различённых ID связей. Первичное различение возникает из остенсивного рисунка самозамыкания полюсов.

Четыре формы в теоретической метанотации:

```text
∞
♂e
b♀
b ⟼ e
```

Структурно:

```text
R = R ⟼ R
S = S ⟼ e
E = b ⟼ E
X = b ⟼ e
```

Несамозамкнутый полюс должен быть уже различён самозамыканием или связанностью с ранее различёнными связями.

`♂` и `♀` здесь являются остенсивной метанотацией теории. В принятом F1 MTS v0.9 они не входят в минимальный внутренний реестр знаков и остаются отложенными.

## А2. Акорень единственен

Существует ровно одна полностью самозамкнутая связь — акорень:

```text
∞
R = ∞
R = R ⟼ R
```

Если:

```text
X = X ⟼ X
```

то:

```text
X = R = ∞
```

Номер записи, адрес памяти, слот или временная ссылка построения не могут различить несколько полностью самозамкнутых связей.

## А3. Однополюсное самозамыкание различает ориентацию

Для уже различённого `e`:

```text
♂e = S = S ⟼ e
```

Для уже различённого `b`:

```text
b♀ = E = b ⟼ E
```

`♂` и `♀` не являются командами получения начала или конца. Они остенсивно показывают, какой полюс замкнут на саму связь.

Для одного и того же различённого внешнего полюса соответствующая однополюсная форма единственна.

## А4. Бинарность и направленность

Полная связь имеет два упорядоченных уже различённых полюса:

```text
X = b ⟼ e
```

В общем случае:

```text
b ⟼ e ≠ e ⟼ b
```

если порядок различённых полюсов действительно изменился.

## А5. Пятисвязный корневой базис

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

Остенсивное чтение в метаязыке:

```text
O = O ⟼ R   # ♂∞
C = R ⟼ C   # ∞♀
```

`[ ] 1 0` — ровно четыре корневых абита. `∞` является основанием их различения, а не пятым абитом.

Минимальный **внутренний F1-реестр MTS v0.9** содержит ровно:

```text
∞ [ ] 1 0 ( ) ⟼ : =
```

Отложены как внутренние знаки:

```text
≡ ♂ ♀ ↑ { } ¬ ↛
```

Только в метаязыке используются:

```text
∧ ⇔ ⇒ ≠ →
```

Таким образом остенсивная теоретическая запись не обязана один-в-один совпадать с текущим внутренним алфавитом самовведения F1.

## А6. Тождество связи определяется полюсами

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Следовательно:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=> P1 = P2
```

В МТС не существует двух различных смысловых связей с одной и той же упорядоченной парой уже различённых полюсов.

Важно: А6 не означает сравнение сырых технических указателей. Сами `A`, `B`, `C`, `D` должны быть различены по А1–А5 либо через последующую связанность с уже различённой структурой.

F2/F3 дополнительно выводят это свойство из конечной рекурсивно заземлённой формы, а не используют runtime identity как основание доказательства.

## А7. Различимость распространяется от корня

Нормативная цепочка:

```text
самозамыкание
→ R
→ O / C
→ L / U
→ связи с уже различёнными полюсами
→ дальнейшая асеть
```

Технический ID не входит в эту цепочку.

Если две физические записи нельзя структурно различить относительно уже различённого основания, они не образуют две смысловые связи МТС.

## А8. Петля отличается от полного самозамыкания

Для данного `a`:

```text
Loop(a) = a ⟼ a
```

задаёт единственную связь этой пары.

Обычно:

```text
Loop(a) ≠ a
```

Но если:

```text
a = a ⟼ a
```

то это уже полное самозамыкание и по А2:

```text
a = R = ∞
```

В частности:

```text
Loop(R) = R
```

### Следствие А2 + А6. Взаимное самозамыкание `♂♀` схлопывается в акорень

Запись `♂♀` здесь не означает последовательное применение двух операторов и не вводит самостоятельные связи `♂` и `♀`. Это краткое обозначение **замкнутого остенсивного шаблона без внешнего уже различённого полюса**.

Временно обозначим связь, несущую самозамыкание начала, через `y`, а связь, несущую самозамыкание конца, через `x`:

```text
y = ♂x
x = y♀
```

На уровне полюсов это одна замкнутая система:

```text
y = y ⟼ x
x = y ⟼ x
```

У `x` и `y` совпадает одна и та же упорядоченная пара полюсов `(y, x)`. По А6:

```text
x = y
```

Обозначим эту единственную связь через `z`. Подстановка даёт:

```text
z = z ⟼ z
```

По А2 полностью самозамкнутая связь единственна, следовательно:

```text
z = R = ∞
```

и тем самым:

```text
♂♀ = ∞
```

Это не противоречит А3. Формы `♂e` и `b♀` являются однополюсными только пока второй полюс действительно внешне различён относительно самой связи. В замкнутом шаблоне `♂♀` попытка сделать два полюса взаимным основанием различения устраняет это различие и переводит систему в более специальный случай полного самозамыкания.

Следствие также запрещает трактовать два технических ID такой системы как две смысловые связи: ID не может предотвратить схлопывание по А6 и не создаёт второй акорень.

### Производная конструкция: конечная левая итерация связи

Для уже различённой связи `a` вводится **только как внешняя метанотация** положительная конечная степень:

```text
a¹ = a
aⁿ⁺¹ = aⁿ ⟼ a,  n >= 1
```

То есть:

```text
a² = a ⟼ a = Loop(a)
a³ = (a ⟼ a) ⟼ a
a⁴ = ((a ⟼ a) ⟼ a) ⟼ a
```

Рекурсия фиксирует левоассоциативность: на каждом шаге предыдущий результат является началом, а исходный `a` — концом новой связи.

`n` здесь принадлежит метаязыку описания конечного числа шагов. Это **не** внутреннее определение натурального числа МТС. В частности, `a⁰` и `a^∞` этой конструкцией не определяются.

По А6 каждый следующий шаг однозначен. Если два вычисления начинают с одной и той же `a` и выполняют одинаковое конечное число шагов, они получают одну и ту же смысловую связь; отдельное тождество вычислительного употребления не возникает.

Для акорня:

```text
R¹ = R
Rⁿ⁺¹ = Rⁿ ⟼ R
```

и по индукции на внешнем конечном индексе:

```text
Rⁿ = R,  n >= 1
```

поскольку базовый случай равен `R`, а шаг сводится к `R ⟼ R = R`.

### Производный результат F5: натуральный счёт как степень связности `L`

Предыдущая нормативная специализация через `C` (`N0=R`, `N1=C`, `S(n)=n⟼C`, `Nat_C`) признана ошибочной и не является частью принятой системы аксиом.

Завершённый F5-результат использует:

```text
0 → U = C ⟼ O
1 → L = O ⟼ C

D1 = L
D2 = L ⟼ L
D3 = (L ⟼ L) ⟼ L
D4 = ((L ⟼ L) ⟼ L) ⟼ L
...
```

Положительный носитель:

```text
L ∈ Pos
D ∈ Pos => D ⟼ L ∈ Pos
```

и:

```text
Nat+ = Pos
Nat0 = {U} ∪ Pos
```

Критически:

```text
U ⟼ L ≠ L
```

поэтому единственный primitive successor `x ↦ x⟼L` не работает от нуля. Производный Peano-successor задаётся кусочно:

```text
S0(U) = L
S0(D) = D ⟼ L,  D ∈ Pos
```

F3-normal-form identity даёт pairwise distinct finite degrees, единственного predecessor, отсутствие finite positive cycles и injectivity successor. Поэтому точный статус результата:

```text
connectivity-degree algebra
→ derived Peano algebra
```

Это **производная теория**, а не новый root primitive и не изменение F1 machine alphabet.

### Count считает вхождения, а не semantic copies

Generic `Count` применяется к явно структурно различённым occurrence/provenance-позициям:

```text
Count(empty) = U
one occurrence -> L
next occurrence -> S0(previous degree)
```

Одна semantic Link может быть посчитана несколько раз только через разные структурные позиции. Поэтому:

```text
semantic Link identity
!= occurrence identity
!= cardinality degree
```

Результат cardinality инвариантен относительно допустимого переупорядочивания конечного набора вхождений, хотя конкретная история/порядок свидетельств может различаться.

## А9. Роли выражаются связями

Примитивная связь имеет только начало и конец. Тип, теория, правило, контекст или роль не являются скрытыми обязательными полями примитива.

Например:

```text
T ⟼ Rule
```

выражает допуск правила самой связевой структурой.

## А10. Форма отделена от действия

```text
форма ≠ команда
```

Поиск, проверка, разрешение и материализация являются различными актами. Разные акты получения одной формы не создают несколько экземпляров результирующей связи.

Наличие `Rule` как данных также не означает автоматического исполнения: выполнение требует явного Interpreter/Act/context.

## А11. Контекст явен

В MTS v0.9 accepted structural context записывается:

```text
P = parent ⟼ current
K = K ⟼ P
I ⟼ K
```

`current(K)` допустимо только как внешняя метанотация чтения структуры `K`. Отдельный знак `↑` в F1 v0.9 не принят и остаётся отложенным.

Лексическая вложенность принадлежит `K.parent`, а временной порядок актов — Run/Act. OPEN/CLOSE и parent continuation являются явными структурными переходами, а не скрытым host stack.

Повтор той же полной формы `K` обозначает ту же связь. Если требуется различить два момента использования одного контекста, различие должно находиться в структуре истории актов.

## А12. Исходная запись отделена от формы

```text
точные bytes
→ canonical per-byte STRING→QUATERNARY carrier
→ связевое представление источника
→ позиция / история употребления
→ словарь D
→ грамматика G
→ теория T
→ форма F
```

Для каждого byte используется один `[8 bits]` carrier. Unicode normalization не является скрытой частью основания, а runtime byte ID не создаёт semantic identity.

Написание знака не является самостоятельным семантическим авторитетом: representation, interpretation и denotation различаются.

## А13. Словарь и история явны

Состояние словаря может быть выражено:

```text
D = D ⟼ (parentScope ⟼ localHistory)
```

Определение:

```text
Entry      = sourceContent ⟼ form
Definition = D_before ⟼ Entry
H_after    = H_before ⟼ Definition
D_after    = D_after ⟼ (parentScope ⟼ H_after)
```

Повтор уже существующей пары не создаёт копию связи. Если два события определения должны различаться, их различает структура предшествующей истории.

## А14. Чтение отделено от изменения

```text
читать / искать / разрешать / проверять / воспроизводить
                    ≠
создавать / удалять / изменять
```

Критически:

```text
не найдено ≠ не существует
find ≠ materialize
```

Семантическая однозначность связи не означает, что её физическая запись уже присутствует в конкретной апамяти.

## А15. Локальное отношение представителей не заменяет А6

Дополнительное контекстное отношение может быть выражено:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Оно не переопределяет фундаментальное тождество связи и не вводит автоматически глобальную подстановку, транзитивное замыкание или конгруэнтность.

## А16. Правило вывода требует явного допуска

```text
Rule = DR ⟼ Body
T ⟼ Rule
```

Правило не становится частью МТС только потому, что удобно реализации. Structural Rule replay в accepted v0.9 является read-only и опирается на явные роли/допуск.

## А17. Акт, вычислитель и результат различаются структурно

Следует различать:

```text
I — вычислитель
A — акт
R — результат
```

Разные акты могут иметь один результат, но различие актов должно быть выражено их собственной связевой структурой или историей, а не скрытым номером экземпляра.

Временной порядок принадлежит явной структуре Run. Повтор одного и того же semantic Act в разных позициях не создаёт новую semantic Link акта; позиционность задаётся структурой истории.

## А18. Циклы допустимы только при структурной различимости

Асеть может содержать:

- однополюсное самозамыкание;
- петли `a ⟼ a`;
- совместное использование одной связи;
- повтор ссылок в последовательности;
- взаимные циклы, **если их элементы уже структурно различимы относительно корневого основания**.

Нельзя создать смысловое различие взаимного цикла только предварительной выдачей двум записям разных технических ID.

## А19. Физический адрес не является тождеством связи

Различаются:

```text
оперативный адрес
долговременный адрес
номер записи в снимке
смысловая связь
```

Перемещение записи не меняет связь. Несколько физических записей одной структурно неразличимой формы должны быть канонизированы либо отклонены на границе импорта.

Произвольный физический граф поэтому не тождественен готовой асети МТС:

```text
physical graph
→ structural canonicalization
→ semantic MTS network
```

## А20. Остенсивность предшествует машинному представлению

Правильный порядок:

```text
∞ / ♂e / b♀ / b⟼e
→ структурное различение
→ тождество по полюсам
→ Link(start,end)
```

`Link(start,end)` является техническим носителем уже понятой структуры, а не источником первичного тождества.

## F2/F3: рекурсивно заземлённая форма и no-instance

Для конечных proof-форм используются:

```text
ROOT
START(F)
END(F)
PAIR(F,G)
```

с наименьшим конечным fold/unfold relation `≈` и alpha-neutral normal form.

Из этого выведено:

```text
нет рекурсивно выраженного различия
=> нет двух semantic Links
```

а также unique full selfclosure, one-sided uniqueness и ordered-pole identity в обе стороны.

Поэтому semantic Link не тождественна occurrence, source position, runtime handle, UUID или storage row.

## F4: внутренняя рекурсивная реверсия

Производная anti-operation `J`:

```text
J(R)=R
J(O)=C
J(C)=O
J(L)=L
J(U)=U
```

Она involutive и отличается от простой перестановки полюсов `P`, navigation converse, logical negation и unconnection. В частности:

```text
P(L)=U
P(U)=L
```

но:

```text
J(L)=L
J(U)=U
```

## F6: производные теории не переопределяют корень

Коллекции, функции-данные, relative navigation и application interpretations строятся только как derived theory/context structures поверх ordinary Links и explicit occurrence/provenance evidence.

Они не вводят новые root sorts. В частности:

```text
semantic Link
!= occurrence
!= collection member instance
!= function invocation
!= navigation coordinate
!= application event
```

И для всех open-world derived reads сохраняется:

```text
not found
!= empty
!= does not exist
```

если отсутствует explicit closure evidence.

## Историческая граница

В принятой версии 0.2 использовались обозначения:

```text
♀F / F♂
```

Они относятся к исторической проекционной семантике и не определяют текущее самозамыкание.

Текущая остенсивная теоретическая ориентация:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

При этом `♂`/`♀` остаются deferred как внутренние F1 signs v0.9.
