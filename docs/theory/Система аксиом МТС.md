# Система аксиом МТС

Этот документ фиксирует компактный нормативный набор обязательств принятого основания МТС. Текущий машинный выпуск — **МТС v0.9**; его `semanticBase` — `mts-contract/v0.8`, а `observableSemanticDelta = true`. Мотивация и разъяснения находятся в [Основаниях МТС](Основания%20МТС.md).

Исторические версии сохраняются в Git и не определяют текущую семантику автоматически.

## А0. Онтологическая замкнутость

```text
всё есть связь
```

Любое семантически существенное различие должно быть выражаемо связью или сетью связей.

Несвязь не вводится как отдельный вид существующего:

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
0 ≠ DELETE_LINK
```

## А1. Самозамыкание является первичным источником различения

МТС не начинает с заранее различённых идентификаторов связей. Первичное различение возникает из остенсивного рисунка самозамыкания полюсов.

В теоретической метанотации:

```text
∞
♂e
b♀
b ⟼ e
```

Структурно:

```text
R = R ⟼ R
S = S ⟼ e
E = b ⟼ E
X = b ⟼ e
```

Несамозамкнутый полюс должен быть уже различён самозамыканием или связанностью с ранее различёнными связями.

`♂` и `♀` здесь являются остенсивной метанотацией. В принятом F1 МТС v0.9 они не входят в минимальный внутренний реестр и остаются отложенными.

## А2. Акорень единственен

```text
∞
R = ∞
R = R ⟼ R
```

Если:

```text
X = X ⟼ X
```

то:

```text
X = R = ∞
```

Номер записи, адрес памяти, слот или временная ссылка построения не могут различить несколько полностью самозамкнутых смысловых связей.

## А3. Однополюсное самозамыкание различает ориентацию

Для уже различённого `e`:

```text
♂e = S = S ⟼ e
```

Для уже различённого `b`:

```text
b♀ = E = b ⟼ E
```

`♂` и `♀` не являются командами получения начала или конца. Они остенсивно показывают, какой полюс замкнут на саму связь.

Для одного и того же различённого внешнего полюса соответствующая однополюсная форма единственна.

## А4. Бинарность и направленность

```text
X = b ⟼ e
```

Полная связь имеет два упорядоченных уже различённых полюса.

В общем случае:

```text
b ⟼ e ≠ e ⟼ b
```

если порядок действительно изменился.

## А5. Пятисвязный корневой базис

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

`[ ] 1 0` — ровно четыре корневых абита. `∞` является основанием их различения, а не пятым абитом.

Минимальный внутренний реестр F1 МТС v0.9:

```text
∞ [ ] 1 0 ( ) ⟼ : =
```

Отложены:

```text
≡ ♂ ♀ ↑ { } ¬ ↛
```

Только метаязык:

```text
∧ ⇔ ⇒ ≠ →
```

## А6. Тождество связи определяется полюсами

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Следовательно:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=> P1 = P2
```

Технические указатели не участвуют в смысловом тождестве. Сами полюса должны быть структурно различены относительно основания.

## А7. Различимость распространяется от корня

```text
самозамыкание
→ R
→ O / C
→ L / U
→ связи с уже различёнными полюсами
→ дальнейшая асеть
```

Технический идентификатор не входит в эту цепочку.

## А8. Петля отличается от полного самозамыкания

```text
Loop(a) = a ⟼ a
```

Обычно:

```text
Loop(a) ≠ a
```

Но если:

```text
a = a ⟼ a
```

то:

```text
a = R = ∞
```

В частности:

```text
Loop(R) = R
```

### Следствие: `♂♀ = ∞`

Пусть:

```text
y = y ⟼ x
x = y ⟼ x
```

Обе предполагаемые связи имеют одну и ту же упорядоченную пару полюсов. По А6:

```text
x = y
```

После подстановки:

```text
x = x ⟼ x
```

и по А2:

```text
♂♀ = ∞
```

Это вывод для остенсивной метанотации и не принимает `♂`/`♀` как внутренние знаки F1.

### Конечная левая итерация

Для уже различённой связи `a` допустима внешняя метанотация:

```text
a¹ = a
aⁿ⁺¹ = aⁿ ⟼ a,  n >= 1
```

Она задаёт левоориентированную конечную последовательность:

```text
a² = a ⟼ a
a³ = (a ⟼ a) ⟼ a
a⁴ = ((a ⟼ a) ⟼ a) ⟼ a
```

`n` принадлежит метаязыку и не является внутренним числом МТС.

Для акорня:

```text
Rⁿ = R, n >= 1
```

## А9. Роли выражаются связями

Примитивная связь имеет только начало и конец. Тип, теория, правило, контекст или роль не являются скрытыми обязательными полями примитива.

Например:

```text
T ⟼ Rule
```

выражает допуск правила самой связевой структурой.

## А10. Форма отделена от действия

```text
форма ≠ команда
```

Поиск, проверка, разрешение и материализация являются различными актами. Наличие правила как данных не означает автоматического выполнения.

## А11. Контекст явен

В МТС v0.9:

```text
P = parent ⟼ current
K = K ⟼ P
I ⟼ K
```

`current(K)` — внешняя метанотация. Отдельный знак `↑` в F1 v0.9 не принят.

Лексическая вложенность хранится через `K.parent`, временной порядок — через `Run`/`Act`. Открытие, закрытие и продолжение родителя являются явными структурными переходами.

## А12. Исходная запись отделена от формы

```text
точные байты
→ канонический носитель STRING→QUATERNARY
→ связевое представление источника
→ позиция / история употребления
→ словарь D
→ грамматика G
→ теория T
→ форма F
```

Для каждого байта используется один `[8 bits]`-конверт. Нормализация `Unicode` не является скрытой частью основания.

Представление, интерпретация и денотация различаются.

## А13. Словарь и история явны

```text
D = D ⟼ (parentScope ⟼ localHistory)
```

Например:

```text
Entry      = sourceContent ⟼ form
Definition = D_before ⟼ Entry
H_after    = H_before ⟼ Definition
D_after    = D_after ⟼ (parentScope ⟼ H_after)
```

Если два события определения должны различаться, это различие хранится в истории, а не в техническом экземпляре одной пары.

## А14. Чтение отделено от изменения

```text
читать / искать / разрешать / проверять / воспроизводить
                    ≠
создавать / удалять / изменять
```

```text
не найдено ≠ не существует
find ≠ materialize
```

## А15. Локальное отношение представителей не заменяет А6

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Это дополнительное контекстное отношение. Оно не переопределяет фундаментальное тождество связи и не вводит автоматически глобальную подстановку или транзитивное замыкание.

## А16. Правило вывода требует явного допуска

```text
Rule = DR ⟼ Body
T ⟼ Rule
```

Правило не становится частью МТС только потому, что удобно реализации. Проверка структурного правила выполняется только чтением.

## А17. Акт, интерпретатор и результат различаются

Нужно различать:

```text
I — интерпретатор
A — акт
R — результат
```

Разные акты могут иметь один результат, но различие актов должно быть выражено связевой структурой истории, а не скрытым номером экземпляра.

## А18. Циклы допустимы только при структурной различимости

Асеть может содержать самозамыкания, петли, совместное использование и взаимные циклы, если их элементы уже структурно различимы относительно корневого основания.

Нельзя создать смысловое различие взаимного цикла только предварительной выдачей разных технических идентификаторов.

## А19. Физический адрес не является тождеством связи

Различаются:

```text
оперативный адрес
долговременный адрес
номер записи в снимке
смысловая связь
```

Перемещение записи не меняет связь. Несколько физических записей одной структурно неразличимой формы канонизируются либо отклоняются.

## А20. Остенсивность предшествует машинному представлению

```text
∞ / ♂e / b♀ / b⟼e
→ структурное различение
→ тождество по полюсам
→ Link(start,end)
```

`Link(start,end)` является техническим носителем уже понятой структуры, а не источником первичного тождества.

# Производные результаты основания

## F2/F3. Рекурсивно заземлённая форма и отсутствие смысловых экземпляров

Внешние формы доказательства:

```text
ROOT
START(F)
END(F)
PAIR(F,G)
```

связываются наименьшим конечным отношением `≈`.

Для каждого класса существует одна нейтральная к именам нормальная форма.

Отсюда выведено:

```text
нет рекурсивно выраженного различия
=> нет двух смысловых связей
```

Следствия:

- единственный полностью самозамкнутый корень;
- единственная однополюсная форма при фиксированном внешнем полюсе;
- тождество полной связи по упорядоченным полюсам в обе стороны;
- псевдонимы не создают множественность;
- смысловая связь не равна вхождению, позиции, истории, технической ссылке или записи хранения.

## F4. Рекурсивная реверсия

Производная операция `J`:

```text
J(R)=R
J(O)=C
J(C)=O
J(L)=L
J(U)=U
```

Она является инволюцией и антиоперацией относительно `⟼`.

Простая перестановка полюсов `P` отличается:

```text
P(L)=U
P(U)=L
```

Поэтому рекурсивная реверсия, перестановка полюсов, обратное отношение навигации, логическое отрицание и несвязь — разные понятия.

## F5. Счёт по степени связности

Корневой словарь:

```text
0 -> U
1 -> L
```

Положительные степени:

```text
D1 = L
D2 = L ⟼ L
D3 = (L ⟼ L) ⟼ L
D4 = ((L ⟼ L) ⟼ L) ⟼ L
...
```

```text
L ∈ Pos
D ∈ Pos => D ⟼ L ∈ Pos
```

Из F3 следует, что конечные положительные степени попарно различны, имеют единственного предшественника и не образуют конечных положительных циклов.

Критически:

```text
U ⟼ L != L
```

Поэтому производный следующий элемент задаётся:

```text
S0(U) = L
S0(D) = D ⟼ L, D∈Pos
```

И точный результат:

```text
алгебра степеней связности
→ производная алгебра Пеано
```

### Счёт относится к вхождениям

```text
Count(empty)=U
one occurrence -> L
next occurrence -> S0(previous degree)
```

Одна смысловая связь может считаться несколько раз только через разные структурные вхождения.

```text
тождество смысловой связи
!= тождество вхождения
!= степень количества
```

## F6. Производные теории

### Коллекции

Коллекция не вводится как новый корневой вид сущности.

```text
смысловой элемент
→ вхождение членства / происхождения
→ конечный ExactSequence
→ явное закрытое определение
→ представление множества / мультимножества / последовательности
```

Пустая коллекция — положительное закрытое свидетельство, а не «ничего не найдено».

### Функции как данные

```text
Args(...) := ExactSequence(...)
Map(Args,Y) := ExactSequence(Args,Y)
FunDef(T,F,D,K)
```

Функциональность, частичность, тотальность, экстенсиональное равенство и обычная композиция являются производными конечными суждениями.

```text
данные функции
!= вызов
!= исполнение
```

### Навигация

Проекции начала и конца детерминированы. Обратная инцидентность требует явного конечного закрытого контекста и может дать ноль, один или много результатов.

Путь — конечная композиция отношений. Координата пути не является тождеством смысловой связи.

Обратное отношение навигации отличается от `J`, от перестановки полюсов и от несвязи.

### Прикладные интерпретации

Прикладной смысл существует только как:

```text
принятая структура МТС
+ явная теория / контекст T
+ обычные связи ролей
+ структурные связывания и происхождение
```

Прикладная роль не переименовывает `O/C/L/U` и не создаёт смысловые копии одной связи.

## Открытый мир производных чтений

Если нет явного свидетельства замкнутости, сохраняется:

```text
не найдено
!= пусто
!= не существует
```

## Историческая граница

Старые записи:

```text
♀F / F♂
```

относятся к исторической проекционной семантике и не определяют текущее самозамыкание.

Текущая остенсивная ориентация:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

При этом `♂` и `♀` остаются отложенными внутренними знаками F1 v0.9.
