# Система аксиом МТС

Статус: **актуальная аксиоматическая рамка Foundation v2 candidate**.

> Foundation v2 ещё не является опубликованной accepted версией МТС. Формулировки ниже фиксируют текущие основания, которые уже поддержаны Gate-P executable evidence и должны войти в следующую версию после release/acceptance gate.

Исторические accepted-контракты v0.2–v0.5 и их десятиформульная корневая программа сохраняются без ретроактивного изменения; см. раздел [«Историческая корневая программа»](#историческая-корневая-программа-v02v05).

# 1. Зачем новая формулировка

Историческая линия МТС постепенно смешала несколько разных слоёв:

```text
онтологию связи
текстовую нотацию
ContextFrame
AST-node identity
корневые определения
операции памяти
proof rules
```

Foundation v2 разделяет их.

Аксиоматический уровень должен говорить только о тех свойствах, без которых теория перестаёт быть МТС, а не о конкретном Python parser-е или конкретном spelling-е символа.

Поэтому текущая система ниже формулируется как **аксиоматические обязательства**, а исполнимые Gate-P contracts проверяют, что их можно реализовать без скрытых дополнительных сущностей.

---

# 2. A0 — онтологическая замкнутость связи

```text
всё есть связь
```

Любая семантически существенная сущность МТС должна быть представима связью или сетью связей.

Не вводятся независимые первичные категории:

```text
node
object
type
context
rule
meaning
```

как обязательные дополнительные онтологические примитивы.

---

# 3. A1 — бинарность и направленность

Каждая связь имеет ровно два упорядоченных полюса:

```text
L = start ⟼ end
```

Порядок существенен:

```text
A ⟼ B
```

и

```text
B ⟼ A
```

не отождествляются автоматически.

Все структуры большей арности должны быть выражены композициями бинарных связей.

---

# 4. A2 — exact occurrence identity

Каждое вхождение связи имеет собственную точную идентичность.

```text
P1 = A ⟼ B
P2 = A ⟼ B

P1 ≠ P2
```

Совпадение полюсов не даёт права схлопнуть occurrences.

Следствия:

- pair interning не является аксиомой;
- multiplicity сохраняется;
- provenance может быть частью сети;
- одинаково выглядящие акты/утверждения могут оставаться различными.

---

# 5. A3 — форма не определяет универсальную identity

Ни локальная форма связи, ни форма целой сети не заменяют exact identity.

В частности:

```text
R = R ⟼ R
X = X ⟼ X
```

не влечёт:

```text
R = X
```

Graph isomorphism допускается как внешний структурный анализ, но не как примитивное семантическое равенство.

---

# 6. A4 — различённые bootstrap occurrences

Foundation v2 может выделять конечный bootstrap-набор exact occurrences, например:

```text
R / O / C / L / U
```

Их роль задаётся тем, **какие конкретно occurrences выбраны**, а не глобальной классификацией всех связей по форме.

Это значит:

```text
self-closed(x)
```

не эквивалентно автоматически:

```text
x is R
```

Самозамыкание — структурное свойство, а bootstrap-роль — остенсивное различение.

---

# 7. A5 — состояние выражается сетью

Контекст, словарь, теория и actual act не требуют скрытой mutable host-state.

Пример explicit context:

```text
P = parent ⟼ current
K = K ⟼ P
```

`K` является exact occurrence снимка состояния.

Переход состояния создаёт новый exact snapshot/evidence вместо неявной перезаписи прошлого состояния.

---

# 8. A6 — source, form и theory различны

Исходный текст не является смыслом сам по себе.

Foundation v2 различает:

```text
source bytes
canonical content C
exact source occurrence S
selected segmentation
resolved form F
theory T
```

и не отождествляет их по spelling-у.

Следовательно:

```text
same bytes ≠ same semantic occurrence
same form  ≠ same theory admission
```

Любое разрешение source должно быть подкреплено explicit evidence.

---

# 9. A7 — словарь имеет explicit scope/history

Семантический словарь не считается внешним глобальным namespace.

Его состояние выражается сетью, например:

```text
D = D ⟼ (parentScope ⟼ localHistory)
```

Определение создаёт explicit occurrence в истории.

Операция `:` в текущем Foundation-v2 candidate интерпретируется как persistent dictionary effect, а не как равенство, assignment host-языка или theorem assertion.

---

# 10. A8 — чтение отделено от materialization

Trusted интерпретация и доказательная проверка не должны менять сеть как побочный эффект.

```text
read / find / resolve / replay
        ≠
materialize / define / delete
```

Если требуемой связи нет, read-only replay не получает права создать её только потому, что она ожидалась логикой.

Это один из ключевых мостов от теории к апамяти.

---

# 11. A9 — равенство локально и явно

Текущее `=` Foundation v2 — local representative constraint.

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Локальное сравнение:

```text
Equal_K(a,b)
⇔ rep_K(a) is rep_K(b)
```

где отсутствие binding оставляет representative равным самому exact occurrence.

Из этого **не выводятся автоматически**:

```text
transitivity chains
substitution
global congruence
recursive rewriting
global union-find
```

Если теория хочет такое правило, оно должно быть отдельно представлено и допущено.

---

# 12. A10 — направление операции задаётся evidence, а не формой самой по себе

Самозамыкание полюса является структурой:

```text
F = F ⟼ X
```

или

```text
F = X ⟼ F
```

Но operational meaning возникает только в выбранном контексте интерпретации и при предъявленном binding/evidence.

То есть структура формы не является скрытым executable opcode.

Это позволяет одной и той же онтологии связей описывать данные, формы и правила без специального type-tag в `Link`.

---

# 13. A11 — actual act отличен от возможности действия

Следует различать:

```text
I — интерпретатор / возможность действия
A — конкретный actual act
```

Actual act связывает exact evidence конкретного случая интерпретации.

Благодаря этому проверяющий может повторить действие без доверия к процедуре, которая его нашла.

---

# 14. A12 — последовательность acts имеет exact provenance

Последовательность интерпретации или доказательства представима самой сетью:

```text
Run_0     = R
Run_(i+1) = Run_i ⟼ A_i
```

Соседние acts обязаны быть согласованы по exact состоянию:

```text
A_i.after is A_(i+1).before
```

Но из adjacency не выводится логическая транзитивность.

Run хранит **порядок и provenance**, а не заменяет proof rule.

---

# 15. A13 — логический вывод только через explicit admitted rule

Никакое правило вывода не считается глобально встроенным только потому, что оно кажется естественным.

Правило должно иметь explicit admission:

```text
T ⟼ Rule
```

и конкретное применение должно предъявить premise/conclusion evidence.

Первый executable Foundation-v2 proof candidate демонстрирует это на decomposition истинного локального равенства двух завершённых связей:

```text
Equal_K(L,R) = true
T ⟼ Rule

L = ls ⟼ le
R = rs ⟼ re

Rule(L,R)
→ ls ⟼ rs
→ le ⟼ re
```

Само `=` этого вывода не делает.

---

# 16. A14 — trusted replay детерминирован предъявленным evidence

Foundation v2 отделяет поиск от проверки:

```text
untrusted search / ranking
→ selected exact evidence
→ trusted deterministic replay
→ accept / reject
```

Trusted layer не должен:

- угадывать segmentation;
- выбирать «лучшее» правило;
- искать proof path;
- интернировать одинаковые формы;
- достраивать отсутствующие связи;
- доверять host AST class как semantic authority.

Он только проверяет уже предъявленный exact artifact.

Это ключевой принцип будущего `aprover`.

---

# 17. Ачисла и область рекурсивного описания

Ачисло остаётся важным структурным языком МТС, но Foundation v2 уточняет его статус.

Рекурсивное ачисло описывает структуру относительно выбранного корня в той области, где такое рекурсивное представление корректно.

Оно не объявляется универсальной semantic identity любой shared/cyclic асети.

```text
recursive Anum
    — structural description

exact occurrence ref
    — identity конкретного вхождения произвольной сети
```

Будущий gate #242 должен дать точную executable-семантику materialization последовательности ачисла в апамять.

---

# 18. Историческая корневая программа v0.2–v0.5

В репозитории сохранена принятая десятиформульная программа:

[`tests/mtc_formulas.mtc`](../../tests/mtc_formulas.mtc)

Она является неизменяемым машинным источником historical accepted-линии v0.2–v0.5 и проверяется соответствующими conformance-корпусами.

В ней присутствует старая семантическая архитектура, включая context projections и связанные конструкции.

Foundation v2 **не переписывает эту историю задним числом**.

Вместо этого действует граница:

```text
v0.2–v0.5 root program
= accepted historical contract

Foundation v2 axiomatic commitments
= candidate следующей версии
```

При cutover должна быть явно решена судьба каждого legacy construct: перенесён, переопределён, заменён или объявлен историческим.

---

# 19. Что ещё не является аксиомой Foundation v2

До отдельного принятого решения нельзя автоматически считать фундаментальными:

```text
TokenKind
AST node classes
ContextFrame
◁ / ▷ как онтологические полюса контекста
host string dictionary
graph-isomorphism equality
pair interning
physical backend address
longest-match tokenizer
recursive equality decomposition
global substitution
proof search algorithm
```

Все эти механизмы могут существовать как реализация или historical compatibility layer, но не должны проникать в следующую нормативную систему без явного обоснования.

---

# 20. Минимальная картина

Foundation v2 в аксиоматическом виде можно читать так:

```text
1. существует только связь;
2. связь бинарна и ориентирована;
3. каждое вхождение имеет exact identity;
4. форма не заменяет identity;
5. состояние и роли выражаются связями;
6. source разрешается только через explicit evidence;
7. replay не materialize-ит;
8. equality локально;
9. inference требует explicit T-admitted rule;
10. proof search может быть недоверенным, если selected evidence точно replay-ится.
```

Именно эти обязательства должны пережить смену языка программирования, backend-а памяти и алгоритма поиска доказательства.
