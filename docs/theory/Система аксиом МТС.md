# Система аксиом МТС

Статус: **актуальное, нормативное**.

Каноническая машинная root-программа: [`tests/mtc_formulas.mtc`](../../tests/mtc_formulas.mtc).

Архитектурные уровни и исполнимая семантика: [Reference model МТС v0.2](../specs/Reference%20model%20МТС%20v0.2.md).

## 1. Что входит в корневую систему

В v0.2 корень содержит только **именованные определения базовых различий**.

В него сознательно не входят:

```text
parser conformance;
grouping identities;
sequence examples;
bundle algebra examples;
временные protocol hypotheses;
глобальные rewrite-rules.
```

Исторически эти категории находились рядом в одном fixture, из-за чего реализация могла ошибочно трактовать conformance-пример как аксиому. В v0.2 эта неоднозначность устранена.

Корень содержит 10 определений.

## A1. Акорень

```text
∞ : {◁ = ∞, ▷ = ∞}
```

`◁` и `▷` — два атомарных местоимения ролей текущего бинарного контекста.

При проверке кандидата `∞` interpreter получает:

```text
ContextFrame(start, end)
```

и определение требует:

```text
start = ∞
end   = ∞
```

На L1 этому соответствует конечный self-cycle:

```text
root.start = root
root.end   = root
```

Старая запись:

```text
[] = ∞
∞ = ∞ ⟼ ∞
```

не нужна как глобальная система переписывания и не входит в canonical root.

## A2. Минимальная круглая форма смысла

```text
() : ♀() ⟼ ()♂
```

Чтение:

```text
()   — минимальная формальная форма смысла
♀()  — форма её начала
()♂  — форма её конца
```

Смысл не существует отдельно от связи.

## A3. Смыслы квадратных полюсных знаков

```text
([) : (♀∞)
(]) : (∞♂)
```

В `([)` и `(])` квадратные glyph являются литералами внутри круглой формальной формы.

Они не являются незакрытыми L2-контейнерами и не являются автоматически L3-абитами.

## A4. Смысл связи

```text
(⟼) : (♀∞ ⟼ ∞♂)
```

`(⟼)` — круглая формальная форма смысла связи.

Нужно отличать её от оператора:

```text
A ⟼ B
```

который строит конкретную `LinkForm(A,B)`.

## A5. Смысл несвязи

```text
(↛) : (∞♂ ⟼ ♀∞)
```

Несвязь не существует как отдельная натуральная сущность. Её смысл выражается связью обратной ориентации различённых полюсных форм акорня.

## A6. Квадратная форма абита связи

```text
[1] : (⟼)
```

`[1]` — L2-форма, связанная со смыслом связи.

Это не означает автоматического тождества L2 glyph и L3 serialization token.

## A7. Квадратная форма абита несвязи

```text
[0] : (↛)
```

`0` означает абит связи, несущей смысл несвязи; отсутствие натуральной связи из этого не следует.

## A8. Равенство

```text
(=) : {♀◁ = ♀▷, ◁♂ = ▷♂}
```

Если текущий interpreter context:

```text
ContextFrame(start=A, end=B)
```

то definition сравнивает:

```text
♀A = ♀B
A♂ = B♂
```

То есть два полюса текущего контекста совпадают по соответствующим формам начала и конца.

### Почему здесь нет `a`, `b` и повторных `[]`

МТС не нуждается во внешнем алфавите metavariables для двух ролей бинарной связи.

Роли уже существуют структурно:

```text
◁  — первый полюс
▷  — второй полюс
```

Поэтому definition не использует:

```text
a, b, x, y;
[]₁, []₂;
скрытый slot-counter;
текстовое совпадение glyph как binding.
```

### Область `=`

`=` — локальное identity/unification constraint одного запуска `interpret`.

Оно не является правилом:

```text
«если где-то A = B, заменить A на B во всём универсуме».
```

Именно это различие устраняет global-collapse, обнаруженный в issue #79.

## A9. Неравенство

```text
(!=) : ¬(=)
```

Смысл различимости вводится через инверсию формы смысла равенства.

## 2. Anonymous form `[]`

`[]` больше не является отдельной корневой аксиомой.

В исполняемой L2-нотации это минимальное **анонимное вхождение формы связи**.

Каждое occurrence имеет собственный structural `HoleId`:

```text
{[] = ◁, [] = ▷}
```

содержит два независимых holes.

Их совпадающий display glyph не создаёт co-reference.

Это свойство относится к semantics formal interpretation и зафиксировано в [`contracts/mts-contract-v0.2.json`](../../contracts/mts-contract-v0.2.json).

## 3. Формы начала и конца

Операторы:

```text
♀F
F♂
```

не требуют отдельных root definitions вида `♀[] : ...` и `[]♂ : ...`.

Их L1 carrier semantics уже заданы reference model:

```text
start(F).start = start(F)
start(F).end   = F

end(F).start = F
end(F).end   = end(F)
```

Таким образом корневая программа не дублирует semantics операторов, уже принадлежащую L1/L2 contract.

## 4. Что стало conformance вместо аксиом

Следующие исторические классы формул полезны как tests, но не входят в root:

### Grouping

```text
([]) = []
([] ⟼ []) = [] ⟼ []
```

Они проверяют чтение/grouping, а не вводят новое фундаментальное различие.

### Последовательности

```text
[][]
[][][]
[]([][])
```

Они проверяют parser/structural semantics последовательностей и ассоциацию формы.

### Пучки

```text
{A, A} = {A}
{A, B} = {B, A}
```

Это semantic/conformance properties пучкового слоя, а не определения корневого словаря.

### Protocol hypotheses

Проекция:

```text
[] → 0
][ → 1
```

относится к L3 Anum и остаётся experimental issue #61.

## 5. Одновременность корневых определений

Определения корня могут ссылаться друг на друга и рассматриваются как единая минимальная система различий.

Но «решаются одновременно» не означает:

```text
глобально переписывать одинаковые строки;
отождествлять все occurrences одного glyph;
материализовать все упомянутые связи в память.
```

Interpretation создаёт локальное окружение сопоставления; materialization выполняется только явным L4 `realize`.

## 6. Канонический список

Полная активная root-программа v0.2:

```text
∞ : {◁ = ∞, ▷ = ∞}
() : ♀() ⟼ ()♂
([) : (♀∞)
(]) : (∞♂)
(⟼) : (♀∞ ⟼ ∞♂)
(↛) : (∞♂ ⟼ ♀∞)
[1] : (⟼)
[0] : (↛)
(=) : {♀◁ = ♀▷, ◁♂ = ▷♂}
(!=) : ¬(=)
```

Эта копия приведена для чтения человеком. Машинным источником истины остаётся [`tests/mtc_formulas.mtc`](../../tests/mtc_formulas.mtc); CI защищает его точный contract hash.
