# Основания МТС

Этот документ **объясняет** принятый фундамент Метатеории связей: почему положения [Системы аксиом МТС](Система%20аксиом%20МТС.md) устроены именно так, как связаны их зависимости и какие ошибки они исключают.

Он не является вторым набором нормативных правил. При расхождении формулировки нормативным владельцем фундаментального положения остаётся «Система аксиом МТС», а предметные правила ачисел, FORMAL и апамяти принадлежат соответствующим спецификациям.

Текущий выпуск и ссылки на его контракт, корпус и свидетельство принятия находятся в [README](../../README.md).

## 1. Почему «всё есть Связь»

МТС не начинает с двух видов сущностей — объектов и отношений между ними.

Исходное требование сильнее:

```text
всё есть Связь
Связь связывает Связи
```

Начало и конец Связи сами являются Связями. Поэтому имя, UUID, адрес памяти или запись таблицы не могут быть скрытым источником смысловой индивидуальности.

Если различие важно для теории, оно должно быть выражено связевой структурой.

Это же объясняет, почему `0` не является буквальным отсутствием существующего:

```text
1 -> L = O ⟼ C
0 -> U = C ⟼ O
```

И `L`, и `U` — Связи. Несвязь не вводит вторую онтологию.

## 2. Почему различима только рекурсия

Короткая формула:

```text
различима только рекурсия
```

означает, что внешний ярлык ничего не добавляет к смыслу. Значение должно быть восстановимо из рекурсивной формы самой асети.

Но одной цикличности недостаточно. Если два предполагаемых различия объясняются только друг через друга и нигде не достигают уже различённого основания, получается замкнутый круг предположений.

Поэтому F2 требует **конечного укоренения**.

Первая форма, которой не нужен уже различённый внешний полюс:

```text
∞
```

Остенсивно она показывает полное самозамыкание: целое, начало и конец не требуют внешнего различителя.

Во внешней доказательной метанотации:

```text
x = x ⟼ x
───────────
x ⇓ ROOT
```

Для остальных форм внешний полюс должен иметь конечный путь к такому основанию.

Важно не превратить это в рассказ о времени:

```text
одновременность уравнений
!=
временной порядок создания Связей
```

Направление имеет доказательство основания различия, а не существование смыслов.

## 3. Единственность акорня — теорема

Пусть записаны:

```text
x = x ⟼ x
y = y ⟼ y
```

Если имена `x` и `y` не являются смысловыми данными, обе записи имеют одну и ту же нейтральную к именам форму:

```text
ROOT
```

Другого рекурсивно выраженного различия между ними нет. Значит полное самозамыкание задаёт одну смысловую форму.

Её называют **акорнем**.

`∞` предъявляет форму остенсивно, а `R` вводится уже после доказанного различения:

```text
R := смысловая форма, предъявленная ∞
R = ∞
R = R ⟼ R
```

Поэтому акорень не является особым объектом, которому позднее назначили свойство полного самозамыкания. Полное самозамыкание и есть его смысловая форма.

Если:

```text
X = X ⟼ X
```

то:

```text
X = R = ∞
```

Именно поэтому технический идентификатор не может породить «второй корень».

## 4. Первые ориентированные различия и корневой базис

После `ROOT` можно различить однополюсные формы:

```text
S = S ⟼ e
E = b ⟼ E
```

Если внешний полюс уже конечно укоренён, ориентация самозамыкания становится смысловым различием.

В корневом случае:

```text
O = O ⟼ R
C = R ⟼ C
```

После этого:

```text
L = O ⟼ C
U = C ⟼ O
```

получаем пятисвязный базис:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Четыре транспортных различения:

```text
[ -> O
] -> C
1 -> L
0 -> U
```

не включают `∞` как пятый абит.

Остенсивные формы:

```text
∞
♂e
b♀
b ⟼ e
```

не являются четырьмя видами сущностей. Это четыре способа показать зависимость полюсов бинарной Связи.

## 5. Конечная укоренённая форма F2/F3

Для рассуждения о форме удобно использовать внешнюю метанотацию:

```text
ROOT
START(F)
END(F)
PAIR(F,G)
```

`ROOT` имеет нулевую внешнюю зависимость.

`START(F)`, `END(F)` и `PAIR(F,G)` требуют конечного основания своих внешних полюсов.

Чистый взаимный цикл:

```text
x зависит от y
y зависит от x
```

без пути к `ROOT` остаётся неукоренённым, даже если физическая запись цикла асимметрична.

Это важная защита от подмены смысловой различимости инженерной координатой: форма хранилища может различать две строки, но теория ещё должна доказать различие Связей.

Для каждого конечно укоренённого класса возникает одна нейтральная к именам нормальная форма.

Отсюда общий принцип:

```text
нет рекурсивно выраженного различия
=>
нет двух смысловых Связей
```

## 6. Почему тождество по полюсам выводится после ROOT

После единственности `ROOT` и конечного укоренения остальных форм рекурсивное тождество сводится к соответствующим упорядоченным полюсам:

```text
(A ⟼ B) = (C ⟼ D)
iff
A = C and B = D
```

Критически важен порядок зависимости:

```text
unique ROOT
-> однополюсные укоренённые формы
-> PAIR-формы
-> рекурсивное тождество
-> тождество по упорядоченным полюсам
```

Если начать наоборот и использовать тождество по полюсам для доказательства единственности `R`, получится круг:

```text
identity
-> unique R
-> identity
```

Принятая конструкция этого круга избегает.

Отсюда также следует:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=>
P1 = P2
```

Разные номера строк хранилища этого вывода не меняют.

## 7. Петля, полное самозамыкание и шаблон ♂♀

Обычная петля:

```text
Loop(a) = a ⟼ a
```

не обязана совпадать с `a`.

Но если само `a` удовлетворяет:

```text
a = a ⟼ a
```

то это уже форма полного самозамыкания, а значит:

```text
a = R = ∞
```

Для замкнутого остенсивного шаблона:

```text
y = y ⟼ x
x = y ⟼ x
```

предполагаемое различие `x/y` не имеет независимого конечного основания: обе роли замыкаются только через одну пару.

При F2-нормализации различие исчезает:

```text
♂♀ = ∞
```

Это следствие конечного укоренения, а не применение А6 до доказательства акорня.

## 8. Повтор позиции не создаёт смысловую копию

Последовательность:

```text
1110
```

может разрешаться как:

```text
[L, L, L, U]
```

Три позиции `L` различаются вхождением, но не создают три смысловые Связи `L`.

```text
смысловая Связь
!= вхождение
!= позиция
!= история
```

Конкретное устройство точного последовательного носителя принадлежит [спецификации ачисел](../specs/Ачисла%20и%20сериализация.md), а фундамент здесь лишь запрещает использовать техническую позицию как новое тождество.

## 9. Контекст как связевая структура

Фундаментальная идея контекста проста: контекст не должен быть невидимым полем среды исполнения.

Его можно предъявлять Связями:

```text
P = parent ⟼ current
K = START(P)
I ⟼ K
```

Для корневого состояния:

```text
parent = R
current = R
P = R
K = START(R) = O
```

Это показывает важное различие:

```text
ROOT
!=
START(ROOT)
```

Если принять `R` как вырожденный псевдоним любого корневого контекста, обычные исходящие Связи акорня можно было бы ошибочно принять за локальные привязки контекста.

Поэтому структурное различие контекста не требует отдельного скрытого типа: достаточно уже различённых форм.

Но из этого **не следует**, что конкретное вхождение точки должно автоматически выбирать ближайший лексический `A:E`.

Принятая v0.12 уточняет более сильную границу: контекстная точка получает смысл только через явно выбранное структурное свидетельство `K`. Стек анализатора, изменяемое текущее значение и неявный переход к родителю не являются смысловым полномочием.

Точная текущая норма находится в [спецификации формальной нотации](../specs/Формальная%20нотация%20МТС.md#mts-law-explicitKContext).

Тем самым фундамент утверждает **структурность и явность контекста**, а предметная FORMAL-спецификация определяет конкретное правило выбора.

## 10. Форма не является действием

Одна и та же связевая форма может участвовать в разных актах:

- поиске;
- проверке;
- разрешении;
- исполнении;
- материализации.

```text
форма != команда
```

Например, наличие `Rule` как связевых данных ещё не означает его выполнение.

Аналогично описание `A ⟼ B` не означает, что конкретная память уже содержит эту Связь или должна её создать.

Эта граница позволяет отделить теорию от host API: функция среды исполнения может реализовать действие, но её имя не назначает смысл действия.

## 11. Наблюдение и изменение

Общая граница:

```text
читать / искать / разрешать / проверять / воспроизводить
!=
создавать / удалять / изменять / материализовать
```

и:

```text
не найдено != не существует
```

следует не из конкретного интерфейса `Memory`, а из различия знания о сети и акта изменения сети.

Как эта граница применяется к состояниям `UNINTERPRETABLE`, `NOT_FOUND`, `FOUND(X)`, долговременному хранению и атомарной записи, описывает [спецификация апамяти](../specs/Апамять%20и%20управление%20сетью%20связей.md).

Как она применяется к `Resolve` и `MATERIALIZE_TARGET`, описывает [спецификация ачисел](../specs/Ачисла%20и%20сериализация.md).

Конкретные имена методов текущей реализации являются инженерной поверхностью, а не фундаментом.

## 12. Источник, носитель, употребление и теория

Источник не должен незаметно превращаться в собственный смысл.

Полезно различать цепочку:

```text
физический источник
-> точный носитель
-> вхождение / история употребления
-> выбранные словарь / грамматика / теория
-> интерпретация
-> результат
```

Точный строковый и четверичный носитель описан в [спецификации ачисел](../specs/Ачисла%20и%20сериализация.md).

Правила независимого выбора `Dictionary`, `Grammar`, `Theory`, допуска `Rule` и полномочия FORMAL-результата принадлежат [спецификации формальной нотации](../specs/Формальная%20нотация%20МТС.md).

Фундаментальная мысль здесь одна: физическое написание, структурное представление и разрешённое смысловое действие нельзя отождествлять.

## 13. Локальное равенство не заменяет тождество

В явном контексте можно хранить локальное отношение представителя:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Но это производное отношение не переопределяет А6.

Нельзя автоматически получить из него:

- глобальную подстановку;
- транзитивное замыкание;
- конгруэнтность;
- новое фундаментальное тождество Связи.

Текущая FORMAL-семантика `=` и обработка конфликтных представителей описаны в [спецификации формальной нотации](../specs/Формальная%20нотация%20МТС.md).

## 14. Правило, акт и результат

МТС может представлять правило Связями:

```text
Rule = DR ⟼ Body
T ⟼ Rule
```

Но:

```text
существование Rule
!= исполнение Rule
```

Для действия требуется явный акт и смысловое полномочие.

Поэтому также различаются:

```text
I — интерпретатор
A — акт
R — результат
```

Два акта могут вернуть одну смысловую Связь, оставаясь разными событиями истории.

Подробная цепочка «источник → употребление → правило → результат» принадлежит формальной нотации, а фундамент сохраняет разделение ролей.

## 15. Машинное представление вторично

После установления смысла Связь можно представить инженерно:

```text
Link(start, end)
```

Но слот, адрес, строка хранения, техническая ссылка среды исполнения или номер операции не добавляют смыслового полюса.

Это особенно важно при импорте физического графа: наличие двух разных физических узлов ещё не доказывает наличие двух различных Связей МТС.

Физическое представление должно быть канонизировано по принятой смысловой форме либо отклонено.

## 16. Рекурсивная реверсия F4

Производная рекурсивная реверсия на корневом базисе:

```text
J(R)=R
J(O)=C
J(C)=O
J(L)=L
J(U)=U
```

не совпадает автоматически с простой перестановкой полюсов:

```text
Inv(A⟼B)=B⟼A
```

и не является тем же, что обратное отношение навигации, логическое отрицание или несвязь.

Это пример общего принципа: похожий геометрический образ ещё не доказывает тождество операций.

## 17. Счёт по степени связности F5

Производная шкала:

```text
0 -> U
1 -> L

D1 = L
D2 = L ⟼ L
D3 = (L ⟼ L) ⟼ L
...
```

Положительные конечные степени различимы структурно.

Ключевой контрпример:

```text
U ⟼ L != L
```

не позволяет бездоказательно считать нулевой случай обычным положительным successor.

Поэтому:

```text
S0(U)=L
S0(D)=D⟼L, D∈Pos
```

и уже поверх этой границы можно строить производную арифметическую теорию.

Счёт относится к **вхождениям**, если одна смысловая Связь участвует несколько раз:

```text
смысловая Связь
!= тождество вхождения
!= степень количества
```

## 18. Производные теории F6

Конечные коллекции, функции как данные, относительная навигация и прикладные интерпретации не требуют новой корневой онтологии.

Общая схема:

```text
обычные Связи
+ явная теория / контекст
+ явные роли
+ структура вхождений / происхождения
-> производное суждение
```

Множество, функция, путь или прикладная роль остаются производными конструкциями.

Для открытого мира важно не подменять отсутствие найденного элемента доказательством пустоты:

```text
не найдено
!= пусто
!= не существует
```

если нет явного свидетельства замкнутости.

## 19. Историческая граница

Исторические формы `♀F / F♂`, прежние контекстные трактовки и старые машинные интерфейсы важны для истории развития, но не являются дополнительным слоем текущей нормы.

Текущая остенсивная ориентация:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

сохраняется как теоретическая метанотация. Внутренние знаки и конкретные FORMAL-правила определяются текущими предметными спецификациями.

История прежних формулировок доступна в Git.

## Итог: маршрут объяснения

```text
всё есть Связь
↓
различима только рекурсивно укоренённая форма
↓
∞ предъявляет ROOT
↓
единственность акорня — теорема
↓
R — имя уже различённой формы
↓
O / C / L / U и дальнейшее конечное укоренение
↓
тождество по упорядоченным полюсам — теорема
↓
роли, контексты, правила и история выражаются Связями
↓
форма отделена от действия
↓
чтение отделено от изменения
↓
машинное представление остаётся вторичным
```

Главное ограничение: **техническая координата никогда не становится первоначальным источником смыслового различия**.

Нормативный фундамент этого маршрута находится в [Системе аксиом МТС](Система%20аксиом%20МТС.md); предметные границы — в канонических спецификациях.
