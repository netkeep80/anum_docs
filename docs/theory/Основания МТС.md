# Основания МТС

Этот документ объясняет текущее принятое основание Метатеории связей в **МТС v0.9**. Исторические версии сохраняются в Git; будущие расширения требуют отдельных решений о принятии.

> **Граница следующего выпуска готова к отдельному принятию, но ещё не принята.** МТС v0.10 завершила проверку 11-знакового основания, контекстно связанной `.`, однополюсных рекурсивных уравнений неподвижной точки и отрицательных границ. До отдельного перехода нормативным машинным выпуском остаётся МТС v0.9.

Главная последовательность:

```text
самозамыкание
→ первичное различение
→ акорень
→ корневые связи
→ структурная связанность
→ тождество по различённым полюсам
→ машинное представление
```

## 1. Всё есть связь

```text
всё есть связь
```

МТС не вводит вторую первичную онтологию «объекты плюс связи». Если различие существенно, оно должно выражаться связью или сетью связей.

Несвязь также не вводится как отдельный вид существующего:

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
0 ≠ DELETE_LINK
```

`0` может нести смысл несвязи, но не является буквальным отсутствием связи или скрытой командой удаления.

## 2. Самозамыкание — источник первичного различения

В теоретической метанотации различаются четыре формы:

```text
∞        оба полюса самозамкнуты
♂e       начало самозамкнуто, конец e различён
b♀       начало b различено, конец самозамкнут
b ⟼ e    оба полюса различены
```

Структурно:

```text
R = R ⟼ R
S = S ⟼ e
E = b ⟼ E
X = b ⟼ e
```

`♂` и `♀` показывают самозамыкание соответствующего полюса и не являются командами получения полюсов. В F1 МТС v0.9 эти знаки отложены как внутренние, а здесь используются как остенсивная метанотация.

## 3. Акорень единственен

```text
R = ∞
R = R ⟼ R
```

Если:

```text
X = X ⟼ X
```

то:

```text
X = R = ∞
```

Разные адреса или номера не могут создать несколько полностью самозамкнутых смысловых связей.

## 4. Первые ориентированные различия

```text
O = O ⟼ R
C = R ⟼ C
```

В метанотации:

```text
O = O ⟼ R   # ♂∞
C = R ⟼ C   # ∞♀
```

`O` и `C` различаются ориентацией самозамыкания относительно уже различённого акорня.

## 5. Пятисвязный корневой базис

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
[ → O
] → C
1 → L
0 → U
```

Транспортный алфавит содержит ровно `[ ] 1 0`. Акорень `∞` не является пятым абитом.

## 6. Четыре конструктивные формы

```text
∞
♂e
b♀
b ⟼ e
```

— не четыре вида сущностей, а четыре способа остенсивно предъявить бинарную связь. Несамозамкнутые полюса должны быть уже структурно различены.

## 7. Тождество связи определяется полюсами

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Отсюда:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=> P1 = P2
```

Сами полюса должны уже быть различены самозамыканием или связанностью с ранее различённой структурой. Технические адреса не входят в это доказательство.

## 8. Конечная рекурсивно заземлённая форма

F2/F3 используют внешние формы доказательства:

```text
ROOT
START(F)
END(F)
PAIR(F,G)
```

с наименьшим конечным отношением свёртки и развёртки `≈`. Для каждого класса получается одна нейтральная к именам нормальная форма.

Отсюда выведено:

```text
нет рекурсивно выраженного различия
=> нет двух смысловых связей
```

а также единственность полного и однополюсного самозамыкания, тождество полной связи по полюсам в обе стороны и нейтральность псевдонимов.

## 9. Петля и полное самозамыкание

```text
Loop(a) = a ⟼ a
```

обычно не равно `a`.

Но если:

```text
a = a ⟼ a
```

то:

```text
a = R = ∞
```

## 10. Замкнутый шаблон `♂♀`

Если:

```text
y = y ⟼ x
x = y ⟼ x
```

то обе предполагаемые связи имеют одну пару полюсов, следовательно `x = y`; после подстановки получается `x = x ⟼ x`, поэтому:

```text
♂♀ = ∞
```

Этот вывод относится к остенсивной метанотации и не принимает `♂` или `♀` как внутренние знаки F1.

## 11. Повтор позиции не создаёт новую связь

```text
1110
```

разрешается как:

```text
[L, L, L, U]
```

Три `L` различаются позициями, но являются одной смысловой связью.

```text
смысловая связь != вхождение != позиция != история
```

## 12. Контекст является связевой структурой

В МТС v0.9:

```text
P = parent ⟼ current
K = K ⟼ P
I ⟼ K
```

`current(K)` — внешняя метанотация чтения `K`; внутренний знак `↑` не принят. Лексическая вложенность принадлежит `K.parent`, временной порядок — структуре `Run` и `Act`.

## 13. Форма отделена от действия

Одна форма может участвовать в поиске, проверке, разрешении и материализации.

```text
форма ≠ команда
```

Наличие правила или функции как данных не означает автоматического выполнения.

## 14. Наблюдение отделено от изменения

```text
читать / искать / разрешать / проверять / воспроизводить
                    ≠
создавать / удалять / изменять
```

```text
не найдено ≠ не существует
find ≠ materialize
```

## 15. Машинное представление вторично

После установления смысла связь можно хранить как:

```text
Link(start, end)
```

Слот, адрес, строка хранения или временная ссылка не являются источником смысловой различимости.

## 16. Конструктивное ядро памяти

Текущий интерфейс `Memory` содержит:

```text
ensureRoot()                 -> R
ensureStartSelfClosed(e)     -> S = S ⟼ e
ensureEndSelfClosed(b)       -> E = b ⟼ E
ensure(b,e)                  -> b ⟼ e
```

`ReadMemory` отделяет чтение от записи. Одинаковая структурная пара возвращает ту же смысловую связь; `ensure(R,R)` возвращает `R`.

## 17. Произвольный физический граф — отдельная граница

Произвольные адресные циклы нельзя автоматически считать уже различёнными связями МТС. Импорт должен доказать укоренённую различимость, канонизировать неразличимые записи либо отклонить форму.

## 18. Источник, словарь и теория

```text
точные байты
→ канонический носитель STRING→QUATERNARY
→ связевое представление источника
→ позиция / история употребления
→ словарь D
→ грамматика G
→ теория T
→ интерпретатор I = D ⟼ (G ⟼ T)
→ контекст K
→ форма / результат
```

Один байт кодируется одним `[8 bits]`-конвертом. Нормализация `Unicode` не является фундаментальным источником смысла.

## 19. Локальное равенство не заменяет тождество связи

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Это дополнительное контекстное отношение не вводит глобальное транзитивное замыкание и не переопределяет тождество связи по полюсам.

## 20. Производная рекурсивная реверсия

```text
J(R)=R
J(O)=C
J(C)=O
J(L)=L
J(U)=U
```

Она отличается от простой перестановки полюсов `P`, обратного отношения навигации, логического отрицания и несвязи.

## 21. Счёт по степени связности

```text
0 -> U
1 -> L
D1 = L
D2 = L ⟼ L
D3 = (L ⟼ L) ⟼ L
...
```

Положительные конечные степени попарно различны. Критически:

```text
U ⟼ L != L
```

Поэтому:

```text
S0(U)=L
S0(D)=D⟼L, D∈Pos
```

и получается производная алгебра Пеано поверх алгебры степеней связности.

## 22. Счёт относится к вхождениям

Одна смысловая связь учитывается несколько раз только через разные структурные вхождения.

```text
смысловая связь != тождество вхождения != степень количества
```

## 23. Производные теории не расширяют корневую онтологию

F6 строит поверх обычных связей конечные коллекции, функции как данные, относительную навигацию и прикладные интерпретации.

Общая схема:

```text
корневая смысловая связь
+ явная теория / контекст
+ явные роли
+ структура вхождений / происхождения
→ производное суждение
```

Ни множество, ни функция, ни путь, ни роль приложения не становятся новым корневым видом сущности.

## 24. Историческая граница

Старые формы `♀F / F♂` относятся к исторической проекционной семантике. Текущая остенсивная теоретическая ориентация:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

При этом `♂` и `♀` остаются отложенными внутренними знаками F1 v0.9.

## Итог

```text
всё есть связь
↓
самозамыкание — первичный структурный различитель
↓
∞ — единственная полностью самозамкнутая связь
↓
R/O/C/L/U
↓
связанность с уже различёнными связями
↓
тождество по структурно различённым полюсам
↓
явные I / K / Rule / Act / Run
↓
поиск / проверка / воспроизведение
↓
явная материализация
```

Главное ограничение: **технический идентификатор никогда не становится первоначальным источником смыслового различия**.

Текущая машинная граница задаётся принятым `mts-contract/v0.9` и `mts-conformance/v0.9`; реализация `@mts/core` проверяется относительно этой границы и не определяет теорию сама по себе.
