# Основания МТС

Этот документ объясняет текущее принятое основание Метатеории связей в **MTS v0.9**. Машинный выпуск v0.9 имеет `semanticBase = mts-contract/v0.8` и `observableSemanticDelta = true`. Исторические версии сохраняются как история и не переписываются задним числом; будущие расширения требуют отдельных решений о принятии.

Главная последовательность:

```text
самозамыкание
→ первичное различение
→ акорень
→ корневые связи
→ структурная связанность
→ тождество по различённым полюсам
→ машинное представление
```

## 1. Всё есть связь

Исходный постулат:

```text
всё есть связь
```

МТС не вводит вторую первичную онтологию «объекты плюс связи». Если различие существенно, оно должно выражаться связью или сетью связей.

Несвязь также не вводится как отдельный вид существующего. Корневые значения `1` и `0` сами являются связями:

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
```

Поэтому `0` может нести смысл несвязи, но не является буквальным отсутствием связи или скрытой командой удаления:

```text
0 ≠ DELETE_LINK
```

## 2. Самозамыкание — источник первичного различения

Для связи различаются четыре остенсивные формы в теоретической метанотации:

```text
∞        оба полюса самозамкнуты
♂e       начало самозамкнуто, конец e различён
b♀       начало b различено, конец самозамкнут
b ⟼ e    оба полюса различены
```

Структурно:

```text
R = R ⟼ R
S = S ⟼ e
E = b ⟼ E
X = b ⟼ e
```

`♂` и `♀` показывают самозамыкание соответствующего полюса и **не являются командами получения полюсов**.

В accepted F1 MTS v0.9 `♂` и `♀` не входят в минимальный внутренний реестр знаков и остаются deferred. Их остенсивная роль здесь сохраняется как теория/метанотация, а структура выражается самими связями.

Самозамыкание важно не как специальный «тип объекта», а как первичная структурная возможность различить связь без ссылки на внешний ID.

## 3. Акорень — единственная полностью самозамкнутая связь

Акорень:

```text
R = ∞
R = R ⟼ R
```

Полностью самозамкнутая форма одна:

```text
X = X ⟼ X
=>
X = R = ∞
```

Нельзя сказать:

```text
R = R ⟼ R
Q = Q ⟼ Q
R ≠ Q
```

только потому, что реализации выдали `R` и `Q` разные адреса. Это было бы круговым рассуждением: техническая ссылка сначала создаёт различие, а затем используется как доказательство различия полюсов.

Если две полностью самозамкнутые записи ничем структурно не различимы, в МТС это одна связь — акорень.

## 4. Различение начинается с отличия от акорня

После `R` возникают первые ориентированные различия:

```text
O = O ⟼ R
C = R ⟼ C
```

Остенсивно, в метаязыке:

```text
O = O ⟼ R   # ♂∞
C = R ⟼ C   # ∞♀
```

`O` отличается от `R`, потому что у `O` только начало самозамкнуто, а конец связан с уже различённым `R`.

`C` отличается от `R` и от `O`, потому что самозамкнут уже другой полюс:

```text
O : self ⟼ R
C : R ⟼ self
```

То есть первичное различение задаётся не именем связи, а рисунком самозамыкания и ориентацией относительно уже различённой корневой связи.

## 5. Пятисвязный корневой базис

Корневой базис:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
[ → O
] → C
1 → L = O ⟼ C
0 → U = C ⟼ O
```

Транспортный алфавит ачисла содержит ровно четыре абита:

```text
[ ] 1 0
```

Акорень `R = ∞` является основанием этих четырёх различений и **не является пятым абитом**.

Различение распространяется наружу:

```text
R
↓
O / C
↓
L / U
↓
дальнейшие связи
```

`L` и `U` уже не требуют нового самозамыкания: их различимость задаётся порядком ранее различённых `O` и `C`.

Текущий F1 MTS v0.9 самовводит ровно десять внутренних знаков:

```text
∞ [ ] 1 0 ( ) ⟼ : =
```

Отложены как внутренние знаки:

```text
≡ ♂ ♀ ↑ { } ¬ ↛
```

Только в метаязыке используются:

```text
∧ ⇔ ⇒ ≠ →
```

## 6. Четыре конструктивные формы

Семантическое ядро удобно читать как четыре конструктивные формы:

```text
∞
♂e
b♀
b ⟼ e
```

где несамозамкнутые полюса должны быть уже структурно различены.

Отсюда:

```text
∞      — нулевой корневой случай
♂e     — новое различение от уже различённого e
b♀     — новое различение от уже различённого b
b⟼e    — связь двух уже различённых полюсов
```

Это не означает введение четырёх онтологических типов. Это четыре способа остенсивно предъявить одну и ту же бинарную сущность — связь.

## 7. Тождество связи определяется полюсами

Фундаментальное тождество:

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Следовательно:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=> P1 = P2
```

Но это не должно пониматься как сравнение сырых адресов `A`, `B`, `C`, `D`.

Сами полюса должны уже быть различены через:

```text
самозамыкание
или
структурную связанность с уже различёнными связями
```

Именно поэтому различение начинается от акорня, а не от заранее выданного множества ID.

F2/F3 дают более строгую конечную форму этого результата: для grounded proof-форм `ROOT / START(F) / END(F) / PAIR(F,G)` существует alpha-neutral normal form, и отсутствие рекурсивно выраженного различия означает отсутствие двух semantic Links.

## 8. Укоренённость различимости

Общий принцип:

```text
самозамыкание полюсов
→ различение корневых связей
→ связанность с уже различёнными связями
→ дальнейшее структурное различение
```

Техническая нумерация в эту цепочку не входит.

Если две технические записи невозможно различить относительно уже различённой корневой структуры, они не должны становиться двумя смысловыми связями МТС.

Это означает, в частности, что произвольный цикл, различимый только тем, что его вершинам заранее назначены разные номера, не является достаточным основанием для смыслового тождества.

## 9. Петля и полное самозамыкание — не одно и то же

Петля над данным `a`:

```text
Loop(a) = a ⟼ a
```

имеет одинаковые **внешние** полюса, но сама связь `Loop(a)` обычно не является этими полюсами.

То есть обычно:

```text
Loop(a) ≠ a
```

и, в метаязыке чтения полюсов:

```text
start(Loop(a)) = a
end(Loop(a))   = a
```

Совсем другой случай:

```text
a = a ⟼ a
```

Здесь сама связь совпала и со своим началом, и со своим концом. Это полное самозамыкание, поэтому:

```text
a = R = ∞
```

Следовательно, нужно строго различать:

```text
L = a ⟼ a    # петля над a

a = a ⟼ a    # полное самозамыкание самой a
```

### Следствие: `♂♀ = ∞`

Замкнутый шаблон `♂♀` не содержит внешнего уже различённого полюса. Чтобы раскрыть его без обращения к техническим ID, обозначим левую и правую самозамкнутые связи через `y` и `x`:

```text
y = y ⟼ x
x = y ⟼ x
```

Обе связи имеют одну и ту же упорядоченную пару полюсов, поэтому по тождеству связи:

```text
x = y
```

После подстановки остаётся:

```text
x = x ⟼ x
```

а это единственная полностью самозамкнутая связь:

```text
♂♀ = ∞
```

Таким образом взаимное однополюсное самозамыкание **не создаёт ещё один источник различения**. При замыкании контура различие `x/y` исчезает, и шаблон вырождается в акорень. Полное доказательство и оговорка о статусе знаков `♂/♀` приведены в [Системе аксиом МТС](Система%20аксиом%20МТС.md).

## 10. Повтор позиции не создаёт новую связь

Например:

```text
1110
```

разрешается как:

```text
[L, L, L, U]
```

Три позиции `1` — три употребления одной связи `L`, а не три экземпляра `L`.

Если происхождение или порядок существенны, они должны быть выражены структурой последовательности или истории.

В производных теориях этот же принцип формулируется как:

```text
semantic Link
!= occurrence
!= position
!= history
```

## 11. Контекст также является связевой структурой

В accepted MTS v0.9 контекст выражается явно:

```text
P = parent ⟼ current
K = K ⟼ P
I ⟼ K
```

Здесь `current(K)` — допустимая внешняя метанотация чтения `K`, но отдельный внутренний знак `↑` в F1 v0.9 не принят.

Лексическая вложенность принадлежит `K.parent`, временной порядок — Run/Act. Q/FORMAL OPEN/CLOSE/re-entry и parent continuation являются явными структурными переходами, а не скрытым стеком языка реализации.

Если повторно строится тот же `K = K ⟼ P` для того же уже различённого `P`, это не новый экземпляр контекста, а та же связь.

Если нужно различить два момента использования одного контекста, различие должно находиться в истории актов.

## 12. Форма отделена от действия

Одна и та же связь может участвовать в разных операциях:

```text
поиск
проверка
разрешение
материализация
```

Поэтому:

```text
форма ≠ команда
```

Разные акты получения одной связи не создают несколько экземпляров результата. Наличие `Rule` или function-data также не означает автоматического исполнения.

## 13. Наблюдение отделено от изменения

Критический инвариант:

```text
читать / искать / разрешать / проверять / воспроизводить
                    ≠
создавать / удалять / изменять
```

И:

```text
не найдено ≠ не существует
```

Связь может быть однозначно определена структурой, но её физическая запись ещё отсутствовать в конкретной апамяти.

Поэтому:

```text
find ≠ materialize
```

Каноническая операция явной материализации в текущем TypeScript owner имеет вид:

```text
ensure(A,B):
    если связь этой структурно различённой пары уже записана -> вернуть её
    иначе -> материализовать её
```

## 14. Машинное представление вторично

После установления семантики связь можно хранить как:

```text
Link(start, end)
```

Но техническая ссылка не является третьим полюсом.

Реализация может использовать:

```text
slot
address
row id
build handle
```

для хранения и доступа, но эти значения не являются источником различимости.

Правильная граница:

```text
semantic Link
≠
storage/runtime handle
```

## 15. Конструктивное машинное ядро

Текущий TypeScript Memory API сохраняет прямую конструктивную границу:

```text
ensureRoot()                 -> R
ensureStartSelfClosed(e)     -> S = S ⟼ e
ensureEndSelfClosed(b)       -> E = b ⟼ E
ensure(b,e)                  -> b ⟼ e
```

При этом:

- `e` и `b` должны уже быть известными валидными handles данной Memory;
- одинаковая структурная пара возвращает ту же semantic Link;
- `ensure(R,R)` возвращает `R`;
- read-only `find/poles/outgoing/incoming` не материализуют связи;
- `LinkHandle.slot` и порядок выдачи handles не являются semantic identity.

Таким образом машинное API является реализацией принятой структурной границы, но не источником самой теории.

## 16. Произвольный физический граф — отдельная граница

Внешнее хранилище может содержать произвольные адресные циклы. Их нельзя автоматически считать уже различёнными МТС-связями.

Импорт должен либо:

```text
доказать структурную различимость относительно корня
```

либо:

```text
канонизировать структурно неразличимые технические записи
```

либо отклонить неподдерживаемую форму.

То есть:

```text
physical graph
→ structural canonicalization
→ semantic MTS network
```

а не наоборот.

## 17. Исходная запись, словарь и теория

Текстовый знак ещё не является смыслом.

В MTS v0.9 рабочая цепочка уточнена:

```text
точные bytes
→ canonical per-byte STRING→QUATERNARY carrier
→ связевое представление источника
→ позиция / история употребления
→ словарь D
→ грамматика G
→ теория T
→ интерпретатор I = D ⟼ (G ⟼ T)
→ контекст K
→ форма / результат
```

Один byte кодируется одним `[8 bits]` envelope. Unicode normalization и code-point segmentation не являются foundation authority.

Если два акта чтения разрешают один и тот же структурный результат, сам результат остаётся одной связью.

## 18. Локальное равенство не заменяет фундаментальное тождество

Дополнительное контекстное отношение может быть представлено:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Но оно не переопределяет тождество самой связи по её структурно различённым полюсам и не вводит global transitive closure.

## 19. Производные результаты не расширяют root ontology

Завершённый foundation/derived цикл F2–F6 дал, в частности:

- F2/F3 finite grounded normalization и no-instance theorem;
- F4 recursive reversal `J`, отличную от pole swap и navigation converse;
- F5 connectivity-degree Count и derived Peano algebra;
- F6 finite collections, functions-as-data, relative navigation и application interpretations.

Во всех этих слоях сохраняется общий принцип:

```text
root semantic Link
+ explicit theory/context roles
+ explicit occurrence/provenance structure
→ derived judgment
```

Ни Set, ни Function, ни Path, ни Count, ни application role не становятся новым root sort.

## 20. Историческая граница

В исторической версии использовались формы:

```text
♀F / F♂
```

Они относятся к старой проекционной семантике.

Текущая остенсивная ориентация теории:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

При этом `♂`/`♀` остаются deferred как внутренние F1 signs v0.9 и не должны незаметно возвращаться в машинный алфавит.

## Итог

Основание можно сжать до цепочки:

```text
всё есть связь
↓
самозамыкание является первичным структурным различителем
↓
∞ = единственная полностью самозамкнутая связь
↓
R/O/C/L/U
↓
связанность с уже различёнными связями
↓
тождество по структурно различённым полюсам
↓
явный I / K / Rule / Act / Run
↓
поиск / проверка / replay
↓
явная материализация
```

Главное ограничение: **технический ID никогда не должен становиться первоначальным источником смыслового различия**.

Текущий machine source of truth — accepted `mts-contract/v0.9` + `mts-conformance/v0.9`; TypeScript `@mts/core` реализует эту границу, но не определяет теорию сам по себе.
