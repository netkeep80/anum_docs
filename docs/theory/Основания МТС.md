# Основания МТС

Этот документ объясняет текущее принятое основание Метатеории связей в **МТС v0.9**. Машинный выпуск v0.9 имеет `semanticBase = mts-contract/v0.8` и `observableSemanticDelta = true`. Исторические версии сохраняются в Git; будущие расширения требуют отдельных решений о принятии.

Главная последовательность:

```text
самозамыкание
→ первичное различение
→ акорень
→ корневые связи
→ структурная связанность
→ тождество по различённым полюсам
→ машинное представление
```

## 1. Всё есть связь

```text
всё есть связь
```

МТС не вводит вторую первичную онтологию «объекты плюс связи». Если различие существенно, оно должно выражаться связью или сетью связей.

Несвязь также не вводится как отдельный вид существующего:

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
0 ≠ DELETE_LINK
```

`0` может нести смысл несвязи, но не является буквальным отсутствием связи или скрытой командой удаления.

## 2. Самозамыкание — источник первичного различения

В теоретической метанотации различаются четыре формы:

```text
∞        оба полюса самозамкнуты
♂e       начало самозамкнуто, конец e различён
b♀       начало b различено, конец самозамкнут
b ⟼ e    оба полюса различены
```

Структурно:

```text
R = R ⟼ R
S = S ⟼ e
E = b ⟼ E
X = b ⟼ e
```

`♂` и `♀` показывают самозамыкание соответствующего полюса и не являются командами получения полюсов.

В F1 МТС v0.9 эти знаки не входят в минимальный внутренний реестр и остаются отложенными. Их остенсивная роль сохраняется как теория и метанотация.

## 3. Акорень единственен

```text
R = ∞
R = R ⟼ R
```

Если:

```text
X = X ⟼ X
```

то:

```text
X = R = ∞
```

Разные адреса или номера не могут создать несколько полностью самозамкнутых смысловых связей.

## 4. Первые ориентированные различия

После `R`:

```text
O = O ⟼ R
C = R ⟼ C
```

В метанотации:

```text
O = O ⟼ R   # ♂∞
C = R ⟼ C   # ∞♀
```

`O` и `C` различаются ориентацией самозамыкания относительно уже различённого акорня.

## 5. Пятисвязный корневой базис

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
[ → O
] → C
1 → L
0 → U
```

Транспортный алфавит содержит ровно:

```text
[ ] 1 0
```

Акорень `∞` не является пятым абитом.

Текущий внутренний F1-реестр:

```text
∞ [ ] 1 0 ( ) ⟼ : =
```

Отложены:

```text
≡ ♂ ♀ ↑ { } ¬ ↛
```

Только метаязык:

```text
∧ ⇔ ⇒ ≠ →
```

## 6. Четыре конструктивные формы

```text
∞
♂e
b♀
b ⟼ e
```

— не четыре вида сущностей, а четыре способа остенсивно предъявить бинарную связь.

Несамозамкнутые полюса должны быть уже структурно различены.

## 7. Тождество связи определяется полюсами

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Отсюда:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=> P1 = P2
```

Сами полюса должны уже быть различены самозамыканием или связанностью с ранее различённой структурой.

Технические адреса не входят в это доказательство.

## 8. Конечная рекурсивно заземлённая форма

F2/F3 используют внешние формы доказательства:

```text
ROOT
START(F)
END(F)
PAIR(F,G)
```

с наименьшим конечным отношением свёртки/развёртки `≈`.

Для каждого класса получается одна нейтральная к именам нормальная форма.

Отсюда выведено:

```text
нет рекурсивно выраженного различия
=> нет двух смысловых связей
```

а также:

- единственность полного самозамыкания;
- единственность однополюсного самозамыкания при фиксированном внешнем полюсе;
- тождество полной связи по упорядоченным полюсам в обе стороны;
- нейтральность псевдонимов и имён связок.

## 9. Петля и полное самозамыкание

```text
Loop(a) = a ⟼ a
```

обычно не равно `a`.

Но если:

```text
a = a ⟼ a
```

то:

```text
a = R = ∞
```

Поэтому петля над уже различённой связью и полное самозамыкание самой связи — разные случаи.

## 10. Замкнутый шаблон `♂♀`

Если:

```text
y = y ⟼ x
x = y ⟼ x
```

то обе предполагаемые связи имеют одну пару полюсов, следовательно:

```text
x = y
```

После подстановки:

```text
x = x ⟼ x
```

и потому:

```text
♂♀ = ∞
```

Этот вывод относится к остенсивной метанотации и не принимает `♂`/`♀` как внутренние знаки F1.

## 11. Повтор позиции не создаёт новую связь

```text
1110
```

разрешается как:

```text
[L, L, L, U]
```

Три `L` различаются позициями, но являются одной смысловой связью.

```text
смысловая связь
!= вхождение
!= позиция
!= история
```

## 12. Контекст является связевой структурой

В МТС v0.9:

```text
P = parent ⟼ current
K = K ⟼ P
I ⟼ K
```

`current(K)` — внешняя метанотация чтения `K`; внутренний знак `↑` не принят.

Лексическая вложенность принадлежит `K.parent`, временной порядок — структуре `Run`/`Act`.

Открытие, закрытие и возврат между `Q` и `FORMAL` являются явными структурными переходами.

## 13. Форма отделена от действия

Одна форма может участвовать в разных актах:

```text
поиск
проверка
разрешение
материализация
```

Поэтому:

```text
форма ≠ команда
```

Наличие правила или функции как данных не означает автоматического выполнения.

## 14. Наблюдение отделено от изменения

```text
читать / искать / разрешать / проверять / воспроизводить
                    ≠
создавать / удалять / изменять
```

И:

```text
не найдено ≠ не существует
find ≠ materialize
```

Связь может быть структурно однозначна, но ещё не иметь физической записи в конкретной памяти.

## 15. Машинное представление вторично

После установления смысла связь можно хранить как:

```text
Link(start, end)
```

Реализация может использовать слот, адрес, номер строки или временную ссылку, но они не являются источником смысловой различимости.

```text
смысловая связь
!= техническая ссылка среды исполнения или хранения
```

## 16. Конструктивное ядро памяти

Текущий интерфейс `Memory` содержит:

```text
ensureRoot()                 -> R
ensureStartSelfClosed(e)     -> S = S ⟼ e
ensureEndSelfClosed(b)       -> E = b ⟼ E
ensure(b,e)                  -> b ⟼ e
```

А интерфейс `ReadMemory` отделяет чтение от записи.

Одинаковая структурная пара возвращает ту же смысловую связь; `ensure(R,R)` возвращает `R`.

## 17. Произвольный физический граф — отдельная граница

Произвольные адресные циклы нельзя автоматически считать уже различёнными связями МТС.

Импорт должен либо доказать укоренённую структурную различимость, либо канонизировать неразличимые записи, либо отклонить форму.

```text
physical graph
→ structural canonicalization
→ semantic MTS network
```

Эта запись находится в технической метанотации; смысловой принцип — «физическое представление не определяет онтологию».

## 18. Источник, словарь и теория

Текстовый знак ещё не является смыслом.

```text
точные байты
→ канонический носитель STRING→QUATERNARY
→ связевое представление источника
→ позиция / история употребления
→ словарь D
→ грамматика G
→ теория T
→ интерпретатор I = D ⟼ (G ⟼ T)
→ контекст K
→ форма / результат
```

Один байт кодируется одним `[8 bits]`-конвертом. Нормализация `Unicode` и деление на кодовые точки не являются фундаментальным источником смысла.

## 19. Локальное равенство не заменяет тождество связи

Дополнительное контекстное отношение может быть представлено:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Оно не переопределяет тождество связи по полюсам и не вводит глобальное транзитивное замыкание.

## 20. Производная рекурсивная реверсия

F4 вводит производную антиизоморфную операцию `J`:

```text
J(R)=R
J(O)=C
J(C)=O
J(L)=L
J(U)=U
```

Она отличается от простой перестановки полюсов `P`:

```text
P(L)=U
P(U)=L
```

и также отличается от обратного отношения навигации, логического отрицания и несвязи.

## 21. Счёт по степени связности

F5 использует:

```text
0 -> U
1 -> L

D1 = L
D2 = L ⟼ L
D3 = (L ⟼ L) ⟼ L
...
```

Положительные конечные степени попарно различны и не образуют конечных положительных циклов.

Критически:

```text
U ⟼ L != L
```

Поэтому производный следующий элемент задаётся:

```text
S0(U)=L
S0(D)=D⟼L, D∈Pos
```

и получается:

```text
алгебра степеней связности
→ производная алгебра Пеано
```

## 22. Счёт относится к вхождениям

Одна смысловая связь может учитываться несколько раз только через разные структурные вхождения.

```text
смысловая связь
!= тождество вхождения
!= степень количества
```

## 23. Производные теории не расширяют корневую онтологию

F6 строит поверх обычных связей:

- конечные коллекции;
- конечные функции как данные;
- относительную навигацию и пути;
- прикладные интерпретации.

Общая схема:

```text
корневая смысловая связь
+ явная теория / контекст
+ явные роли
+ структура вхождений / происхождения
→ производное суждение
```

Ни множество, ни функция, ни путь, ни роль приложения не становятся новым корневым видом сущности.

## 24. Историческая граница

Старые формы:

```text
♀F / F♂
```

относятся к исторической проекционной семантике.

Текущая остенсивная теоретическая ориентация:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

При этом `♂`/`♀` остаются отложенными внутренними знаками F1 v0.9.

## Итог

```text
всё есть связь
↓
самозамыкание — первичный структурный различитель
↓
∞ — единственная полностью самозамкнутая связь
↓
R/O/C/L/U
↓
связанность с уже различёнными связями
↓
тождество по структурно различённым полюсам
↓
явные I / K / Rule / Act / Run
↓
поиск / проверка / воспроизведение
↓
явная материализация
```

Главное ограничение: **технический идентификатор никогда не становится первоначальным источником смыслового различия**.

Текущая машинная граница задаётся принятым `mts-contract/v0.9` и `mts-conformance/v0.9`; реализация `@mts/core` проверяется относительно этой границы и не определяет теорию сама по себе.
