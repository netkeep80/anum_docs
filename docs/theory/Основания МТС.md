# Основания МТС

Статус: **актуальное теоретическое основание Foundation v2 candidate**.

Уровень: **онтология / остенсивность / границы семантической идентичности**.

Этот документ отвечает на три исходных вопроса:

1. что считается существующим в МТС;
2. как фундаментальная структура связи показывается **остенсивно**, без внешнего типа;
3. что нельзя незаметно добавлять к теории как host-метаданные.

Следующая версия МТС ещё не принята формально. Historical contracts v0.2–v0.5 сохраняют accepted-статус, но Foundation v2 опирается на более глубокое основание, изложенное ниже.

---

# 1. Исходный постулат

```text
всё есть связь
```

Внутри МТС нет второй первичной онтологии «узлы + связи».

Любая семантически существенная сущность должна быть представима связью либо сетью связей.

Это относится и к тому, что обычно считают метаобъектами:

```text
смысл
контекст
словарь
теория
правило
источник
акт интерпретации
доказательство
состояние памяти
```

Они не получают привилегированный ontological type только потому, что реализации так удобнее.

---

# 2. Акорень `∞` — исходная остенсивная связь

МТС имеет различённый акорень:

```text
∞
```

Его собственная форма показывает его структуру:

```text
∞ = ∞ ⟼ ∞
```

То есть оба полюса акорня замыкаются на него самого.

Это не сокращение для host-object и не графический decoration. Знак `∞` **остенсивно предъявляет** полностью самозамкнутую форму.

Foundation-v2 чтение:

> акорень является различённой неподвижной точкой смысла; «смысл смысла» снова является связью смыслов.

Но из этого не вводится внешний operator:

```text
Meaning(x)
```

и не возникает отдельный сорт «значений связи».

Смысл остаётся внутри той же link-only ontology.

---

# 3. Четыре остенсивные формы бинарной связи

Для начала `b` и конца `e` Foundation v2 сохраняет четыре формы различённости:

```text
∞        ни один внешний полюс не различён;
♂e       конец e различён, начало самозамкнуто;
b♀       начало b различено, конец самозамкнут;
b ⟼ e    оба полюса различены.
```

Их структурные уравнения:

```text
R = R ⟼ R      # ∞
S = S ⟼ e      # ♂e
E = b ⟼ E      # b♀
X = b ⟼ e      # b ⟼ e
```

Здесь положение знака имеет буквальную структурную наглядность:

```text
♂e
^ самозамкнутое начало слева

b♀
 ^ самозамкнутый конец справа
```

Именно это — **остенсивный смысл** `♂` и `♀`.

Знаки не означают сами по себе:

```text
PUSH
POP
constructor
destructor
getStart
getEnd
```

Операционное направление принадлежит акту разрешения, в котором уже известно, какие occurrences/bindings предъявлены.

---

# 4. Самозамыкание — форма, а не type-tag

Из:

```text
S = S ⟼ e
```

не следует, что `S` всегда является «недостроенным объектом».

Та же exact occurrence может быть полностью известным значением в другой связи.

Аналогично из:

```text
Q = Q ⟼ Q
```

не следует:

```text
Q = ∞
```

Акорень — **различённая exact occurrence**, а не глобальный класс всех fully-self-closed links.

Поэтому Foundation v2 различает:

```text
self-closed shape
exact occurrence
роль этой occurrence в конкретном акте
```

Эти три вещи нельзя схлопывать.

---

# 5. Ромб различённости

Четыре формы удобно видеть как наглядный ромб:

```text
              b ⟼ e
             /     \
           ♂e       b♀
             \     /
                ∞
```

Это не внешний enum и не lattice-type в реализации.

Ромб показывает только остенсивный факт:

- `∞` не предъявляет внешних полюсов;
- `♂e` предъявляет только `e`;
- `b♀` предъявляет только `b`;
- `b⟼e` предъявляет оба.

При явном binding обе однополюсные формы могут разрешаться к одной complete relation:

```text
♂e + b  → b ⟼ e
b♀ + e  → b ⟼ e
```

При этом исходные `♂e` и `b♀` не мутируют.

---

# 6. Инверсия также видима структурно

Инверсия complete relation меняет направление:

```text
b ⟼ e
↕
e ⟼ b
```

Для partial forms инверсия меняет ветви:

```text
♂e  ↔  e♀
b♀  ↔  ♂b
```

То есть start-self-closure и end-self-closure являются симметричными остенсивными формами.

Это сильнее и экономнее модели, где для каждой операции вводится отдельный opcode.

---

# 7. Пятисвязный корневой bootstrap

Акорень даёт первое ориентированное различение смыслов:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

Остенсивно:

```text
O = O ⟼ R  ≡  ♂∞
C = R ⟼ C  ≡  ∞♀
L = O ⟼ C
U = C ⟼ O
```

Поэтому генеалогия не является произвольным присваиванием четырём токенам:

```text
∞
↓
♂∞       ∞♀
 \       /
  O     C
   \   /
    L / U
```

В терминах ачисел:

```text
[ ] 1 0
```

являются четырьмя различёнными root-derived bootstrap/serialization meanings; сам `∞` не является абитом.

---

# 8. Корневые абиты и `♂/♀` нельзя смешивать

Есть два разных слоя знаков:

```text
[ ] 1 0   — корневые абиты ачисел;
♂ ♀ ⟼     — знаки формальной нотации форм связи.
```

Они связаны через root semantics, но не являются одними и теми же source occurrences.

Например:

```text
[ → O = O ⟼ R ≡ ♂∞
```

не означает, что UTF-8 character `[` тождественен UTF-8 character `♂`.

В bootstrap сначала существуют различённые root meanings; затем становится возможным Anum/string transport; только потом source glyph `♂` может быть разрешён словарём в соответствующую ostensive form.

Это предотвращает bootstrap circularity.

---

# 9. Машинный `Link(start,end)` — проекция, не фундаментальная нотация

Reference implementation удобно хранит binary relation как:

```text
Link(start, end)
```

Но это машинная запись уже понятой структуры.

Правильная иерархия:

```text
остенсивная форма        structural equation       machine carrier
∞                    →  R = R ⟼ R             → Link(R,R)
♂e                   →  S = S ⟼ e             → Link(S,e)
b♀                   →  E = b ⟼ E             → Link(b,E)
b⟼e                  →  X = b ⟼ e             → Link(b,e)
```

Если документация начинает с `Link(start,end)` и теряет левую колонку, она теряет один из главных принципов МТС: **форма сама показывает отношение**.

---

# 10. Связь не имеет скрытых свойств

В machine carrier достаточно двух полюсов:

```text
start
end
```

Такие понятия, как:

```text
type
name
meaning
context
isAxiom
isRoot
stage
owner
```

не должны появляться как привилегированные semantic fields.

Если роль важна, она выражается дополнительными links/evidence.

Например:

```text
T ⟼ Rule
```

является admission evidence; `Rule.isAxiom=true` не требуется.

---

# 11. Exact occurrence предшествует structural equality

Две связи могут иметь одну форму и оставаться разными:

```text
P1 = A ⟼ B
P2 = A ⟼ B

P1 ≠ P2
```

Даже partial self-closed forms не обязаны быть уникальны:

```text
S1 = S1 ⟼ e
S2 = S2 ⟼ e

S1 ≠ S2
```

Обе можно остенсивно записать как `♂e`, если речь идёт о pattern/форме, но exact evidence обязано указать, какая occurrence выбрана.

Отсюда:

```text
остенсивная форма ≠ exact identity
```

Остенсивность показывает структуру; identity различает существование.

---

# 12. Cycles, sharing и multiplicity остаются native

МТС естественно допускает:

```text
self cycles
mutual cycles
sharing
duplicate pairs
```

Их не нужно разворачивать в бесконечные деревья.

Recursive Anum может быть canonical root-relative occurrence-tree description на своей области, но arbitrary shared/cyclic aset остаётся конечной native network с exact occurrences.

Graph isomorphism/bisimulation не создаёт semantic identity.

---

# 13. Контекст — сеть связей

Foundation v2 представляет active context явно:

```text
P = parent ⟼ current
K = K ⟼ P
```

и:

```text
↑ = current(K)
```

`current` может быть любой exact relation, включая:

```text
∞
♂e
b♀
b⟼e
```

Поэтому `↑` означает current relation выбранного `K`, а не «текущую завершённую пару» и не ambient host variable.

Создание нового current даёт новый persistent `K_after`; старый `K_before` остаётся неизменным.

---

# 14. Structural declaration отделена от execution

Одна декларативная форма:

```text
♂e
```

может участвовать в разных актах:

```text
known e + binding b   → resolve/find b⟼e
known S occurrence    → read/check distinguished e
known both            → verify relation
pattern only          → associative search candidates
```

Ни один из этих режимов не является вторым intrinsic meaning glyph-а `♂`.

То же относится к `b♀` и `b⟼e`.

Это фундаментальное Foundation-v2 разделение:

```text
form is declarative
execution = directional resolution under explicit evidence
```

---

# 15. Source не равен форме

UTF-8 glyph — это source, а не semantic occurrence.

Foundation-v2 source path:

```text
raw UTF-8
→ canonical astring content C
→ exact source occurrence S
→ selected segmentation
→ scoped D
→ explicit G/T admission
→ exact form F
```

Поэтому source character `♂` не несёт семантику магически.

Словарь явно связывает его content с ostensive self-closure form.

Аналогично source spelling `[`, `]`, `1`, `0` не создаёт root kernel; root kernel логически предшествует string notation.

---

# 16. Контекст, словарь, теория и акт остаются link-only

Foundation v2 выражает ordinary links:

```text
K — context
D — dictionary
G — grammar admission
T — theory admission
I — interpreter
A — actual act
```

Actual act фиксирует exact evidence конкретного resolution:

```text
source
selected form
D/G/T
K_before
binding
result
K_after
```

Роли сами в конечном счёте также разрешаются через link/string vocabulary, а не встроенный record type.

---

# 17. Read/replay не равно materialize

```text
read / find / resolve / replay
```

не должны скрыто создавать отсутствующие relations.

Effect side отделён:

```text
materialize / define / persist transition
```

Это особенно важно для остенсивной partial form.

Запрос:

```text
♂e + b
```

может искать existing `b⟼e`; сам факт запроса не обязан создать такую связь.

---

# 18. Локальное равенство не уничтожает различённость

Foundation v2 использует explicit representative evidence:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

```text
Equal_K(a,b)
⇔ rep_K(a) is rep_K(b)
```

Остенсивно одинаковая форма двух occurrences не делает их равными.

```text
♂e occurrence S1
♂e occurrence S2
```

могут оставаться различными, пока context/theory не предъявит explicit relation.

---

# 19. Persistent identity не равна физическому адресу

В runtime exact occurrence может иметь opaque ref.

Persistent L4 различает:

```text
runtime occurrence ref
persistent dataset-local logical occurrence id
snapshot-local slot
physical backend address
```

Только dataset-local logical identity сохраняет lineage внутри одного persistent artifact.

Физическое положение записи не является смыслом.

---

# 20. Итоговое основание

Foundation v2 можно свести к следующей последовательности:

```text
всё есть связь
↓
∞ = ∞⟼∞
↓
остенсивные формы ∞ / ♂e / b♀ / b⟼e
↓
пятисвязный root bootstrap ∞ [ ] 1 0
↓
exact occurrence identity
↓
explicit K / D / G / T / I / A
↓
associative search + trusted replay
↓
explicit materialization + persistent apamemory
```

Главное здесь не в символах самих по себе, а в принципе:

> **МТС стремится показывать структуру отношением непосредственно, а не объяснять её внешним типом.**

Поэтому `∞`, `♂`, `♀` и `⟼` являются фундаментальным остенсивным слоем теории, а `Link(start,end)` — только одним из способов её машинного воплощения.
