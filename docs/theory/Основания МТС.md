# Основания МТС

Этот документ объясняет текущее основание следующей версии Метатеории связей. Оно остаётся кандидатом до отдельного решения о принятии. Ранее принятые версии сохраняются как воспроизводимая история и не переписываются задним числом.

Главная последовательность изложения:

```text
остенсивная форма
→ структурное уравнение
→ тождество связи по полюсам
→ явные связи контекста и свидетельств
→ машинное представление
```

## 1. Всё есть связь

Исходный постулат МТС:

```text
всё есть связь
```

МТС не вводит вторую первичную онтологию «объекты плюс связи». Если различие существенно для смысла, оно должно быть представимо связью или сетью связей.

Это относится и к понятиям:

```text
контекст
словарь
теория
правило
исходная запись
акт интерпретации
доказательство
состояние памяти
```

Их не требуется превращать в скрытые типы примитивной связи.

### 1.1. Несвязь не является второй сущностью

**Несвязь не вводится как отдельный вид существующего**.

Если абсолютную несвязь можно различить, указать или связать с чем-либо, само это различение уже делает её участником связи. Поэтому различаются:

```text
несвязь                 — отсутствие связности
смысл несвязи           — может быть выражен связью
знак или ачисло несвязи — может существовать как описание
```

В пятисвязном корне:

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
```

`U` существует как связь. Абит `0` может нести корневой смысл несвязи, но не является буквальным отсутствием связи и не является встроенной командой удаления.

## 2. Акорень

Акорень обозначается остенсивным знаком:

```text
∞
```

Его структура:

```text
∞ = ∞ ⟼ ∞
```

Оба полюса самозамкнуты на сам акорень. Знак непосредственно показывает форму связи.

## 3. Четыре остенсивные формы

Для начала `b` и конца `e` различаются:

```text
∞        оба полюса самозамкнуты
♂e       начало самозамкнуто, конец e различён
b♀       начало b различено, конец самозамкнут
b ⟼ e    оба полюса различены
```

Структурно:

```text
R = R ⟼ R      # ∞
S = S ⟼ e      # ♂e
E = b ⟼ E      # b♀
X = b ⟼ e      # b ⟼ e
```

`♂` и `♀` показывают самозамыкание соответствующего полюса. Они сами по себе не являются командами получения полюсов, построения, стека или изменения памяти.

## 4. Самозамыкание не является специальным типом

Из:

```text
S = S ⟼ e
```

не следует, что `S` является «незавершённым объектом». Это обычная связь с полюсами `(S,e)`.

Из:

```text
Q = Q ⟼ Q
```

также не следует:

```text
Q = R
```

Если `Q ≠ R`, то пары полюсов `(Q,Q)` и `(R,R)` различны. Поэтому несколько разных петель допустимы без нарушения аксиомы тождества.

## 5. Тождество связи определяется полюсами

Фундаментальная аксиома:

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Следовательно:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=> P1 = P2
```

В МТС не существует двух разных связей с одной и той же упорядоченной парой полюсов.

При этом похожая запись не всегда означает одну пару. Например:

```text
S1 = S1 ⟼ e
S2 = S2 ⟼ e
```

может задавать разные связи, потому что их начала `S1` и `S2` различны.

Таким образом нужно отличать:

```text
одинаковый образец записи
от
одинаковой упорядоченной пары конкретных полюсов
```

## 6. Инверсия

Для полной связи:

```text
b ⟼ e  ↔  e ⟼ b
```

Для однополюсных форм:

```text
♂e  ↔  e♀
b♀  ↔  ♂b
```

Инверсия меняет порядок полюсов. Если оба полюса совпадают, инверсия не меняет связь.

## 7. Пятисвязный корень

Первое корневое различение задаётся пятью связями:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Остенсивно:

```text
O = O ⟼ R ≡ ♂∞
C = R ⟼ C ≡ ∞♀
```

Корневой четверичный словарь:

```text
[ → O
] → C
1 → L
0 → U
```

Нужно различать:

```text
семантический корневой базис: R/O/C/L/U — 5 связей
транспортный алфавит:        [ ] 1 0   — 4 абита
```

Акорень `R` не является пятым абитом.

## 8. Исходные символы не являются корневыми связями

Символ `[` в текстовом файле не тождественен связи `O` по самому написанию.

Порядок уровней:

```text
корневые связи
→ абиты
→ ачисла
→ строки
→ формальные знаки
→ словарное разрешение знаков
```

Так корень не определяется языком, существование которого само зависит от корня.

## 9. Машинное представление вторично

В реализации связь можно хранить как:

```text
Link(start, end)
```

У примитивной связи только два обязательных полюса. Поля вида «тип», «контекст», «теория», «правило» или «аксиома» не являются частью примитива.

Если роль существенна, она выражается связью. Например:

```text
T ⟼ Rule
```

## 10. Техническая ссылка не является третьим полюсом

Реализация вправе использовать:

```text
адрес записи
номер слота
временную ссылку построения
идентификатор операции
```

для доступа к данным и построения циклов.

Но эти значения не создают дополнительное смысловое тождество связи. После разрешения структуры связь определяется только своими началом и концом.

Если физический артефакт содержит две записи одной пары полюсов, они должны быть отклонены как дублирующее представление или канонизированы в одну связь.

## 11. Циклы, петли и совместное использование естественны

Асеть может содержать:

```text
самозамыкание
взаимные циклы
одну связь, используемую несколькими структурами
повтор ссылки на одну связь в последовательности
```

Для данного `a` петля:

```text
Loop(a) = a ⟼ a
```

единственна.

Если:

```text
a = a ⟼ a
```

то:

```text
Loop(a) = a
```

В частности:

```text
Loop(R) = R
```

## 12. Позиционная множественность не является множественностью связей

Последовательность:

```text
[L, L, L, U]
```

содержит четыре позиции, но только две используемые здесь связи `L` и `U`.

Если необходимо различить первый и второй акты употребления `L`, различие хранится структурой последовательности или историей актов, а не копированием `L`.

## 13. Контекст является сетью

Кандидат контекста:

```text
P = parent ⟼ current
K = K ⟼ P
```

Тогда:

```text
↑ = current(K)
```

`↑` означает текущую связь явно выбранного `K`, а не скрытую глобальную переменную среды исполнения.

Если два состояния имеют одну и ту же полную связевую форму, по аксиоме тождества это одна связь. История переходов должна различаться собственной структурой актов.

## 14. Форма отделена от действия

Одна форма может участвовать в разных действиях:

```text
поиск
проверка
разрешение
материализация
```

Поэтому:

```text
форма ≠ команда
```

Разные акты получения одной связи не создают разные экземпляры результата.

## 15. Исходная запись отделена от формы

Текстовый знак ещё не является смыслом.

Рабочая цепочка:

```text
байты исходной записи
→ каноническое содержимое
→ позиция или связевая история употребления
→ выбранное разбиение
→ словарь D
→ допуск грамматикой G и теорией T
→ форма F
```

Одна последовательность байтов может участвовать в разных актах чтения. Их различие выражается контекстом и историей, а не скрытым экземплярным тождеством одной связи.

## 16. Словарь, теория и акт также являются связями

Состояние словаря может иметь форму:

```text
D = D ⟼ (parentScope ⟼ localHistory)
```

Допуск формы или правила:

```text
G ⟼ Form
T ⟼ Form
T ⟼ Rule
```

Конкретный акт интерпретации связывает источник, контекст, выбранные формы и результат. Разные акты могут указывать на одну и ту же результирующую связь.

## 17. Чтение отделено от изменения

Один из главных инвариантов:

```text
читать / искать / разрешать / проверять
                    ≠
создавать / удалять / изменять
```

```text
не найдено ≠ не существует
```

Семантическая однозначность `A ⟼ B` не означает, что физическая запись этой связи уже присутствует в конкретной апамяти.

Явная операция получения может вести себя так:

```text
ensureLink(A,B):
    если A ⟼ B уже записана -> вернуть её
    иначе -> материализовать её
```

## 18. Локальное равенство не заменяет фундаментальное тождество

Кандидат локального отношения представителей:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

не переопределяет аксиому тождества связи по полюсам.

Из локального отношения не следуют автоматически:

```text
транзитивное замыкание
глобальная подстановка
конгруэнтность
переписывание всей сети
```

Дополнительное правило вывода должно быть отдельно допущено теорией.

## 19. Поиск доказательства отделён от проверки

Поиск может использовать сложные и недоверенные методы. Доверенная часть получает выбранные свидетельства и воспроизводит их.

```text
поиск
→ выбранное доказательство
→ детерминированная проверка
→ принять / отвергнуть
```

Проверка не должна материализовать отсутствующие записи ради собственного успеха.

## 20. Последовательность актов хранит происхождение

Порядок действий может быть связан так:

```text
Run_0 = R
Run_(i+1) = Run_i ⟼ A_i
```

Повтор одного и того же `A_i` в разных позициях остаётся повтором ссылки на одну связь. Порядок задаётся самой структурой `Run`.

## 21. Долговременное хранение не определяет тождество

При сохранении могут различаться:

```text
оперативная ссылка
номер записи
номер в снимке
физический адрес
```

Они являются техническими координатами. Смысловое тождество связи остаётся определённым полюсами.

После загрузки хранилище должно восстановить каноническую сеть без двух смысловых связей одной пары.

Вопрос универсального сравнения произвольных независимых циклических представлений может решаться отдельно и не даёт права вводить скрытый экземплярный идентификатор.

## 22. Историческая граница обозначений

В исторической версии использовались формы:

```text
♀F / F♂
```

Они относятся к старому чтению проекций начала и конца.

Текущее остенсивное основание фиксирует:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

Историческую запись нельзя незаметно переносить в новую семантику самозамыкания.

## 23. Что ещё не принято

Текущее основание ещё не является новой опубликованной версией МТС. Отдельного решения требуют:

- окончательный договор следующей версии;
- граница переноса исторических возможностей;
- полная семантика вложенной десериализации ачисел;
- производственное долговременное хранилище;
- перевод внешних потребителей на новую принятую версию.

## Итог

Основание можно сжать до цепочки:

```text
всё есть связь
↓
несвязь не существует как отдельная сущность; её смысл выражается связью
↓
∞
↓
∞ / ♂e / b♀ / b⟼e
↓
R/O/C/L/U и [ ] 1 0
↓
тождество связи по началу и концу
↓
явные K / D / G / T / A
↓
поиск и проверка
↓
явное изменение апамяти
```

Главное ограничение: удобство реализации не должно незаметно становиться новой онтологией МТС.
