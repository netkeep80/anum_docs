# Основания МТС

Этот документ объясняет текущее основание следующей версии Метатеории связей. Оно остаётся кандидатом до отдельного решения о принятии. Ранее принятые версии 0.2–0.5 сохраняются как воспроизводимая история и не переписываются задним числом.

Главная последовательность изложения:

```text
остенсивная форма
→ структурное уравнение
→ точное вхождение связи
→ явные связи контекста и свидетельств
→ машинное представление
```

## 1. Всё есть связь

Исходный постулат МТС:

```text
всё есть связь
```

МТС не вводит вторую первичную онтологию «объекты плюс связи». Если различие существенно для смысла, оно должно быть представимо связью или сетью связей.

Это относится и к понятиям:

```text
контекст
словарь
теория
правило
исходная запись
акт интерпретации
доказательство
состояние памяти
```

Их не требуется превращать в скрытые типы примитивной связи.

### 1.1. Несвязь не является второй сущностью

Постулат «всё есть связь» означает также, что **несвязь не вводится как отдельный вид существующего**.

Если бы абсолютная несвязь была некоторой сущностью `N`, которую можно различить, указать или связать с чем-либо, то само это различение уже делало бы `N` участником связи. Поэтому в МТС различаются:

```text
несвязь                 — отсутствие связности;
смысл несвязи           — может быть выражен связью;
знак или ачисло несвязи — может существовать как описание;
```

То есть субъект или интерпретатор может различить **смысл несвязи**, но не саму несвязь как натуральный объект: различить её означало бы уже установить связь.

В пятисвязном корне этому соответствует пара противоположно ориентированных связей:

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
```

`U` существует в натуре как связь. Абит `0` поэтому можно читать как корневой носитель смысла несвязи, но нельзя отождествлять с буквальным отсутствием связи.

Важно также не превращать это чтение во встроенную команду:

```text
0 ≠ DELETE_LINK
```

Конкретный протокол вправе использовать `0` как явный знак запроса удаления, но само удаление остаётся отдельным актом интерпретации и апамяти. Значение абита и действие над сетью — разные уровни.

Отсюда полезная граница:

```text
нет связи в натуре
≠
есть связь, несущая смысл несвязи
≠
есть описание отсутствующей или возможной связи
≠
произошёл акт удаления связи
```

## 2. Акорень

Акорень обозначается остенсивным знаком:

```text
∞
```

Его структура:

```text
∞ = ∞ ⟼ ∞
```

Оба полюса самозамкнуты на сам акорень. Знак не является украшением над другой моделью: он непосредственно показывает форму связи.

Акорень можно читать как различённую неподвижную точку смысла: смысл смысла снова является связью смыслов. Для этого не нужен отдельный внешний объект «смысл».

## 3. Четыре остенсивные формы

Для начала `b` и конца `e` различаются четыре формы:

```text
∞        оба внешних полюса самозамкнуты
♂e       начало самозамкнуто, конец e различён
b♀       начало b различено, конец самозамкнут
b ⟼ e    оба полюса различены
```

Структурно:

```text
R = R ⟼ R      # ∞
S = S ⟼ e      # ♂e
E = b ⟼ E      # b♀
X = b ⟼ e      # b ⟼ e
```

Положение знаков `♂` и `♀` показывает, какой полюс самозамкнут.

Они **не означают сами по себе** команды:

```text
getStart
getEnd
constructor
destructor
PUSH
POP
```

Действие определяется конкретным актом разрешения и предъявленными связями.

## 4. Самозамыкание не является типом состояния

Из:

```text
S = S ⟼ e
```

не следует, что `S` всегда «незавершённый объект». В другой ситуации то же точное вхождение может быть обычным известным значением.

Из:

```text
Q = Q ⟼ Q
```

также не следует:

```text
Q = ∞
```

Акорень различён как конкретное вхождение. Одинаковая самозамкнутая форма не создаёт тождество.

## 5. Различённость полюсов

Четыре формы можно видеть как ромб:

```text
              b ⟼ e
             /     \
           ♂e       b♀
             \     /
                ∞
```

Это не перечисление типов в реализации. Ромб показывает только степень различённости полюсов.

При явной подстановке две однополюсные формы могут привести к одной полной связи:

```text
♂e + b  → b ⟼ e
b♀ + e  → b ⟼ e
```

Исходные частичные связи при этом не изменяются.

## 6. Инверсия

Для полной связи:

```text
b ⟼ e  ↔  e ⟼ b
```

Для однополюсных форм:

```text
♂e  ↔  e♀
b♀  ↔  ♂b
```

Инверсия меняет ориентацию структуры, а не присваивает знакам `♂` и `♀` отдельные команды.

## 7. Пятисвязный корень

Первое корневое различение задаётся пятью связями:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

Остенсивно:

```text
O = O ⟼ R ≡ ♂∞
C = R ⟼ C ≡ ∞♀
```

Поэтому `[ ] 1 0` — **корневые абиты ачисел**, а `♂ ♀ ⟼` — **знаки формальной нотации форм связи**. Эти уровни связаны, но не тождественны.

## 8. Исходные символы не являются корневыми связями

Символ `[` в текстовом файле не тождественен связи `O`, а символ `♂` не тождественен той же связи по написанию.

Порядок возникновения уровней:

```text
корневые связи
→ абиты
→ ачисла
→ строки
→ формальные знаки
→ словарное разрешение знаков
```

Так устраняется круг, в котором корень пришлось бы определять языком, существование которого само зависит от корня.

## 9. Машинное представление вторично

В реализации удобно хранить связь как:

```text
Link(start, end)
```

Но эта запись появляется после остенсивной и структурной:

```text
∞    → R = R ⟼ R → Link(R,R)
♂e   → S = S ⟼ e → Link(S,e)
b♀   → E = b ⟼ E → Link(b,E)
b⟼e  → X = b ⟼ e → Link(b,e)
```

Программный тип помогает хранить связь, но не заменяет язык МТС.

## 10. У связи только два обязательных полюса

Примитивная машинная связь не нуждается в обязательных полях:

```text
type
name
meaning
context
isRoot
isAxiom
stage
owner
```

Если роль существенна, она выражается дополнительной связью. Например допуск правила теорией:

```text
T ⟼ Rule
```

не требует поля `Rule.isAxiom`.

## 11. Точное вхождение

Две связи с одинаковыми полюсами могут существовать одновременно:

```text
P1 = A ⟼ B
P2 = A ⟼ B
P1 ≠ P2
```

То же относится к самозамкнутым формам:

```text
S1 = S1 ⟼ e
S2 = S2 ⟼ e
S1 ≠ S2
```

Остенсивная форма показывает структуру, но не заменяет тождество конкретного существования.

Поэтому:

```text
одинаковая форма ≠ одно вхождение
одинаковая пара полюсов ≠ одно вхождение
изоморфная сеть ≠ тождество
```

## 12. Циклы, совместное использование и множественность естественны

Асеть может содержать:

```text
самозамыкание
взаимные циклы
одну связь, используемую несколькими другими
несколько вхождений одной пары полюсов
```

Их не требуется разворачивать в бесконечное дерево.

Рекурсивное ачисло может описывать древовидную область, но произвольная циклическая или разделяемая асеть остаётся конечной сетью точных вхождений.

## 13. Контекст является сетью

Текущий кандидат контекста:

```text
P = parent ⟼ current
K = K ⟼ P
```

Тогда:

```text
↑ = current(K)
```

`↑` означает текущую связь явно выбранного `K`, а не скрытую глобальную переменную среды исполнения.

Новое состояние создаёт новое точное `K_after`; `K_before` остаётся неизменным.

## 14. Форма отделена от действия

Одна форма:

```text
♂e
```

может участвовать в разных действиях:

```text
поиск связи b ⟼ e
проверка предъявленной связи
разрешение недостающего b
использование самого S = S ⟼ e как значения
```

Поэтому:

```text
форма ≠ команда
```

Направление вычисления определяется явными свидетельствами конкретного акта.

## 15. Исходная запись отделена от формы

Текстовый знак ещё не является смыслом.

Рабочая цепочка:

```text
байты исходной записи
→ каноническое содержимое
→ конкретное вхождение исходной записи
→ выбранное разбиение
→ словарь D
→ допуск грамматикой G и теорией T
→ точная форма F
```

Одна и та же последовательность байтов может разрешаться по-разному в разных словарях.

## 16. Словарь, теория и акт также являются связями

Состояние словаря может иметь форму:

```text
D = D ⟼ (parentScope ⟼ localHistory)
```

Допуск формы или правила:

```text
G ⟼ Form
T ⟼ Form
T ⟼ Rule
```

Конкретный акт интерпретации `A` связывает выбранные точные свидетельства. Сам интерпретатор и произошедший акт — разные связи.

## 17. Чтение отделено от изменения

Один из главных инвариантов:

```text
читать / искать / разрешать / проверять
                    ≠
создавать / удалять / изменять
```

Отсутствующая связь не должна появляться только потому, что её искали.

Материализация является отдельным явным действием апамяти.

## 18. Локальное равенство не является глобальным переписыванием

Текущий кандидат использует явного представителя в контексте:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

```text
Equal_K(a,b)
⇔ rep_K(a) is rep_K(b)
```

Проверяется один явный шаг представителя. Из этого не следуют автоматически:

```text
транзитивное замыкание
глобальная подстановка
конгруэнтность
изоморфическое равенство сетей
```

Дополнительное правило вывода должно быть отдельно допущено теорией.

## 19. Поиск доказательства отделён от проверки

Поиск может использовать сложные и недоверенные методы. Доверенная часть получает выбранные точные свидетельства и воспроизводит их.

```text
поиск
→ выбранное доказательство
→ детерминированная проверка
→ принять / отвергнуть
```

Сложность поиска не должна автоматически увеличивать доверенную семантическую основу.

## 20. Последовательность актов хранит происхождение

Порядок действий может быть связан так:

```text
Run_0 = R
Run_(i+1) = Run_i ⟼ A_i
```

Соседние действия требуют точного совпадения переходного контекста:

```text
A_i.after is A_(i+1).before
```

Такая последовательность хранит порядок, но сама не создаёт логическую транзитивность между началом и концом.

## 21. Долговременное тождество не является физическим адресом

При сохранении различаются:

```text
оперативная ссылка
долговременный логический идентификатор
номер в снимке
физический адрес
```

После повторного открытия набора данных логическое тождество должно сохраняться, даже если оперативная ссылка и физическое расположение изменились.

Одинаковая топология, импортированная в независимый набор данных, не обязана означать те же точные вхождения.

## 22. Историческая граница обозначений

В принятой версии 0.2 использовались формы:

```text
♀F / F♂
```

Они относятся к историческому чтению проекций начала и конца.

Текущее остенсивное основание фиксирует другую ориентацию:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

Историческую запись нельзя незаметно переносить в новую семантику самозамыкания.

## 23. Что ещё не принято

Текущее основание ещё не является новой опубликованной версией МТС. Отдельного решения требуют, в частности:

- окончательный договор следующей версии;
- граница переноса исторических возможностей;
- универсальное представление произвольных асетей через ачисла, если оно вообще необходимо;
- производственное долговременное хранилище;
- перевод внешних потребителей на новую принятую версию.

## Итог

Основание можно сжать до цепочки:

```text
всё есть связь
↓
несвязь не существует как отдельная сущность; её смысл выражается связью
↓
∞
↓
∞ / ♂e / b♀ / b⟼e
↓
R/O/C/L/U и [ ] 1 0
↓
точные вхождения связей
↓
явные K / D / G / T / A
↓
поиск и проверка
↓
явное изменение апамяти
```

Главное ограничение: удобство реализации не должно незаметно становиться новой онтологией МТС.
