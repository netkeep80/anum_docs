# Основания МТС

Статус: **актуальное теоретическое основание Foundation v2 candidate**.

Уровень: **онтология / границы семантической идентичности**.

Этот документ отвечает на вопрос: **что считается существующим в МТС и что не следует добавлять к теории скрыто**.

Следующая версия МТС ещё не принята формально. Исторические контракты v0.2–v0.5 сохраняют свой accepted-статус, но текущая разработка Foundation v2 опирается на более строгие основания, изложенные здесь.

---

## 1. Исходный постулат

```text
всё есть связь
```

Минимальная сущность МТС — бинарная ориентированная связь:

```text
L = A ⟼ B
```

где:

- `L` — сама связь;
- `A` — её начало;
- `B` — её конец.

Внутри онтологии МТС не требуется отдельная первичная категория «узел». То, что в графовых библиотеках может быть представлено vertex-ом, здесь также является связью.

Поэтому сеть МТС — не обычный граф «узлы + рёбра», а **сеть связей между связями**.

---

## 2. Связь не имеет скрытых свойств

В онтологическом ядре связь имеет только два полюса:

```text
start
end
```

Такие понятия, как:

```text
тип
имя
роль
контекст
словарь
теория
источник
доказательство
время
владелец
```

не должны незаметно добавляться в структуру `Link` как привилегированные метаданные.

Если они существенны для семантики, они выражаются дополнительными связями.

Например теория может быть не host-object с полем `rules`, а exact occurrence `T`, связанная с допущенными формами и правилами обычными связями.

---

## 3. Точная идентичность вхождения

Один из центральных выводов Foundation v2:

```text
структура связи ≠ идентичность вхождения связи
```

Две связи могут иметь одинаковые полюса и оставаться разными сущностями:

```text
P1 = A ⟼ B
P2 = A ⟼ B

P1 ≠ P2
```

Эта возможность необходима для:

- provenance;
- нескольких одинаковых утверждений;
- истории словаря;
- actual acts;
- доказательств;
- циклов;
- sharing;
- различения одинаково выглядящих, но разных источников.

Поэтому pair interning не является аксиомой МТС.

---

## 4. Самозамыкание не отменяет exact identity

Допустима связь:

```text
R = R ⟼ R
```

Но из одинаковой формы не следует тождество:

```text
R = R ⟼ R
X = X ⟼ X

R ≠ X
```

Следовательно, самозамкнутая форма не должна использоваться как глобальная проверка класса объекта:

```text
if link.start == link and link.end == link:
    object_is_root
```

такое правило было бы слишком сильным.

Foundation v2 различает конкретные bootstrap occurrences (`R/O/C/L/U`) **остенсивно** — как exact выбранные элементы системы. Их роль не распространяется автоматически на все связи той же формы.

---

## 5. Форма сети не является универсальным тождеством

МТС допускает конечные сети с:

```text
sharing
cycles
duplicate pairs
multiple self-cycles
```

Поэтому два изоморфных подграфа не считаются автоматически одной сущностью.

Graph isomorphism может быть полезным внешним алгоритмом сравнения структуры, но не является примитивным отношением семантической идентичности Foundation v2.

Аналогично:

```text
runtime slot
memory address
persistent backend handle
snapshot number
```

могут служить техническими идентификаторами реализации, но не объявляются универсальными именами сущностей МТС.

Portable representation обязана сохранять topology и multiplicity, а при загрузке может создавать новую область exact runtime identity.

---

## 6. Различённость предшествует равенству

В МТС полезно считать различённость исходной, а отождествление — явно заданным отношением.

Если две exact occurrences существуют отдельно, они остаются разными, пока конкретный контекст не предъявляет явное основание считать их представителями одного локального значения.

Foundation v2 поэтому использует локальную representative-семантику:

```text
K ⟼ (member ⟼ representative)
```

а не глобальное структурное равенство.

Это сохраняет важную асимметрию:

```text
факт существования двух вхождений
```

не уничтожается последующим логическим или контекстным их отождествлением.

---

## 7. Контекст — часть сети, а не внешний стек

Контекст интерпретации сам представим связями.

Минимальный Foundation-v2 снимок:

```text
P = parent ⟼ current
K = K ⟼ P
```

Здесь `K` — exact occurrence состояния контекста.

Это отличается от скрытого mutable `ContextFrame`:

- состояние можно предъявить как evidence;
- старое состояние сохраняется;
- переход можно проверять;
- нет необходимости доверять ambient stack интерпретатора.

Исторические `ContextFrame`, `◁`, `▷`, `↑◁`, `↑▷` относятся к accepted-линии v0.2–v0.5 и не являются онтологическими примитивами Foundation v2.

---

## 8. Словарь и теория — также сети

Foundation v2 не предполагает внешний глобальный namespace.

Scoped dictionary `D` хранит explicit parent/history structure, а definition occurrence является обычной связью.

Теория `T` аналогично выражает admission через exact membership evidence:

```text
T ⟼ Form
T ⟼ Rule
```

Тем самым один и тот же source или одна и та же структура могут интерпретироваться по-разному в разных explicit contexts/theories без изменения онтологии связей.

---

## 9. Source не равен смыслу

Последовательность байтов, строка, token и AST-node — не онтологические сущности особого сорта.

Если исходный текст должен участвовать в проверке, он получает собственное представление сетью связей:

```text
UTF-8 bytes
→ canonical content C
→ exact source occurrence S
```

Затем выбранное разрешение source связывается с `D/G/T` evidence.

Поэтому:

```text
одинаковый spelling ≠ один semantic occurrence
source occurrence    ≠ semantic form
semantic form        ≠ theory membership
```

---

## 10. Интерпретация не равна материализации

Это фундаментальная граница между теорией и контроллером памяти.

```text
read / find / select / replay
```

могут проверять уже существующую сеть, не создавая новых связей.

```text
materialize / define / delete
```

являются explicit effects и требуют отдельного основания.

Если read-only интерпретатор незаметно создаёт связь только потому, что она логически ожидается, он смешивает семантику и состояние памяти.

Foundation v2 запрещает такое смешение в trusted replay.

Подробнее: [Апамять и управление сетью связей](../specs/Апамять%20и%20управление%20сетью%20связей.md).

---

## 11. Actuality: описание не равно событию

Следует различать:

```text
I — интерпретатор / правило действия
A — конкретный произошедший actual act
```

`I` описывает возможность интерпретации.

`A` фиксирует конкретно выбранные exact occurrences и контекст её исполнения/проверки.

Это различие позволяет хранить provenance и строить доказательство как последовательность реально предъявленных актов, а не как текстовую реконструкцию после факта.

---

## 12. Доказательство не является скрытым свойством сети

Из наличия двух соседних связей или двух последовательных acts не следует новый логический факт автоматически.

```text
A0
A1
```

могут быть соседними в exact `Run`, но adjacency не означает transitivity.

Логическое правило должно быть:

1. явно выбрано;
2. явно допущено конкретной `T`;
3. снабжено exact premise/conclusion evidence;
4. повторно проверено trusted replay.

Эта граница нужна, чтобы proof search мог оставаться недоверенным.

---

## 13. Ачисло — описание, а не универсальная identity

Рекурсивное ачисло полезно как структурное описание сети от выбранного корня.

Однако произвольная асеть может содержать sharing и циклы, которые нельзя без потерь считать обычным рекурсивным деревом.

Поэтому Foundation v2 проводит границу:

```text
recursive Anum
= root-relative structural description на своей области

exact occurrence network
= общая identity-модель произвольной shared/cyclic асети
```

Это не обесценивает ачисла; наоборот, делает область их корректного применения точной.

---

## 14. Что является внешним по отношению к онтологии

Реализация может использовать:

```text
Python objects
C++ handles
hash tables
indices
B-trees
persistent addresses
AST classes
Unicode strings
SQL
```

Но эти механизмы не становятся сущностями МТС автоматически.

Критерий простой:

> если удалить конкретную реализацию и заменить её другой, должна ли исчезнуть семантика?

Если ответ «нет», значит соответствующее понятие должно иметь storage/language-neutral выражение через сеть связей и exact evidence.

---

## 15. Короткая формула Foundation v2

Текущие основания можно свернуть в несколько строк:

```text
есть только связи;
каждая связь бинарна и ориентирована;
каждое вхождение различимо точно;
форма не заменяет identity;
состояние выражается связями;
смысл выбирается explicit context/theory evidence;
поиск не равен доказательству;
replay не равен materialization;
вывод существует только через явно допущенное правило.
```
