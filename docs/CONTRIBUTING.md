# Руководство по вкладу

Изменения активного ядра вносятся через pull request.

## Канонические области

| Содержимое | Каталог |
|---|---|
| корневые формулы и тесты | `tests/` |
| reader, загрузка, reference contract и валидация | `core/` |
| практические преобразования | `converters/` |
| нормативная теория | `docs/theory/` |
| технические спецификации | `docs/specs/` |
| ненормативные исходные заметки | `docs/research/` |

Каждый активный документ должен иметь уникальную роль, а каждая функция — одну активную реализацию. Исторические варианты не сохраняются в `archive`, `legacy`, `old` или аналогичных каталогах: история уже находится в Git.

## Reference model и уровни

Архитектурные границы текущей версии задаёт [Reference model МТС v0.1](specs/Reference%20model%20МТС%20v0.1.md).

Изменение одного уровня не должно скрыто менять другой:

```text
L0 — онтология
L1 — семантическая модель
L2 — формальный язык
L3 — сериализация
L4 — исполнение
L5 — теория вывода
```

Если одинаковый видимый знак используется на нескольких уровнях, тождество его денотаций должно быть задано отдельным явным правилом.

## Жизненный цикл фундаментального решения

Изменение онтологии, reference semantics, формальной нотации, базового протокола или trusted proof rules не должно попадать прямо из исследовательской заметки в нормативное ядро.

Минимальный путь:

```text
Research
→ Problem
→ Candidate
→ Challenged
→ Modeled
→ Accepted
→ Released
```

`Accepted` означает явное решение владельца теории. До этого кандидат имеет статус `experimental`, даже если для него уже существует код или тестовая модель.

Состояния `Rejected`, `Deferred` и `Superseded` не требуют сохранения старой реализации в рабочем дереве: история решения остаётся в Git и GitHub.

## Ограничения

Изменение существующей теории, нотации, формата, reference model или корневой формулы должно выполняться отдельной задачей. Рефакторинг не должен вводить parser, prover, interpreter, compatibility layer или новый нормативный документ без самостоятельного обоснования.

Защищённый файл `docs/research/Исходные мысли МТС.md` изменяется только владельцем репозитория.

## Проверка

```bash
python -m pytest tests -v --tb=short
ruff check converters/ core/ tests/ --ignore E501,F401
git diff --check
```

Кодировка текстовых файлов — UTF-8. Пользовательские ошибки должны проверяться явно.
