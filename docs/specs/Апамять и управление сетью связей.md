# Апамять и управление сетью связей

Апамять — слой МТС, который хранит конкретно материализованную асеть, позволяет искать в ней связи, явно материализовать недостающие записи и воспроизводить засвидетельствованные действия.

Связанные документы:

- [Система аксиом МТС](../theory/Система%20аксиом%20МТС.md)
- [Основания МТС](../theory/Основания%20МТС.md)
- [Формальная нотация МТС](Формальная%20нотация%20МТС.md)
- [Ачисла и сериализация](Ачисла%20и%20сериализация.md)

Документ описывает текущую принятую границу апамяти МТС v0.9. Единственная действующая смысловая реализация написана на `TypeScript`; предыдущая неизменяемая машинная версия — v0.8.

## 1. Апамять хранит связи

Базовая структура МТС бинарна:

```text
Link(start, end)
```

Контекст, словарь, теория, исходная запись, акт интерпретации, история и доказательство могут быть представлены связями той же сети.

## 2. Тождество связи определяется полюсами

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Следовательно:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=> P1 = P2
```

Индекс, адрес записи, номер операции, позиция в последовательности или техническая ссылка не создают второе смысловое тождество связи.

F2/F3 дополнительно выводят отсутствие двух смысловых экземпляров без рекурсивно выраженного различия.

## 3. Апамять не равна универсуму МТС

Если конкретная память не содержит физической записи:

```text
A ⟼ B
```

из этого не следует, что такая связь невозможна или не существует в смысловом отношении.

```text
не найдено != не существует
```

## 4. Чтение и изменение разделены

```text
читать / искать / разрешать / проверять / воспроизводить
                    !=
создавать / удалять / изменять
```

Текущий `ReadMemory` предоставляет только чтение:

```text
root
linkCount
poles(link)
find(start,end)
outgoing(start)
incoming(end)
```

Явная материализация принадлежит `WriteMemory`:

```text
ensure(start,end)
```

Если связь уже присутствует, `ensure` возвращает её; иначе явно материализует.

## 5. Повторная материализация не создаёт второй экземпляр

```text
X = A ⟼ B
ensure(A,B) = X
ensure(A,B) = X
```

Допустимо различать два акта обращения к памяти, но их результат остаётся одной смысловой связью.

## 6. История не является скрытым тождеством связи

Разные акты чтения, построения или наблюдения могут различаться отдельной структурой истории, происхождения или позиций.

```text
разные акты получения одной связи
!=
разные смысловые связи
```

## 7. Циклы и совместное использование

Апамять поддерживает:

```text
R = R ⟼ R
Loop(a) = a ⟼ a
```

а также взаимные циклы и совместное использование одной связи несколькими структурами, если различимость укоренена относительно уже различённого основания.

Для данного `a` связь `a ⟼ a` единственна.

Если:

```text
a = a ⟼ a
```

то:

```text
a = R
```

## 8. Корень каноничен

```text
R = R ⟼ R
```

Поэтому отдельная смысловая связь с той же парой `(R,R)` невозможна. Внутренний слот или техническая ссылка не создают второй корень.

## 9. Позиционная множественность хранится структурой

```text
[L, L, L]
```

обозначает три позиции одной смысловой связи `L`.

Различие позиций хранится структурой последовательности или вхождений, а не созданием копий `L`.

## 10. Результат свёртки и точная последовательность — разные роли

Для вычисления результата допустима левая свёртка:

```text
AB  = ensure(A,B)
ABC = ensure(AB,C)
```

Но такая свёртка не является универсальным тождеством последовательности:

```text
[]  -> R
[R] -> R
```

Поэтому для последовательностей, где `R` может быть явной позицией, используется `ExactSequence`:

```text
Seq([]) = R
Cell(prev,value) = start-self-closed(prev ⟼ value)
```

и:

```text
Seq([]) != Seq([R])
```

без создания второго `R`.

## 11. Импорт физического артефакта

Внешнее хранилище может содержать:

```text
row42 -> (A,B)
row77 -> (A,B)
```

Это не две смысловые связи МТС.

Импорт обязан либо отклонить дублирующее физическое представление, либо канонизировать его в одну связь `A ⟼ B`.

## 12. Техническая ссылка не является смыслом

Текущий код использует `LinkHandle` для локального доступа к `Memory`.

Нужно различать:

```text
смысловая связь
LinkHandle / локальный слот
идентификатор записи хранилища
координата снимка
физический адрес
```

`LinkHandle.slot` и внутренний владелец ссылки являются координатами реализации, а не третьим полюсом связи.

Поддельная или чужая ссылка отклоняется как неверная координата доступа, но различие ссылок само по себе не доказывает различие смысловых связей.

## 13. Долговременное хранение

После повторного открытия восстанавливается та же каноническая топология с точностью до переименования технических ссылок среды исполнения.

Нормативно важны:

- сохранение полюсов;
- сохранение циклов;
- сохранение совместного использования;
- отсутствие смысловой множественности от дубликата одной пары;
- отсутствие записи при чтении и проверке;
- независимость смысла от физического адреса.

Текущие владельцы долговременного слоя находятся в `persistence-topology.ts`, `persistent-store.ts` и `persistent-sequence.ts`, но конкретный формат хранения не является онтологией МТС.

## 14. Атомарная изменяющая операция

Для сложных операций построения реализация может временно использовать технические координаты будущих элементов. После разрешения структуры они не участвуют в смысловом тождестве.

Публикация изменяющей операции должна иметь явную атомарную границу:

```text
успех  -> виден согласованный результат
ошибка -> видно исходное состояние
```

## 15. Контекст хранится связями

В МТС v0.9:

```text
P = parent ⟼ current
K = K ⟼ P
I ⟼ K
```

Лексическая вложенность принадлежит `K.parent`, временной порядок — структуре `Run`/`Act`.

Повтор той же полной формы `K` обозначает ту же смысловую связь. Различие моментов использования хранится в структуре истории.

## 16. Словарь и определения

```text
Entry      = sourceContent ⟼ Form
Definition = D_before ⟼ Entry
H_after    = H_before ⟼ Definition
```

Если требуется различить два объявления одного содержания и одной формы, различие выражается происхождением или историей, а не вторым экземпляром `Entry` той же пары.

## 17. Источник и запись в памяти различаются

Факт наличия описания:

```text
A B
```

не означает, что запись:

```text
A ⟼ B
```

уже присутствует в памяти.

```text
источник
→ разбор / разрешение
→ структурное описание
→ поиск / проверка
→ только затем явная материализация
```

## 18. Проверка доказательства не материализует факты

Поиск доказательства может использовать индексы, эвристики и перебор. Доверенная проверка получает предъявленное свидетельство и проверяет его без записи.

```text
proof search != proof checking
proof checking != materialization
```

## 19. Последовательность актов

Временной порядок хранится явной структурой `Run` и истории. Повтор одного смыслового акта или результата в нескольких позициях не создаёт смысловых копий.

## 20. Текущий интерфейс памяти

```text
ReadMemory
  root
  linkCount
  poles(link)
  find(start,end)
  outgoing(start)
  incoming(end)

WriteMemory extends ReadMemory
  ensureRoot()
  ensureStartSelfClosed(end)
  ensureEndSelfClosed(start)
  ensure(start,end)
```

Дополнительные читающие возможности:

```text
AppendOnlyReadMemory.issuanceIndex(link)
EnumerableReadMemory.allLinks()
```

Их технические координаты не входят в смысловое тождество.

## 21. Текущая граница МТС v0.9

Текущий владелец `ts/src/memory.ts` содержит одно ядро `Memory` с индексированными операциями `find`, `outgoing`, `incoming` и отдельными возможностями чтения и записи.

Принятый контракт v0.9 фиксирует:

```text
single live semantic runtime = TypeScript
runtime handle is not semantic identity
storage id is not semantic identity
source position is not semantic identity
occurrence is not semantic identity
second fully-self-closed root is forbidden
read may not materialize
not-found does not imply non-existence
```

Среда исполнения Python и режим совместимости отсутствуют.

Произвольный граф физических идентификаторов не является автоматически асетью МТС: он должен пройти укоренённую структурную проверку и канонизацию либо быть отклонён.

## Итог

```text
(A⟼B) однозначна по структурно различённым полюсам
повтор смысловой формы не создаёт второй связи

find / read / replay != ensure / materialize / write
verify != write
не найдено != не существует
```

Совместное соблюдение этих принципов отделяет смысловое тождество связи от инженерного факта наличия её записи в конкретной памяти.
