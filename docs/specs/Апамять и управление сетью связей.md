# Апамять и управление сетью связей
<!-- версия документа МТС; mts-doc-version: v0.13 -->
> **Версия МТС: v0.13**

Этот документ задаёт текущую границу апамяти, материализации и заземлённого исполнения МТС v0.13.

Документ является нормативным владельцем законов `L1`, `L8` и `L9`.

Связанные владельцы:

- [Система аксиом МТС](../theory/Система%20аксиом%20МТС.md) — тождество Связи, акорень и граница фундаментальных положений;
- [Основания МТС](../theory/Основания%20МТС.md) — объяснение укоренения, хиральности и области теории;
- [Ачисла и сериализация](Ачисла%20и%20сериализация.md) — `Resolve`, структурный перенос и целевая материализация;
- [Формальная нотация МТС](Формальная%20нотация%20МТС.md) — `Context`, `Dictionary / Grammar / Theory / Rule` и полномочия `FORMAL`.

## 1. Что такое апамять

Апамять — конкретная материализованная асеть Связей и доступные над ней возможности чтения и изменения.

Она не является универсумом всех Связей, допускаемых МТС.

Смысловая запись:

```text
X = A ⟼ B
```

и технический доступ к ней различаются:

```text
semantic Link
!= local handle
!= storage slot
!= source occurrence
!= path coordinate
```

Тождество Связи задаётся структурой МТС, а не номером записи в конкретной памяти.

<a id="mts-law-L1"></a> <!-- нормативный владелец -->

### L1. Корневое основание остаётся системой Связей

Онтологическая сущность одна:

```text
Link
```

Единственный акорень:

```text
R = R ⟼ R
```

Корневой базис:

```text
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Апамять не вводит второй корень, отдельную пустую сущность или глобальный технический идентификатор Связи.

## 2. Состояния знания при чтении

<a id="mts-law-knowledgeStateSeparation"></a> <!-- служебный якорь -->

Для чтения и разрешения различаются три результата:

```text
UNINTERPRETABLE
NOT_FOUND
FOUND(X)
```

`UNINTERPRETABLE` означает: предъявленного структурного основания недостаточно, чтобы корректно интерпретировать запрос.

`NOT_FOUND` означает: запрос интерпретируем, но соответствующая материализованная Связь не найдена в выбранной памяти.

`FOUND(X)` означает: найдена конкретная Связь `X`.

Поэтому:

```text
NOT_FOUND
!= доказательство несуществования

UNINTERPRETABLE
!= NOT_FOUND
```

Конкретная апамять сообщает о своём текущем состоянии, а не о полном универсуме МТС.

## 3. Чтение и изменение — разные возможности

```text
читать
искать
разрешать
проверять
воспроизводить
!=
создавать
удалять
изменять
материализовать
```

В частности:

- `Resolve` является чтением;
- отсутствие цели при `Resolve` не даёт права её создать;
- построение носителя адреса и построение адресуемой смысловой цели — разные действия;
- целевая материализация требует отдельного полномочия.

Точные адресные правила принадлежат [спецификации ачисел](Ачисла%20и%20сериализация.md#mts-law-resolveMaterializeSeparation).

## 4. Каноническая материализация

Если материализация `A ⟼ B` разрешена, повторный запрос той же смысловой пары должен сходиться к той же Связи:

```text
X = A ⟼ B

ensure(A,B) -> X
ensure(A,B) -> X
```

Технически разные акты записи не создают разные смысловые экземпляры одной пары.

Отдельные формы самовхождения канонизируются по своей структуре:

```text
ROOT
START(X)
END(X)
PAIR(A,B)
```

Материализация не может использовать технический handle как дополнительный смысловой полюс.

## 5. Полномочие смысловой записи

<a id="mts-law-L8"></a> <!-- нормативный владелец -->

### L8. Смысловая материализация требует явного полномочия

Для записи смысловых `START`, `END` или `PAIR` требуется согласованная цепочка:

```text
точный source
+ выбранный Dictionary Use
+ Grammar
+ фиксированная Theory
+ допущенный StructuralRule
+ проверенный запрос построения
```

Наличие представления или структурного описания само по себе не даёт права создавать смысловую цель.

До прохождения этой границы могут существовать Связи представления и доказательства, но не новая авторизованная смысловая цель.

Неуспешная авторизация должна завершаться до смысловой записи.

## 6. Область допустимых Связей и циклы

<a id="mts-law-L9"></a> <!-- нормативный владелец -->

### L9. Тождество требует конечного ROOT-заземления

Принятая смысловая область v0.13 требует конечной рекурсивной декомпозиции до `ROOT`.

Прямые собственные самовхождения:

```text
ROOT
START
END
```

не считаются новой внешней зависимостью.

Но цикл зависимостей между **разными** предполагаемыми Связями не входит в текущую принятую смысловую область:

```text
A depends on B
B depends on A
->
cyclic-grounding
```

Поэтому для v0.13 одновременно верны два утверждения:

```text
accepted semantic domain:
  distinct-node dependency cycles = not admitted

ontology:
  any conceivable rooted cyclic structure is not declared impossible
```

Циклическая структура может существовать как данные описания, однако текущие доказательство тождества, канонический древовидный носитель, перенос и рабочая материализация не устанавливают для неё смысловую Связь.

Это **не** превращает граф в основание МТС: основанием остаётся Связь. Упоминание циклического графа относится только к возможной форме данных представления вне текущего доказанного носителя.

## 7. Позиции, вхождения и техническая история

Одна смысловая Связь может участвовать во многих местах:

```text
[L, L, L]
```

Отсюда не возникают три смысловые `L`.

Необходимо различать:

```text
смысловая Связь
позиция
вхождение
акт доступа
техническая история
```

Если происхождение или временной порядок важны, они должны быть представлены отдельной структурой, а не скрыты в техническом идентификаторе самой Связи.

## 8. Сохранение и технические адреса

При переносе или долговременном восстановлении смысл должен сохраняться с точностью до переименования локальных технических handles.

```text
same semantic structure
may use
different local handles
```

Текущая v0.13 не включает доказательство восстановления нефундированных взаимных циклов только по техническим идентификаторам.

Поэтому persistence-механизм не может расширять принятую смысловую область лишь потому, что умеет хранить произвольные идентификаторы.

## 9. Атомарная граница изменений

Сложная операция может внутренне подготавливать несколько Связей, но публикация смыслового изменения должна иметь одну явную границу:

```text
успех
-> виден согласованный новый результат

ошибка
-> смысловая цель не опубликована частично
```

Для целевой материализации действует более сильное требование fail-closed: неверное точное свидетельство должно быть отклонено до записи смысловой цели.

## 10. Контекст и область исполнения — разные конструкции

`Context` задаёт структурное отношение:

```text
Context(parent,current)
=
START(parent ⟼ current)
```

Его владельцем является [формальная нотация](Формальная%20нотация%20МТС.md#mts-law-explicitKContext).

`Scope` заземлённого исполнения — другая конструкция. Он задаёт текущий рабочий набор истин относительно выбранной `Theory`:

```text
Scope = START(seed ⟼ Theory)

Scope ⟼ truth_1
Scope ⟼ truth_2
...
```

Следовательно:

```text
Context
!=
Scope
```

Обе конструкции имеют `START)-форму в текущей конвенции, но выполняют разные роли.

## 11. Контекстная истина и заземлённая Theory

Текущая истина имеет форму:

```text
truth = K ⟼ A
```

где `K` — явный контекст, а `A` — текущее утверждаемое значение.

Исполнимое заземлённое отношение:

```text
relation = A ⟼ ExactSequence(B...)
```

получает полномочие только через:

```text
admission = Theory ⟼ relation
```

Текущая `Theory` является полным фронтиром исполнимых заземлённых отношений: отдельно скрытый список opcodes или функций не требуется.

Отношение другой `Theory` для текущего `Scope` инертно.

## 12. Обобщённая реакция

Текущий закон заземлённого исполнения:

```text
K ⟼ A
Theory ⟼ (A ⟼ ExactSequence(B...))
------------------------------------
K ⟼ B...
```

Контекст `K` сохраняется, а значение заменяется всеми выходами всех допущенных отношений для `A`.

Исполнение не использует отдельное смысловое ветвление по имени функции, `opcode`, типу правила или конкретному терму.

## 13. Нет отношения, `ZERO`, `ONE` и `MANY`

Это различие принципиально.

### Нет допущенного отношения

Если для текущего `A` под выбранной `Theory` нет ни одного допущенного отношения:

```text
K ⟼ A
->
K ⟼ A
```

Текущая истина сохраняется.

Это ветвь «нет продолжения», а не явное нулевое отображение.

### Нулевой образ (`ZERO`)

Если допущено отношение с пустой точной последовательностью:

```text
Theory ⟼ (A ⟼ ExactSequence())
```

то:

```text
K ⟼ A
->
<нет этой истины в successor Scope>
```

То есть явный пустой образ удаляет текущую истину из следующего `Scope`.

### Один выход (`ONE`)

```text
A -> [B]
```

даёт:

```text
K ⟼ A
->
K ⟼ B
```

### Много выходов (`MANY`)

```text
A -> [B,C,...]
```

или несколько одновременно допущенных отношений для `A` порождают все их выходы.

Если разные ветви сходятся к одной и той же `K ⟼ E`, каноническое тождество Связи схлопывает дубль.

### E2/W2/W3. Полный элементарный переход

> **Статус:** производный результат исследования #1558 после принятия MTS v0.13. Он уточняет уже реализованный закон заземлённой реакции и не изменяет принятую семантику v0.13.

Для текущей истины `K ⟼ A` обозначим через `R_T(A)` все отношения, которые одновременно:

```text
допущены выбранной Theory
и
имеют A своим antecedent
```

Тогда элементарный переход полностью задаётся одним законом:

```text
если R_T(A) пусто:
  successor contribution = { K ⟼ A }

иначе:
  successor contribution =
    объединение всех { K ⟼ B_j }
    по всем выходам всех отношений из R_T(A)
```

Отсюда без дополнительных ветвей следуют:

```text
нет допущенного отношения
  -> сохранить K ⟼ A

все допущенные образы пусты
  -> не переносить K ⟼ A в следующий Scope

ровно один канонический выход
  -> K ⟼ B

несколько канонических выходов
  -> K ⟼ B, K ⟼ C, ...
```

Если для одного `A` одновременно допущены пустой и непустой образы, пустой образ просто не добавляет выходов, а непустые образы продолжают участвовать в общем объединении. `ZERO` не является запретом для других одновременно допущенных отношений.

#### `NOT_FOUND` не является условием сохранения само по себе

Состояние чтения `NOT_FOUND` относится к **конкретному запросу** на материализованную Связь. Из того, что один кандидат `A ⟼ X` не найден, не следует, что под текущей `Theory` отсутствует другое допущенное отношение для того же `A`.

Поэтому:

```text
specific relation lookup = NOT_FOUND
!=
R_T(A) is empty
```

Сохранение `K ⟼ A` разрешено только после установления более сильного факта:

```text
NO_ADMITTED_RELATION(A, Theory)
```

то есть после исчерпывающего просмотра релевантного фронтира допущений выбранной `Theory`. Реализация может получать отдельные `NOT_FOUND` во время такого поиска, но они не являются самостоятельным семантическим исходом реакции.

#### W3. Семантическое удаление без физического удаления

Когда `K ⟼ A` не входит в следующий `Scope`, это означает только:

```text
K ⟼ A не является членом опубликованного successor Scope
```

Из этого не следует удаление самой Связи `K ⟼ A`, старого `Scope` или их физического носителя. Они могут оставаться канонически доступными как техническая история, пока текущесть определяется опубликованным корнем апамяти.

W2/W3 проверены одним исполняемым свидетелем после принятия v0.13 для:

```text
NO_ADMITTED_RELATION
ZERO
ONE
MANY
ZERO + непустой образ одновременно
конвергенция дублей
specific NOT_FOUND при наличии другого допущенного отношения
сохранение старой физической топологии
```

Для E2 принятой v0.13 достаточно: принятый заземлённый исполнитель уже реализует этот закон. Это **локальный вывод E2**; итоговая классификация всей #1558 остаётся открытой.

## 14. Следующая область исполнения и текущесть

Реакция строит новый полный `Scope`, не изменяя текущий рабочий набор поэлементно в процессе вычисления.

После успешного построения выполняется один атомарный handoff:

```text
old current Scope
-> successor Scope
```

До handoff текущим остаётся старый `Scope`.

Сам выбор «какой `Scope` сейчас текущий» остаётся непрозрачной изменяемой границей апамяти. Он не выводится из порядка добавления Связей в техническую историю.

Это важная граница substrate:

```text
Link-carried program state
!=
mechanism selecting current Scope
```

<a id="amemory-currentness"></a> <!-- текущесть -->
### E1/W1. Точное полномочие текущести

> **Статус:** производный результат исследования #1558 после принятия MTS v0.13. Он уточняет уже принятую границу апамяти и не добавляет новый семантический закон v0.13.

Текущесть не является внутренним свойством самого `Scope` и не выводится из физического возраста Связей. Смысловое состояние исполняемой апамяти задаётся относительно **единственного опубликованного текущего корня** этой апамяти:

```text
publishedRoot(M) = S_t
semanticState(M,t) = members(S_t)
```

Структура `S_t` и его членство выражены Связями. Механизм хранения опубликованного корня остаётся технической границей апамяти.

Минимальный контракт публикации:

```text
до построения successor:
  publishedRoot = S_t

во время построения successor:
  publishedRoot = S_t

атомарная публикация:
  expected current = S_t
  publish S_t -> S_(t+1)

после публикации:
  publishedRoot = S_(t+1)
```

Поэтому существование старого `S_t` или его членов в физической памяти после публикации не делает их текущими. Текущим является только `Scope`, выбранный опубликованным корнем.

Это полномочие нельзя подменять локальной переменной конкретной реализации. Такая переменная, ячейка базы или регистр ускорителя может быть лишь реализацией одного и того же контракта апамяти: наблюдаемым смысловым фактом остаётся выбранная структурная Связь `Scope` и атомарная смена выбора.

Простой append-only кандидат:

```text
CURRENT ⟼ S_t
CURRENT ⟼ S_(t+1)
```

недостаточен: обе Связи остаются одинаково доступными, и сама топология не указывает, какая из них новее. Это уже зафиксировано falsifier-свидетелем A72n. Для чисто связевого выбора потребовалась бы дополнительная семантика жизненного цикла или порядка; E1 её не вводит.

Минимальный W1 имеет вид:

```text
до реакции:
  publishedRoot = S0
  S0 ⟼ (K ⟼ A)
  Theory ⟼ (A ⟼ [B])

кандидат:
  S1 ⟼ (K ⟼ B)
  publishedRoot всё ещё S0

handoff:
  publish S0 -> S1

после реакции:
  publishedRoot = S1
  semantic state = { K ⟼ B }

физически могут сохраниться:
  S0
  K ⟼ A
```

Таким образом, для E1 принятой v0.13 достаточно: структурное состояние уже задаётся `Scope`, а текущесть уже принадлежит явно оставленной границе current-root апамяти. Это **локальный вывод E1**; итоговая классификация всей #1558 остаётся открытой до E2–E7.

### E3/W4/W5. Логическая реакция и физический планировщик

> **Статус:** производный результат исследования #1558 после принятия MTS v0.13. W4 подтверждает инвариантный класс, W5 обнаруживает границу принятого исполнителя. Нового семантического закона этот шаг не вводит.

Для параллельного исполнения нужно строго развести четыре слоя:

```text
1. logical pre-state
2. physical scheduling
3. candidate generation
4. semantic publication
```

Физический порядок потоков, рабочих групп, ядер или обхода массива не может определять смысловой `state(t+1)`.

#### W4. Инвариантный класс

Если во время одной логической реакции:

```text
Theory frontier не изменяется
и
применимость реакции одного текущего члена
не изменяется действиями другого текущего члена
```

то перестановка порядка обработки текущих членов даёт один и тот же экстенсиональный successor `Scope`.

Для этого класса принятая v0.13 уже достаточна: результаты всех независимых реакций можно вычислять в любом физическом порядке, канонически объединить и опубликовать одним handoff.

#### W5. Взаимодействующая реакция с живой `Theory`

Принятый заземлённый исполнитель читает фронтир `Theory` из живой памяти. Поэтому текущий член может в ходе реакции материализовать новую:

```text
Theory ⟼ relation
```

и другой член той же реакции увидит её только в том случае, если физически обрабатывается позже.

Исполняемый свидетель воспроизводит два порядка одного исходного состояния:

```text
generator first:
  matches = 2
  generated relation действует на target в той же реакции

target first:
  matches = 1
  target сохраняется до следующей реакции
```

Следовательно:

```text
same semantic pre-state
+
different physical schedule
->
different immediate successor Scope
```

Сохранённый A73k дополнительно показывает, что в этом конкретном монотонном примере обе траектории затем сходятся к одной экстенсиональной неподвижной точке. Но:

```text
same final fixed point
!=
same semantic trajectory
```

и потому равенства конечного результата недостаточно для определения `state(t) -> state(t+1)`.

### Граница E3

Для общей конкурентной апамяти принятой v0.13 **недостаточно как полного определения одного логического шага**, пока не определена видимость изменений `Theory` внутри реакции.

Это само по себе не доказывает необходимость нового семантического закона. E4 ниже проверяет, достаточно ли отдельного профиля исполнения с явной границей снимка/публикации.

До этого запрещено считать порядок:

```text
thread
work-group
GPU lane
array iteration
allocation
```

семантическим законом.

### E4. Видимость изменений `Theory` и граница снимка

> **Статус:** производный результат исследования #1558 после принятия `MTS v0.13`. Принятая `v0.13` не изменяется. `E4` классифицирует недостающую границу переносимого исполнения.

`W5` показал, что текущая рабочая реализация заземлённой реакции читает `Theory` из живой памяти повторно для каждого текущего члена. Поэтому новое допущение:

```text
Theory ⟼ relation
```

может стать видимым другому члену в той же реакции или не стать — в зависимости от физического порядка обхода.

Такое поведение допустимо как конкретная реализация принятого исполнителя, но оно не может быть полным переносимым определением одного логического шага: `thread / work-group / GPU lane / array order` не имеют смыслового полномочия.

#### Кандидат профиля: снимок `Theory` в начале реакции

Минимальная schedule-independent граница задаётся так:

```text
reaction t begins
  TheorySnapshot_t := admitted grounded relations
                      visible before candidate generation

for every member of current Scope:
  discover images only in TheorySnapshot_t
  generate candidate successor Links

writes during reaction:
  may materialize physically immediately
  but do not enter TheorySnapshot_t

publish successor Scope atomically

reaction t+1 begins
  TheorySnapshot_(t+1) := then-current admitted relations
```

Снимок — не новая сущность МТС и не обязательный массив или копия памяти. Это логическая граница наблюдаемости. Процессор, БД, браузер или ускоритель могут реализовать её любым способом, если все участники одного логического шага видят один и тот же фронтир полномочия.

#### Свидетель E4

Для исходного состояния, где один текущий член порождает новое допущение для другого:

```text
generator:
  Theory ⟼ BOOT
  BOOT ⟼ [candidateRelation]

target:
  K ⟼ A

candidateRelation:
  A ⟼ [B]
```

Профиль снимка даёт одну и ту же траекторию при обоих физических порядках:

```text
reaction 1:
  matches = 1
  new Theory ⟼ candidateRelation physically exists
  current target remains K ⟼ A

reaction 2:
  matches = 1
  target becomes K ⟼ B

reaction 3:
  matches = 0
  quiescent
```

То есть:

```text
generator-first trajectory
=
target-first trajectory
```

в отличие от поведения принятой реализации с видимостью `live same-reaction`, где первый непосредственный преемник различается.

#### Почему это профиль исполнения, а не новая семантика основания

E4 не вводит:

```text
новый вид Связи
новый структурный аспект
новое тождество
новое отношение Context / Theory
новую MTS-онтологию времени
```

Он выбирает **когда уже существующее структурное полномочие `Theory` наблюдается исполнителем** относительно границы одной реакции.

Принятая `v0.13` содержит необходимые структуры и операции, но её принятый контракт не выбирает между:

```text
same-reaction live visibility
и
reaction-start snapshot visibility
```

Поэтому для полной переносимой апамяти результат `E4`:

```text
E4_CLASSIFICATION = V013_PLUS_EXECUTION_PROFILE
V013_SUFFICIENT for complete #1558 = eliminated
SEMANTIC_EXTENSION_REQUIRED = not established
```

Это ещё не окончательный вердикт всей #1558: `E5–E7` могут обнаружить необходимость будущего смыслового закона. Но вариант `V013_SUFFICIENT` уже недостаточен, потому что независимая реализация не может вывести границу видимости `Theory` только из принятой `v0.13`.

Независимое от планировщика причинное замыкание внутри одного шага теоретически может быть другим профилем, но оно потребовало бы отдельного определения замыкания, его наблюдаемых границ и поведения при бесконечной активации. `E4` не добавляет такую более сильную механику: минимальным кандидатом остаётся снимок на входе реакции.

## 15. Покой и неподвижная точка

Текущая реакция считается `quiescent`, когда ни одна текущая истина не имеет допущенного отношения под выбранной `Theory`:

```text
matchedRelations = 0
```

Тогда:

```text
successor Scope не создаётся
atomic handoff не выполняется
current Scope остаётся прежним
```

Это точное понятие `fixed point` для принятого заземлённого исполнителя.

Оно не определяется техническим порядком обхода памяти и не означает автоматически равенство любых двух произвольно построенных снимков.

## 16. Живая Theory и самoактивация

Исполнимые отношения обнаруживаются непосредственно через текущие Связи:

```text
Theory ⟼ relation
```

Поэтому новое корректно материализованное допущение `Theory ⟼ relation` становится частью исполнимого фронтира той же живой апамяти без отдельной host-регистрации функции.

Это позволяет `Theory` изменять набор будущих реакций связевой структурой.

Принятая рабочая реализация `v0.13` читает этот фронтир из живой памяти и потому может увидеть новое допущение ещё внутри текущего вызова реакции. `E3/E4` показали, что точная **межреакционная граница видимости** этим фактом не определяется: для переносимого конкурентного исполнения #1558 требуется отдельно управляемый профиль исполнения. Минимальный кандидат `E4` фиксирует `Theory` на входе логической реакции и допускает новые допуски к исполнению со следующей реакции.

Но отсюда не следует, что произвольное высокоуровневое `StructuralRule` уже полностью самохостящимся образом компилируется в заземлённое отношение.

## 17. Граница self-hosting

Внутри Связей уже находятся:

```text
Theory
admitted grounded relations
Context / Scope structures
contextual truths
outputs
program-specific semantic selection
```

Заземлённый исполнитель использует один общий закон реакции и не содержит смыслового ветвления по функции или `opcode`.

Внешней substrate-границей остаются:

- сама апамять и операции доступа к её Связям;
- механизм выбора текущего `Scope`;
- атомарное переключение на следующий `Scope`;
- общий цикл исполнения;
- механика `ExactSequence`;
- ввод-вывод и долговременный технический носитель;
- отдельный слой заземления произвольных высокоуровневых правил.

Поэтому корректная формулировка:

```text
scoped self-hosted program semantics
!=
fully self-hosted MTS system
```

## 18. Производный результат: инверсия исполнения

**Статус: производный результат о принятой v0.13, а не принятая рабочая семантика исполнения.**

Для точной двойственной конвенции доказано:

```text
dualReact(J(state))
=
J(react(state))
```

Чтобы равенство выполнялось, одновременно инвертируются:

```text
Scope orientation
Scope membership
Theory admission
relation
truth
output
```

Ветви `MANY`, `ZERO` и отсутствие отношения сохраняют свою структурную двойственность.

Но текущий исполнитель остаётся в принятой ориентации. Двойственный исполнитель является доказательным свидетелем `THEORY_DUALIZATION`, а не второй production-конвенцией.

Машиночитаемый результат ограниченной области: [`EXE-01` в реестре теорем](../../theorems/registry.json) и [итоговый аудит дуализации](../../theorems/v0.13/inversion/dualization-audit.json).

## 19. Инженерная поверхность

Текущая эталонная реализация разделяет читающую и изменяющую способности:

```text
ReadMemory:
  root
  linkCount
  poles
  find
  outgoing
  incoming

WriteMemory:
  ensureRoot
  ensureStartSelfClosed
  ensureEndSelfClosed
  ensure
```

Эти имена являются реализационным свидетельством, а не смысловым авторитетом.

Индексы `outgoing/incoming`, порядок выдачи handles и слот памяти могут ускорять исполнение, но не участвуют в тождестве Связи.

## 20. Что апамять не утверждает

Из текущей спецификации не следуют:

```text
NOT_FOUND -> не существует
read -> materialize
handle identity -> semantic identity
описание -> semantic target
cyclic description -> admitted cyclic semantic Link
Scope -> Context
Rule exists -> Rule admitted
no relation -> ZERO relation
scoped self-hosting -> full self-hosting
dual executor -> accepted production executor
```

## Итог

Текущая динамика апамяти v0.13 имеет три чётко разделённых слоя:

```text
смысловая структура Связей
-> заземлённое Link-carried исполнение
-> технический substrate апамяти
```

Заземлённая реакция уже выражает программу через саму сеть Связей, но механизм текущести и физическое выполнение реакции остаются границей апамяти.
