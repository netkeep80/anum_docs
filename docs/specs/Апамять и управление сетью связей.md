Этот документ — единственный human semantic owner апамяти. Машинная проекция профиля: [`profiles/amemory-execution-profile.json`](../../profiles/amemory-execution-profile.json). Она проверяет этот текст, но не конкурирует с ним как второй источник смысла.

## 1. Что такое апамять

Апамять — конкретная материализованная асеть Links вместе с возможностями чтения, разрешённой материализации и исполнения.

Она **не** является:

- второй онтологией рядом с Link;
- универсумом всех мыслимых Links;
- физическим массивом/Doublets/GPU-layout как частью МТС;
- host cursor как скрытым смысловым состоянием.

<a id="mts-law-L1"></a> <!-- исторический стабильный якорь -->

Основание принадлежит МТС v0.14: одна онтология Link, структурное тождество, Context и generalized reaction. Полный portable runtime boundary задаётся отдельным execution profile.

## 2. Три уровня, которые нельзя смешивать

Принятие v0.14 **не переписывает задним числом** foundation pin профиля 0.1.0. Репин/новая версия профиля — отдельное управляемое действие.

```text

```

## 3. Состояние знания при чтении

<a id="mts-law-knowledgeStateSeparation"></a> <!-- исторический стабильный якорь -->

Необходимо различать:

```text
FOUND(X)
NOT_FOUND
UNINTERPRETABLE
```

`NOT_FOUND` — результат конкретного чтения. Он не является доказательством глобального отсутствия смысловой структуры.

`UNINTERPRETABLE` означает, что выбранный interpreter/profile не может придать текущему представлению требуемый смысл.

## 4. Чтение и изменение

Чтение не должно скрыто материализовать структуру.

```text
Resolve      -> найти/проверить существующее
Materialize  -> создать разрешённую отсутствующую структуру
```

<a id="mts-law-L8"></a> <!-- исторический стабильный якорь -->

Материализация требует явного semantic authority. Технический handle, индекс, адрес или локальный ID не являются дополнительным смысловым полюсом.

<a id="mts-law-L9"></a> <!-- исторический стабильный якорь -->

Текущий доказанный канонический носитель Link identity остаётся ROOT-grounded. Произвольные нефундированные взаимные циклы не получают semantic identity только потому, что backend способен хранить циклический граф.

## 5. Current Scope

<a id="amemory-currentness"></a>

В профиле 0.1.0 текущее смысловое состояние:

```text
members of one published current Scope
```

Authority текущести:

```text
one published current root
```

Физические Links старых состояний могут оставаться в памяти. Семантическое замещение **не требует физического удаления**.

```text
physical existence != current semantic state
```

Публикация следующего состояния происходит атомарным handoff текущего корня после построения полного successor Scope.

## 6. Theory и допуск отношения

<a id="amemory-theory-admission"></a>

Отношение исполнимо только при явном допуске выбранной Theory.

Удобная форма:

```text
Theory ⟼ relation
```

Ambient Link, совпадение по форме или найденный в памяти похожий relation не получает authority автоматически.

## 7. Один логический переход

<a id="amemory-elementary-transition"></a>

Для текущей истины:

```text

```

исполнитель исчерпывает все отношения выбранного Theory snapshot, antecedent которых соответствует `A`.

Общая реакция согласуется с принятым v0.14 [V14-L11](../theory/Система%20аксиом%20МТС.md#mts-v014-v14-l11).

## 8. NO_ADMITTED_RELATION, ZERO, ONE, MANY

Критическое различие:

```text
NO_ADMITTED_RELATION(A, Theory)
  -> сохранить текущую истину

specific relation lookup = NOT_FOUND
  -> только результат одного чтения
  -> НЕ доказательство NO_ADMITTED_RELATION

ZERO
  admitted A -> []
  -> нулевой вклад в successor

ONE
  admitted A -> [B]
  -> один канонический successor

MANY
  admitted A -> [B,C,...]
  -> объединить все канонические successors
```

Совпавшие выходы сходятся по canonical Link identity.

`ZERO` не отменяет одновременно найденные непустые выходы.

## 9. Theory snapshot

<a id="amemory-theory-snapshot"></a>

Portable profile 0.1.0 фиксирует:

```text
TheorySnapshot_t
  = admissions visible at reaction start

all current members of reaction t
  use the same TheorySnapshot_t

new admission created during t
  may exist physically immediately
  becomes executable in reaction t+1
```

Это устраняет semantic authority физического schedule.

Минимальный interacting witness:

```text
generator-first trajectory
target-first trajectory
```

при snapshot profile дают одинаковую нормализованную смысловую траекторию.

Snapshot не является новой сущностью МТС: это execution-profile boundary.

## 10. Планировщик не является семантикой

Для одного исходного состояния и одного Theory snapshot:

```text
thread order
work-group order
GPU lane order
array order
allocation order
```

не должны менять нормализованный смысловой результат.

```text
normalized successor A = normalized successor B
```

Физический backend вправе использовать любую стратегию, если observable semantics совпадает.

## 11. Публикация

Полный successor Scope строится **до** publication.

Если хотя бы одно отношение сработало:

```text
build complete successor
-> publish exactly one atomic current-root handoff
```

Если после полного логического шага:

```text
matchedRelations = 0
handoffCount     = 0
```

наступает quiescence.

Временная пустая очередь worker’а, GPU lane или scheduler inactivity покоем не является.

## 12. Рекуррентность и неограниченное исполнение

<a id="amemory-recurrence"></a>

Минимальный recurrent witness:

```text
S0 = { K ⟼ A }

A ⟼ [B]
B ⟼ [A]

S0 -> {K⟼B} -> S0 -> ...
```

Следовательно:

```text
RECURRENCE_IMPLIES_QUIESCENCE = FALSE
GLOBAL_TERMINATION_REQUIRED   = FALSE
STRUCTURAL_END_IS_GLOBAL_HALT = FALSE
```

Рекуррентность — достаточный пример nontermination, но не всякое бесконечное исполнение обязано быть периодическим.

## 13. Иерархический результат

<a id="amemory-hierarchical-result"></a>

Nested Link может быть обычным результатом минимальной реакции:

```text
H = X ⟼ (Y ⟼ Z)

K ⟼ A
A ⟼ [H]
------
K ⟼ H
```

Текущая классификация:

```text
HIERARCHICAL_LINK_AS_RESULT = supported by minimal reaction

dynamic hierarchical Result construction = INDEPENDENT_LATER_FEATURE
nested Context / Result lifecycle         = INDEPENDENT_LATER_FEATURE
persistent Result versions               = INDEPENDENT_LATER_FEATURE

DEFERRED != REJECTED
```

A72u dual-tree/single-assignment slots сохраняется как scoped research. A72v persistent versions/path-copy сохраняется как deferred research.

## 14. Субстрат

<a id="amemory-substrate-boundary"></a>

Profile различает три технических слоя:

```text
link-carrier substrate
execution-publication substrate
representation substrate
```

Не являются онтологией МТС:

- local handles;
- allocation order;
- concrete Memory API;
- Doublets layout;
- array layout;
- GPU buffer layout;
- thread/work-group order.

W7 строит одну смысловую сеть в независимо адресованных Memories. Сравнение выполняется после структурной нормализации, а не по локальным адресам.

## 15. Самохостинг

Доказано ограниченное утверждение:

```text
PROGRAM_SEMANTIC_AUTHORITY = LINK_CARRIED_THEORY_RELATIONS
SCOPED_SELF_HOSTED_PROGRAM_SEMANTICS = TRUE
FULLY_SELF_HOSTED_MTS_SYSTEM = FALSE
```

То есть программа/relations/Theory могут быть представлены Link-структурами.

Внешними пока остаются как минимум substrate, publication current root, общий execution loop, I/O и часть grounding mechanics.

Это граница доказанного результата, а не запрет на дальнейший self-hosting.

## 17. Матрица обязательных примеров D5

| Пример | Минимальная идея | Что доказывает |
|---|---|---|
| A | `K⟼A; A⟼[B]` | transformation + physical history |
| B | no relation vs `A⟼[]` | NOT_FOUND/NO_ADMITTED_RELATION ≠ ZERO |
| C | `A⟼[B,C]` | MANY + duplicate convergence |
| D | два независимых current truths | schedule independence |
| E | generator + sibling target | Theory snapshot visibility |
| F | `A↔B` cycle | recurrence/nontermination |
| G | две независимо адресованные Memories | substrate/address independence |

### Пример A — transformation

```text
current:
  K ⟼ A

admitted:
  A ⟼ [B]

next:
  K ⟼ B
```

Старый `K⟼A` может физически остаться, но больше не входить в current Scope.

### Пример B — NO_ADMITTED_RELATION и ZERO

```text
no admitted relation
-> preserve K ⟼ A

admitted A -> []
-> do not include K ⟼ A in successor
```

### Пример C — MANY

```text
A -> [B,C,B]
```

даёт канонический successor с `B` и `C`; дубль `B` сходится.

### Пример D — независимый schedule

Два разных физических порядка должны дать один normalized successor.

### Пример E — interacting Theory

```text
generator-first trajectory
target-first trajectory
```

различаются физическим порядком, но snapshot profile даёт одинаковый semantic result.

### Пример F — recurrence

```text
{K⟼A} -> {K⟼B} -> {K⟼A} -> ...
```

активно и не quiescent.

### Пример G — substrate

Одна и та же сеть строится в двух Memories с разными handles/allocation order:

```text
normalized successor A = normalized successor B
```

<a id="d9-acceptance"></a>
## D9. Самодостаточная приёмка внешнего читателя

Ниже ответы не требуют истории research issues.

**D9-Q01 — Что является смысловым состоянием апамяти?** Члены единственного опубликованного текущего `Scope`.

**D9-Q02 — Что делает состояние текущим?** Единственный опубликованный текущий корень; backend register/cursor может лишь реализовать это полномочие.

**D9-Q03 — Нужно ли физически удалять старую истину?** Нет: старые `Scope` и `K ⟼ A` могут оставаться физически доступными после semantic handoff.

**D9-Q04 — Что такое один элементарный переход?** Для каждого текущего `K ⟼ A` исполнитель исчерпывает все отношения выбранного snapshot, строит полный successor и публикует его одной атомарной сменой текущего корня.

**D9-Q05 — Чем `NOT_FOUND` отличается от `ZERO`?** `NOT_FOUND` относится к отдельному чтению и не доказывает отсутствия всех допущенных отношений. `ZERO` — допущенное отношение с пустым образом.

**D9-Q06 — Что делают `ONE` и `MANY`?** `ONE` даёт один successor, `MANY` — объединение всех; совпавшие выходы сходятся по canonical Link identity.

**D9-Q07 — Что значит concurrency?** Все current members видят одно исходное состояние и один снимок `Theory`; физический schedule не является authority.

**D9-Q08 — Какие schedule differences наблюдаемы?** Перестановка потоков/work-groups/GPU lanes не должна менять нормализованный смысловой результат.

**D9-Q09 — Когда виден новый Theory admission?** Созданный во время реакции `t` допуск становится исполнимым начиная с реакции `t+1`.

**D9-Q10 — Что такое покой?** После полного шага `matchedRelations = 0` и нет handoff; простое бездействие планировщика покоем не является.

**D9-Q11 — Чем recurrence отличается от quiescence?** При recurrence нормализованное состояние возвращается после одного или нескольких активных переходов.

**D9-Q12 — Требуется ли глобальное завершение?** Нет: разрешено неограниченное исполнение; структурный `END` не является глобальным halt.

**D9-Q13 — Обязательны ли hierarchical Result / nested Context?** Нет. Nested Link поддержан обычной реакцией, а динамический hierarchy/lifecycle/versions — независимая более поздняя возможность.

**D9-Q14 — Что остаётся физическим substrate?** Хранение/адресация, техническое чтение, разрешённая materialization, publication mechanism и representations; handles/API/Doublets/GPU layout не являются онтологией МТС.

**D9-Q15 — Что именно self-hosted?** Доказан ограниченный самохостинг семантики программы через Link-carried Theory/relations; fully self-hosted system не доказана.

**D9-Q16 — Где проходит граница МТС/profile/implementation?** Принятая MTS v0.13 задаёт основание profile 0.1.0; сам profile задаёт portable execution observables; CPU/GPU/layout/scheduler принадлежат реализации `amemory`. Текущая MTS v0.14 принята отдельно и не меняет исторический foundation pin profile без отдельного repin.

## 19. Сохранённые исследовательские линии — не нормативно

Этот раздел намеренно сохраняет полезные идеи, которые **не входят** в accepted v0.14 contract и не являются обязательными законами profile 0.1.0.

### R1. Нефундированные циклы

Arbitrary mutually recursive cycles могут быть полезным будущим carrier, но их semantic identity не доказана текущим ROOT-grounded путём.

### R2. Полностью Link-native currentness

Profile использует published current root. Возможна ли структура lifecycle/order, делающая даже publication choice полностью Link-native без host cursor, остаётся открытым вопросом.

### R3. Causal closure внутри одной реакции

Snapshot — минимальный переносимый профиль. Альтернативный scheduler-independent causal closure внутри одного logical step остаётся возможным, но требует отдельного определения closure, observables и поведения при бесконечной активации.

### R4. A72u/A72v

```text
A72u dual-tree / single-assignment Result slots = GREEN_SCOPED_RESEARCH
A72v persistent Result versions / path-copy      = RETAINED_DEFERRED_RESEARCH
```

Их исключение из minimal profile не является отрицанием идеи.

### R5. Минимальный физический substrate

Текущие carrier capabilities — evidence, но не доказанный минимальный набор независимых hardware operations. Их дальнейшая сводимость открыта.

### R6. Полный self-hosting

Scoped self-hosting доказан. Вопрос полного переноса grounding/publication/execution-loop authority внутрь Link structures остаётся исследовательским.

### R7. FULL_AUTOMORPHISM

J-dual witness показывает covariance/THEORY_DUALIZATION. Более сильный полностью автоморфный execution profile остаётся отдельным вопросом там, где это ещё не доказано.

### R8. Nonperiodic infinite evolution

Recurrence доказывает возможность nontermination, но не исчерпывает все классы бесконечной эволюции.

### R9. Явные termination theories

Structural END не halt. Будущая Theory/profile может определить отдельное явное условие завершения.

### R10. Альтернативные carriers/backends

ExactSequence, current storage и publication mechanics — текущие переносимые choices. Другие carriers/layouts допустимы при сохранении observables.

### R11. Full backend reaction conformance

Смысловая граница profile завершена, но это не тождественно полной CPU/WASM ↔ WebGPU реализации всех P01–P17. Downstream differential evidence остаётся инженерной и falsification surface.

## 21. Что апамять не утверждает

Нельзя выводить из этого документа:

- host cursor как новую сущность МТС;
- thread/GPU order как semantic law;
- concrete Memory/Doublets API как онтологию;
- обязательное физическое удаление старой истины;
- глобальную остановку из аспекта END;
- full self-hosting без отдельного witness;
- включение deferred research в accepted v0.14;
- автоматический repin profile 0.1.0 с v0.13 на v0.14.

## Итог

Апамять разделяется на три честных слоя:

```text
accepted MTS semantics
        ↓
separately governed portable execution profile
        ↓
concrete backend implementation
```

Так сохраняется одновременно строгость принятого основания, переносимость исполнения и возможность развивать неподтверждённые идеи без их потери и без преждевременного превращения в закон.
