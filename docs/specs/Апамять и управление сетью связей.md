# Апамять и управление сетью связей

Апамять — слой МТС, который хранит конкретно материализованную асеть, позволяет искать в ней связи, явно материализовать недостающие записи и воспроизводить засвидетельствованные действия.

Связанные документы:

- [Система аксиом МТС](../theory/Система%20аксиом%20МТС.md)
- [Основания МТС](../theory/Основания%20МТС.md)
- [Формальная нотация МТС](Формальная%20нотация%20МТС.md)
- [Ачисла и сериализация](Ачисла%20и%20сериализация.md)

Этот документ описывает текущую принятую границу апамяти версии 0.7 после завершённого перехода #401 и пересмотра семантики #343.

## 1. Апамять хранит связи

Базовая структура МТС бинарна:

```text
Link(start, end)
```

Контекст, словарь, теория, исходная запись, акт интерпретации, история и доказательство могут быть представлены связями той же сети. Для их различения не требуется вводить отдельную онтологическую категорию объектов поверх связей.

## 2. Тождество связи определяется полюсами

Фундаментальный инвариант:

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Следовательно:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=> P1 = P2
```

В МТС не существует двух разных смысловых связей с одной и той же упорядоченной парой `(start,end)`.

Индекс, адрес записи, номер операции, позиция в последовательности или техническая ссылка времени исполнения могут различаться, но не создают второе смысловое тождество связи.

## 3. Апамять не равна универсуму МТС

Если конкретная память не содержит физической записи формы:

```text
A ⟼ B
```

из этого не следует, что такая связь «не существует» в семантическом смысле.

Поэтому:

```text
не найдено != не существует
```

Апамять — конкретно материализованная часть возможной связевой структуры, а не обязательное перечисление всех возможных связей.

## 4. Поиск и изменение строго разделены

Критический инженерный инвариант:

```text
читать / искать / разрешать / проверять
                    !=
создавать / удалять / изменять
```

Операция:

```text
find(A,B)
```

не должна изменять память независимо от результата поиска.

Явная операция получения с возможной материализацией может иметь вид:

```text
ensureLink(A,B):
    если A ⟼ B уже присутствует в конкретной асети -> вернуть эту же связь
    иначе -> материализовать A ⟼ B и вернуть её
```

То есть семантическая однозначность связи не отменяет различие между проверкой наличия записи и записью.

## 5. Повторная материализация не создаёт второй экземпляр

Если в памяти уже присутствует:

```text
X = A ⟼ B
```

повторная явная операция `ensureLink(A,B)` возвращает `X`.

Неверная для МТС модель:

```text
X = materialize(A,B)
Y = materialize(A,B)
X != Y
```

не допускается в принятой MTS v0.7.

Допустимо различать два **акта обращения к памяти**, но их общий результат остаётся одной связью `A ⟼ B`.

## 6. История и акт не являются скрытым тождеством связи

Разные акты построения, чтения или наблюдения одной связи могут быть различены, если это существенно.

Но различие должно выражаться самой связевой структурой истории, например через разные позиции в последовательности актов, разные состояния контекста, источники или иные отношения.

Принцип:

```text
разные акты получения одной связи
!=
разные экземпляры самой связи
```

Если две предполагаемые «записи акта» имеют полностью одинаковые полюса и ничем связево не различены, по аксиоме тождества это одна связь.

## 7. Циклы и совместное использование допустимы

Апамять должна поддерживать самозамыкание:

```text
R = R ⟼ R
```

петли:

```text
Loop(a) = a ⟼ a
```

взаимные циклы и совместное использование одной связи несколькими структурами.

Для данного `a` связь `a ⟼ a` единственна.

Если:

```text
a = a ⟼ a
```

то:

```text
Loop(a) = a
```

В частности:

```text
Loop(R) = R
```

## 8. Корень каноничен

Для акорня:

```text
R = R ⟼ R
```

поэтому отдельная связь `L != R` с полюсами `(R,R)` невозможна.

Физическая реализация может использовать временную ссылку построения, слот или специальный этап фиксации самоссылки, но после интерпретации это одна смысловая связь `R`.

## 9. Позиционная множественность хранится структурой последовательности

Последовательность может несколько раз ссылаться на одну и ту же связь.

Например три вхождения `L`:

```text
[L, L, L]
```

не требуют трёх объектов `L`.

Различие первого, второго и третьего употребления задаётся структурой самой последовательности — её порядком и связями префиксов.

Это особенно важно для ачисел: повтор абита означает повтор ссылки, а не материализацию дубликата той же пары.

## 10. Материализация последовательности

Для последовательности значений:

```text
A B C
```

денотат может строиться левой свёрткой:

```text
AB  = ensureLink(A,B)
ABC = ensureLink(AB,C)
```

Если требуемая пара уже присутствует, соответствующий шаг переиспользует существующую связь.

Поэтому два одинаковых вычислительных шага могут иметь разные записи трассы `created/reused`, но один смысловой результат.

Подробнее: [Ачисла и сериализация](Ачисла%20и%20сериализация.md).

## 11. Импорт физического артефакта

Внешнее хранилище может содержать технические идентификаторы:

```text
row42 -> (A,B)
row77 -> (A,B)
```

Это не означает наличие двух связей МТС.

Импорт обязан выбрать явную политику:

```text
reject duplicate physical representation
```

или:

```text
canonicalize row42,row77 -> one Link(A,B)
```

Молчаливо превращать разные идентификаторы хранения в разные смысловые связи запрещено.

## 12. Физический адрес не является смыслом

Нужно различать:

```text
semantic Link
storage record / logical handle
snapshot slot
physical address
```

Хранилище может менять физическое расположение записи при уплотнении, восстановлении, копировании при записи или миграции формата.

Это не меняет смысловое тождество, которое определяется полюсами.

Техническая ссылка `LinkRef` в принятой реализации MTS v0.7 допустима как локальная инженерная координата доступа, но не как скрытый третий параметр связи. `LinkRef` локален для конкретного экземпляра сети и сам по себе не различает смысловые связи.

## 13. Долговременное хранение

После повторного открытия памяти должна восстанавливаться та же каноническая сеть по полюсам.

Если сохраняемый артефакт содержит несколько технических записей одной формы, слой восстановления должен отклонить или канонизировать их до передачи в семантическую модель.

Нормативно важны свойства:

- полюса сохраняются;
- циклы сохраняются;
- совместное использование сохраняется;
- дубликат одной пары не превращается в смысловую множественность;
- чтение не пишет;
- проверка не пишет;
- физический адрес не становится смыслом.

Конкретный JSON, база данных или `PersistMemoryManager` являются реализациями этого контракта, а не частью онтологии МТС.

## 14. Атомарное построение циклической группы

Для циклических структур реализация может временно использовать ссылки построения, позволяющие сослаться на элементы создаваемой группы до публикации результата.

Например технически:

```text
BuildRef(0)
BuildRef(1)
```

Такие ссылки существуют только на инженерной границе построения и хранения.

После разрешения группы каждая смысловая связь определяется только своими финальными полюсами. Если две разрешённые записи получают одну пару полюсов, они должны канонизироваться или операция должна быть отклонена как дублирующее представление.

Публикация группы должна быть атомарной:

```text
успех  -> видна целостная каноническая группа
ошибка -> видно исходное состояние
```

## 15. Контекст хранится связями

Контекст не обязан быть скрытым объектом языка реализации.

Текущее принятое представление состояния использует связевую форму:

```text
P = parent ⟼ current
K = K ⟼ P
```

Повтор той же полной формы `K` обозначает ту же смысловую связь. Если требуется различить два момента использования одного контекста, различие должно находиться в структуре истории актов или позиций `Run`, а не в отдельном идентификаторе вхождения.

## 16. Словарь и определения

Словарь и определения также могут быть представлены сетью связей.

Пример схемы:

```text
Entry      = sourceContent ⟼ Form
Definition = D_before ⟼ Entry
H_after    = H_before ⟼ Definition
```

Если требуемая связь уже существует, её повторное получение не создаёт копию.

Если необходимо различать два объявления одного текста и одной формы, различие должно быть выражено дополнительной связевой историей или позицией объявления, а не вторым экземпляром `Entry` той же пары.

## 17. Исходная запись и результирующая сеть различны

Факт наличия описания:

```text
A B
```

не означает автоматически, что физическая запись:

```text
A ⟼ B
```

уже присутствует в данной апамяти.

Правильное разделение:

```text
источник
→ разбор / разрешение
→ структурное описание
→ поиск
```

и только при явном изменяющем действии:

```text
→ ensure/materialize
→ новая физическая запись, если её ещё не было
```

## 18. Проверка доказательства не материализует факты

Поиск доказательства может быть сложным и недоверенным:

```text
индексы
эвристики
параллельный перебор
ранжирование
```

Доверенная проверка получает предъявленные связи и только проверяет их.

Если нужная запись не найдена в памяти, проверяющий не должен создавать её ради успешной проверки.

```text
proof search != proof checking
proof checking != materialization
```

## 19. Последовательность актов

История действий может быть представлена связевой последовательностью:

```text
Run0 = R
Run1 = Run0 ⟼ A0
Run2 = Run1 ⟼ A1
```

Если один и тот же акт или результат упоминается повторно, последовательность может ссылаться на ту же связь несколько раз.

Порядок хранится структурой `Run`, а не экземплярностью элементов.

## 20. Минимальный интерфейс апамяти

Понятийно достаточно разделить читающие и изменяющие операции:

```text
# чтение
poles(link)
find(start?, end?)
outgoing(start)
incoming(end)
snapshot()

# явное изменение
ensureLink(start,end)
ensureBatch(edges)

# проверка
replay(evidence) -> accept/reject
```

Критические свойства:

```text
semantic identity = (start,end)
find не пишет
replay не пишет
ensureLink не создаёт duplicate pair
циклы сохраняются
sharing сохраняется
позиционный повтор ссылки допустим
storage handle != semantic identity
physical address != semantic identity
```

## 21. Граница принятой версии 0.7

Текущий `core/rooted_link_network.py` канонизирует смысловые связи по упорядоченной паре уже структурно различённых полюсов. Повторное получение одной пары возвращает ту же смысловую связь, а второй полностью самозамкнутый акорень не допускается.

`LinkRef` остаётся локальным техническим механизмом доступа к уже канонизированной сети и не является источником смыслового тождества. Разные адреса, слоты или физические записи не могут сами по себе различить две связи одинаковой формы.

Граница импорта и восстановления обязана отклонять или канонизировать дублирующее физическое представление; цикл, различённый только заранее выданными техническими ID, также не становится автоматически смысловой асетью.

Пересмотр семантики #343 завершён переходом #401. В текущем `main` используется одна укоренённая семантика, а режим совместимости, сохраняющий старую множественность одинаковых пар, не входит в действующую реализацию.

## Итог

Апамять должна сохранять одновременно два класса принципов:

```text
(A⟼B) однозначна по (A,B)
повтор пары не создаёт вторую semantic Link

и

find != ensure/materialize
verify != write
не найдено != не существует
```

Именно их совместное соблюдение отделяет онтологическое тождество связи от инженерного факта наличия её записи в конкретной памяти.
