# Ачисла и сериализация

Ачисло — корневое последовательное описание связей через четыре абита:

```text
[ ] 1 0
```

Акорень `∞` не является пятым абитом. Каждый контекст десериализации **уже начинается** с акорня как со своего значения по умолчанию, поэтому передавать `∞` отдельным состоянием не требуется.

В текущем Foundation-v2 режиме:

```text
des(ε)  = ∞
des([]) = ∞
```

Пара `[]` открывает новый контекст десериализации и сразу закрывает его, не различив в нём другого значения. Поэтому `[]` является четверичной записью акорня внутри ачисла, а физический алфавит передачи остаётся строго четырёхсостоянием `[ ] 1 0`.

Главная граница:

```text
носитель ачисла
≠ описываемая связь
≠ материализованная сеть
```

Это позволяет описывать и искать связь, не создавая её скрыто. Сам носитель, как всё существующее в МТС, тоже является связевой структурой.

См. также [Основания МТС](../theory/Основания%20МТС.md), [Формальную нотацию МТС](Формальная%20нотация%20МТС.md) и [Апамять](Апамять%20и%20управление%20сетью%20связей.md).

## 1. Корень и абиты

Пятисвязное ядро:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

Остенсивно:

```text
O ≡ ♂∞
C ≡ ∞♀
```

Здесь важно не смешивать **пятисвязное семантическое ядро** и **четверичный транспортный алфавит**:

```text
семантическое ядро:  R O C L U
передаваемые абиты:    [ ] 1 0
```

`R=∞` — основание интерпретации, а не передаваемый абит. При входе в любой новый контекст:

```text
current := R
```

Поэтому `R` можно получить без пятого символа, а внутри потока явно представить пустым вложенным контекстом `[]`.

`[ ] 1 0` — корневые абиты ачисел. `♂` и `♀` — знаки форм самозамыкания, а не дополнительные абиты.

### Связь и несвязь

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
```

`1` несёт корневой смысл связи, `0` — смысл несвязи. Но `L` и `U` сами являются существующими точными связями.

Поэтому возможно:

```text
описание X существует
X в апамяти не существует
```

Здесь описание само является связевой структурой, но не тождественно своему денотату.

Абит `0` не является встроенным удалением:

```text
0 ≠ DELETE_LINK
```

Удаление требует отдельного правила и конкретного акта интерпретации.

## 2. Форма не является командой

Из последовательности:

```text
[01]
```

не следуют встроенные команды:

```text
[ = PUSH
] = POP
1 = CREATE_LINK
0 = DELETE_LINK
```

Роль абита определяется выбранным режимом и точными свидетельствами. В частности, `O/C` могут служить границами вложенной десериализации только в явно выбранном режиме; это не второй врождённый смысл корневых связей.

Правило `des([])=∞` также не означает, что `[` и `]` получили скрытые команды среды исполнения. Оно является результатом выбранного режима последовательностной десериализации: новый вложенный контекст начинается с `R`, а немедленное закрытие возвращает это исходное значение.

## 3. Историческая версия 0.2

Foundation v2 не переписывает историческую версию 0.2 задним числом.

В ней была принята корневая проекция:

```text
[  → ♀∞
]  → ∞♂
[] → 1
][ → 0
```

а формы `[[` и `]]` оставались граничными носителями без отдельного значения `0/1`. Это историческое правило отдельного протокольного режима, а не текущая семантика пустого контекста десериализации.

Историческая ориентация также не меняет текущую остенсивную ориентацию Foundation v2:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

Исторический протокол различал:

```text
root
quote
relative
```

Корневой режим применял принятую проекцию и рекурсивное чтение. Цитирование снимало ровно одну настоящую внешнюю пару скобок и возвращало содержимое как данные. Общая относительная семантика в версии 0.2 намеренно не была определена.

Для принятой конечной рекурсивной области:

```text
Atom  := 0 | 1
Value := Atom | '[' Pair ']'
Pair  := Value Value
Root  := Atom | Pair

D(A B) = D(A) ⟼ D(B)
```

Здесь `D` — историческое обозначение функции денотации. В Foundation v2 буква `D` уже используется для **словаря**, поэтому для текущей операции ниже применяется имя `des`, чтобы не смешивать два разных смысла.

Древовидное описание не является универсальным тождеством произвольной асети: оно не сохраняет в общем случае совместное использование, произвольные циклы и множественность точных вхождений одной формы.

## 4. Аксиома начала

Несколько начальных открытий после акорня могут схлопываться в одно физически представленное открытие.

Исторический пример:

```text
развёрнуто:   [[01]1]0
канонически:  [01]1]0
```

В текущем кандидате восстановление выполняется уже над разрешёнными точными формами:

```text
(O, U, L, C, L, C, U)
→ (O, O, U, L, C, L, C, U)
```

Второй `O` — не новая связь, а повторное употребление **того же точного корневого O** как виртуальной начальной границы.

Восстановление допустимо только если носитель действительно начинается с выбранного точного `O`. Связь той же формы не получает эту роль автоматически. Само восстановление ничего не группирует и не материализует.

## 5. От исходной записи к точным значениям

Физический четверичный носитель остаётся последовательностью `[ ] 1 0`. Строковые имена, знак `∞` и другой внешний текст не становятся новыми абитами линии передачи.

Текущий путь разрешения:

```text
исходная запись
→ каноническое содержимое
→ разбиение
→ D
→ точные формы в исходном порядке
```

Здесь `D` — явно выбранный **словарь** Foundation v2.

Словарь может разрешить фрагмент непосредственно в **любое существующее точное вхождение связи**:

```text
фрагмент
→ D
→ точная связь A
```

Поэтому на разрешённом уровне не нужен второй онтологический тип «ссылка на связь». Один и тот же текст может разрешаться по-разному в разных явно выбранных словарях; скрытого правила самого длинного совпадения нет.

## 6. Носитель, значение и две левые свёртки

После словарного разрешения внешний слой работает только с точными связями. Уже существующая связь может быть передана наружу как то же точное вхождение, а выбранная последовательность может быть явно материализована в новое точное вхождение.

Носитель последовательности и её десериализация используют похожую, но **не одну и ту же** свёртку.

Связевой носитель включает акорень как начальное значение:

```text
carrier(ε)     = R
carrier(a)     = R ⟼ a
carrier(a,b)   = (R ⟼ a) ⟼ b
carrier(a,b,c) = ((R ⟼ a) ⟼ b) ⟼ c
```

То есть понятийно:

```text
carrier(v1...vn) = foldl(⟼, R, v1...vn)
```

Десериализация использует `R` как значение пустого случая, но **не как дополнительный операнд** непустой свёртки:

```text
des(ε)     = R
des(a)     = a
des(a,b)   = a ⟼ b
des(a,b,c) = (a ⟼ b) ⟼ c
```

Поэтому для:

```text
C_ab = carrier(a,b) = (R ⟼ a) ⟼ b
X    = des(a,b)     = a ⟼ b
```

получаем разные структуры и, тем более, разные точные вхождения:

```text
C_ab ≠ X
```

Остенсивный корневой префикс не требует создания цепочки новых `R⟼R`. Различённый `R` уже удовлетворяет `R=R⟼R`; повторное написание корневого начала не даёт права подменять его новыми повторными точными вхождениями.

### Три проверенных вида действия

Для исследования дополнительных уровней удобно различать три **аналитических** действия:

```text
pass(v) = передать существующее точное вхождение v без изменения памяти
des(seq) = выполнить явную левую свёртку последовательности
enc(v) = явно построить carrier одного значения R ⟼ v
```

Это не новые встроенные команды и не новые сущности МТС. `pass` — отсутствие эффекта над уже выбранным значением; `des` использует существующий материализатор последовательностей; `enc` — обычное явное создание связи с точным `R` и точным `v`.

Текущие исследуемые примеры воспроизводятся так:

```text
ab       → des(a,b)
[ab]     → enc(des(a,b))
[[ab]]   → enc(pass(C_ab))
ab[ab]   → des(a,b,des(a,b))
[[ab]]ab → des(enc(pass(C_ab)),a,b)
```

Это **проверенная декомпозиция конкретных примеров**, а не универсальный контекстно-независимый закон квадратных скобок. Она показывает важную вещь: дополнительный уровень может менять не саму онтологию значения, а **выбранное действие над тем же носителем**.

## 7. Скобочная глубина сохраняется до материализации

После словарного разрешения различённые точные `O/C` могут быть выбраны границами вложенного чтения. Проверка группировки сохраняет глубину:

```text
[ab]   → Group(a,b)
[[ab]] → Group(Group(a,b))
```

Эти `SequenceDescription` различны. Следовательно, скрытый счётчик глубины среды исполнения не нужен: свидетельство вложенности уже присутствует в выбранной последовательности точных `O/C` и в полученной структуре группировки.

Границы определяются **точным тождеством O/C**. Другая связь с теми же полюсами остаётся обычным значением.

При этом общий материализатор вложенных последовательностей пока умеет только рекурсивно получить точный результат вложенной последовательности. Он **не устанавливает универсальное правило**, что второй `Group` обязан создать дополнительный уровень носителя. Исполнимая проверка показывает границу:

```text
Group(a,b)
Group(Group(a,b))
```

различимы до материализации, но текущий общий материализатор в обоих случаях способен закончить одной новой связью `a⟼b`.

Поэтому это поведение нельзя считать окончательной семантикой физических скобок. Выбор `pass / des / enc` должен быть предъявлен конкретным чтением, а не угадываться по форме связи или скрытому счётчику.

Пустой вложенный запуск остаётся полноценным нулевым случаем выбранного режима последовательностной десериализации:

```text
(O, C)
→ ([])
→ des(ε)
→ R = ∞
```

Проверка вложенности строгая и выполняется только для чтения: неожиданное закрытие и незакрытая группа отвергаются. Пустая группа не является ошибкой. Проверка не читает байты повторно и не создаёт отдельный синтаксический анализатор.

## 8. Явная материализация последовательности

Для разрешённых значений:

```text
∞ A B C
```

`des` выполняет левую свёртку накопленного префикса:

```text
AB  = A ⟼ B
ABC = AB ⟼ C
```

то есть:

```text
des(∞ A B C)
= (A ⟼ B) ⟼ C
= A ⟼ B ⟼ C
```

`∞` задаёт пустой начальный контекст и не становится дополнительным операндом свёртки. Первый разрешённый элемент становится текущим значением. Каждый следующий элемент связывается **с уже построенным точным префиксом**, а не просто с предыдущим исходным элементом.

Каждый шаг явной левой свёртки создаёт **новое точное вхождение**, даже если связь с такими полюсами уже существует.

Если для вложенной группы конкретным чтением выбран именно `des`, её точный результат становится обычным значением внешней свёртки:

```text
des(A,B) = X = A ⟼ B
des(X,C) = Y = X ⟼ C
```

Для смешанного случая:

```text
ab[ab]
```

внутренняя и внешняя материализации `a⟼b` являются разными точными вхождениями:

```text
X_inner = a ⟼ b
X_outer = a ⟼ b
X_inner ≠ X_outer
result = X_outer ⟼ X_inner
```

Никакого интернирования пар из совпадения полюсов не следует.

## 9. Проверенный сквозной путь

Для записи:

```text
[ab]c
```

в режиме, где внутренней группе выбран `des`, уже проверяется:

```text
байты
→ D
→ (O, A, B, C, C₁)
→ проверка вложенности
→ Group(A,B), C₁
→ des(A,B) = X
→ des(X,C₁) = Y
```

`O/C` здесь — настоящие точные связи пятисвязного корня. До явно выбранной материализации исходная сеть не меняется.

Тот же общий механизм последовательностей работает для смеси уже существующих точных связей и вложенных результатов. Но наличие более глубокой `Group(Group(...))` само по себе ещё не определяет, должен ли следующий акт выполнить `pass`, `des` или `enc`.

## 10. Поиск, создание и хранение

Поиск отсутствующей связи означает только:

```text
не найдено
```

Поэтому:

```text
find ≠ materialize
```

Это позволяет существующему ачислу описывать искомую связь без её появления в апамяти.

Для долговременного хранения различаются:

```text
оперативная ссылка
долговременный логический идентификатор
номер в снимке
физический адрес
```

Физический адрес не является смысловым тождеством связи. Подробнее: [Апамять](Апамять%20и%20управление%20сетью%20связей.md).

## 11. Относительное чтение как конкретный акт

Foundation v2 уже способен представить неоднозначность чтения без новой сущности `RelativeContext`.

Одна и та же точная исходная запись может участвовать в разных точных актах `A`. Акт способен связать, в частности:

```text
source
source-selection
form-sequence
D
G
T
K_before
точные роли O/C
result
K_after
```

Два акта могут иметь одну исходную запись и один `K_before`, но разные `G`, `T`, `form-sequence` и `result`. Их точное тождество при этом не схлопывается:

```text
A₁ ≠ A₂
```

Явный `K` может выбрать конкретный `A` как `current`. Поэтому относительность можно искать в **отношении исходная запись ↔ конкретный акт чтения**, а не в скрытом режиме интерпретатора.

Доверенная проверка уже использует общий принцип для полей акта: обязательная роль должна содержать ровно одно ожидаемое точное вхождение; отсутствие, дубль или подмена отвергаются. Будущая проверка скобочной семантики должна переиспользовать эту границу, а не заводить второй механизм доказательств.

Пока это решает вопрос **представимости свидетельств**, но не универсальное правило выбора. Поиск может предложить конкретный акт, а доверенная часть должна получить уже выбранные `A/K/D/G/T/...` и проверить, почему предъявленный результат следует из выбранной последовательности действий.

## 12. Текущая граница

Проверенная лестница:

```text
сырой носитель
→ исходная запись и D
→ точные формы
→ при необходимости восстановление начала
→ exact O/C grouping с сохранением глубины
→ выбранное чтение / конкретный A
→ pass / des / enc как предъявленная композиция
→ проверка или явная materialization
→ долговременное хранение
```

Машинные носители:

```text
SequenceAtom
SequenceGroup
SequenceDescription
OccurrenceRef
```

не являются новыми онтологическими типами МТС.

Ещё не приняты:

1. универсальное правило, по которому физические скобки выбирают конкретную композицию `pass / des / enc`;
2. доверенная проверка, связывающая выбранные свидетельства исходной записи/D/G/T/K/O/C с конкретным результатом такой композиции;
3. общий канонический обратный путь за пределами принятой рекурсивной области;
4. граница представимости произвольных циклических и разделяемых асетей одним ачислом.

До отдельного решения нельзя вводить:

```text
[ → start(current)
] → end(current)
```

нельзя считать число скобок скрытым состоянием среды исполнения и нельзя молча превращать дополнительную пару скобок в универсальную встроенную команду.

## Итог

Ачисло позволяет существующей связевой структурой описать другую связевую структуру без её немедленного создания:

```text
пятисвязное semantic kernel: R/O/C/L/U
четверичный transport:       [ ] 1 0

carrier(v1...vn) = left-fold from R
des(v1...vn)     = left-fold without R as nonempty operand

носитель ≠ денотат
поиск ≠ создание
форма скобок ≠ встроенная команда
```

Для текущих примеров достаточно обычных действий над точными связями `pass / des / enc`; относительность их выбора может быть засвидетельствована конкретным актом `A` под явными `K/D/G/T`.

```text
описать связь ≠ создать связь
описать несвязь ≠ сделать несвязь сущностью
```
