# Ачисла и сериализация

Ачисло — корневое последовательное описание связей через **ровно четыре абита**:

```text
[ ] 1 0
```

Акорень `∞` не является пятым абитом. Он является основанием четырёх корневых различений и начальной точкой каждого нового контекста `Q`.

Документ сохраняет историческую четверичную границу МТС v0.9 и унаследованные из неё свойства носителя, а также описывает принятую нормативную дельту v0.12. Текущей принятой системой является МТС v0.12; v0.11 сохраняется как предыдущая неизменяемая граница свидетельств.


МТС v0.12 наследует принятую в v0.11 линию четверичного носителя и уточняет само понятие ачисла и строкового носителя. Следующий раздел является принятой нормативной дельтой v0.12 и имеет приоритет над историческими формулами ниже при чтении текущей версии.

## МТС v0.12: укоренённое ачисло и один корневой срез

<a id="mts-law-exactAnumRooting"></a> <!-- нормативный владелец -->
Ачисло остаётся Связью в специальной роли адреса: каждое локальное ачисло начинается с R. Точное ачисло и адресуемая им Связь — разные отношения.

<a id="mts-law-resolveMaterializeSeparation"></a> <!-- нормативный владелец -->
Разрешение точного адреса и материализация цели — разные возможности; чтение само по себе не даёт права записи.

```text
Resolve = один корневой срез только для чтения
MATERIALIZE_TARGET = один разрешённый корневой срез с записью
```

Состояния результата чтения определяются нормативно в [спецификации апамяти](Апамять%20и%20управление%20сетью%20связей.md#mts-law-knowledgeStateSeparation). <!-- mts-law-ref:knowledgeStateSeparation -->

<a id="mts-law-targetMaterializationBound"></a> <!-- нормативный владелец -->
Оба вида среза снимают ровно один начальный уровень `R` по всей иерархии и сохраняют оставшуюся косвенность. `Resolve` никогда не материализует отсутствующую цель. `MATERIALIZE_TARGET` допускает запись только после полной проверки точного адресного свидетельства и при ошибке не оставляет частичных целевых записей.

<a id="mts-law-v012StringByteIdentity"></a> <!-- нормативный владелец -->
В v0.12 байт определяется не историческим `Byte_v09`, а точным восьмибитным ачислом:

```text
Byte_v012(p) = Anum(bits8(p))
             = Resolve_Q([bits8(p)])
```

<a id="mts-law-utf8CarrierBoundary"></a> <!-- нормативный владелец -->
Последовательность таких байтовых ачисел уже является точным `StringAnum_v012`. Поэтому сгруппированный четверичный носитель байтов не является внешней упаковкой над строкой — это сама её точная связевая иерархия. Строгое чтение UTF-8 выполняется поверх этих байтов и не переписывает топологию носителя.

<a id="mts-law-stringNestedAnum"></a> <!-- нормативный владелец -->
В контексте `STRING` конструкция `[...]` открывает дочерний `I_STRING` от `R` и возвращает родителю ровно одно значение-связь; вложенность сохраняется структурой ачисла, а не скрытым стеком анализатора.

<a id="mts-law-stringOneVsQOne"></a> <!-- нормативный владелец -->
Физический строковый знак `1` является UTF-8-символом/знаком `1`, тогда как `Q`-значение `1` является абитом `L`; совпадение написания не отождествляет эти роли.

<a id="mts-law-rootBasisBoundary"></a> <!-- нормативный владелец -->
Объявленный `RootBasis` должен структурно подтверждать `R/O/C/L/U`, включая правильное остенсивное различение `O` и `C` относительно `R`. Схлопнутый, поддельный или чужой базис отклоняется до записи.

## 1. Корневой базис и транспортный алфавит

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

В теоретической метанотации:

```text
O = O ⟼ R   # ♂∞
C = R ⟼ C   # ∞♀
```

Корневой четверичный словарь:

```text
[ -> O
] -> C
1 -> L
0 -> U
```

```text
семантический базис: R/O/C/L/U  — 5 связей
транспортный алфавит: [ ] 1 0   — 4 абита
```

## 2. Повтор абита не создаёт новую связь

```text
1110
```

разрешается как:

```text
[L, L, L, U]
```

Три позиции `1` — три вхождения одной смысловой связи `L`.

```text
смысловая связь
!= вхождение источника
!= позиция последовательности
```

## 3. Пустой поток и пустой контекст `Q`

```text
des(ε) = R
des("") = R
des("[]") = R
```

Пустая группа `[]` допустима и позволяет предъявить `R` без пятого абита.

## 4. Состояние `Q` структурно

Скрытый флаг `started:boolean` не является смысловым основанием.

```text
QEmpty = R
QNonEmpty(inner) = start-self-closed(inner)
```

Это различает пустое состояние и непустое состояние, первым значением которого является `R`, без второго экземпляра корня.

<a id="mts-law-quaternaryNestedContext"></a> <!-- нормативный владелец -->
## 5. Переходы `Q`

`Q [...]` остаётся рекурсией собственного контекста `I_Q`; вложенный `Q` не выбирается строковым или формальным режимом по эвристике хоста.

Для объяснения последовательного чтения используется метанотация:

```text
Q_OPEN
Q_VALUE
Q_CLOSE
Q_FINALIZE
```

Но смысл определяется структурой контекста, а не скрытым стеком языка реализации.

Обязательные свойства:

- новый дочерний контекст начинается с пустого структурного состояния;
- `[] -> R`;
- `R` не является абитом;
- результат вложенного контекста возвращается родителю как одно значение;
- возвращённый `R` не теряется, если родитель хранит точные позиции;
- чтение и проверка не материализуют связи.

## 6. Историческая граница v0.9: вложенный `Q` внутри `FORMAL`

МТС v0.9 различает:

```text
Q_CLOSE
!=
PARENT_CONTINUE
```

Закрытие дочернего контекста возвращает смысловой результат, а отдельное продолжение родителя добавляет его в `ExactSequence`.

Примеры:

```text
[]
[[]]
([[]])
```

сохраняют явную структуру вложенности.

## 7. Метанотация результата и физические скобки

Можно писать:

```text
[a]  = des("a")
[ab] = des("ab")
```

если ясно, что внешние скобки слева — метанотация результата.

Это отличается от физического источника:

```text
"[ab]"
```

где `[` и `]` действительно участвуют в открытии и закрытии `Q`.

## 8. Результат свёртки

Для уже разрешённых значений:

```text
des(ε)       = R
des(a)       = a
des(a,b)     = a ⟼ b
des(a,b,c)   = (a ⟼ b) ⟼ c
```

Это денотат результата, а не универсальное тождество исходной последовательности.

## 9. Точная последовательность отличается от результата свёртки

Если `R` допустим как явная позиция, простая свёртка неинъективна:

```text
[]   -> R
[R]  -> R
```

Поэтому используется `ExactSequence`:

```text
Seq([]) = R
Cell(prev,value) = start-self-closed(prev ⟼ value)
Seq(xs + [x]) = Cell(Seq(xs),x)
```

и:

```text
Seq([]) != Seq([R])
```

без создания второго `R`.

Нужно различать:

```text
EXACT_SEQUENCE
FOLD_RESULT
RESTRICTED_ROOTED_SEQUENCE
```

## 10. Носитель, денотат и материализация

```text
физический источник
структурный носитель
смысловой денотат
запись в конкретной памяти
```

— разные уровни.

```text
носитель != денотат
описать != материализовать
не найдено != не существует
find != ensure
```

## 11. Каноническая материализация

В текущей памяти:

```text
find(A,B)   — только чтение
ensure(A,B) — явное изменение
```

`ensure(A,B)` возвращает уже существующую связь той же пары либо материализует её один раз.

## 12. Корневая пара переиспользуется

```text
R ⟼ R = R
```

Поэтому повторное получение `(R,R)` не создаёт новую связь.

```text
[][] -> R
```

не означает два смысловых корня.

## 13. Два вида транспортного входа

Принятая семантика допускает внешний четверичный поток и уже существующий укоренённый связевой носитель как два транспорта одной линии десериализации.

Для существующего носителя `S` чтение только для чтения концептуально выполняется так:

```text
S = R  -> empty
S != R -> взять end(S); продолжить через start(S)
```

Цепочка начала должна конечно прийти к `R`, после чего собранные концы обращаются в прямой порядок.

## 14. Одна связь может играть разные явные роли

Например:

```text
U = C ⟼ O
```

как значение словаря означает абит `0`.

Но та же `U`, явно выбранная как укоренённый носитель, читается по своей цепочке начала. Совпадение со словарной связью не создаёт сокращение до одноэлементной последовательности.

```text
одна смысловая связь
+ разные явные роли
!= смысловое копирование
```

## 15. Проверка носителя не пишет

При чтении существующего носителя:

- цепочка начала должна конечно прийти к `R`;
- каждый элемент четверичного носителя должен быть `O/C/L/U`;
- посторонняя или повреждённая форма отклоняется;
- чтение не материализует;
- техническая координата хранения не является смысловым тождеством.

## 16. Строка в МТС v0.9

Формальный источник переносится как точная последовательность байтов.

Для каждого байта `p`:

```text
Rep_SQ(byte p) = [bbbbbbbb]
Byte(p) := Denote_Q([p])
```

Внутри конверта ровно восемь бит, старший бит первым. Один физический байт соответствует одному четверичному конверту.

Все 256 значений `Byte(p)` выводятся из структуры `Q`, а не вводятся непрозрачными техническими идентификаторами.

## 17. Текстовый слой отделён от точных байтов

Скрыто не выполняются:

```text
Unicode normalization
case folding
newline rewriting
locale conversion
lossy malformed-byte replacement
```

Интерпретация UTF-8 является отдельным строгим текстовым слоем. Повреждённая последовательность может быть допустима как точный набор байтов и отклоняться как текст UTF-8.

<a id="mts-law-representationNotInterpretation"></a> <!-- нормативный владелец -->
## 18. Знак источника и действие `Q` различаются

Физический знак `[` имеет байтовый носитель:

```text
[01011011]
```

Это не автоматически действие открытия `Q`.

```text
один носитель + строковое чтение
!=
тот же носитель + четверичное чтение
```

Выбор контекста должен быть явным.

## 19. Относительное продолжение — отдельный производный режим

После того как словарь, грамматика и теория уже выбрали конечную последовательность значений:

```text
F = (f1,...,fn)
```

можно продолжить свёртку от явного префикса контекста:

```text
P = parent ⟼ prefix
K = K ⟼ P

rel_K(ε) = prefix
r0 = prefix
r(i+1) = r(i) ⟼ f(i+1)
rel_K(F) = rn
```

Это не меняет смысл четырёх абитов и не означает:

```text
[ -> взять начало текущей связи
] -> взять конец текущей связи
```

## 20. Относительное продолжение не равно общей навигации

Завершённая производная теория F6.3 отдельно определяет проекции начала/конца, обратную инцидентность и конечную композицию путей при явном контексте.

Поэтому:

```text
относительная свёртка
!= общая навигация
!= координата пути
!= обратное отношение навигации
```

Гипотеза «ANUM = программа навигации» отвергнута.

## 21. Пустое относительное продолжение

```text
rel_K(ε) = prefix
```

отличается от нового корневого чтения:

```text
des(ε) = R
```

Если следующим значением является `R`, результат свёртки в специальном случае может схлопнуться:

```text
R ⟼ R = R
```

Это ещё одна причина не использовать денотат свёртки как тождество исходной последовательности.

## 22. Обратный анализ не угадывает историю

Если восстановление последовательности неоднозначно из-за схлопывания, проверяющая сторона должна вернуть отказ или неопределённость, а не угадывать историю по техническим идентификаторам.

Любое чтение и воспроизведение сохраняет:

```text
replay != materialize
find != ensure
```

## 23. Историческая граница

Старые записи:

```text
♀F / F♂
```

не определяют текущую семантику самозамыкания.

Остенсивные:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

остаются теоретической метанотацией, но `♂` и `♀` отложены как внутренние знаки F1 v0.9.

## 24. Внешняя лаборатория не определяет МТС

Репозиторий `netkeep80/anum_parser` может использоваться как экспериментальная лаборатория. Его поведение становится частью МТС только после отдельной теоретической проверки и жизненного цикла контракта.

## Итог

```text
[ ] 1 0 — ровно четыре абита
R/∞ — основание, а не пятый абит
новый Q-контекст начинается относительно R
[] = R
состояние Q структурно
вложенный результат возвращается явно
результат свёртки != тождество последовательности
ExactSequence сохраняет явные позиции R
одна смысловая связь может повторяться во многих позициях
(A⟼B) канонична по структурно различённым полюсам
два транспорта -> одна семантика ачисла
STRING→Q = один [8 bits] на байт
представление != интерпретация
относительная свёртка != навигация
find / read / replay != ensure / materialize / write
не найдено != не существует
```

Эти инварианты должны одновременно сохраняться в нормативной документации, принятом контракте, корпусе соответствия и реализации.
