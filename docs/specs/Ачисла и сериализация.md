# Ачисла и сериализация

Ачисло — корневое последовательное описание связей через **ровно четыре абита**:

```text
[ ] 1 0
```

Акорень `∞` не является пятым абитом. Он является основанием, относительно которого определены четыре корневых абита и с которого начинается каждый новый контекст десериализации.

## 1. Корневой базис и транспортный алфавит

Семантический корневой базис содержит пять связей:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Остенсивно:

```text
O ≡ ♂∞
C ≡ ∞♀
```

Корневой четверичный словарь:

```text
[ -> O
] -> C
1 -> L
0 -> U
```

Поэтому необходимо различать:

```text
семантический базис: R/O/C/L/U  — 5 связей
транспортный алфавит: [ ] 1 0   — 4 абита
```

`R` не передаётся как отдельное пятое состояние линии.

## 2. Тождество абитов и связей

В МТС связь полностью определяется своими полюсами:

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Следовательно, повтор одного абита в ачисле означает повторную ссылку на **ту же связь**, а не создание новых экземпляров.

Например:

```text
1110
```

разрешается в последовательность ссылок:

```text
[L, L, L, U]
```

Три позиции `1` различаются своим положением в последовательности, но все три указывают на одну связь `L`.

Позиционная множественность хранится последовательностью; она не создаёт дополнительную identity связи.

## 3. Пустая последовательность и пустой контекст

Каждый новый контекст десериализации автоматически начинается с акорня:

```text
current := R
```

Поэтому:

```text
des(ε) = R
des("") = R
des("[]") = R
```

Пустая группа `[]` **не является ошибкой**.

Открытие `[`:

```text
OPEN:
    сохранить внешний контекст
    открыть новый контекст
    current := R
```

Если следующий значимый переход сразу закрывает этот контекст, его значением остаётся `R`.

Таким образом `[]` позволяет записать акорень внутри четверичного ачисла без введения пятого абита.

## 4. Метанотация результата и физические скобки

В теоретических формулах удобно писать:

```text
[a]  = des("a")
[ab] = des("ab")
```

Здесь внешние квадратные скобки слева — метанотация значения `des`, а не дополнительные символы физического источника.

Например:

```text
des("")   = R
des("a")  = a
des("ab") = a ⟼ b
des("[]") = R
```

Нужно отличать метанотацию `[ab] = des("ab")` от физического источника `"[ab]"`, который действительно содержит абиты открытия и закрытия контекста.

## 5. Стековая десериализация

Каноническая линия разработки десериализатора использует явное состояние:

```text
state = (stack, top, current)
```

где каждый новый контекст начинается с `R`.

Минимальные переходы:

```text
OPEN  : сохранить внешний контекст; открыть новый; current := R
VALUE : включить очередное разрешённое значение в текущий контекст
CLOSE : завершить текущий контекст; вернуть его значение родителю
```

Твёрдо установлено:

- каждый контекст стартует от `R`;
- `[] -> R`;
- `R` не является абитом;
- результат вложенного контекста возвращается во внешний контекст как значение;
- состояние стековой машины должно быть наблюдаемым и в конечном счёте представимым связями МТС.

Пока не следует объявлять универсальной аксиомой конкретную carrier/re-carrierization семантику всех вложенных случаев. Точный алгоритм композиции nested-контекстов должен выводиться и проверяться отдельно; см. задачу #333.

## 6. Базовая последовательная свёртка

Для последовательности уже разрешённых значений без физической группировки используется левая свёртка:

```text
des(ε)       = R
des(a)       = a
des(a,b)     = a ⟼ b
des(a,b,c)   = (a ⟼ b) ⟼ c
```

При этом каждая связь свёртки подчиняется общему тождеству по полюсам.

Если на некотором шаге требуется связь:

```text
X = A ⟼ B
```

и эта связь уже представлена в конкретной апамяти, материализатор должен переиспользовать `X`, а не создавать второй экземпляр той же формы.

## 7. Носитель, денотат и материализация

Нужно различать три уровня:

```text
физический/связевой носитель ачисла
денотат десериализации
материализованная запись денотата в конкретной апамяти
```

То есть:

```text
носитель ≠ денотат
описать связь ≠ записать связь
```

Ачисло может описывать связь, которой ещё нет как физической записи в данной памяти.

Отсюда:

```text
не найдено ≠ не существует
find ≠ materialize
```

## 8. Правильная материализация

Семантическая операция построения связи концептуально имеет вид:

```text
ensureLink(A,B):
    если A ⟼ B уже присутствует в конкретной асети -> вернуть эту же связь
    иначе -> материализовать A ⟼ B и вернуть её
```

Это не означает, что `find` получает право записи. Должны существовать отдельные режимы:

```text
find(A,B)        — только поиск
ensureLink(A,B)  — явная операция получения с возможной материализацией
```

Если физический импорт содержит две разные записи/ID с одинаковыми полюсами `(A,B)`, это не две связи МТС. Импорт должен либо:

- отклонить дублирующее физическое представление;
- либо явно канонизировать его в одну semantic Link.

## 9. `R = R ⟼ R` и повторное использование

Из аксиомы тождества непосредственно следует:

```text
R ⟼ R = R
```

Поэтому операция, логически требующая `R ⟼ R`, не создаёт новую связь.

Проверочный пример:

```text
[][] -> R
```

На повторном получении формы `R ⟼ R` результатом остаётся `R`.

В отладочной трассе допустимо различать:

```text
created
reused
```

как свойства **операции над конкретной памятью**, но не как разные semantic identity результата.

## 10. Источник и позиции

Ачисло может поступать как внешний поток символов или как уже существующий связевой носитель.

Позиция символа, номер операции, offset, JSON-id или адрес памяти являются техническими координатами. Они могут различаться при повторном чтении одного и того же абита или одной и той же связи, но не создают вторую связь той же формы.

Если история чтения существенна, она должна быть выражена отдельной связевой структурой акта/последовательности.

## 11. Историческая версия v0.2

Историческая accepted-линия v0.2 использовала собственную boundary-проекцию и проекционную семантику скобок. Она сохраняется как история версии и не переписывается задним числом.

Текущая остенсивная ориентация:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

Старые записи `♀F / F♂` не являются текущим определением этих самозамыканий.

Исторические механизмы не должны переноситься в Foundation v2 автоматически, если они противоречат текущей системе аксиом.

## 12. Экспериментальная лаборатория

Репозиторий `netkeep80/anum_parser` служит экспериментальной лабораторией, а не нормативным источником МТС.

Текущая лабораторная модель использует:

```text
identity = by-poles
```

и различает в трассе создание физической записи и переиспользование уже существующей канонической связи.

Результаты лаборатории могут переноситься в `anum_docs` только после отдельной теоретической проверки.

## Итог

Нормативное ядро текущей линии:

```text
[ ] 1 0 — ровно четыре абита
R/∞ — основание, а не пятый абит
каждый новый контекст начинается с R
[] = R
повтор позиции != новая связь
(A⟼B) однозначна по (A,B)
find != materialize
не найдено != не существует
```

Вложенная стековая десериализация должна развиваться поверх этих инвариантов, а не возвращать occurrence-multiplicity под другим именем.
