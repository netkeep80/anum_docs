# Ачисла и сериализация

Ачисло — корневое последовательное описание связей через четыре абита:

```text
[ ] 1 0
```

Акорень `∞` не является пятым абитом: он уже присутствует как основание корневого чтения.

```text
носитель ачисла ≠ денотат ≠ материализованная сеть
```

Связь поэтому можно описывать и искать, не создавая её скрыто.

См. также [Основания МТС](../theory/Основания%20МТС.md), [Формальную нотацию МТС](Формальная%20нотация%20МТС.md) и [Апамять](Апамять%20и%20управление%20сетью%20связей.md).

## 1. Корневое ядро

```text
R = ∞ = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O

∞ → R
[ → O
] → C
1 → L
0 → U
```

Остенсивно:

```text
O ≡ ♂∞
C ≡ ∞♀
```

Нужно различать пятисвязное ядро `R/O/C/L/U` и передаваемые абиты `[ ] 1 0`. `R` — основание интерпретации, а не передаваемый абит. `♂/♀` — знаки форм самозамыкания.

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
```

`1` несёт корневой смысл связи, `0` — несвязи, но `L` и `U` сами являются существующими точными связями. Поэтому возможно:

```text
описание X существует
X в апамяти не существует
```

Здесь описание само является связевой структурой, но не тождественно своему денотату.

```text
0 ≠ DELETE_LINK
```

## 2. Метанотация и физические скобки

В формулах:

```text
[a]  = des('a')
[ab] = des('ab')
```

внешние скобки слева — метанотация результата `des`, а не абиты источника. Поэтому:

```text
[ab]       = des('ab')
[[ab]]     = des('[ab]')
[[[ab]]]   = des('[[ab]]')
[[[ab]]ab] = des('[[ab]]ab')
```

Например:

```text
des('a')   = a
des('[a]') = R ⟼ a

des(ε)    = R
des('[]') = R
```

В последнем случае пустое тело даёт `R`, а связь акорня с самим собой схлопывается к выбранному точному акорню.

## 3. Форма не является универсальной командой

Физическая форма `[`, взятая сама по себе, не означает врождённую команду МТС. Её операционная роль задаётся конкретным интерпретатором и теорией.

В выбранном десериализаторе ачисел `[` **открывает новый контекст десериализации**. Перед входом текущая связь сохраняется в стеке, после чего текущий указатель сбрасывается на `R`.

```text
OPEN:
stack.push(current)
current := R
```

Это не требует скрытого стека языка реализации. Семантически стек сам является ачислом — связевой последовательностью от акорня — и имеет явный указатель вершины.

Точный переход закрытия `]` должен быть задан той же машиной; его нельзя подменять универсальными правилами формы вроде:

```text
[ → start(current)
] → end(current)
```

Иными словами, скобка может быть командой **конкретного десериализатора**, но не является контекстно-независимым opcode связи.

## 4. Историческая версия 0.2 и аксиома начала

Foundation v2 не переписывает версию 0.2 задним числом. В ней была принята проекция:

```text
[  → ♀∞
]  → ∞♂
[] → 1
][ → 0
```

а `[[` и `]]` оставались граничными формами. Историческая ориентация не меняет текущую:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

В исторической конечной рекурсивной области использовалось `D(A B)=D(A)⟼D(B)`. Сейчас `D` означает **словарь**, поэтому текущая денотация последовательности называется `des`.

Аксиома начала допускает восстановление:

```text
(O,U,L,C,L,C,U)
→ (O,O,U,L,C,L,C,U)
```

Второй `O` — повторное употребление **того же точного O**, а не новая связь той же формы. Восстановление ничего не материализует.

## 5. Источник, словарь и подвыборка

Проверяемый путь:

```text
исходная запись
→ каноническое содержимое
→ выбранное разбиение
→ D
→ точные формы
```

Словарь может разрешить фрагмент непосредственно в любое существующее точное вхождение. Отдельный тип «ссылка на связь» не нужен; скрытого правила самого длинного совпадения нет.

Каждый сегмент уже имеет точные `span`, `slice-content`, `lexeme`, `resolution`, `selection`. Поэтому вложенному чтению не нужна сущность `NestedSource`.

Непрерывная подвыборка представляется обычными связями:

```text
source-selection = fold(R, selection₁, ..., selectionₙ)
form-sequence    = fold(R, form₁, ..., formₙ)
G ⟼ form-sequence
T ⟼ form-sequence
```

Доверенная проверка сначала воспроизводит полный источник, затем подвыборку. Номера сегментов — лишь координаты проверяющей программы; пустая подвыборка использует точный `R`.

## 6. Свёртки и продолжение

Носитель включает `R` как начальное значение:

```text
carrier(ε)     = R
carrier(a)     = R ⟼ a
carrier(a,b)   = (R ⟼ a) ⟼ b
carrier(a,b,c) = ((R ⟼ a) ⟼ b) ⟼ c
```

Десериализация не использует `R` как дополнительный операнд непустого результата:

```text
des(ε)     = R
des(a)     = a
des(a,b)   = a ⟼ b
des(a,b,c) = (a ⟼ b) ⟼ c
```

Поэтому:

```text
C_ab = carrier(a,b) = (R ⟼ a) ⟼ b
X    = des(a,b)     = a ⟼ b
C_ab ≠ X
```

Каждый явный создаваемый шаг сохраняет exact-occurrence identity: одинаковые полюса не означают одно вхождение.

Если `K.current=P`, хвост может продолжить левую свёртку:

```text
continuation(P; a,b) = (P ⟼ a) ⟼ b
```

Этот уже проверенный механизм остаётся полезным, но его место в каноническом `des` теперь должно выводиться из переходов стековой машины.

## 7. Глубина и явный стек

Структурная группировка по точным `O/C` по-прежнему различает:

```text
[ab]   → Group(a,b)
[[ab]] → Group(Group(a,b))
```

Но `SequenceGroup` — только машинный носитель структурного свидетельства, а не основание семантики десериализации.

Каноническая операционная модель из issue #333 использует явный стек указателей связей и текущий указатель. Стек сам является ачислом, то есть связевой последовательностью, начинающейся от `R`. Поэтому глубина не обязана существовать как скрытый счётчик среды исполнения: она должна восстанавливаться из явного состояния машины.

## 8. Проверенные результаты и текущая интерпретация

Следующие результаты уже имеют executable challenges:

```text
des(ε) = R
des(a) = a
des(ab) = a ⟼ b

des('[ab]')     = R ⟼ (a ⟼ b)
des('[[ab]]')   = R ⟼ carrier(a,b)
des('[[ab]]ab') = continuation(R ⟼ carrier(a,b); a,b)
```

Проверенные `SequenceGroup`/actual-act цепочки доказывают представимость этих результатов без скрытого host-state. После issue #333 они рассматриваются как **проверочные векторы** для явной стековой машины, а не как окончательное основание её алгоритма.

То же относится к смешанному примеру:

```text
ab[ab]

X_inner = a ⟼ b
X_outer = a ⟼ b
X_inner ≠ X_outer
result = X_outer ⟼ X_inner
```

Совпадение полюсов не означает точного тождества; интернирование пар не является семантическим законом.

## 9. Два представления входного ачисла

Ачисло может поступать как внешняя последовательность — например UTF-8 запись — либо уже существовать в асети как последняя связь последовательности:

```text
abc
↔
(((R ⟼ a) ⟼ b) ⟼ c)
```

Связь имеет смысл носителя ачисла, если рекурсивный проход по началам её префикса приводит к акорню.

Канонический десериализатор должен давать одну и ту же последовательность смысловых переходов для потокового входа и для эквивалентного связевого носителя. Физический формат чтения не должен менять денотат.

## 10. Относительное чтение как точный акт

Один источник может участвовать в разных актах `A`:

```text
source
source-selection
form-sequence
D / G / T
K_before
form / binding
result
K_after
```

Акты могут иметь общий источник, но разные подвыборки, `G/T`, формы и результаты. Доверенная проверка требует ровно одно ожидаемое точное значение каждой обязательной роли.

Относительность находится в **отношении источник ↔ конкретный засвидетельствованный акт чтения**, а не в скрытом режиме. Для десериализатора к этому свидетельству должно добавиться явное состояние его стека/current, а не неявный host-stack.

## 11. Поиск и хранение

```text
не найдено ≠ не существует
find ≠ materialize
```

Существующий носитель может описывать искомую связь без её появления в апамяти.

При долговременном хранении различаются оперативная ссылка, логический идентификатор, номер в снимке и физический адрес. Физический адрес не является смысловым тождеством связи. Подробнее: [Апамять](Апамять%20и%20управление%20сетью%20связей.md).

## 12. Текущая граница

Уже проверены source/D/G/T, точные `O/C`, подвыборки, actual acts, `K`-непрерывность, левая свёртка и её продолжение. Но issue #333 уточняет, что канонический `des` должен быть основан на явной стековой машине.

Следующий обязательный слой:

```text
state = (stack, top, current)

OPEN  : сохранить current в стеке; current := R
VALUE : обновить current очередным значением
CLOSE : закрыть текущий контекст, восстановить предыдущий и включить результат
```

Нужно проверить:

1. точную связевую форму `stack` и указателя `top`;
2. `VALUE` для `ε`, `a`, `ab` и акорневого схлопывания;
3. `CLOSE` на `[ab]`, `[[ab]]`, `ab[ab]`, `[[ab]]ab`;
4. эквивалентность потокового и асетевого входов;
5. связь каждого перехода с exact actual act и `K`, без скрытого состояния.

Не требуются как новые онтологические сущности:

```text
NestedSource
RelativeContext
Quote
pass
enc
скрытый host-stack
скрытый счётчик глубины
интернирование пар
```

`PUSH/POP` больше не исключаются как операции выбранного десериализатора: исключается только их **скрытая реализация**, не засвидетельствованная связями.

## Итог

```text
carrier(v₁...vₙ) = левая свёртка от R

носитель ≠ денотат
поиск ≠ создание
форма скобок ≠ универсальная команда МТС
```

Для конкретного десериализатора скобки задают переходы контекста стековой машины. Сам стек и его указатели должны быть представлены в той же связевой онтологии, которую машина интерпретирует.

```text
описать связь ≠ создать связь
описать несвязь ≠ сделать несвязь сущностью
```
