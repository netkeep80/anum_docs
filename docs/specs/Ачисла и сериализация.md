# Ачисла и сериализация

Ачисло — корневое структурное описание связей через четыре абита:

```text
[ ] 1 0
```

Акорень `∞` не является пятым абитом. Он задаёт исходную точку, относительно которой читается последовательность.

Главная граница:

```text
носитель ачисла
≠ описываемая структура
≠ материализованная сеть
```

Поэтому чтение ачисла не должно само по себе создавать описываемые связи.

## 1. Корневые абиты

Пятисвязное ядро МТС:

```text
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

Поэтому `[ ] 1 0` являются корневыми различениями, из которых можно строить более длинные описания.

Знаки `♂` и `♀` относятся к формальной записи самозамыкания и не являются дополнительными абитами.

### 1.1. Абиты связи и несвязи

Связи `L` и `U` имеют противоположную ориентацию:

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
```

В корневом чтении `1` несёт смысл связи, а `0` — смысл несвязи. Но это **два существующих корневых вхождения связи**. Сам абит `0` не является дырой в асети и не создаёт отдельную сущность «ничто».

Поэтому нужно различать:

```text
несвязь                       — отсутствие связности;
U = C ⟼ O                    — связь, несущая корневой смысл несвязи;
0                            — абит, указывающий на U в корневом словаре;
ачисло с 0                   — существующее описание;
отсутствующая описанная связь — может не существовать в апамяти;
```

Это особенно важно для сериализации. МТС может иметь ачисло, описывающее некоторую связь, хотя самой описываемой связи ещё нет в натуре:

```text
описание X существует
X в апамяти не существует
```

Противоречия здесь нет: описание само является связевой структурой, но не тождественно своему денотату.

Абит `0` также **не является встроенной командой удаления**:

```text
0 ≠ DELETE_LINK
```

Интерпретатор может иметь явно допущенное правило, в котором `0` участвует в запросе удаления, но тогда удаление определяется этим правилом и конкретным актом, а не самим абитом.

## 2. Сырые абиты не являются командами

Последовательность:

```text
[01]
```

сначала является только последовательностью четырёх допустимых знаков.

Из самих символов нельзя автоматически заключать:

```text
[ = PUSH
] = POP
1 = CREATE_LINK
0 = DELETE_LINK
```

Смысл возникает только в явно выбранном режиме чтения и относительно корневых значений.

Это позволяет одной и той же физической последовательности участвовать в разных протоколах без скрытой смены онтологии.

## 3. Историческая корневая проекция версии 0.2

Для принятой исторической линии версии 0.2 действует проекция:

```text
[  → ♀∞
]  → ∞♂
[] → 1
][ → 0
```

При этом:

```text
[[
]]
```

являются допустимыми граничными формами, но не получают отдельного значения `0` или `1`.

Эта ориентация относится к принятой версии 0.2 и не переопределяет текущую остенсивную запись Foundation v2:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

## 4. Явный режим чтения

Исторический протокол различает три режима:

```text
root
quote
relative
```

### Корневой режим

Применяет корневые правила проекции.

Если для последовательности ещё нет принятого структурного смысла, результат остаётся сырым носителем, а не получает придуманную эвристикой денотацию.

### Цитирование

В режиме цитирования внешний уровень:

```text
[A]
```

может быть снят ровно один раз, после чего содержимое рассматривается как данные.

Отдельная сущность `Quote` для этого не нужна.

### Относительный режим

В принятой версии 0.2 относительная семантика общего носителя не определена. Поэтому последовательность сохраняется как сырая, без скрытой нормализации.

## 5. Разбор и сериализация

Сырой разбор принимает только:

```text
[ ] 1 0
```

а также разрешённые пробелы и комментарии транспортного формата.

Каноническая сериализация удаляет пробелы и комментарии и оставляет только последовательность абитов.

То есть:

```text
parse
→ canonical serialize
→ parse
```

должно сохранять тот же сырой носитель.

Это свойство не означает, что уже определено обратное преобразование любой произвольной асети в ачисло.

## 6. Строковые имена находятся выше абитов

Имена вроде:

```text
window
position
int
```

не являются новыми абитами.

Они могут разрешаться явным словарём:

```text
имя
→ зарегистрированный носитель ачисла
```

Неизвестное имя должно приводить к ошибке, а не к скрытому кодированию через UTF-8.

Кодирование обычного текста и словарь имён — разные слои.

## 7. Прямые значения `0` и `1`

В исторической версии 0.2 существуют два протокольных значения:

```text
0
1
```

и минимальный набор прямых пар:

```text
00 → 0 ⟼ 0
01 → 0 ⟼ 1
10 → 1 ⟼ 0
11 → 1 ⟼ 1
```

Это ограниченный принятый фрагмент структурного чтения, а не универсальная грамматика произвольной сети.

## 8. Рекурсивное структурное чтение

Для принятой области дерева вхождений используется грамматика:

```text
Atom  := 0 | 1
Value := Atom | '[' Pair ']'
Pair  := Value Value
Root  := Atom | Pair
```

и правило:

```text
D(A B) = D(A) ⟼ D(B)
```

Такое ачисло описывает конечную рекурсивную структуру.

Но оно не является универсальным тождеством произвольной асети, потому что дерево не сохраняет в общем случае:

- совместное использование одного точного вхождения несколькими связями;
- произвольные циклы;
- различие двух одинаковых по форме точных вхождений, если описание их схлопывает.

Поэтому произвольная асеть хранится как сеть точных связей, а рекурсивное ачисло остаётся её возможным структурным представлением на поддерживаемой области.

## 9. Последовательностное чтение

Исходный замысел ачисла допускает более общий случай:

```text
∞ A B C
```

который при явной материализации означает создание новых соседних связей:

```text
AB = A ⟼ B
BC = B ⟼ C
```

`∞` служит началом последовательности и не создаёт автоматически связь `∞ ⟼ A`.

Каждая соседняя пара создаёт **новое точное вхождение**, даже если связь с такими же полюсами уже существует.

## 10. Вложенные группы

Одиночная группа:

```text
[A]
```

возвращает `A` без создания новой связи.

Группа из двух элементов:

```text
[A B]
```

создаёт:

```text
X = A ⟼ B
```

и возвращает точное `X` внешней последовательности.

Поэтому:

```text
∞ [A B] C
```

создаёт:

```text
X = A ⟼ B
Y = X ⟼ C
```

Для группы из нескольких элементов наружу возвращается последнее созданное соседнее вхождение.

## 11. Пример вложенной последовательности

```text
∞[window][cursor][position][[[x][int]][point]]
```

После разрешения одиночных имён сначала строится вложенная часть:

```text
XI = X ⟼ Int
Q  = XI ⟼ Point
```

а затем верхняя последовательность:

```text
WC = Window ⟼ Cursor
CP = Cursor ⟼ Position
PQ = Position ⟼ Q
```

Порядок материализации детерминирован: сначала вложенные значения, затем внешние соседства.

## 12. Поиск не является материализацией

Если запрос ищет:

```text
A ⟼ B
```

то отсутствие такой связи означает только:

```text
не найдено
```

а не:

```text
создать A ⟼ B
```

Поэтому:

```text
find
≠ materialize
```

Это один из главных инвариантов связи ачисел с апамятью.

## 13. Сохранение после перезапуска

При долговременном хранении нужно различать:

```text
оперативную ссылку
долговременный логический идентификатор
номер в снимке
физический адрес записи
```

Ачисло не должно зависеть от физического адреса в конкретном хранилище.

После повторного открытия точные вхождения, их циклы, совместное использование и множественность одинаковых пар должны сохраняться логически.

Подробнее: [Апамять и управление сетью связей](Апамять%20и%20управление%20сетью%20связей.md).

## 14. Машинные границы

Текущая реализация разделена на несколько технических частей:

```text
core/anum_parser.py
core/anum_protocol.py
core/anum_recursive_denotation.py
core/foundation_v2_materialization.py
core/foundation_v2_persistent.py
```

Имена модулей являются деталями реализации. Понятийная граница важнее:

```text
сырой носитель
→ выбранное структурное чтение
→ поиск
→ явная материализация
→ долговременное хранение
```

Нельзя создавать второй параллельный разборщик или второй механизм материализации только ради новой формы записи.

## 15. Что остаётся открытым

Следующая версия МТС ещё должна окончательно определить:

- универсальна ли какая-либо форма ачисла для произвольных циклических и разделяемых асетей;
- нужен ли отдельный ссылочный транспорт для точных вхождений;
- окончательную относительную семантику;
- каноническое обратное представление за пределами уже принятой рекурсивной области;
- границу между структурным описанием и контекстным смыслом.

До этого нельзя молча расширять грамматику эвристикой реализации.

## Итог

Ачисло полезно именно потому, что отделяет **описание структуры** от немедленного изменения сети.

Короткая лестница:

```text
∞
→ [ ] 1 0
→ сырое ачисло
→ структурное чтение
→ поиск или проверка
→ явная материализация
→ апамять
```

Главный принцип:

```text
описать связь ≠ создать связь
```

И дополнительная граница:

```text
описать несвязь ≠ сделать несвязь сущностью
```
