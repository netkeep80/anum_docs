# Ачисла и сериализация

Ачисло — корневое последовательное описание связей через четыре абита:

```text
[ ] 1 0
```

Акорень `∞` не является пятым абитом. Он уже присутствует как основание каждого корневого чтения.

Главная граница:

```text
носитель ачисла
≠ его денотат
≠ сеть, полученная явной материализацией
```

Поэтому связь можно описывать и искать, не создавая её скрыто.

См. также [Основания МТС](../theory/Основания%20МТС.md), [Формальную нотацию МТС](Формальная%20нотация%20МТС.md) и [Апамять](Апамять%20и%20управление%20сетью%20связей.md).

## 1. Корень и четыре абита

Пятисвязное корневое ядро:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

Остенсивно:

```text
O ≡ ♂∞
C ≡ ∞♀
```

Нужно различать:

```text
корневое ядро:      R O C L U
передаваемые абиты:   [ ] 1 0
```

`R=∞` — основание интерпретации, а не передаваемый абит.

`[ ] 1 0` — корневые абиты ачисел. `♂` и `♀` — знаки форм самозамыкания, а не дополнительные абиты.

### Связь и несвязь

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
```

`1` несёт корневой смысл связи, `0` — смысл несвязи. Но `L` и `U` сами являются существующими точными связями.

Поэтому допустимо:

```text
описание X существует
X в апамяти не существует
```

Абит `0` не является встроенной командой удаления:

```text
0 ≠ DELETE_LINK
```

## 2. Метанотация и физические скобки

В исследовательских формулах вида:

```text
[a]  = des('a')
[ab] = des('ab')
```

**внешние квадратные скобки слева являются метанотацией результата `des`, а не физическими абитами источника**.

Поэтому нужно различать:

```text
[ab]       = des('ab')
[[ab]]     = des('[ab]')
[[[ab]]]   = des('[[ab]]')
```

Первый уровень слева только обозначает вызов десериализации. Каждый дополнительный уровень уже присутствует в физическом источнике.

Это различие особенно важно для `a` и `[a]`:

```text
des('a')   = a
des('[a]') = R ⟼ a
```

Для пустого случая оба пути приходят к акорню:

```text
des(ε)    = R
des('[]') = R
```

Во втором равенстве пустое тело даёт `R`, а точная закрывающая корневая форма снова приводит к `R=R⟼R`.

## 3. Форма не является командой

Из физического источника:

```text
[01]
```

не следуют встроенные команды:

```text
[ = PUSH
] = POP
1 = CREATE_LINK
0 = DELETE_LINK
```

Роль точной формы определяется выбранными свидетельствами чтения. `O/C` могут быть выбраны границами вложенного чтения, но это не превращает их в скрытые команды среды исполнения.

Нельзя выводить универсальные правила:

```text
[ → start(current)
] → end(current)
```

и нельзя считать число скобок скрытым состоянием интерпретатора.

## 4. Историческая версия 0.2

Foundation v2 не переписывает историческую версию 0.2 задним числом.

В ней была принята корневая проекция:

```text
[  → ♀∞
]  → ∞♂
[] → 1
][ → 0
```

а `[[` и `]]` оставались граничными формами без отдельного значения `0/1`.

Историческая ориентация не меняет текущую остенсивную ориентацию Foundation v2:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

Исторический протокол различал корневое, цитирующее и относительное чтение. Общая относительная семантика тогда намеренно не была определена.

Для принятой конечной рекурсивной области использовалось:

```text
Atom  := 0 | 1
Value := Atom | '[' Pair ']'
Pair  := Value Value
Root  := Atom | Pair

D(A B) = D(A) ⟼ D(B)
```

Здесь `D` — историческое обозначение денотации. В Foundation v2 буква `D` уже занята **словарём**, поэтому текущая операция называется `des`.

Древовидное описание не является универсальным тождеством произвольной асети: оно не обязано сохранять совместное использование, произвольные циклы и множественность точных вхождений одной формы.

## 5. Аксиома начала

Несколько начальных открытий после акорня могут схлопываться в одно физически представленное открытие.

Исторический пример:

```text
развёрнуто:   [[01]1]0
канонически:  [01]1]0
```

В Foundation-v2 кандидате восстановление выполняется над уже разрешёнными точными формами:

```text
(O, U, L, C, L, C, U)
→ (O, O, U, L, C, L, C, U)
```

Второй `O` — повторное употребление **того же точного корневого O**, а не новая связь той же формы.

Восстановление допустимо только для выбранного точного `O`. Связь с теми же полюсами не получает эту роль автоматически. Само восстановление ничего не материализует.

## 6. От источника к точным значениям

Физический носитель остаётся четверичной последовательностью `[ ] 1 0`. Строковые имена и знак `∞` не становятся дополнительными абитами.

Проверяемый путь разрешения:

```text
исходная запись
→ каноническое содержимое
→ выбранное разбиение
→ D
→ точные формы в исходном порядке
```

Один фрагмент может быть разрешён словарём непосредственно в **любое существующее точное вхождение связи**:

```text
фрагмент
→ D
→ точная связь A
```

Поэтому отдельный онтологический тип «ссылка на связь» не нужен.

Один и тот же физический источник может иметь разные явно выбранные разбиения, `G`, `T` и результаты. Скрытого правила самого длинного совпадения нет.

### Подвыборка того же источника

Каждый выбранный сегмент уже имеет точные свидетельства:

```text
span
slice-content
lexeme
resolution
selection
```

Поэтому вложенному чтению не требуется новая сущность `NestedSource`.

Непрерывное тело можно засвидетельствовать обычными корневыми последовательностями уже существующих точных сегментов:

```text
source-selection = fold(R, selection₁, ..., selectionₙ)
form-sequence    = fold(R, form₁, ..., formₙ)
G ⟼ form-sequence
T ⟼ form-sequence
```

Доверенная проверка сначала воспроизводит весь точный источник, затем выбранную непрерывную подвыборку. Номера сегментов являются только координатами проверяющей программы; смысловые свидетельства остаются связями.

Пустая подвыборка использует точный `R` как пустую последовательность.

## 7. Носитель и десериализация: две левые свёртки

Носитель последовательности включает акорень как начальное значение:

```text
carrier(ε)     = R
carrier(a)     = R ⟼ a
carrier(a,b)   = (R ⟼ a) ⟼ b
carrier(a,b,c) = ((R ⟼ a) ⟼ b) ⟼ c
```

То есть:

```text
carrier(v₁...vₙ) = foldl(⟼, R, v₁...vₙ)
```

Десериализация использует `R` только для пустого случая, но не как дополнительный операнд непустой свёртки:

```text
des(ε)     = R
des(a)     = a
des(a,b)   = a ⟼ b
des(a,b,c) = (a ⟼ b) ⟼ c
```

Для:

```text
C_ab = carrier(a,b) = (R ⟼ a) ⟼ b
X    = des(a,b)     = a ⟼ b
```

получаем:

```text
C_ab ≠ X
```

и это различие не исчезает из-за совпадения форм других связей.

Каждый шаг явной материализации `des` создаёт новое точное вхождение, даже если связь с такими полюсами уже существует.

### Никаких отдельных `pass` и `enc`

Ранее в исследовательских проверках использовались вспомогательные названия `pass` и `enc`. После дальнейшей редукции они не нужны.

Передача уже выбранного значения является одноэлементной десериализацией:

```text
des(v) = v
```

без эффекта над сетью.

Подъём значения в одноэлементный корневой носитель:

```text
R ⟼ v
```

уже выражается обычным применением точной закрывающей корневой формы:

```text
C = R ⟼ C
C(v) → R ⟼ v
```

То есть отдельной операции кодирования для этого не требуется.

## 8. Скобочная глубина сохраняется до интерпретации

После словарного разрешения точные `O/C` могут быть выбраны границами вложенного чтения.

Группировка сохраняет глубину:

```text
[ab]   → Group(a,b)
[[ab]] → Group(Group(a,b))
```

Эти описания различны до интерпретации. Следовательно, скрытый счётчик глубины не нужен: свидетельство вложенности уже присутствует в точной последовательности `O/C`.

Границы определяются **точным тождеством O/C**. Другая связь с теми же полюсами остаётся обычным значением.

Общий материализатор вложенных последовательностей сам по себе не задаёт универсальную семантику дополнительной глубины. Выбор результата должен быть подтверждён конкретными актами чтения.

## 9. Проверенный физический `[ab]`

После PR #328 проверяется полный путь для **одного физического источника**:

```text
'[ab]'
```

Словарное разрешение whole source даёт:

```text
(O, a, b, C)
```

Точная группировка даёт:

```text
Group(a,b)
```

Затем два акта того же источника образуют точный Run.

Первый акт читает подвыборку тела:

```text
source            = whole '[ab]'
source-selection  = selection(a,b)
form-sequence     = (a,b)
D/G/T             = точные свидетельства тела

des(a,b) = X = a ⟼ b
K₀ → K₁(current=X)
```

Второй акт читает точный закрывающий сегмент **того же source**:

```text
source            = whole '[ab]'
source-selection  = selection(C)
form-sequence     = (C)
D/G/T             = точные свидетельства закрытия
form              = C = R ⟼ C
binding           = X
result            = R ⟼ X
K₁ → K₂
```

Итого:

```text
des('[ab]') = R ⟼ (a ⟼ b)
```

В пользовательской метанотации это соответствует:

```text
[[ab]] = des('[ab]') = R ⟼ (a ⟼ b)
```

`O` здесь участвует в точном whole-source свидетельстве и группировке. Для получения `R⟼X` не требуется приписывать `O` или `C` скрытый машинный код: используется уже существующая one-pole семантика точной формы `C`.

Проверка также показывает, что контекст с теми же `parent/current`, но другим точным вхождением `K₁'`, не может заменить `K₁` между актами:

```text
K₁' ≠ K₁
```

Даже если второй акт отдельно корректен при `K₁'`, Run с ним отвергается.

## 10. Смешанная вложенность и точные дубликаты

Для:

```text
ab[ab]
```

если внутреннему телу выбран `des`, внутреннее и внешнее `a⟼b` являются разными точными вхождениями:

```text
X_inner = a ⟼ b
X_outer = a ⟼ b
X_inner ≠ X_outer
result = X_outer ⟼ X_inner
```

Совпадение полюсов не означает точного тождества. Интернирование пар не допускается как семантический закон.

## 11. Поиск, создание и хранение

Поиск отсутствующей связи означает только:

```text
не найдено
```

Поэтому:

```text
find ≠ materialize
```

Существующий носитель может описывать искомую связь без её появления в апамяти.

Для долговременного хранения различаются:

```text
оперативная ссылка
долговременный логический идентификатор
номер в снимке
физический адрес
```

Физический адрес не является смысловым тождеством связи. Подробнее: [Апамять](Апамять%20и%20управление%20сетью%20связей.md).

## 12. Относительное чтение как конкретный акт

Foundation v2 уже представляет неоднозначность чтения без сущности `RelativeContext`.

Один exact source может участвовать в разных точных актах `A`, связывающих, в частности:

```text
source
source-selection
form-sequence
D
G
T
K_before
form / binding, если это relation-step
result
K_after
```

Два акта могут иметь один source, но разные подвыборки, `G`, `T`, последовательности форм и результаты:

```text
A₁ ≠ A₂
```

Доверенная проверка требует ровно одно ожидаемое точное значение каждой обязательной роли. Отсутствие, дубль или подмена отвергаются.

Тем самым относительность находится не в скрытом режиме интерпретатора, а в **отношении между точным источником и конкретным засвидетельствованным актом его чтения**.

Поиск может предложить акт; доверенный слой только воспроизводит уже предъявленные точные свидетельства.

## 13. Текущая граница

Проверенная лестница теперь выглядит так:

```text
сырой носитель
→ exact whole source
→ D и выбранные сегменты
→ точные формы
→ при необходимости восстановление начала
→ exact O/C grouping с сохранением глубины
→ exact source-subselection
→ конкретный actual act
→ des или обычный one-pole relation-step
→ exact Run
→ при необходимости явная материализация и хранение
```

Машинные носители:

```text
SequenceAtom
SequenceGroup
SequenceDescription
OccurrenceRef
```

не являются новыми онтологическими типами МТС.

### Что уже снято как лишнее

Не требуются как новые сущности или встроенные операции:

```text
NestedSource
RelativeContext
Quote
pass
enc
PUSH / POP
скрытый depth counter
pair interning
```

### Что ещё не принято

Главная ближайшая граница — **второй физический уровень**:

```text
'[[ab]]'
```

Пользовательская формула указывает на:

```text
des('[[ab]]') = R ⟼ carrier(a,b)
```

а не на автоматическое повторение результата первого уровня:

```text
R ⟼ (R ⟼ des(a,b))
```

Эти структуры уже доказано различимы по точным полюсам и вхождениям. Поэтому следующий уровень нужно вывести как композицию уже существующих подвыборок, актов и точных `O/C`, а не вводить универсальную команду «ещё одна скобка».

Также остаются открыты:

1. общий канонический обратный путь за пределами принятой рекурсивной области;
2. граница представимости произвольных циклических и разделяемых асетей одним ачислом.

## Итог

Ачисло позволяет существующей связевой структурой описать другую структуру без её немедленного создания:

```text
carrier(v₁...vₙ) = left-fold от R
des(v₁...vₙ)     = left-fold без R как операнда непустого случая

носитель ≠ денотат
поиск ≠ создание
форма скобок ≠ встроенная команда
```

Для первого физического скобочного уровня уже достаточно существующего ядра:

```text
des(a,b) = X
C(X)     = R ⟼ X
```

оба шага засвидетельствованы как точные акты **одного и того же physical source `[ab]`** и соединены точным `K` в Run.

```text
описать связь ≠ создать связь
описать несвязь ≠ сделать несвязь сущностью
```
