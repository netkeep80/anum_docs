# Ачисла и сериализация

Ачисло — корневое последовательное описание связей через **ровно четыре абита**:

```text
[ ] 1 0
```

Акорень `∞` не является пятым абитом. Он является основанием, относительно которого определены четыре корневых абита и с которого начинается каждый новый Q-контекст.

Этот документ описывает current accepted boundary MTS v0.9 и различает:

```text
QUATERNARY/Q denotation
STRING→QUATERNARY representation
source occurrence
semantic Link identity
materialization
```

## 1. Корневой базис и транспортный алфавит

Семантический корневой базис содержит пять связей:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Остенсивное чтение в метаязыке:

```text
O = O ⟼ R   # ♂∞
C = R ⟼ C   # ∞♀
```

Корневой четверичный словарь:

```text
[ -> O
] -> C
1 -> L
0 -> U
```

Поэтому необходимо различать:

```text
семантический базис: R/O/C/L/U  — 5 связей
транспортный алфавит: [ ] 1 0   — 4 абита
```

`R` не передаётся как отдельное пятое состояние линии.

## 2. Тождество абитов и связей

Semantic Link не получает новое тождество из позиции в источнике.

Например:

```text
1110
```

разрешается в значения:

```text
[L, L, L, U]
```

Три позиции `1` различаются occurrence/position structure, но все три указывают на одну semantic Link `L`.

```text
semantic Link
!= source occurrence
!= sequence position
```

## 3. Пустой поток и пустой Q-контекст

Каждый новый Q-контекст начинается относительно акорня.

Поэтому:

```text
des(ε) = R
des("") = R
des("[]") = R
```

Пустая группа `[]` **не является ошибкой**.

`[]` позволяет предъявить `R` внутри четверичного потока без пятого абита.

## 4. QState в MTS v0.9 структурен

Старый host-side `started:boolean` не является semantic authority.

Accepted structural state:

```text
QEmpty = R
QNonEmpty(inner) = start-self-closed(inner)
```

Это необходимо, чтобы различать:

```text
пустой state
```

и:

```text
непустой state, первым значением которого является R
```

без второго root instance и без скрытого boolean.

## 5. OPEN / VALUE / CLOSE / FINALIZE

Для объяснения последовательного чтения допустима операционная метанотация:

```text
Q_OPEN
Q_VALUE
Q_CLOSE
Q_FINALIZE
```

Но эти переходы в accepted v0.9 опираются на structural Q/context evidence, а не на скрытый host stack как определение семантики.

Твёрдые инварианты:

- каждый Q child начинается от structural empty state;
- `[] -> R`;
- `R` не является абитом;
- nested result возвращается родителю как одно значение;
- returned `R` не должен исчезать, если родитель хранит identity-sensitive positions;
- Q read/replay не материализует отсутствующие связи.

## 6. Nested Q внутри FORMAL

MTS v0.9 различает:

```text
Q_CLOSE
```

и:

```text
PARENT_CONTINUE
```

Закрытие Q child возвращает semantic result, а отдельный parent continuation добавляет его в прежний FORMAL ExactSequence.

Например:

```text
[]
[[]]
([[]])
```

должны сохранять явную структуру вложенности.

## 7. Метанотация результата и физические скобки

В теоретических формулах можно писать:

```text
[a]  = des("a")
[ab] = des("ab")
```

если явно понятно, что внешние brackets слева являются **метанотацией результата**, а не physical source symbols.

Это нужно отличать от физического источника:

```text
"[ab]"
```

где `[`/`]` действительно участвуют в Q OPEN/CLOSE.

## 8. Fold result

Для последовательности уже разрешённых значений результат может быть левой свёрткой:

```text
des(ε)       = R
des(a)       = a
des(a,b)     = a ⟼ b
des(a,b,c)   = (a ⟼ b) ⟼ c
```

Это определяет **result denotation**, а не универсальное identity-представление исходной последовательности.

## 9. ExactSequence отличается от fold result

Если значение `R` допустимо как явная позиция, обычный fold неинъективен:

```text
[]   -> R
[R]  -> R
```

Поэтому v0.9 использует root-safe carrier:

```text
Seq([]) = R
Cell(prev,value) = start-self-closed(prev ⟼ value)
Seq(xs + [x]) = Cell(Seq(xs),x)
```

и:

```text
Seq([]) != Seq([R])
```

без создания второго `R`.

Нужно строго различать три класса:

```text
EXACT_SEQUENCE
FOLD_RESULT
RESTRICTED_ROOTED_SEQUENCE(non-root domain)
```

## 10. Носитель, денотат и materialization

Различаются:

```text
physical/source carrier
structural carrier Link
semantic denotation
materialized record in a concrete Memory
```

То есть:

```text
carrier != denotation
describe != materialize
```

И:

```text
not found != does not exist
find != ensure/materialize
```

## 11. Materialization канонична

В текущем TypeScript `Memory`:

```text
find(A,B)   — read-only lookup
ensure(A,B) — explicit write capability
```

`ensure(A,B)`:

```text
если A ⟼ B уже присутствует -> вернуть эту же semantic Link
иначе -> materialize A ⟼ B
```

Different operation occurrences могут иметь разные traces, но semantic result одной grounded pair остаётся одним.

## 12. `R = R ⟼ R` и reuse

Из корневого selfclosure:

```text
R ⟼ R = R
```

Поэтому операция, логически требующая pair `(R,R)`, не создаёт новую Link.

Например:

```text
[][] -> R
```

не означает два semantic roots.

## 13. Два transport inputs одной ANUM semantics

Accepted baseline допускает внешний quaternary stream и уже существующий R-rooted carrier как два транспорта к одной semantic line.

Для существующего rooted sequence carrier `S` read-only unfold концептуально:

```text
S = R  -> empty
S != R -> взять end(S); продолжить через start(S)
```

с конечным достижением `R` и обращением собранных ends в прямой порядок.

Carrier-role не является новым Link type или identity.

## 14. Корневая связь как carrier и как abit — разные use roles

Например:

```text
U = C ⟼ O
```

как vocabulary value означает abit `0`.

Но та же `U`, **явно выбранная как rooted carrier**, читается структурно через start-chain и не получает singleton shortcut только потому, что она одновременно является vocabulary Link.

Это ещё один пример:

```text
same semantic Link
+ different explicit use role
!= semantic cloning
```

## 15. Carrier read-only

При чтении existing carrier:

- start-chain должна конечно прийти к `R`;
- каждый элемент четверичного carrier должен быть `O/C/L/U`;
- foreign/malformed carrier отклоняется;
- reading не materialize;
- technical storage coordinate не является semantic identity.

## 16. STRING→QUATERNARY в MTS v0.9

FORMAL source carried as exact STRING content.

MTS v0.9 принимает canonical per-byte representation:

```text
Rep_SQ(byte p) = [bbbbbbbb]
```

где:

- ровно восемь bits;
- MSB-first;
- один physical byte — один Q envelope.

Для byte `p`:

```text
Byte(p) := Denote_Q([p])
```

256 `Byte(p)` выводятся структурно из Q semantics, а не вводятся как 256 opaque runtime IDs.

## 17. Unicode не является foundation segmentation

STRING layer сохраняет exact bytes.

Не выполняются скрыто:

```text
Unicode normalization
case folding
newline rewriting
locale conversion
replacement of malformed UTF-8
```

UTF-8 interpretation — отдельный strict text layer.

Поэтому malformed byte sequence может быть валидна как exact STRING carrier и невалидна как strict UTF-8 text.

## 18. Source glyph и Q delimiter use различаются

Например byte glyph `[` имеет own per-byte carrier:

```text
[01011011]
```

Это не автоматически Q OPEN event.

Нужно explicit interpretation context:

```text
same carrier
+ STRING reading
!=
same carrier
+ QUATERNARY structural reading
```

## 19. Relative continuation — отдельный derived режим, не смысл абитов

Исторически и в baseline runtime существует чтение уже выбранной semantic sequence как continuation от explicit context prefix.

Его нужно отделять от F1 Q delimiter semantics.

В метанотации:

```text
P = parent ⟼ prefix
K = K ⟼ P
```

После того как D/G/T уже выбрали sequence values:

```text
F = (f1,...,fn)
```

можно определить fold continuation:

```text
rel_K(ε) = prefix
r0 = prefix
r(i+1) = r(i) ⟼ f(i+1)
rel_K(F) = rn
```

Это **не** означает:

```text
[ = take start of current
] = take end of current
```

и не превращает `[ ] 1 0` в navigation opcodes.

## 20. Relative continuation не является generic navigation

Завершённая derived navigation theory F6.3 отдельно определяет BEGIN/END, inverse incidence и finite path composition under explicit context.

Поэтому:

```text
relative fold continuation
!= generic navigation algebra
!= path coordinate
!= navigation converse
```

Strong claim `ANUM = navigation program` отвергнут.

## 21. Empty relative continuation и `R` position

Для derived continuation:

```text
rel_K(ε) = prefix
```

Это отличается от нового root Q reading:

```text
des(ε) = R
```

Если semantic `R` включается как явный next value, fold may collapse in special cases such as:

```text
R ⟼ R = R
```

Поэтому fold result нельзя использовать как доказательство identity исходной sequence. Для exact positional identity нужен `ExactSequence`/occurrence evidence.

## 22. Чтение и обратный анализ не пишут

Любой read/replay of carrier or continuation сохраняет:

```text
replay != materialize
find != ensure
```

Если inversion/recovery неоднозначен из-за fold collapse, checker должен вернуть отказ/unknown boundary, а не угадывать историю по runtime IDs.

## 23. Историческая версия v0.2

Исторические projection semantics и старые carrier contracts сохраняются Git history, а не current active semantics.

Старые записи:

```text
♀F / F♂
```

не определяют current selfclosure.

Остенсивные:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

остаются theory metanotation, но `♂/♀` deferred как internal F1 signs v0.9.

## 24. Экспериментальные consumers не определяют МТС

Например `netkeep80/anum_parser` может служить лабораторией.

Но результат внешней лаборатории становится частью `anum_docs` только после отдельного theory/contract/conformance lifecycle.

Implementation behavior не импортируется как теория автоматически.

## Итог

Current MTS v0.9 boundary:

```text
[ ] 1 0 — ровно четыре абита
R/∞ — основание, а не пятый абит
new Q context starts structurally empty relative to R
[] = R
QState is structural; no hidden started authority
nested Q result returns explicitly to parent
fold result != sequence identity
ExactSequence preserves explicit R positions
same semantic value may repeat in many positions
(A⟼B) canonical by grounded ordered poles
raw stream + existing carrier -> one accepted ANUM semantics
STRING→Q = one [8 bits] envelope per byte
representation != interpretation
relative fold continuation != navigation
find/read/replay != materialize/write
not found != does not exist
```

Эти инварианты должны сохраняться одновременно в normative docs, accepted contract/conformance и TypeScript implementation.
