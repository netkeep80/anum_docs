# Ачисла и сериализация

Ачисло — корневое последовательное описание связей через четыре абита:

```text
[ ] 1 0
```

Акорень `∞` не является пятым абитом: он уже присутствует как основание корневого чтения.

Главная граница:

```text
носитель ачисла ≠ денотат ≠ материализованная сеть
```

Связь поэтому можно описывать и искать, не создавая её скрыто.

См. также [Основания МТС](../theory/Основания%20МТС.md), [Формальную нотацию МТС](Формальная%20нотация%20МТС.md) и [Апамять](Апамять%20и%20управление%20сетью%20связей.md).

## 1. Корневое ядро

```text
R = ∞ = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

Остенсивно:

```text
O ≡ ♂∞
C ≡ ∞♀
```

Нужно различать пятисвязное ядро `R/O/C/L/U` и передаваемые абиты `[ ] 1 0`. `R` — основание интерпретации, а не передаваемый абит. `♂/♀` — знаки форм самозамыкания, а не дополнительные абиты.

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
```

`1` несёт корневой смысл связи, `0` — несвязи, но `L` и `U` сами являются существующими точными связями. Поэтому возможно:

```text
описание X существует
X в апамяти не существует
```

Здесь описание само является связевой структурой, но не тождественно своему денотату.

И в частности:

```text
0 ≠ DELETE_LINK
```

## 2. Метанотация не равна физическим скобкам

В исследовательских формулах:

```text
[a]  = des('a')
[ab] = des('ab')
```

внешние скобки **слева** — метанотация результата `des`, а не абиты источника. Поэтому:

```text
[ab]        = des('ab')
[[ab]]      = des('[ab]')
[[[ab]]]    = des('[[ab]]')
[[[ab]]ab]  = des('[[ab]]ab')
```

Это важно уже для одного значения:

```text
des('a')   = a
des('[a]') = R ⟼ a
```

Пустой случай:

```text
des(ε)    = R
des('[]') = R
```

Во втором случае пустое тело даёт `R`, а закрывающая корневая форма снова приводит к точному `R=R⟼R`.

## 3. Форма не является командой

Физическое `[01]` не означает:

```text
[ = PUSH
] = POP
1 = CREATE_LINK
0 = DELETE_LINK
```

Роль формы определяется конкретным чтением. Точные `O/C` могут быть выбраны границами вложенности, но из этого не следуют универсальные команды:

```text
[ → start(current)
] → end(current)
```

Число скобок также не является скрытым состоянием интерпретатора.

## 4. Историческая версия 0.2 и аксиома начала

Foundation v2 не переписывает версию 0.2 задним числом. В ней была принята проекция:

```text
[  → ♀∞
]  → ∞♂
[] → 1
][ → 0
```

а `[[` и `]]` оставались граничными формами. Историческая ориентация не меняет текущую:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

Для исторической конечной рекурсивной области использовалось `D(A B)=D(A)⟼D(B)`. Сейчас `D` уже означает **словарь**, поэтому операция денотации последовательности называется `des`.

Аксиома начала позволяет восстанавливать виртуальное начальное открытие:

```text
(O,U,L,C,L,C,U)
→ (O,O,U,L,C,L,C,U)
```

Второй `O` — повторное употребление **того же точного O**, а не новая связь той же формы. Восстановление само ничего не материализует.

## 5. Источник, словарь и подвыборка

Проверяемый путь:

```text
исходная запись
→ каноническое содержимое
→ выбранное разбиение
→ D
→ точные формы
```

Словарь может разрешить фрагмент непосредственно в любое существующее точное вхождение. Отдельный тип «ссылка на связь» не нужен; скрытого правила самого длинного совпадения нет.

Каждый выбранный сегмент уже имеет точные свидетельства `span`, `slice-content`, `lexeme`, `resolution`, `selection`. Поэтому вложенному чтению не нужна сущность `NestedSource`.

Непрерывная подвыборка представляется обычными связями:

```text
source-selection = fold(R, selection₁, ..., selectionₙ)
form-sequence    = fold(R, form₁, ..., formₙ)
G ⟼ form-sequence
T ⟼ form-sequence
```

Доверенная проверка сначала воспроизводит полный источник, затем эту подвыборку. Номера сегментов — лишь координаты проверяющей программы. Пустая подвыборка использует точный `R`.

## 6. Две левые свёртки

Носитель включает `R` как начальное значение:

```text
carrier(ε)     = R
carrier(a)     = R ⟼ a
carrier(a,b)   = (R ⟼ a) ⟼ b
carrier(a,b,c) = ((R ⟼ a) ⟼ b) ⟼ c
```

То есть `carrier(v₁...vₙ)` — левая свёртка от `R`.

Десериализация не использует `R` как операнд непустой свёртки:

```text
des(ε)     = R
des(a)     = a
des(a,b)   = a ⟼ b
des(a,b,c) = (a ⟼ b) ⟼ c
```

Поэтому:

```text
C_ab = carrier(a,b) = (R ⟼ a) ⟼ b
X    = des(a,b)     = a ⟼ b
C_ab ≠ X
```

Каждый шаг явной материализации создаёт новое точное вхождение, даже если такие полюса уже существуют.

Ранние лабораторные названия `pass` и `enc` больше не нужны:

```text
des(v) = v
C = R ⟼ C
C(v) → R ⟼ v
```

Одноэлементный `des` возвращает то же точное значение без эффекта, а `R⟼v` уже выражается обычным шагом отношения с одним открытым полюсом для точной корневой формы `C`.

Если текущий контекст уже содержит префикс `P`, выбранный хвост продолжает ту же левую свёртку:

```text
K.current = P
continuation(P; a,b) = (P ⟼ a) ⟼ b
```

Доверенная проверка продолжения ничего не создаёт: она проверяет уже существующую точную цепочку от `K.current`.

## 7. Глубина сохраняется до интерпретации

Точная группировка различает:

```text
[ab]   → Group(a,b)
[[ab]] → Group(Group(a,b))
```

Скрытый счётчик глубины не нужен: вложенность уже засвидетельствована последовательностью точных `O/C`.

Граница определяется **точным тождеством O/C**. Связь с теми же полюсами остаётся обычным значением.

Группировка сама не устанавливает, какие закрывающие `C` должны стать актами отношения. Это задаётся выбранным Run и его точными свидетельствами.

## 8. Проверенные физические чтения

### `[ab]`

Один физический источник разрешается и группируется:

```text
'[ab]'
→ (O,a,b,C)
→ Group(a,b)
```

Два акта того же источника:

```text
A₁: des(a,b) = X = a ⟼ b
A₂: C(X) = R ⟼ X
```

с точной непрерывностью `K₀→K₁→K₂` дают:

```text
des('[ab]') = R ⟼ (a ⟼ b)
```

То есть в пользовательской метанотации:

```text
[[ab]] = R ⟼ (a ⟼ b)
```

### `[[ab]]`

Пусть словарь разрешает `ab` сразу в существующий носитель:

```text
C_ab = carrier(a,b) = (R ⟼ a) ⟼ b
```

Тогда выбранное чтение физического источника:

```text
'[[ab]]'
→ (O,O,C_ab,C,C)
→ Group(Group(C_ab))
```

может иметь Run:

```text
A₁: des(C_ab) = C_ab
A₂: внешний C(C_ab) = P = R ⟼ C_ab
```

Итого:

```text
des('[[ab]]') = R ⟼ carrier(a,b)
```

или:

```text
[[[ab]]] = R ⟼ carrier(a,b)
```

Два закрывающих сегмента имеют разные точные `selection`, хотя оба разрешаются в один корневой `C`. Если применить как акты отношения оба закрытия, получится другая точная структура:

```text
R ⟼ P
```

Она не смешивается с результатом выбранного Run.

### `[[ab]]ab`

После предыдущих двух актов `K.current=P`. Остаток источника становится обычным продолжением последовательности:

```text
P = R ⟼ C_ab
P ⟼ a
(P ⟼ a) ⟼ b
```

Поэтому один Run того же физического источника:

```text
A₁: des(C_ab) = C_ab
A₂: внешний C(C_ab) = P
A₃: continuation(P; a,b) = (P ⟼ a) ⟼ b
```

даёт:

```text
des('[[ab]]ab') = (P ⟼ a) ⟼ b
```

Это соответствует пользовательской формуле `[[[ab]]ab]`.

## 9. Смешанная вложенность и точные дубликаты

Для `ab[ab]`, если внутреннему телу выбран `des`:

```text
X_inner = a ⟼ b
X_outer = a ⟼ b
X_inner ≠ X_outer
result = X_outer ⟼ X_inner
```

Совпадение полюсов не означает точного тождества. Интернирование пар не является семантическим законом.

Таким образом, вложенный результат после выбранного Run становится обычным точным значением внешнего уровня. Внешняя последовательность может продолжаться от него тем же механизмом, что и от любого другого `K.current`.

## 10. Относительное чтение как точный акт

Один источник может участвовать в разных актах `A`:

```text
source
source-selection
form-sequence
D / G / T
K_before
form / binding
result
K_after
```

Два акта могут иметь общий источник, но разные подвыборки, `G/T`, последовательности форм и результаты:

```text
A₁ ≠ A₂
```

Доверенная проверка требует ровно одно ожидаемое точное значение каждой обязательной роли; отсутствие, дубль или подмена отвергаются.

Относительность поэтому находится в **отношении источник ↔ конкретный засвидетельствованный акт чтения**, а не в скрытом режиме. Поиск может предложить акт; доверенная часть только воспроизводит предъявленные свидетельства.

## 11. Поиск и хранение

```text
не найдено ≠ не существует
find ≠ materialize
```

Существующий носитель может описывать искомую связь без её появления в апамяти.

При долговременном хранении различаются оперативная ссылка, логический идентификатор, номер в снимке и физический адрес. Физический адрес не является смысловым тождеством связи. Подробнее: [Апамять](Апамять%20и%20управление%20сетью%20связей.md).

## 12. Текущая граница

Проверенная лестница:

```text
сырой носитель
→ полный точный источник
→ D и сегменты
→ точные формы
→ восстановление начала при необходимости
→ точная O/C-группировка
→ точные подвыборки источника
→ конкретные акты
→ des / шаг отношения / продолжение свёртки
→ точный Run
```

`SequenceAtom`, `SequenceGroup`, `SequenceDescription` и `OccurrenceRef` — машинные носители проверки, а не новые онтологические типы.

Уже не требуются как новые сущности или операции:

```text
NestedSource
RelativeContext
Quote
pass
enc
PUSH / POP
скрытый счётчик глубины
интернирование пар
```

Конкретные примеры `ε`, `a`, `ab`, `[ab]`, `ab[ab]`, `[[ab]]` и `[[ab]]ab` уже согласованы с этим каркасом.

Главная следующая граница — **общий рекурсивный закон построения выбранного Run из произвольной вложенной группировки**. Он должен объяснять без скрытого состояния:

1. какая подвыборка становится внутренним чтением;
2. какие точные закрывающие `C` становятся актами отношения, а какие остаются только структурными свидетельствами;
3. как точный результат вложенного Run становится значением внешнего уровня;
4. как внешний уровень продолжает левую свёртку;
5. как один и тот же источник допускает альтернативные, но явно засвидетельствованные чтения.

Пока такой общий генератор Run не принят, проверенные примеры нельзя превращать в контекстно-независимый opcode квадратных скобок.

Также остаются открыты общий канонический обратный путь за пределами принятой рекурсивной области и граница представимости произвольных циклических/разделяемых асетей одним ачислом.

## Итог

```text
carrier(v₁...vₙ) = левая свёртка от R
des(v₁...vₙ)     = левая свёртка без R как операнда непустого случая

носитель ≠ денотат
поиск ≠ создание
форма скобок ≠ встроенная команда
```

Вложенная группа возвращает точное значение через выбранный Run. После этого внешняя последовательность работает с ним как с любым другим точным `K.current`.

```text
описать связь ≠ создать связь
описать несвязь ≠ сделать несвязь сущностью
```
