# Ачисла и сериализация

Этот документ задаёт текущее принятое предметное определение ачисел в МТС v0.12. Исторические версии сохраняются в Git и не образуют слой, который требуется мысленно накладывать на текст ниже.

Ачисло — роль Связи, используемая для точного укоренённого представления последовательности и адреса. Ачисло не является отдельной онтологической сущностью.

Связанные нормативные поверхности:

- [Система аксиом МТС](../theory/Система%20аксиом%20МТС.md) — корневой базис, тождество Связи, роли и граница чтение/изменение;
- [Основания МТС](../theory/Основания%20МТС.md) — объяснение этих фундаментальных положений;
- [Формальная нотация МТС](Формальная%20нотация%20МТС.md) — выбор интерпретатора и смысловые полномочия;
- [Апамять и управление сетью связей](Апамять%20и%20управление%20сетью%20связей.md) — состояния результата чтения и граница конкретной памяти;
- [CONTRIBUTING](../CONTRIBUTING.md) — процесс проверки и принятия изменений.

## 1. Корневой базис и четыре абита

Корневые Связи `R/O/C/L/U` определяются системой аксиом, прежде всего A5. Этот документ не переопределяет их уравнения, а задаёт их использование в транспортном представлении ачисла.

Транспортный алфавит содержит ровно четыре абита:

```text
[ ] 1 0
```

Их корневые значения:

```text
[ -> O
] -> C
1 -> L
0 -> U
```

Акорень:

```text
R = ∞
```

не является пятым абитом. Новый локальный контекст начинается относительно `R`, а не кодирует `R` дополнительным знаком.

<a id="mts-law-rootBasisBoundary"></a> <!-- нормативный владелец -->
Операция, принимающая объявленный `RootBasis`, обязана до записи структурно подтвердить `R/O/C/L/U`, включая остенсивное различение `O` и `C` относительно `R`. Схлопнутый, поддельный или чужой базис отклоняется.

Повтор абита означает повтор позиции, а не создание новой смысловой Связи. Например:

```text
1110 -> [L, L, L, U]
```

Три позиции `1` являются тремя вхождениями одной Связи `L`.

## 2. Точное ачисло, последовательность и результат свёртки

<a id="mts-law-exactAnumRooting"></a> <!-- нормативный владелец -->
Каждое локальное точное ачисло укоренено в `R`. Точное ачисло, последовательность его явных позиций, результат свёртки и адресуемая цель — разные отношения.

Для уже разрешённых значений результат левой свёртки можно записывать как:

```text
des(ε)       = R
des(a)       = a
des(a,b)     = a ⟼ b
des(a,b,c)   = (a ⟼ b) ⟼ c
```

Эта запись задаёт денотат результата, но не тождество исходной последовательности.

Причина существенна уже для `R`:

```text
[]  -> R
[R] -> R
```

Одинаковый результат свёртки не означает одинаковый точный носитель. Для сохранения явных позиций используется укоренённая точная последовательность:

```text
Seq([]) = R
Cell(prev,value) = start-self-closed(prev ⟼ value)
Seq(xs + [x]) = Cell(Seq(xs),x)
```

Поэтому:

```text
Seq([]) != Seq([R])
```

Нормативно различаются как минимум:

```text
EXACT_SEQUENCE
FOLD_RESULT
ADDRESSED_TARGET
```

Физическая координата хранения также не является тождеством Связи.

## 3. Четверичный контекст `Q`

Пустой четверичный поток разрешается к корню:

```text
des(ε) = R
des("") = R
des("[]") = R
```

Пустая группа `[]` тем самым предъявляет `R` без пятого абита.

Состояние `Q` задаётся структурой, а не скрытым флагом языка реализации:

```text
QEmpty = R
QNonEmpty(inner) = start-self-closed(inner)
```

Это позволяет различать пустое состояние и непустое состояние, первым явным значением которого является `R`, без создания второго корня.

<a id="mts-law-quaternaryNestedContext"></a> <!-- нормативный владелец -->
Конструкция `Q [...]` является рекурсией собственного контекста `I_Q`. Дочерний контекст начинается от `R`, возвращает родителю ровно одно значение-Связь и не выбирается строковым или формальным режимом по эвристике хоста.

Для объяснения переходов допустима метанотация:

```text
Q_OPEN
Q_VALUE
Q_CLOSE
Q_FINALIZE
```

Она не вводит скрытый стек как смысловое основание.

Обязательные свойства:

- новый дочерний контекст начинается с пустого структурного состояния;
- `[] -> R`;
- `R` не является абитом;
- результат дочернего контекста возвращается как одно значение;
- явная позиция `R` не теряется;
- чтение и проверка не материализуют Связи.

Внешние скобки в математической метанотации результата следует отличать от физических знаков источника. Запись результата вида:

```text
[a] = des("a")
```

не означает, что печатные `[` и `]` обязательно присутствовали во входе.

## 4. Чтение существующего укоренённого носителя

Четверичный поток и уже существующий укоренённый связевой носитель являются двумя транспортами одной линии чтения.

Для существующего носителя `S` чтение только для чтения концептуально имеет вид:

```text
S = R  -> empty
S != R -> взять end(S); продолжить через start(S)
```

Цепочка начал должна конечно прийти к `R`; собранные концы затем обращаются в прямой порядок.

При проверке существующего четверичного носителя:

- каждый элемент должен разрешаться к `O/C/L/U`;
- посторонняя или повреждённая форма отклоняется;
- чтение не создаёт отсутствующие Связи;
- технический адрес хранения не используется как смысловое тождество.

Одна Связь может играть разные явно выбранные роли. Например, `U` как значение словаря обозначает абит `0`, но та же Связь, явно предъявленная как укоренённый носитель, читается по своей цепочке начала. Совпадение объекта не подменяет роль.

## 5. `Resolve` и `MATERIALIZE_TARGET`

<a id="mts-law-resolveMaterializeSeparation"></a> <!-- нормативный владелец -->
Разрешение точного адреса и материализация адресуемой цели являются разными возможностями.

```text
Resolve              = чтение
MATERIALIZE_TARGET   = разрешённая запись
```

`Resolve` не создаёт отсутствующую цель. Результаты чтения `UNINTERPRETABLE`, `NOT_FOUND` и `FOUND(X)` определяются нормативно в [спецификации апамяти](Апамять%20и%20управление%20сетью%20связей.md#mts-law-knowledgeStateSeparation). <!-- ссылка:mts-law-knowledgeStateSeparation -->

<a id="mts-law-targetMaterializationBound"></a> <!-- нормативный владелец -->
И `Resolve`, и `MATERIALIZE_TARGET` снимают ровно один начальный уровень `R` по всей иерархии точного адреса. Оставшаяся косвенность сохраняется.

`MATERIALIZE_TARGET` получает право записи только после полной проверки точного адресного свидетельства. Ошибка не должна оставлять частичных целевых записей.

Принятая v0.12 не вводит произвольную глубину среза. Возможный будущий режим `CUT_DEPTH=N` находится вне текущей нормы.

Общая граница чтения и изменения задаётся системой аксиом; здесь фиксируется только её применение к адресу ачисла.

## 6. Строковое ачисло и байты

<a id="mts-law-v012StringByteIdentity"></a> <!-- нормативный владелец -->
В v0.12 байт является точным восьмибитным ачислом:

```text
Byte_v012(p) = Anum(bits8(p))
             = Resolve_Q([bits8(p)])
```

Внутри байтового конверта ровно восемь бит, старший бит первым. Все 256 байтов выводятся из четверичной структуры, а не вводятся непрозрачными техническими идентификаторами.

Точный `StringAnum_v012` — последовательность таких байтовых ачисел. Четверичный носитель байтов не является внешней упаковкой поверх строки: это её точная связевая иерархия.

<a id="mts-law-utf8CarrierBoundary"></a> <!-- нормативный владелец -->
Чтение UTF-8 выполняется поверх точных байтов и не переписывает топологию носителя.

Скрыто не выполняются:

```text
Unicode normalization
case folding
newline rewriting
locale conversion
lossy malformed-byte replacement
```

Повреждённая последовательность может оставаться допустимым точным набором байтов и при этом отклоняться как текст UTF-8.

<a id="mts-law-stringNestedAnum"></a> <!-- нормативный владелец -->
В контексте `STRING` конструкция `[...]` открывает дочерний `I_STRING` от `R` и возвращает родителю ровно одно значение-Связь. Вложенность хранится структурой ачисла, а не скрытым стеком анализатора.

<a id="mts-law-stringOneVsQOne"></a> <!-- нормативный владелец -->
Печатный строковый знак `1` является UTF-8-знаком `1`. Значение `1` в контексте `Q` является абитом `L`. Совпадение написания не отождествляет эти роли.

## 7. Представление не выбирает интерпретацию

<a id="mts-law-representationNotInterpretation"></a> <!-- нормативный владелец -->
Точный носитель сам по себе не выбирает смысловой интерпретатор.

Например, физический знак `[` имеет собственный байтовый носитель:

```text
[01011011]
```

Наличие такого носителя не означает автоматического выполнения операции открытия `Q`.

```text
один носитель + строковое чтение
!=
тот же носитель + четверичное чтение
```

Выбор `I_STRING`, `I_Q` или `I_FORMAL` задаётся смысловым контекстом. Его нормативные правила находятся в [формальной нотации](Формальная%20нотация%20МТС.md#mts-law-interpreterSeparation). <!-- ссылка:mts-law-interpreterSeparation -->

Тем самым граница этого документа проходит по точному носителю, его чтению и адресной материализации; выбор смыслового действия принадлежит интерпретационному слою.

## 8. Производный режим относительного продолжения

Относительное продолжение не является определением ачисла и не изменяет четыре абита. Это производный режим, допустимый после того, как словарь, грамматика и теория уже выбрали конечную последовательность значений:

```text
F = (f1,...,fn)

P = parent ⟼ prefix
K = K ⟼ P

rel_K(ε) = prefix
r0 = prefix
r(i+1) = r(i) ⟼ f(i+1)
rel_K(F) = rn
```

Нужно сохранять различия:

```text
относительная свёртка
!= общая навигация
!= координата пути
!= обратное отношение навигации
```

Пустое относительное продолжение:

```text
rel_K(ε) = prefix
```

не совпадает с новым корневым чтением:

```text
des(ε) = R
```

Если следующим значением является `R`, результат свёртки в специальном случае может схлопнуться из-за `R = R ⟼ R`. Поэтому обратная проверка не должна угадывать историю последовательности по техническим идентификаторам.

## 9. Примеры следствий

Корневая пара переиспользуется:

```text
R ⟼ R = R
```

Следовательно, повторное получение пары `(R,R)` не создаёт новую смысловую Связь.

Сходным образом одинаковый денотат двух чтений не доказывает равенство их точных носителей.

При любом воспроизведении сохраняется граница:

```text
replay != materialize
find   != ensure
```

То, что запись не найдена в конкретной памяти, не является доказательством несуществования Связи в МТС.

## 10. Историческая граница

До v0.12 использовались формулировки `Byte_v09` и отдельные описания вложенного `Q` внутри `FORMAL`. Они важны как история развития, но не определяют текущую норму и не должны применяться поверх разделов 1–9.

Текущая норма использует `Byte_v012`, явные интерпретационные контексты и точное разделение носителя, денотата и полномочия действия.

Старые записи вида `♀F / F♂` также не определяют текущую семантику самозамыкания. Историческое происхождение и прежние формулировки доступны через историю Git.

Экспериментальные реализации, включая внешние лаборатории, не становятся частью МТС автоматически. Процесс проверки и принятия таких изменений описан в [CONTRIBUTING](../CONTRIBUTING.md).

## Итог

Текущее определение ачисел v0.12 сводится к следующим границам:

- `[ ] 1 0` — ровно четыре абита;
- `R/∞` — корневое основание, а не пятый абит;
- каждое локальное точное ачисло укоренено в `R`;
- точная последовательность не тождественна результату свёртки;
- точный носитель не тождествен адресуемой цели;
- вложенный `Q` является рекурсией `I_Q`;
- `Resolve` читает, `MATERIALIZE_TARGET` получает отдельное право записи;
- обе адресные операции выполняют ровно один корневой срез;
- объявленный корневой базис проверяется до записи;
- строка состоит из точных восьмибитных байтовых ачисел;
- UTF-8 является отдельным строгим слоем чтения;
- одинаковый печатный знак не отождествляет строковую и четверичную роли;
- представление не выбирает интерпретатор;
- производная относительная свёртка не переопределяет ачисло и не является общей навигацией.

Эти границы должны одновременно сохраняться в нормативной документации, принятом контракте, корпусе соответствия и реализации.
