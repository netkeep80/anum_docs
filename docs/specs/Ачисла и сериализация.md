# Ачисла и сериализация

Статус: актуальное, нормативное для формата `*.anum`; протокольные проекции, явно отмеченные как рабочие, остаются experimental.

Уровень: **L3 — сериализация**.

Граница L2/L3/L4 задаётся [Reference model МТС v0.1](Reference%20model%20МТС%20v0.1.md).

## Ачисло

Ачисло — сериализационный носитель описания связи/структуры, представленный последовательностью абитов и интерпретируемый в явном ассоциативном контексте.

Базовый четверичный алфавит L3:

```text
[ ] 1 0
```

Совпадение glyph `[` и `]` с квадратной нотацией L2 не означает их автоматического тождества. Формулы корневой системы:

```text
([) : (♀∞)
(]) : (∞♂)
[1] : (⟼)
[0] : (↛)
```

принадлежат L2 и вводят формальные чтения квадратных знаков/форм. Конкретная протокольная проекция L2 ↔ L3 должна задаваться отдельно.

`0` не означает отсутствия связи в натуре. На уровне L3 это один из четырёх абитов; его нормативная связь со смыслом несвязи задаётся корневой системой, а рабочая стрелочная реализация протокола исследуется отдельно.

## Рабочий протокол issue #61

[Протокол абитов ачисел](<Протокол абитов ачисел.md>) содержит экспериментальную проекцию, реализованную текущим прототипом.

В частности, текущий prototype исследует:

```text
[] -> 0
][ -> 1
```

Эта проекция имеет статус `experimental` в reference model v0.1. Она не заменяет корневой fixture и не переносится в него автоматически.

Документ issue #61 исторически использует ориентацию полюсов `∞♀ / ♂∞`, тогда как активная L1/L2 reference model использует `♀F / F♂`. До отдельной миграции в #71 это **не нормативное равенство уровней**, а локальная гипотеза прототипа.

## Формат `*.anum`

Контейнерный формат поддерживает два явно различённых режима:

```text
# anum-format: quaternary
# anum-format: string
```

Без заголовка файл читается как `quaternary`.

### Quaternary

Значащими являются только четыре абита:

```text
[ ] 1 0
```

Пробелы, переводы строк и комментарии `# ...` игнорируются. Любой другой символ является ошибкой.

Raw parser не применяет обычную балансировку скобок:

```text
][
[[
]]
[]
```

являются допустимыми последовательностями абитов на уровне синтаксического чтения L3.

Семантическая валидность ачисла и `project_K` не должны скрыто зашиваться в raw parser; их разделение является следующим этапом протокола.

### String

`# anum-format: string` сохраняет человекочитаемый символический носитель как `AnumSource`. Он не передаётся strict quaternary parser и не считается уже скомпилированным четверичным ачислом.

Имена вроде:

```text
window
position
int
boolean
```

не являются дополнительными абитами. Канонический dictionary layer ещё должен быть определён отдельно.

## UTF-8 payload codec

`converters/text_to_anum.py` и `converters/anum_to_text.py` кодируют и декодируют UTF-8 payload:

```text
hello -> [01101000][01100101][01101100][01101100][01101111]
```

Этот codec не является десериализатором связей и не смешивается со string symbolic anum.

## Актуальные модули L3

```text
core/anum_model.py        модели абитов и источников
core/anum_parser.py       raw parser и нормализация *.anum
core/anum_projector.py    экспериментальная проекция двухабитных форм
converters/anum_cli.py    CLI прототипа
```

`core/anum_memory.py` находится на границе с L4 и является только тестовой symbolic-моделью протокольных инвариантов, а не частью нормативной модели хранения.

## Граница с L4

Reference model требует:

```text
raw(A) — носитель ачисла
den(A) — описываемая связь/структура
```

и фиксирует инварианты будущего execution layer:

```text
load(A)    не создаёт den(A)
find(A)    не создаёт den(A)
realize(A) может явно материализовать den(A)
```

Это **L4-контракт**, приведённый здесь только для определения границы сериализации. Реализация настоящей апамяти не входит в L3.

## CLI

```bash
python -m converters.anum_cli parse examples/anum/two_abit_forms.anum
python -m converters.anum_cli project examples/anum/two_abit_forms.anum
python -m converters.anum_cli normalize examples/anum/utf8_payload_hello_quaternary.anum
python -m converters.anum_cli realize examples/anum/string_symbolic_link.anum
```

Команда `realize` текущего CLI использует тестовую symbolic-модель и не означает, что L4 уже реализован как production memory.
