# Ачисла и сериализация
<!-- версия документа МТС; mts-doc-version: v0.14 -->
> **Версия МТС: v0.14**

Этот документ владеет **последовательностными представлениями** МТС: `Anum`, `ExactSequence`, `Q`, `STRING` и UTF-8 boundary. Рекурсивный структурный алфавит `8/9/6/1` здесь только используется как нижележащий слой и не называется Anum/абитами.

## 1. Что изменилось в v0.14

Главное разделение:

```text
Link structure:
  8 / 9 / 6 / 1
  = recursive MTS alphabet

Sequence representation:
  Anum
  ExactSequence
  Q

Text/bytes:
  STRING
  UTF-8
```

То есть старое выражение «структурное ачисло» больше не является current-термином.

<a id="mts-law-rootBasisBoundary"></a> <!-- исторический стабильный якорь -->

## 2. Рекурсивный алфавит — не Anum

Рекурсивный префиксный codec Link:

```text
S ::= 8 | 9 S | 6 S | 1 S S
```

После ориентации Context:

```text
8 = ROOT
9 = START_K
6 = END_K
1 = PAIR
```

Примеры структурного codec:

```text
R = 8
O = 98
C = 68
L = 19868
U = 16898
```

Это codec **одной Link-структуры**. Он не является последовательностью Link и не определяет Anum.

## 3. Anum и ExactSequence

<a id="mts-v014-v14-l13"></a>
<!-- мтс:требование:V14-L13:начало -->
> **МТС `V14-L13`** · вид `semantic-law` · класс `representation/anum/sequence-semantics` · источник `contracts/mts-contract-v0.14.json#/requiredSemanticLaws/V14-L13` · отпечаток `2702db9169c1f2ae` · свидетельства +1/-2 · проверок 3 · трассировка `traceability/mts-v0.14.json`.
<!-- мтс:требование:V14-L13:конец -->

**Anum** — укоренённое компактное представление/кодирование **последовательности Links**.

**ExactSequence** — канонический носитель точной позиционной последовательности.

Критическая граница:

```text
ExactSequence identity ≠ fold denotation
```

Например, две разные последовательности могут иметь одинаковый результат некоторого fold/интерпретатора, но это не делает сами последовательности тождественными.

Также:

```text
recursive Link codec ≠ Anum
Q                    ≠ recursive Link codec
```

## 4. Локальное укоренение

Каждый локальный sequence-context начинается от `R`.

Корень здесь не является «первым значением массива». Он задаёт структурное начало локального носителя последовательности.

Пустая `ExactSequence` и `R` как Link — разные уровни описания: первое относится к последовательностному carrier, второе — к структуре Link.

## 5. Q14 и immutable Q13

<a id="mts-v014-v14-l3"></a>
<!-- мтс:требование:V14-L3:начало -->
> **МТС `V14-L3`** · вид `semantic-law` · класс `representation/anum/q14-version-separation` · источник `contracts/mts-contract-v0.14.json#/requiredSemanticLaws/V14-L3` · отпечаток `d7ffc847cbac68fd` · свидетельства +1/-3 · проверок 1 · трассировка `traceability/mts-v0.14.json`.
<!-- мтс:требование:V14-L3:конец -->

Текущий source-alphabet Q14:

```text
[ ] T F
```

Исторический immutable Q13:

```text
[ ] 1 0
```

Правила совместимости:

- Q14 **не принимает** `1/0` как свой source alphabet;
- Q13 **не принимает** `T/F`;
- mixed source запрещён;
- допускается только **явный versioned transcode**;
- transcode сохраняет денотацию, но не обязан сохранять точное строковое тождество.

## 6. Зачем Q существует отдельно

Q — versioned sequence codec/interpreter. Его задача — не кодировать четыре структурных формы Link, а интерпретировать последовательностный source в рамках конкретной версии Q.

Поэтому совпадение числа символов у двух алфавитов ничего не говорит об их смысловом тождестве.

```text
recursive alphabet: structural aspect of Link
Q alphabet:         source/interpreter alphabet
```

## 7. Resolve и materialize

<a id="mts-law-resolveMaterializeSeparation"></a> <!-- исторический стабильный якорь -->

`Resolve` и materialization разделены:

```text
resolve      = найти/проверить существующее структурное значение
materialize  = создать недостающую допустимую структуру
```

Чтение не должно скрыто превращаться в запись.

<a id="mts-law-targetMaterializationBound"></a> <!-- исторический стабильный якорь -->

Материализация ограничивается выбранным target/контекстом. Наличие похожей структуры где-то в памяти не даёт ей автоматически authority для текущего sequence-context.

## 8. STRING и точные байты

<a id="mts-term-string"></a>
<a id="mts-law-stringByteIdentity"></a> <!-- исторический стабильный якорь -->
<a id="mts-law-L11"></a> <!-- исторический стабильный якорь -->

`STRING` находится уровнем выше sequence codecs и ниже symbolic metanotation.

Для строкового носителя:

```text
identity = exact bytes
```

Unicode normalization не используется как скрытое правило семантического тождества.

<a id="mts-law-utf8CarrierBoundary"></a> <!-- исторический стабильный якорь -->

UTF-8 — транспорт/byte boundary. Он не создаёт новую онтологическую сущность.

<a id="mts-law-stringNestedAnum"></a> <!-- исторический стабильный якорь -->

Вложенные Anum/sequence structures могут быть представлены строковым carrier, но STRING не становится самим Link и не подменяет sequence identity.

<a id="mts-law-stringOneVsQOne"></a> <!-- исторический стабильный якорь -->

Символ `"1"` как байтовая строка, legacy Q13 token `1` и структурный символ `1 = PAIR` принадлежат разным слоям. Совпадение глифа не даёт смыслового равенства.

## 9. Физическая граница хранения

<a id="mts-law-L13"></a> <!-- исторический стабильный якорь -->

v0.14 **не требует**, чтобы физический процессор имел четыре opcode `8/9/6/1`.

Реализация обязана сохранять четыре различимых структурных случая Link, но может использовать:

- одну generic Link-forming operation;
- специализированные fast paths;
- packed bits;
- таблицы;
- GPU buffers;
- другой внутренний ISA.

Техническая форма хранения не становится authority теории.

## 10. Представление не выбирает интерпретацию

<a id="mts-law-representationNotInterpretation"></a> <!-- исторический стабильный якорь -->

Один и тот же sequence carrier может участвовать в разных теориях/интерпретаторах.

Следовательно:

```text
carrier != interpreter
description != use
bytes != meaning
```

Интерпретационный authority должен быть явным.

## 11. Отношение к FORMAL

FORMAL — следующий слой:

```text
Anum / ExactSequence / Q
        ↓
STRING / UTF-8
        ↓
names / Dictionary / Grammar / Theory / FORMAL
```

FORMAL может ссылаться на sequence representations, но не владеет их внутренней семантикой.

См. [«Формальная нотация МТС»](Формальная%20нотация%20МТС.md).

## 12. Инверсия и последовательности

Рекурсивная инверсия `J` определена на Link-структуре. Для sequence representations её действие должно быть **явно поднято** на элементы/позиции соответствующего carrier.

Нельзя молча отождествлять:

```text
J(Link)
J(Anum)
reverse(sequence)
swap tokens
```

Это разные операции, пока их эквивалентность не задана конкретным codec/interpreter.

## 13. Сводка

```text
Link ontology
    ↓
recursive structural alphabet 8/9/6/1
    ↓
recursive Link codec

sequence layer:
    Anum
    ExactSequence
    Q14 [ ] T F
    legacy Q13 [ ] 1 0

byte/text:
    STRING
    UTF-8

symbolic layer:
    FORMAL
```

Главная дисциплина v0.14: **структурный аспект Link, последовательность Link, source-codec и текстовый carrier больше не называются одним и тем же словом.**
