# Ачисла и сериализация

Ачисло — корневое последовательное описание связей через четыре абита:

```text
[ ] 1 0
```

Акорень `∞` не является пятым абитом. Последовательность всегда понимается как начинающаяся от него.

Главная граница:

```text
носитель ачисла
≠ описываемая связь
≠ материализованная сеть
```

Связь можно описать, найти или не найти, не создавая её скрыто. При этом сам носитель, как всё существующее в МТС, также является связевой структурой.

## 1. Корневые абиты

Пятисвязное ядро:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

Поэтому `[ ] 1 0` — корневые абиты ачисел, а не четыре внешних команды вычислителя.

Остенсивно:

```text
O = O ⟼ R ≡ ♂∞
C = R ⟼ C ≡ ∞♀
```

Знаки `♂` и `♀` относятся к формам самозамыкания и не являются дополнительными абитами.

### 1.1. Связь и несвязь

Корневые связи `L` и `U` имеют противоположную ориентацию:

```text
1 → L = O ⟼ C
0 → U = C ⟼ O
```

`1` несёт корневой смысл связи, `0` — корневой смысл несвязи. Но оба являются существующими точными вхождениями связи.

Нужно различать:

```text
несвязь                        отсутствие связности
U                              связь, несущая смысл несвязи
0                              абит, указывающий на U
описание отсутствующей связи   существующая связевая структура
```

Поэтому возможно:

```text
описание X существует
X в апамяти не существует
```

Описание само является связевой структурой, но не тождественно своему денотату.

Абит `0` не является встроенным удалением:

```text
0 ≠ DELETE_LINK
```

Удаление возможно только как отдельно определённое правило и конкретный акт интерпретации.

## 2. Абиты не являются командами

Из записи:

```text
[01]
```

самой по себе не следуют команды:

```text
[ = PUSH
] = POP
1 = CREATE_LINK
0 = DELETE_LINK
```

Роль формы определяется выбранным режимом интерпретации и точными свидетельствами этого режима.

Это особенно важно для скобок: корневые `O` и `C` могут играть роль границ вложенной десериализации, но такая роль не является вторым врождённым смыслом связей `O` и `C`.

## 3. Принятая историческая граница версии 0.2

Текущий кандидат не переписывает принятую версию 0.2 задним числом.

### 3.1. Корневая проекция

В версии 0.2 принята проекция:

```text
[  → ♀∞
]  → ∞♂
[] → 1
][ → 0
```

Формы:

```text
[[
]]
```

остаются допустимыми граничными носителями без дополнительного значения `0` или `1`.

Это историческое чтение проекций не меняет текущую остенсивную ориентацию:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

### 3.2. Три режима версии 0.2

Принятый протокол различает:

```text
root
quote
relative
```

Корневой режим применяет принятую корневую проекцию и рекурсивное чтение на своей области.

Режим цитирования снимает ровно одну настоящую внешнюю пару скобок и возвращает содержимое как данные. Отдельная онтологическая сущность для цитаты не требуется.

Общая относительная семантика в версии 0.2 намеренно не определена: такой носитель остаётся сырым.

### 3.3. Принятая рекурсивная область

Для конечного дерева действует грамматика:

```text
Atom  := 0 | 1
Value := Atom | '[' Pair ']'
Pair  := Value Value
Root  := Atom | Pair
```

и структурное правило:

```text
D(A B) = D(A) ⟼ D(B)
```

Это не универсальное тождество произвольной асети. Древовидное описание в общем случае не сохраняет совместное использование, произвольные циклы и различие нескольких точных вхождений одной формы.

## 4. Аксиома начала

В начале ачисла физически представимо только одно открытие, поэтому несколько начальных открытий могут схлопываться.

Исторический пример:

```text
развёрнуто:   [[01]1]0
канонически:  [01]1]0
```

В текущем кандидате та же граница воспроизводится после разрешения исходной записи в точные формы.

Например:

```text
(O, U, L, C, L, C, U)
→ (O, O, U, L, C, L, C, U)
```

Недостающее открытие не создаёт новую связь. Это второе употребление **того же точного `O`** как виртуальной начальной границы.

Восстановление допустимо только если последовательность действительно начинается с выбранного точного `O`. Другая связь с теми же полюсами не получает эту роль автоматически.

Восстановление ничего не материализует и само не определяет вложенность. После него отдельная проверка скобочной структуры должна подтвердить корректность результата.

## 5. Сырой носитель и разрешённые значения

Физический четверичный носитель остаётся последовательностью:

```text
[ ] 1 0
```

Строковые имена или иной внешний текст не становятся новыми абитами. Они находятся выше четверичного основания и должны разрешаться явно.

В текущем кандидате словарь может связать фрагмент исходной записи непосредственно с **любым существующим точным вхождением связи**:

```text
фрагмент исходной записи
→ D
→ точная связь A
```

Поэтому отдельный онтологический тип «ссылка на связь» на разрешённом уровне не требуется.

Одна и та же запись может разрешаться по-разному в разных явно выбранных словарях. Скрытого правила «самое длинное совпадение всегда побеждает» нет.

## 6. Значения последовательностной десериализации

После разрешения исходной записи внешний десериализатор работает только со связями.

Практически различаются два способа получить значение:

```text
уже существующая точная связь
→ та же точная связь

вложенная последовательность
→ вложенная десериализация
→ точная связь-результат
```

Это не два вида существующего. В обоих случаях наружу передаётся связь.

Следовательно, уже существующая полная связь может быть обычным элементом последовательности наравне с результатом вложенного запуска.

Например:

```text
P = A ⟼ B            уже существует
X = C ⟼ D            построен вложенной десериализацией
Y = P ⟼ X            внешний уровень
```

Внешний уровень не копирует `P` и не реконструирует его по полюсам: используется именно выбранное точное вхождение `P`.

## 7. Носитель ачисла и его денотат

Носитель описания и описываемая им связь принципиально различны.

Пусть существует носитель:

```text
carrier = (∞ ⟼ a) ⟼ b
```

но отсутствует целевая связь:

```text
a ⟼ b
```

Тогда передача самого носителя как значения не должна скрыто создавать `a ⟼ b`.

Отдельно выбранная вложенная десериализация содержимого может создать:

```text
X = a ⟼ b
```

и вернуть точное `X` внешнему уровню.

Итак:

```text
носитель как значение  → carrier
денотат носителя        → X
carrier ≠ X
```

Историческое цитирование уже показывает, что дополнительная скобочная оболочка может менять уровень чтения. Но точное правило, связывающее количество физических скобок с выбором «сам носитель / его денотат» в текущем кандидате, ещё не принято. Его нельзя додумывать эвристикой реализации.

## 8. Скобки как границы вложенного запуска

После словарного разрешения формы идут в точном порядке исходной записи.

В явно выбранном режиме последовательностной десериализации различённые корневые `O` и `C` могут быть назначены ролями открытия и закрытия группы:

```text
(O, A, B, C, D)
→ ([A B], D)
```

Здесь квадратные скобки справа — поясняющая запись полученной вложенности.

Роль определяется **точным тождеством O/C**. Другая связь с теми же полюсами остаётся обычным значением.

Проверка группировки:

- не читает байты заново;
- не создаёт второй синтаксический анализатор;
- не материализует связи;
- отвергает неожиданное закрытие;
- отвергает незакрытую группу;
- отвергает пустую группу.

Таким образом, скобки управляют границами рекурсивного запуска только в явно выбранном режиме. Они не становятся врождёнными командами стека.

## 9. Последовательностная материализация

Для уже разрешённых значений:

```text
∞ A B C
```

явная материализация создаёт новые соседние связи:

```text
AB = A ⟼ B
BC = B ⟼ C
```

`∞` обозначает начало последовательности и сам не становится первым операндом соседства.

Каждое соседство создаёт **новое точное вхождение**, даже если связь с такими же полюсами уже существует.

Вложенная группа сначала возвращает свой результат как одно значение наружу:

```text
[A B]
→ X = A ⟼ B
→ вернуть X
```

Поэтому:

```text
∞ [A B] C
```

даёт:

```text
X = A ⟼ B
Y = X ⟼ C
```

Одиночная группа возвращает уже выбранное значение без создания новой связи.

## 10. Сквозной проверенный путь

Для исходной записи:

```text
[ab]c
```

текущий кандидат уже исполнимо проверяет цепочку:

```text
байты
→ точное вхождение исходной записи
→ разбиение
→ D
→ (O, A, B, C, C₁)
→ проверка вложенности
→ ([A B], C₁)
→ явная материализация
→ X = A ⟼ B
→ Y = X ⟼ C₁
```

`O` и первый `C` здесь являются настоящими точными связями пятисвязного корня, а не синтаксическими объектами внешнего анализатора.

До последнего шага исходная сеть остаётся неизменной.

## 11. Большой вложенный пример

После разрешения имён:

```text
∞[window][cursor][position][[[x][int]][point]]
```

вложенная часть может дать:

```text
XI = X ⟼ Int
Q  = XI ⟼ Point
```

а внешний уровень:

```text
WC = Window ⟼ Cursor
CP = Cursor ⟼ Position
PQ = Position ⟼ Q
```

Смысл примера не зависит от того, были ли `Window`, `Cursor`, `Point` и другие значения получены из вложенных ачисел или разрешены словарём непосредственно в уже существующие связи. После разрешения это равноправные точные значения.

## 12. Поиск отделён от создания

Поиск связи:

```text
A ⟼ B
```

при отсутствии результата означает только:

```text
не найдено
```

а не скрытую команду создать такую связь.

Поэтому:

```text
find ≠ materialize
```

Именно это делает ачисло пригодным для запроса: описание искомой связи может существовать, хотя сама связь отсутствует.

## 13. Долговременное хранение

При сохранении различаются:

```text
оперативная ссылка
долговременный логический идентификатор
номер в снимке
физический адрес записи
```

Ачисло не должно зависеть от физического адреса хранилища.

После повторного открытия должны логически сохраняться точные вхождения, циклы, совместное использование и множественность одинаковых пар.

Подробнее: [Апамять и управление сетью связей](Апамять%20и%20управление%20сетью%20связей.md).

## 14. Границы реализации

Текущая лестница разделяет чтение и действие:

```text
сырой носитель
→ исходная запись и словарное разрешение
→ точные формы
→ при необходимости восстановление начала
→ проверка вложенности
→ разрешённое описание последовательности
→ поиск / проверка
→ явная материализация
→ долговременное хранение
```

Технические носители реализации вроде:

```text
SequenceAtom
SequenceGroup
SequenceDescription
OccurrenceRef
```

не являются новыми онтологическими типами МТС. Они только переносят ссылки на уже различённые связи и выбранную структуру проверки.

## 15. Что ещё не принято

Открытыми остаются:

1. точное правило физических дополнительных скобок для выбора между передачей самого носителя и десериализацией его денотата;
2. окончательная относительная семантика и роль явного контекста в выборе значения;
3. каноническое обратное представление за пределами принятой рекурсивной области;
4. достаточность словарного разрешения для всех будущих внешних протоколов ссылок;
5. граница представимости произвольных циклических и разделяемых асетей одним ачислом.

До отдельного решения нельзя вводить навигационное правило вида:

```text
[ → start(current)
] → end(current)
```

и нельзя молча считать дополнительную пару скобок универсальной командой цитирования или десериализации во всех режимах.

## Итог

Ачисло ценно тем, что позволяет существующей связевой структурой **описать другую связевую структуру без её немедленного создания**.

Текущий проверенный путь:

```text
∞ и [ ] 1 0
→ носитель
→ явное разрешение точных значений
→ рекурсивная вложенность
→ поиск или проверка
→ явная материализация
→ апамять
```

Главный принцип:

```text
описать связь ≠ создать связь
```

И дополнительная граница:

```text
описать несвязь ≠ сделать несвязь сущностью
```
