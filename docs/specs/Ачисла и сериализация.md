# Ачисла и сериализация

Ачисло — корневое последовательное описание связей через **ровно четыре абита**:

```text
[ ] 1 0
```

Акорень `∞` не является пятым абитом. Он является основанием, относительно которого определены четыре корневых абита и с которого начинается каждый новый контекст десериализации.

## 1. Корневой базис и транспортный алфавит

Семантический корневой базис содержит пять связей:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Остенсивно:

```text
O ≡ ♂∞
C ≡ ∞♀
```

Корневой четверичный словарь:

```text
[ -> O
] -> C
1 -> L
0 -> U
```

Поэтому необходимо различать:

```text
семантический базис: R/O/C/L/U  — 5 связей
транспортный алфавит: [ ] 1 0   — 4 абита
```

`R` не передаётся как отдельное пятое состояние линии.

## 2. Тождество абитов и связей

В МТС связь полностью определяется своими полюсами:

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Следовательно, повтор одного абита в ачисле означает повторную ссылку на **ту же связь**, а не создание новых экземпляров.

Например:

```text
1110
```

разрешается в последовательность ссылок:

```text
[L, L, L, U]
```

Три позиции `1` различаются своим положением в последовательности, но все три указывают на одну связь `L`.

Позиционная множественность хранится последовательностью; она не создаёт дополнительное тождество связи.

## 3. Пустая последовательность и пустой контекст

Каждый новый контекст десериализации автоматически начинается с акорня:

```text
current := R
```

Поэтому:

```text
des(ε) = R
des("") = R
des("[]") = R
```

Пустая группа `[]` **не является ошибкой**.

Открытие `[`:

```text
OPEN:
    сохранить внешний контекст
    открыть новый контекст
    current := R
```

Если следующий значимый переход сразу закрывает этот контекст, его значением остаётся `R`.

Таким образом `[]` позволяет записать акорень внутри четверичного ачисла без введения пятого абита.

## 4. Метанотация результата и физические скобки

В теоретических формулах удобно писать:

```text
[a]  = des("a")
[ab] = des("ab")
```

Здесь внешние квадратные скобки слева — метанотация значения `des`, а не дополнительные символы физического источника.

Например:

```text
des("")   = R
des("a")  = a
des("ab") = a ⟼ b
des("[]") = R
```

Нужно отличать метанотацию `[ab] = des("ab")` от физического источника `"[ab]"`, который действительно содержит абиты открытия и закрытия контекста.

## 5. Стековая десериализация

Каноническая линия разработки десериализатора использует явное состояние:

```text
state = (stack, top, current)
```

где каждый новый контекст начинается с `R`.

Минимальные переходы:

```text
OPEN  : сохранить внешний контекст; открыть новый; current := R
VALUE : включить очередное разрешённое значение в текущий контекст
CLOSE : завершить текущий контекст; вернуть его значение родителю
```

Твёрдо установлено:

- каждый контекст стартует от `R`;
- `[] -> R`;
- `R` не является абитом;
- результат вложенного контекста возвращается во внешний контекст как значение;
- состояние стековой машины должно быть наблюдаемым и в конечном счёте представимым связями МТС.

Текущая принятая десериализация допускает два входа одного и того же алгоритма: внешний четверичный поток и уже существующую связь-последовательность в асети. Во втором случае сначала только чтением восстанавливается тот же поток абитов, после чего выполняется эта же стековая машина. Второго алгоритма `OPEN/CLOSE/VALUE` не существует.

## 6. Базовая последовательная свёртка

Для последовательности уже разрешённых значений без физической группировки используется левая свёртка:

```text
des(ε)       = R
des(a)       = a
des(a,b)     = a ⟼ b
des(a,b,c)   = (a ⟼ b) ⟼ c
```

При этом каждая связь свёртки подчиняется общему тождеству по полюсам.

Если на некотором шаге требуется связь:

```text
X = A ⟼ B
```

и эта связь уже представлена в конкретной апамяти, материализатор должен переиспользовать `X`, а не создавать второй экземпляр той же формы.

## 7. Носитель, денотат и материализация

Нужно различать три уровня:

```text
физический/связевой носитель ачисла
денотат десериализации
материализованная запись денотата в конкретной апамяти
```

То есть:

```text
носитель ≠ денотат
описать связь ≠ записать связь
```

Ачисло может описывать связь, которой ещё нет как физической записи в данной памяти.

Отсюда:

```text
не найдено ≠ не существует
find ≠ materialize
```

## 8. Правильная материализация

Семантическая операция построения связи концептуально имеет вид:

```text
ensureLink(A,B):
    если A ⟼ B уже присутствует в конкретной асети -> вернуть эту же связь
    иначе -> материализовать A ⟼ B и вернуть её
```

Это не означает, что `find` получает право записи. Должны существовать отдельные режимы:

```text
find(A,B)        — только поиск
ensureLink(A,B)  — явная операция получения с возможной материализацией
```

Если физический импорт содержит две разные записи или идентификатора с одинаковыми полюсами `(A,B)`, это не две связи МТС. Импорт должен либо:

- отклонить дублирующее физическое представление;
- либо явно канонизировать его в одну смысловую связь.

## 9. `R = R ⟼ R` и повторное использование

Из аксиомы тождества непосредственно следует:

```text
R ⟼ R = R
```

Поэтому операция, логически требующая `R ⟼ R`, не создаёт новую связь.

Проверочный пример:

```text
[][] -> R
```

На повторном получении формы `R ⟼ R` результатом остаётся `R`.

В отладочной трассе допустимо различать:

```text
created
reused
```

как свойства **операции над конкретной памятью**, но не как разные тождества результата.

## 10. Два входа и связь-последовательность

Ачисло может поступать как внешний поток символов или как уже существующий связевой носитель.

Связь `S` читается в роли конечной корневой связи-последовательности тогда и только тогда, когда последовательное применение `start` за конечное число шагов приводит к `R`. При чтении каждого шага `end(S)` является последним элементом текущего префикса; после прохода к `R` собранные концы обращаются и дают прямой порядок элементов.

```text
S = R  -> пустая последовательность
S != R -> сохранить end(S); продолжить с start(S)
```

Это **роль существующей связи**, а не новый вид или новое тождество связи. Поэтому совпадение выбранного носителя с одной из корневых связей не превращает его автоматически в одноэлементную последовательность. Например `U = C ⟼ O` как абит означает `0`, но та же связь `U`, выбранная именно как носитель, читается по цепочке `U -> C -> R` как последовательность `][`. Одноэлементный носитель `0` имеет форму `R ⟼ U`.

Для четверичного ачисла каждый прочитанный элемент обязан быть одной из четырёх корневых связей `O/C/L/U`. Чтение носителя ничего не создаёт и не изменяет в асети; неприходящая к `R` цепочка, неверный корневой словарь или посторонний элемент отклоняются.

Позиция символа, номер операции, смещение или адрес памяти являются техническими координатами. Они могут различаться при повторном чтении одного и того же абита или одной и той же связи, но не создают вторую связь той же формы.

Если история чтения существенна, она должна быть выражена отдельной связевой структурой акта или последовательности.

## 11. Относительное ачисло как продолжение от явного контекста

Минимальная относительная семантика не меняет значения четырёх абитов и не вводит отдельные операции для `[` или `]`. Относительность задаётся **начальным аккумулятором** последовательной свёртки.

Пусть явный контекст имеет принятую форму:

```text
P = parent ⟼ prefix
K = K ⟼ P
prefix = current(K)
```

После того как источник, словарь, грамматика и теория уже выбрали конечную последовательность смысловых форм:

```text
F = (f1, f2, ..., fn)
```

корневое чтение и относительное продолжение различаются:

```text
root(F) = des(F)

rel_K(ε) = prefix
r0       = prefix
r(i+1)   = r(i) ⟼ f(i+1)
rel_K(F) = rn
```

Например:

```text
root(a)       = a
rel_K(a)      = prefix ⟼ a
root(a,b)     = a ⟼ b
rel_K(a,b)    = (prefix ⟼ a) ⟼ b
```

Именно такую границу уже исполняет текущая поверхность интерпретатора: обычное чтение выбранной последовательности и её продолжение из `current(before_context)` являются двумя разными явно проверяемыми режимами.

### 11.1. Абиты не становятся относительными операторами

Сохраняется корневой словарь:

```text
[ -> O
] -> C
1 -> L
0 -> U
```

Нельзя выводить без отдельного правила:

```text
[ -> взять start текущей связи
] -> взять end текущей связи
```

или считать `[[` / `]]` самостоятельными относительными командами.

Группировка, цитирование и сегментация источника выбираются на уровне явных `D/G/T` и дают последовательность **уже разрешённых смысловых форм**. Относительный слой лишь продолжает её свёртку от `prefix`.

Поэтому вложенная группа может участвовать в относительном чтении как одно уже выбранное смысловое значение, но сам relative-layer не переинтерпретирует физические скобки второй раз.

### 11.2. Один источник, разные явно выбранные чтения

Один и тот же носитель может быть выбран как несколько атомарных форм либо как одна цитированная/сегментированная форма. Это не требует менять содержимое источника.

Если `carrier_ab` — уже существующая связь-носитель последовательности `(a,b)`, то различаются, например:

```text
rel_K(a,b)
rel_K(carrier_ab)
```

Первая форма продолжает контекст двумя значениями, вторая — одним значением-носителем. Если их полюса различны, результаты являются разными смысловыми связями по общей аксиоме тождества, а не потому, что акты чтения получили разные технические ID.

Повтор одного значения также остаётся повтором той же связи:

```text
rel_K(a,b,a)
```

не создаёт второй `a`.

### 11.3. Пустота, `[]` и акорень

Пустое **относительное продолжение** не означает новый пустой корневой контекст:

```text
rel_K(ε) = prefix
```

Это отличается от нового корневого чтения:

```text
des(ε) = R
```

Физическая пустая группа `[]` по-прежнему разрешается как смысловое значение `R`. Если уже разрешённый `R` затем включён как элемент относительной последовательности, это обычный шаг:

```text
prefix ⟼ R
```

и он подчиняется общей канонизации по полюсам.

В частности, при `prefix = R` шаг с `R` схлопывается:

```text
R ⟼ R = R
```

Это важно для обратимости.

### 11.4. Канонический обратный ход для принятого подмножества

Для результата относительного продолжения и **известного явного `prefix`** можно восстановить формы чтением цепочки назад:

```text
current := result
while current != prefix:
    сохранить end(current)
    current := start(current)
обратить сохранённую последовательность
```

Обратный ход является однозначным на подмножестве, где:

1. цепочка за конечное число шагов достигает данного `prefix`;
2. аккумулятор не повторяется до достижения `prefix`;
3. ни один добавленный шаг не схлопывается в уже пройденный аккумулятор.

Такое подмножество будем называть **канонически обратимым относительным продолжением**.

Если условие нарушено, обратный ход не должен угадывать длину или происхождение по техническим адресам. Относительная запись считается неинвертируемой для данного `prefix`.

Главный отрицательный пример:

```text
prefix = R
F1 = ε
F2 = (R)

rel_R(F1) = R
rel_R(F2) = R ⟼ R = R
```

По одному `(prefix=R, result=R)` невозможно отличить пустое продолжение от добавленного `R`. Поэтому `F2` не входит в канонически обратимое подмножество. Это не ошибка identity-модели, а прямое следствие `R = R ⟼ R`.

Результат без явного `prefix` также не имеет общего однозначного обратного отображения: одна связь может быть концом разных допустимых цепочек относительно разных контекстов.

### 11.5. Чтение не материализует

Относительная **проверка** уже существующего evidence остаётся чтением:

```text
replay != materialize
find != ensure
```

Создание отсутствующих звеньев возможно только в явно выбранной операции материализации. Повторная материализация одной пары переиспользует ту же смысловую связь.

Тестовые challenge-векторы фиксируют:

- различие корневого и относительного чтения одной последовательности;
- прямые относительные атомы и пары;
- повтор значения без копирования связи;
- цитированный носитель против последовательности его элементов;
- пустое относительное продолжение;
- детерминированный обратный ход на простой цепочке;
- явный отказ от обратимости для схлопывания `R ⟼ R = R`;
- неизменность снимка сети при обратном чтении.

Таким образом относительное ачисло не вводит новый слой тождества. Оно является последовательной свёрткой уже выбранных смысловых форм **от явно указанного `current(K)` вместо корневого начала**.

## 12. Историческая версия v0.2

Историческая линия v0.2 использовала собственную граничную проекцию и проекционную семантику скобок. Она сохраняется как история версии и не переписывается задним числом.

Текущая остенсивная ориентация:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

Старые записи `♀F / F♂` не являются текущим определением этих самозамыканий.

Исторические механизмы не должны переноситься в следующий кандидат основания автоматически, если они противоречат текущей системе аксиом.

## 13. Экспериментальная лаборатория

Репозиторий `netkeep80/anum_parser` служит экспериментальной лабораторией, а не нормативным источником МТС.

Текущая лабораторная модель использует:

```text
identity = by-poles
```

и различает в трассе создание физической записи и переиспользование уже существующей канонической связи.

Результаты лаборатории могут переноситься в `anum_docs` только после отдельной теоретической проверки.
