# Структурная денотация ачисел v0.2

Статус: **принятый контракт формы результата L3→L4**.

Machine contract: [`contracts/anum-denotation-v0.2.json`](../../contracts/anum-denotation-v0.2.json).

Conformance corpus: [`contracts/anum-denotation-conformance-v0.2.json`](../../contracts/anum-denotation-conformance-v0.2.json).

## 1. Назначение

L3 должен уметь сообщить структуру денотата, не зная физической памяти и не создавая связи. Поэтому между contextual Anum projection и L4 вводится storage-neutral описание:

```text
raw Anum
→ parse / validate / project
→ AnumDenotation
→ внешний L4 adapter
→ find / realize
```

`AnumDenotation` не содержит `LinkId`, адресов объектов, database handles или команд materialization.

## 2. Виды результата

```text
structural
raw
quoted-raw
```

`structural` означает, что L3 располагает достаточной принятой семантикой для описания ordered Link topology.

`raw` означает, что carrier корректно сохранён, но структурная денотация для данного случая не определена.

`quoted-raw` сохраняет description-level payload цитирования и также не выдаёт его за материализованную связь.

## 3. Ссылки structural description

Ровно два вида ссылок:

```text
Anchor(key)
Node(id)
```

### Anchor

`key` — непрозрачный внешний идентификатор контекста. L3 не решает, какому физическому `LinkId` он соответствует.

Разрешение:

```text
Anchor(key) -> physical/runtime identity
```

является обязанностью L4 adapter.

### Node

`id` существует только внутри одного structural description.

```text
Node(0)
Node(1)
...
```

Node IDs идут подряд и в topological order. Узел может ссылаться только на предыдущие узлы. Это даёт deterministic realization order без привязки к конкретному backend.

## 4. Ordered Link node

```text
Node(id, start, end)
```

где `start` и `end` — `Anchor` или ссылка на более ранний `Node`.

Повторное использование одной `Node(id)` явно сохраняет sharing:

```text
node0 = Link(anchor:a, anchor:b)
node1 = Link(node0, node0)
```

не эквивалентно созданию двух независимых копий `node0`.

## 5. Identity

Не являются runtime identity:

```text
display label
raw spelling
Python object address
JSON object address
```

Structural node identity:

```text
description-local NodeId
```

External identity:

```text
opaque Anchor key
```

Persistent identity появляется только после разрешения anchor/realization на L4.

## 6. Canonical JSON

Canonical serialization:

- UTF-8;
- object keys sorted;
- compact separators;
- anchors sorted and unique;
- nodes in ascending contiguous ID order.

Пример:

```json
{
  "kind": "structural",
  "anchors": ["a", "b"],
  "nodes": [
    {
      "id": 0,
      "start": {"anchor": "a"},
      "end": {"anchor": "b"}
    },
    {
      "id": 1,
      "start": {"node": 0},
      "end": {"node": 0}
    }
  ],
  "root": {"node": 1}
}
```

Exact compact representations находятся в conformance corpus.

## 7. Граница ответственности

Этот контракт **не определяет**:

```text
raw Anum grammar
recursive raw decode rule
какой carrier имеет какую structural denotation
relative-context semantics
persistent LinkId allocation
find
realize
delete
```

Первый набор операций остаётся в L3 protocol/decode work #89. Последний набор относится к L4.

Таким образом принятие IR не означает принятие общей денотации произвольного ачисла. Оно только фиксирует единственную форму передачи уже определённой денотации между уровнями.
