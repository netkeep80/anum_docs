# Асеть доказательства МТС — единая корневая асеть

Статус: текущая каноническая спецификация доказательного авторитета поверх принятой МТС `v0.11`.
Владельцы: #999, #1066, #1087, #1057, #1064, #1093. Переход к семантическому циклу допускается только через #995.
Исторический документ `docs/specs/Асеть доказательства МТС.md` остаётся журналом развития; здесь заменены только устаревшие утверждения о текущем состоянии.

```text
accepted MTS = v0.11
active semantic candidate = NONE
```

## 1. Главный закон

```text
proof authority = one rooted reachable MTS proof Anet
```

Массивы, отображения, множества, внешние объекты, графические модели, обменные форматы и текст являются только рабочими или представительными проекциями. Принадлежность доказательству определяется корневой топологией МТС и достижимым замыканием его обоснования.

## 2. Общая внешняя форма

```text
ProofOccurrence = Claim ⟼ Support
```

Первая координата — точная доказываемая связь. Вторая — топология МТС, из которой доверенная проверка восстанавливает закон доказательства. Названия в записи выше поясняют роли и не являются фундаментальными типами МТС.

Запрещён внешний авторитет вида `ProofStepKind`, `StructuralProofNode`, `IdentityProofNode` или признака `kind`. Если смысл вхождения нельзя восстановить из связей, такая форма ещё не готова войти в общий корневой проверяющий механизм.

## 3. Принятое корневое структурное применение V1

```text
Occurrence = Claim ⟼ ApplicationV1
ApplicationV1 = StructuralDerivationRule ⟼ ExactSequence(dependency ProofOccurrences)
```

Структурное применение остаётся относительным к точной Теории:

```text
Theory ⟼ StructuralRule
Theory ⟼ StructuralDerivationRule
```

Успешная проверка производного доказательства не разрешает создавать `Theory ⟼ DerivedDR`; точная ревизия Теории остаётся неизменной.

## 4. Полная структурная подстановка ρ

Для одного примитивного `StructuralDerivationRule` действует одна подстановка `rho : Role -> Link`, одновременно удовлетворяющая всем посылкам и заключению. Для каждой роли из `RoleDictionary` именно этого примитивного правила требуется ровно одно значение.

```text
missing/conflicting binding -> reject
repeated Role               -> same exact value
grounded subtree            -> exact identity
```

Полнота ρ не ослабляется. Открыт другой вопрос: должна ли примитивная аппликация владеть ролями более широкого окружающего обобщённого контекста. Это исследует #1093.

## 5. Принятое рекурсивное тождество связи

```text
Occurrence = IdentityClaim(left,right) ⟼ ExactSequence(child ProofOccurrences)
IdentityClaim(left,right) = left ⟼ right
```

Проверка восстанавливает рекурсивные обязательства из топологии связей и остаётся замкнутой на корень и запрещающей недоказанные циклы.

```text
intrinsic identity != Theory-specific primitive admission
```

Нельзя создавать искусственное `Theory ⟼ IdentityRule` только ради унификации внешнего программного интерфейса.

## 6. Принятый K1

```text
MIXED_ROOTED_PROOF_ANET_DEPENDENCY = SUPPORTED
```

Корневое структурное применение может использовать корректно проверяемое вхождение рекурсивного тождества как обычную зависимость при точном совпадении требуемой доказываемой связи. Одна доказательная асеть уже совместно содержит структурное применение и рекурсивное тождество связи без внешнего признака вида доказательного шага.

## 7. Выбор закона доказательства

Порядок программных проверок не является семантикой. Нельзя придавать смысл правилом «сначала попробовать тождество, затем структурное применение».

```text
0 valid interpretations -> invalid-proof-occurrence
1 valid interpretation  -> accept exact Claim
>1 interpretations      -> ambiguous-proof-support
```

Неоднозначность всегда закрывается отказом.

## 8. Достижимость от корня

```text
reachable proof-support closure from rooted target = proof membership authority
```

Недостижимое доказательное вхождение, внешнее свидетельство или запись кэша ничего не доказывают.

Поля существующего `Act` читаются через исходящие присоединения. Поэтому до включения `Act` в корневое обоснование надо явно определить, какие исходящие поля достижимого `Act` канонически входят в его доказательное замыкание. Это отдельно фальсифицирует #1093. Текущий `readExactActBindings` нельзя автоматически объявлять совместимым с законом корневой достижимости.

## 9. K1b с `Act` пока не принят

#1092 предложил форму:

```text
ApplicationV2 = StructuralDerivationRule ⟼ ExactSequence(Act, dependency ProofOccurrences...)
```

Она находится под фальсификацией. Исходный пример:

```text
RoleDictionary = [A,B,C]
R1: A -> B
rho = {A=a,B=b,C=c}
```

В форме V1 видны значения A и B, а общий словарь требует ещё C. Общий обзор репозитория показал, что это может быть следствием прежнего намеренно общего словаря ролей, а не фундаментальной необходимостью нести полный `Act` в каждом корневом вхождении.

## 10. Фальсификатор #1093

Сравниваются две архитектуры.

### A. Общий словарь и `Act`

```text
Dglobal=[A,B,C]
R1: A -> B
rho={A=a,B=b,C=c}
```

Если R1 семантически владеет всем общим словарём, невидимое C действительно должно сохраняться собственным носителем МТС.

### B. Локальные словари примитивных правил и существующее μ

```text
D1=[A,B]  R1: A -> B
D2=[B,C]  R2: B -> C
Dglobal=[A,B,C]
mu1: D1 -> Dglobal
mu2: D2 -> Dglobal
rho1={A=a,B=b}
rho2={B=b,C=c}
```

Тогда невидимая роль исчезает не через неполную ρ, а потому что вообще не принадлежит локальному примитивному правилу. До исполнимой классификации #1093 форма с `Act` не считается необходимой.

## 11. Межконтекстное отображение μ уже принято

Этап N2 установил собственное для МТС отображение ролей `mu : source Role -> target Role` с точными исходным и целевым `RoleDictionary`, полной областью определения, проверкой принадлежности целевых ролей, защитой от захвата, точной Теорией и проверкой без записи. Внешнее отображение в памяти программы не является авторитетом.

Поэтому гипотеза локальных словарей обязана быть опровергнута до добавления новой корневой топологии применения.

## 12. Старый путь K2 закрыт

```text
#1090 = CLOSED / not_planned / SUPERSEDED

```

Ошибка `invalid-proof-occurrence` остаётся полезным измерением старого пути, но не разрешает конкретное производственное исправление. После #1093 создаётся новый ограниченный план K2.

## 13. Текущее состояние T4

Для задачи `A ⟼ L = B ⟼ L -> A = B`:

```text
STRUCTURE  = SUPPORTED
PROOF_ANET = GAP / not rerun after final K1b architecture
REUSE      = NOT TESTED
```

Статус доказательной асети нельзя повышать до поддерживаемого до принятия общего корневого пути применения и разрядки допущений и повторной проверки исходного свидетельства T4.

```text

  ↓

  ↓

  ↓
```

Долгосрочная цель: корневая доказательная асеть МТС вместе с точной требуемой Теорией должна позволять доверенной проверке полностью восстановить доказательный авторитет без знания алгоритма построения асети и без внешних программных сортов доказательных сущностей.
