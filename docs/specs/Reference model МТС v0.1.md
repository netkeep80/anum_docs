# Reference model МТС v0.1

Статус: актуальное, нормативное для архитектурных границ версии v0.1.

Этот документ фиксирует **референсную инженерную модель**, относительно которой строятся parser, interpreter, протокол ачисел, апамять и будущий апрувер. Он не объявляет выбранное машинное представление окончательной «природой связи» и не заменяет [Основания МТС](../theory/Основания%20МТС.md).

Машинный контракт находится в [`core/reference_model.py`](../../core/reference_model.py).

## 1. Главный принцип

```text
L0  Онтология
L1  Семантическая модель
L2  Формальный язык
L3  Сериализация
L4  Исполнение
L5  Теория вывода
```

Главное архитектурное правило:

```text
верхний уровень не имеет права тайно определять семантику нижнего;
совпадение написания на разных уровнях не означает тождества объектов.
```

В частности, квадратные знаки L2 и абиты `[ ]` L3 могут иметь одинаковые glyph, но принадлежат разным слоям до явного правила отображения.

## 2. L0 — онтология

```text
всё есть связь;
связь — единственная форма существования;
смысл не существует отдельно от связи;
несвязь не существует как отдельная натуральная сущность;
смысл несвязи выражается связью.
```

L0 не зависит от Python-классов, графов, `*.anum`, скобок или алгоритма доказательства.

## 3. L1 — семантическая reference model

### Связь

```text
Link(start, end)
```

`start` и `end` ссылаются на связи. Конечный carrier модели является ориентированным графом связей и может содержать циклы.

### Акорень

```text
∞ = Link(∞, ∞)
```

### Начало формы

```text
♀F = Link(♀F, F)
```

### Конец формы

```text
F♂ = Link(F, F♂)
```

### Инверсия

```text
¬Link(a, b) = Link(b, a)
```

Инверсия меняет направление одной связи; отсутствие связи из этого не следует.

### Равенство

Равенство v0.1 является структурным, а не строковым и не основанным на identity объекта реализации.

```text
A = B
```

тогда и только тогда, когда корневые ориентированные циклические Link-графы `A` и `B` бисимилярны с сохранением позиций `start` и `end`.

Рекурсивные формы сравниваются без бесконечного unfolding.

### Пучок

Текущий fixture фиксирует:

```text
{A, A} = {A}
{A, B} = {B, A}
```

Поэтому L1-пучок v0.1 экстенсионален: порядок несущественен, повтор не создаёт новый элемент.

## 4. L2 — формальный язык

L2 имеет typed AST:

```text
Expression
├── Form
├── Judgment
└── Definition
```

`Expression` — машинный синтаксический supertype, а не новая онтологическая сущность.

Это различение требуется самим fixture. Например:

```text
∞ : [] = [] ⟼ []
```

имеет справа `Judgment`, а не `Form`.

Формула:

```text
(=) : {♀[] = ♀[], []♂ = []♂}
```

содержит пучок из суждений, поэтому `{...}` принимает список L2-expressions.

Минимальный контракт:

| Конструкция | Вход | Результат | Чтение |
|---|---|---|---|
| `:` | `Form × Expression` | `Definition` | вводит target через выражение |
| `⟼` | `Form × Form` | `Form` | строит `Link(start, end)` |
| `=` | `Form × Form` | `Judgment` | структурное равенство |
| `!=` | `Form × Form` | `Judgment` | различимость |
| juxtaposition | `Form+` | `Form` | последовательность форм |
| `¬` | `Form` | `Form` | инверсия |
| `♀` | `Form` | `Form` | начало, prefix |
| `♂` | `Form` | `Form` | конец, postfix |
| `(...)` | `Expression?` | `Form` | круглая форма |
| `[...]` | `Form?` | `Form` | квадратная форма L2 |
| `{...}` | `Expression*` | `Bundle` | пучковая форма |

Приоритеты основных операторов находятся в `core/reference_model.py`; adjacency/juxtaposition находится между `⟼` и `¬`.

`⟼` в v0.1 читается левоассоциативно:

```text
[][][] = ([] ⟼ []) ⟼ []
[][][] = [] ⟼ [] ⟼ []
```

### Определение не является мутацией памяти

```text
X : expression
```

создаёт L2-definition. Оно само по себе не является L4-командой `realize`.

## 5. L3 — сериализация

L3 содержит:

```text
[ ] 1 0
*.anum
quaternary mode
string mode
UTF-8 payload codec
raw carrier
```

Базовый четверичный алфавит содержит ровно четыре абита:

```text
[ ] 1 0
```

Имена типа `window`, `position`, `int` не являются пятым видом абита.

Рабочая проекция issue #61:

```text
[] → 0
][ → 1
```

остаётся **experimental**. Её наличие в prototype-коде не переносит гипотезу в корневую систему.

## 6. L4 — исполнение

```text
raw(A) — носитель ачисла
den(A) — описываемая связь/структура
```

| Операция | Изменяет память | Материализует `den(A)` | Смысл |
|---|---:|---:|---|
| `load` | да, raw storage | нет | сохраняет носитель |
| `decode` | нет | нет | разбирает носитель |
| `project` | нет | нет | применяет контекст `K` |
| `find` | нет | нет | проверяет наличие denotation |
| `realize` | да | да | явно материализует denotation |
| `delete` | да | нет | явно удаляет материализованную структуру |

Главные инварианты:

```text
load(A) не создаёт den(A)
find(A) не создаёт den(A)
описание состояния ≠ команда изменения состояния
```

## 7. L5 — теория вывода

L5 пока не содержит набора trusted inference rules. Апрувер строится после стабилизации L0–L4.

Будущий L5 обязан различать:

```text
proof search
proof object
proof checker / trusted kernel
```

и не может использовать строковое совпадение как доказательство семантического равенства.

## 8. Статусы утверждений

```text
primitive
 definition
 derived
 conformance
 experimental
```

Нахождение строки в одном fixture рядом с определениями не меняет её статус автоматически.

## 9. Жизненный цикл фундаментального решения

```text
Research
→ Problem
→ Candidate
→ Challenged
→ Modeled
→ Accepted
→ Released
```

Дополнительные состояния:

```text
Rejected
Deferred
Superseded
```

`Accepted` требует явного решения владельца теории. Код или экспериментальные тесты сами по себе не повышают гипотезу до нормативной.

## 10. Реализация границ

На текущем этапе реализованы:

```text
L0/L1/L2/L3/L4/L5 declarative contract   core/reference_model.py
L2 typed AST                              core/mtc_ast.py
L2 tokenizer/parser/static validation     core/mtc_parser.py
L2 root-library loading                   core/root_library.py
```

Ещё не реализованы как production layers:

```text
L1 semantic evaluator;
полная L3 context model *.anum;
настоящая L4 апамять;
L5 proof kernel/search.
```

Если следующая реализация вынуждена нарушить этот документ, это означает необходимость явного изменения reference model, а не специального случая в коде.
