# Reference model МТС v0.1

Статус: актуальное, нормативное для архитектурных границ версии v0.1.

Этот документ фиксирует **референсную инженерную модель**, относительно которой строятся parser, interpreter, протокол ачисел, апамять и будущий апрувер. Он не объявляет выбранное машинное представление окончательной «природой связи» и не заменяет [Основания МТС](../theory/Основания%20МТС.md).

Машинный контракт находится в [`core/reference_model.py`](../../core/reference_model.py).

## 1. Главный принцип

```text
L0  Онтология
L1  Семантическая модель
L2  Формальный язык
L3  Сериализация
L4  Исполнение
L5  Теория вывода
```

Главное архитектурное правило:

```text
верхний уровень не имеет права тайно определять семантику нижнего;
совпадение написания на разных уровнях не означает тождества объектов.
```

В частности, квадратные знаки L2 и абиты `[ ]` L3 могут иметь одинаковые glyph, но принадлежат разным слоям до явного правила отображения.

## 2. L0 — онтология

```text
всё есть связь;
связь — единственная форма существования;
смысл не существует отдельно от связи;
несвязь не существует как отдельная натуральная сущность;
смысл несвязи выражается связью.
```

L0 не зависит от Python-классов, графов, `*.anum`, скобок или алгоритма доказательства.

## 3. L1 — семантическая reference model

### Связь

Для конкретного исполнимого carrier v0.1 используется ориентированная структура:

```text
Link(start, end)
```

`start` и `end` ссылаются на связи. Конечный carrier может содержать циклы. Это позволяет хранить самоссылочные формы без бесконечного unfolding.

Важно: `Link(start, end)` является **reference carrier для уже различённой связи**, а не автоматически полной семантикой всех L2-шаблонов и не правилом подстановки по `=`.

### Акорень

Для carrier полного самозамыкания допустимо:

```text
root.start = root
root.end = root
```

Это конечное представление рекурсивной формы акорня. Из него само по себе не следует разрешение глобально заменять каждый `∞` или каждый `[]` любым равным выражением внутри произвольного L2-контекста.

### Начало формы

Для конкретного carrier начала:

```text
start(F).start = start(F)
start(F).end = F
```

### Конец формы

Для конкретного carrier конца:

```text
end(F).start = F
end(F).end = end(F)
```

### Инверсия конкретной связи

```text
invert(Link(a, b)) = Link(b, a)
```

Инверсия меняет направление уже различённой Link-структуры; отсутствие связи из этого не следует.

### Равенство: принятая часть и открытая часть

Корневая система **уже вводит смысл равенства**:

```text
(=) : {♀[] = ♀[], []♂ = []♂}
```

Но полная метасемантика L2-оператора `=` не стабилизирована.

При попытке реализовать #70 обнаружен обязательный challenge case. Root fixture одновременно содержит:

```text
[] = ∞
∞ = ∞ ⟼ ∞
[][] = [] ⟼ []
[][][] = ([] ⟼ []) ⟼ []
[][][] != [] ⟼ ([] ⟼ [])
```

Если считать каждый `[]` одной глобальной константой, `=` — неограниченно substitutive, а `⟼` — полностью congruent, различие левой и правой ассоциации схлопывается. Это противоречит fixture.

Поэтому до решения [issue #79](https://github.com/netkeep80/anum_docs/issues/79) reference model **не утверждает**, что полный L2-оператор `=` является обычной бисимуляцией циклических Link-графов или что из `A = B` автоматически разрешена подстановка в любой контекст.

#79 должен формализовать:

```text
literal form;
positional occurrence;
pattern slot после `:`;
binding повторных `[]`;
form equality;
denotational equality;
substitution;
congruence `⟼`.
```

Экспериментальный comparator конкретных уже материализованных cyclic Link-carriers допустим как инструмент #70, но его результат нельзя выдавать за полную семантику L2 `=` до принятия #79.

### Пучок

Текущий fixture фиксирует conformance-примеры:

```text
{A, A} = {A}
{A, B} = {B, A}
```

Они требуют экстенсионального чтения перечисленных пучков. Однако метасвойства самого знака `=` — подстановка и congruence — остаются отделены от этих конкретных утверждений до #79.

## 4. L2 — формальный язык

L2 имеет typed AST:

```text
Expression
├── Form
├── Judgment
└── Definition
```

`Expression` — машинный синтаксический supertype, а не новая онтологическая сущность.

Это различение требуется самим fixture. Например:

```text
∞ : [] = [] ⟼ []
```

имеет справа `Judgment`, а не `Form`.

Формула:

```text
(=) : {♀[] = ♀[], []♂ = []♂}
```

содержит пучок из суждений, поэтому `{...}` принимает список L2-expressions.

Минимальный синтаксический контракт:

| Конструкция | Вход | Результат | Чтение |
|---|---|---|---|
| `:` | `Form × Expression` | `Definition` | вводит target через шаблон/выражение; это не присваивание |
| `⟼` | `Form × Form` | `Form` | строит Link-form с упорядоченными позициями |
| `=` | `Form × Form` | `Judgment` | строит суждение равенства; метасемантика открыта в #79 |
| `!=` | `Form × Form` | `Judgment` | строит суждение различимости |
| juxtaposition | `Form+` | `Form` | последовательность позиций форм |
| `¬` | `Form` | `Form` | инверсия формы |
| `♀` | `Form` | `Form` | начало, prefix |
| `♂` | `Form` | `Form` | конец, postfix |
| `(...)` | `Expression?` | `Form` | круглая форма |
| `[...]` | `Form?` | `Form` | квадратная форма L2 |
| `{...}` | `Expression*` | `Bundle` | пучковая форма |

Приоритеты основных операторов находятся в `core/reference_model.py`; adjacency/juxtaposition находится между `⟼` и `¬`.

`⟼` синтаксически левоассоциативен:

```text
[][][] = ([] ⟼ []) ⟼ []
[][][] = [] ⟼ [] ⟼ []
```

Это правило parser-а. Оно не вводит автоматически algebraic associativity или congruence.

### `:` — шаблон, не присваивание

Накопленное рабочее понимание и root fixture требуют читать:

```text
X : expression
```

как введение различия через **шаблон формы**, а не как обычное присваивание значения переменной.

Typed AST уже сохраняет отдельные `SourceSpan` каждого occurrence. Но правило, связывающее повторные одинаково записанные формы внутри одного шаблона, ещё должно быть формализовано в #79; source span сам по себе не является binding semantics.

## 5. L3 — сериализация

L3 содержит:

```text
[ ] 1 0
*.anum
quaternary mode
string mode
UTF-8 payload codec
raw carrier
```

Базовый четверичный алфавит содержит ровно четыре абита:

```text
[ ] 1 0
```

Имена типа `window`, `position`, `int` не являются пятым видом абита.

Рабочая проекция issue #61:

```text
[] → 0
][ → 1
```

остаётся **experimental**. Её наличие в prototype-коде не переносит гипотезу в корневую систему.

## 6. L4 — исполнение

```text
raw(A) — носитель ачисла
den(A) — описываемая связь/структура
```

| Операция | Изменяет память | Материализует `den(A)` | Смысл |
|---|---:|---:|---|
| `load` | да, raw storage | нет | сохраняет носитель |
| `decode` | нет | нет | разбирает носитель |
| `project` | нет | нет | применяет контекст `K` |
| `find` | нет | нет | проверяет наличие denotation |
| `realize` | да | да | явно материализует denotation |
| `delete` | да | нет | явно удаляет материализованную структуру |

Главные инварианты:

```text
load(A) не создаёт den(A)
find(A) не создаёт den(A)
описание состояния ≠ команда изменения состояния
```

## 7. L5 — теория вывода

L5 пока не содержит набора trusted inference rules. Апрувер строится после стабилизации L0–L4 и решения #79 в части bindings/substitution/congruence.

Будущий L5 обязан различать:

```text
proof search
proof object
proof checker / trusted kernel
```

и не может использовать строковое совпадение как доказательство семантического равенства.

## 8. Статусы утверждений

```text
primitive
definition
derived
conformance
experimental
```

Нахождение строки в одном fixture рядом с определениями не меняет её статус автоматически.

На текущем этапе явно `experimental`:

```text
- полная equality/substitution semantics до #79;
- issue #61 projection `[]→0`, `][→1`;
- trusted L5 proof rules.
```

## 9. Жизненный цикл фундаментального решения

```text
Research
→ Problem
→ Candidate
→ Challenged
→ Modeled
→ Accepted
→ Released
```

Дополнительные состояния:

```text
Rejected
Deferred
Superseded
```

`Accepted` требует явного решения владельца теории. Код или экспериментальные тесты сами по себе не повышают гипотезу до нормативной.

## 10. Реализация границ

На текущем этапе реализованы:

```text
L0–L5 declarative contract                 core/reference_model.py
L2 typed AST                               core/mtc_ast.py
L2 tokenizer/parser/static validation      core/mtc_parser.py
L2 root-library loading                    core/root_library.py
```

Открытый gate:

```text
#79 occurrence/binding/equality/substitution semantics
```

Ещё не реализованы как production layers:

```text
полный L1 semantic evaluator (#70, заблокирован #79 в части `:`/`=`);
полная L3 context model *.anum (#71);
настоящая L4 апамять (#72);
L5 proof kernel/search (#73, зависит от #79).
```

Если следующая реализация вынуждена нарушить этот документ, это означает необходимость явного изменения reference model, а не специального случая в коде.
