# Формальная нотация МТС

Этот документ описывает текущую формальную нотацию принятого основания MTS v0.7. Будущие расширения нотации и семантики требуют отдельных решений о принятии.

- [Апамять и управление сетью связей](Апамять%20и%20управление%20сетью%20связей.md)

## 1. Остенсивная запись первична

Главные знаки:

```text
∞
♂
♀
⟼
```

Для начала `b` и конца `e`:

```text
∞        оба полюса самозамкнуты
♂e       начало самозамкнуто, конец e различён
b♀       начало b различено, конец самозамкнут
b ⟼ e    оба полюса различены
```

Структурно:

```text
R = R ⟼ R
S = S ⟼ e
E = b ⟼ E
X = b ⟼ e
```

Остенсивная форма предшествует программному представлению.

## 2. Единственный акорень

```text
∞ = ∞ ⟼ ∞
```

Полностью самозамкнутая связь единственна:

```text
X = X ⟼ X
=>
X = ∞
```

Нельзя различить две такие формы только по внешним техническим адресам. Сам адрес не является знаком МТС и не создаёт смысловой полюс.

## 3. Самозамыкание начала и конца

Форма:

```text
♂e = S = S ⟼ e
```

показывает самозамкнутое начало и уже различённый конец `e`.

Форма:

```text
b♀ = E = b ⟼ E
```

показывает уже различённое начало `b` и самозамкнутый конец.

`♂` и `♀` **не являются встроенными командами получения полюсов**. Они показывают способ структурного различения связи.

Для уже различённого `e` форма `♂e` единственна. Для уже различённого `b` форма `b♀` единственна.

## 4. Полная связь

```text
b ⟼ e
```

обозначает связь двух уже структурно различённых полюсов.

Сам знак `⟼` не означает скрытую команду создания. В конкретном акте связь может быть:

- уже существующим значением;
- искомой связью;
- проверяемым результатом;
- явно материализуемой записью;
- полюсом другой связи.

## 5. Источник различимости

Тождество по полюсам имеет смысл только после того, как сами полюса различены.

Первичный источник различимости:

```text
самозамыкание начала/конца
```

Дальнейший источник:

```text
связанность с уже различёнными корневыми связями
```

Корневая цепочка:

```text
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

То есть:

- `R` различён полным самозамыканием;
- `O` — формой `♂R`;
- `C` — формой `R♀`;
- `L` и `U` — упорядоченными парами уже различённых `O/C`.

## 6. Тождество связи

Фундаментальное тождество:

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Следовательно:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=> P1 = P2
```

Здесь `A=B` и подобные сравнения относятся к уже структурно различённым связям, а не к совпадению или несовпадению адресов памяти.

Для самозамкнутых форм нельзя сначала объявить два технических `ref` различными, а затем использовать это как доказательство различия их собственных полюсов.

## 7. Четыре конструктивные формы

Удобный машинно-независимый контракт:

```text
∞
♂e
b♀
b⟼e
```

Он задаёт четыре способа предъявить одну бинарную сущность — связь.

Несамозамкнутые полюса должны быть уже различены. Поэтому различение распространяется от акорня наружу, а не возникает из заранее выданного множества номеров.

## 8. Петля и полное самозамыкание

Петля над `a`:

```text
Loop(a) = a ⟼ a
```

означает связь с одинаковыми внешними полюсами `a`.

Обычно:

```text
Loop(a) ≠ a
```

Полное самозамыкание — другой случай:

```text
a = a ⟼ a
```

Тогда сама связь совпала со своими полюсами, поэтому:

```text
a = ∞
```

Это различие обязательно сохранять в формулах и коде.

## 9. Корневой словарь

Пятисвязное ядро:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой четверичный словарь:

```text
[ → O
] → C
1 → L
0 → U
```

Первые различения:

```text
[ → O = O ⟼ R ≡ ♂∞
] → C = R ⟼ C ≡ ∞♀
```

Акорень `∞` не является пятым абитом.

## 10. Историческая запись проекций

Исторические формы:

```text
♀F
F♂
```

относятся к старой проекционной семантике.

Текущая остенсивная ориентация:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

Историческая запись не определяет текущий смысл `♂/♀`.

## 11. Исходная запись не является смыслом

Знак в файле ещё не является самой связью.

Рабочая цепочка:

```text
байты
→ связевое представление источника
→ позиция / история употребления
→ словарь D
→ форма F
→ допуск G/T
```

Если два чтения приводят к одной структурной форме, результат остаётся одной связью. Различие актов хранится историей, а не вторым экземпляром результата.

## 12. Строка и последовательность

Каноническое содержимое может строиться как последовательность:

```text
C0     = R
C(n+1) = Cn ⟼ Bn
```

Повтор одной и той же связи в нескольких позициях не создаёт её копии.

Например:

```text
1110
```

использует:

```text
[L, L, L, U]
```

## 13. Контекст K и знак `↑`

Контекст:

```text
P = parent ⟼ current
K = K ⟼ P
```

Тогда:

```text
↑ = current(K)
```

`↑` относится к текущей связи из явно предъявленного `K`, а не к скрытому глобальному состоянию.

Для одного и того же уже различённого `P` форма `K = K ⟼ P` канонически одна. Различие моментов использования должно храниться отдельной историей актов.

## 14. Словарь и определения

Состояние словаря может иметь форму:

```text
ScopePayload = parentScope ⟼ localHistory
D            = D ⟼ ScopePayload
```

Определение:

```text
Entry = sourceContent ⟼ form
```

Если требуемая связь уже существует, повторное получение не создаёт копию.

## 15. Знак `:`

После разрешения исходной записи `:` обозначает явное изменение словаря.

Он не означает автоматически:

```text
равенство
доказанность
глобальную подстановку
```

Проверка уже выполненного изменения должна оставаться чтением.

## 16. Локальное равенство

Дополнительное контекстное отношение представителей может использовать:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

```text
Equal_K(a,b)
⇔ rep_K(a) = rep_K(b)
```

Оно не переопределяет фундаментальное тождество самой связи.

## 17. Грамматика и теория

Допуск задаётся явно:

```text
G ⟼ FormSequence
T ⟼ FormSequence
T ⟼ Rule
```

Нахождение формы в словаре ещё не означает её допустимость во всякой теории.

## 18. Акт интерпретации

Следует различать:

```text
I — интерпретатор
A — конкретный акт
R — результат
```

Разные акты могут иметь один и тот же результат. Это не создаёт нескольких экземпляров результирующей связи.

## 19. Проверка отделена от материализации

Ключевой инвариант:

```text
поиск / разрешение / проверка
              ≠
материализация
```

```text
не найдено ≠ не существует
```

Явная материализация должна переиспользовать уже существующую связь той же структурно различённой пары.

## 20. Ачисла

Уровни возникновения:

```text
акорень ∞
→ корневые [ ] 1 0
→ ачисла
→ строки
→ формальная нотация
```

Каждый новый контекст десериализации начинается от акорня:

```text
des(ε)  = R
des([]) = R
```

Пустая группа допустима и не требует пятого абита.

## 21. Машинное представление

Технический слой может хранить:

```text
Link(start,end)
slot
address
```

Но `slot/address` не являются третьим полюсом и не создают смысловое тождество.

Более точный конструктивный интерфейс текущего основания:

```text
ensureRoot()
ensureStartSelfClosed(e)
ensureEndSelfClosed(b)
ensureLink(b,e)
```

где `b/e` уже структурно различены.

## Краткая памятка

```text
∞      единственная полностью самозамкнутая связь
♂e     самозамкнутое начало, различённый конец e
b♀     различённое начало b, самозамкнутый конец
b ⟼ e  связь двух различённых полюсов
↑      текущая связь из явного K
:      явное изменение словаря после разрешения записи
```

## Главный принцип

> Формальная нотация МТС должна показывать не только полюса связи, но и источник их различимости: самозамыкание и связанность с уже различённой корневой структурой.
