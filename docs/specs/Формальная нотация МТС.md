# Формальная нотация МТС

Этот документ описывает текущий кандидат формальной нотации МТС. Он не объявляет новую версию принятой: окончательное принятие основания выполняется отдельным решением.

## 1. Остенсивная запись первична

Главные знаки текущего основания:

```text
∞
♂
♀
⟼
```

Их расположение показывает форму связи непосредственно.

Для начала `b` и конца `e`:

```text
∞        оба полюса самозамкнуты
♂e       начало самозамкнуто, конец e различён
b♀       начало b различено, конец самозамкнут
b ⟼ e    оба полюса различены
```

Структурно:

```text
R = R ⟼ R      # ∞
S = S ⟼ e      # ♂e
E = b ⟼ E      # b♀
X = b ⟼ e      # b ⟼ e
```

Остенсивная форма предшествует программному представлению.

## 2. Акорень

```text
∞ = ∞ ⟼ ∞
```

`∞` обозначает различённый акорень. Самозамкнутая форма сама по себе ещё не делает любую связь акорнем:

```text
X = X ⟼ X
```

не означает автоматически:

```text
X = ∞
```

Потому что конкретное вхождение связи и её форма — разные вещи.

## 3. Самозамыкание начала и конца

Форма

```text
♂e = S = S ⟼ e
```

показывает самозамкнутое начало и различённый конец.

Форма

```text
b♀ = E = b ⟼ E
```

показывает различённое начало и самозамкнутый конец.

`♂` и `♀` не являются встроенными командами получения полюсов. Направление действия возникает только в конкретном акте разрешения связи.

Например обе частичные формы могут привести к одной полной связи:

```text
♂e + b  → b ⟼ e
b♀ + e  → b ⟼ e
```

При этом исходные частичные связи не изменяются.

## 4. Полная связь

```text
b ⟼ e
```

обозначает форму связи с двумя различёнными полюсами.

В конкретном акте такая связь может быть:

- уже существующим значением;
- искомым образцом;
- проверяемым результатом;
- явно создаваемым новым вхождением;
- частью другой связи.

Сам знак `⟼` не требует скрытой команды создания.

## 5. Форма не равна вхождению

Могут существовать:

```text
S1 = S1 ⟼ e
S2 = S2 ⟼ e
S1 ≠ S2
```

Обе связи имеют форму `♂e`, но остаются разными конкретными вхождениями.

То же относится к полным связям:

```text
P1 = A ⟼ B
P2 = A ⟼ B
P1 ≠ P2
```

Поэтому сравнение только по полюсам или по внешней форме не заменяет тождество связи.

## 6. Корневой словарь

Пятисвязное ядро:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой словарь:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

Первые различения вокруг акорня:

```text
[ → O = O ⟼ R ≡ ♂∞
] → C = R ⟼ C ≡ ∞♀
```

Нельзя смешивать:

```text
корневые абиты [ ] 1 0
знаки формальной записи ♂ ♀
байты исходного текста
программные лексемы
```

Это разные уровни представления.

## 7. Историческая запись проекций

В принятой исторической нотации версии 0.2 использовались формы:

```text
♀F
F♂
```

Они были связаны с историческим чтением проекций начала и конца.

Текущий кандидат основания **не переносит** это чтение на остенсивные формы самозамыкания. Текущая ориентация фиксирована так:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

Исторические версии воспроизводимы через историю репозитория и их принятые машинные артефакты, но не определяют смысл новых знаков.

## 8. Исходная запись не является смыслом

Знак в файле — ещё не сама связь.

Рабочая цепочка различает:

```text
байты исходной записи
→ каноническое содержимое
→ конкретное вхождение исходной записи
→ выбранное разбиение
→ словарь D
→ форму F
→ допуск грамматикой G и теорией T
```

Это позволяет одной и той же строке иметь разные разрешения в разных словарях и сохранять различие двух одинаково написанных вхождений.

Многобайтный знак, например `♂`, должен разрешаться как единое словарное содержимое, а не получать смысл из отдельного программного перечисления символов.

## 9. Строка и её вхождение

Каноническое содержимое строки строится как последовательность представлений байтов:

```text
C0     = R
C(n+1) = Cn ⟼ Bn
```

Конкретное вхождение исходной записи отделено от содержимого:

```text
S1 = S1 ⟼ C
S2 = S2 ⟼ C
S1 ≠ S2
```

Одинаковое содержимое поэтому совместимо с разным происхождением.

Скрытая нормализация текста не должна менять содержимое без явного правила.

## 10. Разбиение исходной записи

Разбиение и поиск возможных чтений могут быть недоверенными. Доверенная проверка получает уже выбранные границы и проверяет их относительно исходной записи и словаря.

То есть допускается:

```text
поиск нескольких вариантов
→ выбор варианта
→ точная проверка выбранных свидетельств
```

но не допускается:

```text
эвристика поиска = истина МТС
```

## 11. Словарь D

Состояние словаря выражается связями:

```text
ScopePayload = parentScope ⟼ localHistory
D            = D ⟼ ScopePayload
```

Запись определения:

```text
Entry = sourceContent ⟼ form
```

Конкретное объявление:

```text
Occurrence = D_before ⟼ Entry
```

История локальных объявлений:

```text
H_after = H_before ⟼ Occurrence
D_after = D_after ⟼ (sameParentScope ⟼ H_after)
```

Новое состояние не переписывает старое.

## 12. Знак `:`

После разрешения исходной записи `:` обозначает явное изменение словаря.

Он не означает автоматически:

```text
равенство
доказанность
глобальную подстановку
скрытое присваивание среды исполнения
```

Проверка уже выполненного изменения словаря должна быть только чтением.

## 13. Контекст K и знак `↑`

Контекст представлен связями:

```text
P = parent ⟼ current
K = K ⟼ P
```

Тогда:

```text
↑ = current(K)
```

`↑` относится к текущей связи из явно предъявленного `K`, а не к скрытому глобальному состоянию.

Текущая связь может иметь любую из остенсивных форм:

```text
∞
♂e
b♀
b ⟼ e
```

## 14. Разрешение формы

Для выбранной точной формы

```text
S = S ⟼ e
```

и предъявленного начала `b` проверяемый результат должен иметь полюса:

```text
b ⟼ e
```

Для формы

```text
E = b ⟼ E
```

аналогично предъявляется конец `e`.

Направление видно из структуры самой выбранной связи. Для этого не требуется разбирать знак `♂` или `♀` как программную команду.

## 15. Локальное равенство

Текущий кандидат равенства использует явного представителя в контексте:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

```text
Equal_K(a,b)
⇔ rep_K(a) is rep_K(b)
```

Это одношаговое локальное отношение. Оно не создаёт автоматически:

- транзитивное замыкание цепочек представителей;
- глобальную подстановку;
- сравнение графов по форме;
- конгруэнтность;
- переписывание всей сети.

Одинаковая остенсивная форма также не означает равенство конкретных вхождений.

## 16. Грамматика G и теория T

Допуск записывается явно:

```text
G ⟼ FormSequence
T ⟼ FormSequence
T ⟼ Rule
```

То, что запись успешно разобрана или найдена в словаре, ещё не означает её допустимость в любой теории.

## 17. Конкретный акт интерпретации

Следует различать интерпретатор и отдельное произошедшее действие интерпретации.

Условно:

```text
I — интерпретатор
A — конкретный акт
```

Акт может связывать точные свидетельства:

```text
исходная запись
выбранное разрешение
D
G
T
форма
K до действия
подстановка
результат
K после действия
```

Таким образом одна и та же форма может участвовать во многих различных действиях.

## 18. Проверка отделена от изменения памяти

Ключевой инвариант:

```text
поиск / разрешение / проверка
              ≠
материализация
```

Если искомой связи нет, проверка не должна создавать её только ради успешного результата.

Явное создание — отдельное действие апамяти.

## 19. Ачисла и текстовая нотация

Порядок возникновения уровней:

```text
акорень ∞
→ корневые абиты [ ] 1 0
→ ачисла
→ строки
→ знаки формальной нотации
→ словари и теории
→ интерпретация
```

Поэтому текстовая формула

```text
∞ = ∞ ⟼ ∞
```

может описывать акорень лишь после появления языка, способного записать эту формулу. Сама строка не создаёт акорень.

## 20. Машинное представление

В реализации допустимы технические имена вроде:

```text
Link(start, end)
OccurrenceRef
PersistentOccurrenceId
```

Но они вторичны по отношению к остенсивной форме:

```text
∞    ↔ R = R ⟼ R
♂e   ↔ S = S ⟼ e
b♀   ↔ E = b ⟼ E
b⟼e  ↔ X = b ⟼ e
```

Программный тип помогает хранить и проверять связь, но не заменяет язык МТС.

## Краткая памятка

```text
∞      акорень, полностью самозамкнутая форма
♂e     самозамкнутое начало, различённый конец e
b♀     различённое начало b, самозамкнутый конец
b ⟼ e  полная связь
↑      текущая точная связь из явного K
:      явное изменение словаря после разрешения записи
=      локальное отношение представителей
```

Не путать:

```text
текущая остенсивная запись:   ♂e / b♀
исторические проекции v0.2:   ♀F / F♂
```

## Главный принцип

> Формальная нотация МТС должна по возможности показывать структуру связи самой формой записи, а не требовать внешнего типа для понимания её основного устройства.

Поэтому `∞`, `♂`, `♀` и `⟼` читаются раньше программного разбора, классов синтаксического дерева и интерфейсов реализации.
