# Формальная нотация МТС

Этот документ описывает текущий кандидат формальной нотации МТС. Окончательное принятие основания выполняется отдельным решением.

- [Система аксиом МТС](../theory/Система%20аксиом%20МТС.md)
- [Ачисла и сериализация](Ачисла%20и%20сериализация.md)
- [Апамять и управление сетью связей](Апамять%20и%20управление%20сетью%20связей.md)

## 1. Остенсивная запись первична

Главные знаки текущего основания:

```text
∞
♂
♀
⟼
```

Для начала `b` и конца `e`:

```text
∞        оба полюса самозамкнуты
♂e       начало самозамкнуто, конец e различён
b♀       начало b различено, конец самозамкнут
b ⟼ e    оба полюса различены
```

Структурно:

```text
R = R ⟼ R      # ∞
S = S ⟼ e      # ♂e
E = b ⟼ E      # b♀
X = b ⟼ e      # b ⟼ e
```

Остенсивная форма предшествует программному представлению.

## 2. Акорень

```text
∞ = ∞ ⟼ ∞
```

`∞` обозначает различённый акорень.

Самозамкнутая связь:

```text
X = X ⟼ X
```

не является акорнем автоматически. Если `X ≠ ∞`, её полюса `(X,X)` отличаются от `(∞,∞)`.

## 3. Самозамыкание начала и конца

Форма:

```text
♂e = S = S ⟼ e
```

показывает самозамкнутое начало и различённый конец.

Форма:

```text
b♀ = E = b ⟼ E
```

показывает различённое начало и самозамкнутый конец.

`♂` и `♀` не являются встроенными командами получения полюсов. Направление действия возникает только в конкретном акте разрешения связи.

Например обе частичные формы могут привести к одной полной связи:

```text
♂e + b  → b ⟼ e
b♀ + e  → b ⟼ e
```

При этом исходные частичные связи не изменяются.

## 4. Полная связь

```text
b ⟼ e
```

обозначает связь с двумя различёнными полюсами.

В конкретном акте она может быть:

- уже существующим значением;
- искомой связью;
- проверяемым результатом;
- явно материализуемой записью;
- полюсом другой связи.

Сам знак `⟼` не требует скрытой команды создания.

## 5. Тождество связи и форма записи

Фундаментальное тождество определяется полюсами:

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Поэтому:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=> P1 = P2
```

Но одинаковый **образец** остенсивной записи ещё не означает одинаковую пару конкретных полюсов. Например:

```text
S1 = S1 ⟼ e
S2 = S2 ⟼ e
```

может задавать разные связи, если `S1 ≠ S2`, потому что их начала различны.

Следовательно, нужно отличать:

```text
одинаковый шаблон записи
от
одинаковой упорядоченной пары конкретных полюсов
```

Адрес записи, номер операции или позиция исходного текста не являются дополнительным тождеством связи.

## 6. Корневой словарь

Пятисвязное ядро:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой четверичный словарь:

```text
[ → O
] → C
1 → L
0 → U
```

Первые различения вокруг акорня:

```text
[ → O = O ⟼ R ≡ ♂∞
] → C = R ⟼ C ≡ ∞♀
```

Нельзя смешивать:

```text
корневые абиты [ ] 1 0
знаки формальной записи ♂ ♀
байты исходного текста
программные лексемы
```

Это разные уровни представления. Акорень `∞` не является пятым абитом.

## 7. Историческая запись проекций

В исторической нотации использовались формы:

```text
♀F
F♂
```

Они были связаны со старым чтением проекций начала и конца.

Текущий кандидат основания не переносит это чтение на остенсивные формы самозамыкания:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

Историческая запись не определяет смысл текущих знаков.

## 8. Исходная запись не является смыслом

Знак в файле — ещё не сама связь.

Рабочая цепочка различает:

```text
байты исходной записи
→ каноническое содержимое
→ позицию или связевую историю употребления
→ выбранное разбиение
→ словарь D
→ форму F
→ допуск грамматикой G и теорией T
```

Одна строка может участвовать в разных актах чтения и разрешаться по-разному в разных словарях. Происхождение различается связями акта и последовательности, а не вторым экземпляром одной смысловой связи.

## 9. Строка и её употребление

Каноническое содержимое строки может строиться как последовательность представлений байтов:

```text
C0     = R
C(n+1) = Cn ⟼ Bn
```

Повтор одного и того же содержимого не требует второй связи `C` той же формы.

Если необходимо различать два появления текста, различие выражается, например:

```text
позициями в исходной последовательности
разными актами чтения
разными контекстами
разной связевой историей
```

Скрытая нормализация текста не должна менять содержимое без явного правила.

## 10. Разбиение исходной записи

Поиск возможных чтений может быть недоверенным. Доверенная проверка получает выбранные границы и проверяет их относительно исходной записи и словаря.

Допускается:

```text
поиск нескольких вариантов
→ выбор варианта
→ проверка выбранных свидетельств
```

но не:

```text
эвристика поиска = истина МТС
```

## 11. Словарь D

Состояние словаря выражается связями:

```text
ScopePayload = parentScope ⟼ localHistory
D            = D ⟼ ScopePayload
```

Запись определения:

```text
Entry = sourceContent ⟼ form
```

Определение в конкретной истории может связываться так:

```text
Definition = D_before ⟼ Entry
H_after    = H_before ⟼ Definition
D_after    = D_after ⟼ (sameParentScope ⟼ H_after)
```

Если какая-либо из требуемых связей уже существует, повторное получение не создаёт её копию.

Различие двух объявлений одной формы должно находиться в структуре их истории или позиции, а не в скрытом экземплярном тождестве `Entry`.

## 12. Знак `:`

После разрешения исходной записи `:` обозначает явное изменение словаря.

Он не означает автоматически:

```text
равенство
доказанность
глобальную подстановку
скрытое присваивание среды исполнения
```

Проверка уже выполненного изменения словаря должна оставаться чтением.

## 13. Контекст K и знак `↑`

Контекст представлен связями:

```text
P = parent ⟼ current
K = K ⟼ P
```

Тогда:

```text
↑ = current(K)
```

`↑` относится к текущей связи из явно предъявленного `K`, а не к скрытому глобальному состоянию.

Текущая связь может иметь любую из остенсивных форм:

```text
∞
♂e
b♀
b ⟼ e
```

Если полная связевая форма двух состояний совпадает, это одна связь; происхождение переходов хранится отдельно в истории актов.

## 14. Разрешение формы

Для выбранной формы:

```text
S = S ⟼ e
```

и предъявленного начала `b` проверяемый результат должен иметь полюса:

```text
b ⟼ e
```

Для:

```text
E = b ⟼ E
```

аналогично предъявляется конец `e`.

Направление видно из структуры выбранной связи. Для этого не требуется разбирать `♂` или `♀` как программную команду.

## 15. Локальное равенство

Текущий кандидат дополнительного отношения представителей использует:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

```text
Equal_K(a,b)
⇔ rep_K(a) = rep_K(b)
```

Этот механизм не переопределяет фундаментальное тождество самой связи по полюсам.

Он не создаёт автоматически:

- транзитивное замыкание цепочек представителей;
- глобальную подстановку;
- конгруэнтность;
- переписывание всей сети.

## 16. Грамматика G и теория T

Допуск записывается явно:

```text
G ⟼ FormSequence
T ⟼ FormSequence
T ⟼ Rule
```

Успешный разбор или нахождение записи в словаре ещё не означает её допустимость в любой теории.

## 17. Конкретный акт интерпретации

Следует различать интерпретатор и отдельное произошедшее действие интерпретации.

Условно:

```text
I — интерпретатор
A — конкретный акт
```

Акт может связывать:

```text
исходную запись
выбранное разрешение
D
G
T
форму
K до действия
подстановку
результат
K после действия
```

Разные акты могут иметь один и тот же результат. Это не создаёт нескольких экземпляров результирующей связи.

## 18. Проверка отделена от изменения памяти

Ключевой инвариант:

```text
поиск / разрешение / проверка
              ≠
материализация
```

Если физическая запись искомой связи не найдена, проверка не должна создавать её только ради успешного результата.

```text
не найдено ≠ не существует
```

Явная материализация — отдельное действие апамяти. Если связь данной пары уже записана, операция получения должна переиспользовать её.

## 19. Ачисла и текстовая нотация

Порядок возникновения уровней:

```text
акорень ∞
→ корневые абиты [ ] 1 0
→ ачисла
→ строки
→ знаки формальной нотации
→ словари и теории
→ интерпретация
```

Каждый новый контекст десериализации начинается от акорня. Поэтому:

```text
des(ε)  = R
des([]) = R
```

Пустая группа допустима и не требует пятого абита.

Текстовая формула:

```text
∞ = ∞ ⟼ ∞
```

может описывать акорень лишь после появления языка, способного записать эту формулу. Сама строка не создаёт акорень.

## 20. Машинное представление

В реализации допустимы технические ссылки и адреса, необходимые для хранения и построения циклов.

Но они вторичны по отношению к остенсивной форме:

```text
∞    ↔ R = R ⟼ R
♂e   ↔ S = S ⟼ e
b♀   ↔ E = b ⟼ E
b⟼e  ↔ X = b ⟼ e
```

Техническая ссылка не является третьим полюсом и не добавляет смысловое тождество поверх `(start,end)`.

## Краткая памятка

```text
∞      акорень, полностью самозамкнутая форма
♂e     самозамкнутое начало, различённый конец e
b♀     различённое начало b, самозамкнутый конец
b ⟼ e  полная связь
↑      текущая связь из явного K
:      явное изменение словаря после разрешения записи
=      фундаментальное тождество связи по полюсам;
       дополнительные локальные отношения представителей задаются явно
```

Не путать:

```text
текущая остенсивная запись:   ♂e / b♀
исторические проекции:        ♀F / F♂
```

## Главный принцип

> Формальная нотация МТС должна по возможности показывать структуру связи самой формой записи, а не требовать внешнего типа для понимания её основного устройства.

Поэтому `∞`, `♂`, `♀` и `⟼` читаются раньше программного разбора и интерфейсов реализации.
