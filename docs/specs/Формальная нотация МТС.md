# Формальная нотация МТС

Этот документ описывает текущую принятую формальную нотацию **МТС v0.9**. Нормативная теория задаёт смысл, принятый контракт и корпус соответствия фиксируют переносимую машинную границу, а пакет `@mts/core` на `TypeScript` реализует её.

Связанные документы:

- [Система аксиом МТС](../theory/Система%20аксиом%20МТС.md)
- [Ачисла и сериализация](Ачисла%20и%20сериализация.md)
- [Апамять и управление сетью связей](Апамять%20и%20управление%20сетью%20связей.md)

## 1. Слои нельзя смешивать

В МТС v0.9 различаются:

```text
физический источник / знак
носитель представления
выбранный контекст интерпретации
смысловой денотат
```

Поэтому один и тот же видимый знак может участвовать на разных уровнях, но его смысл не выбирается эвристикой по форме входных данных.

```text
представление ≠ интерпретация
носитель ≠ денотат
вхождение в источник ≠ тождество смысловой связи
```

## 2. Минимальный внутренний алфавит F1

Принятый F1 v0.9 содержит ровно десять внутренних знаков:

```text
∞ [ ] 1 0 ( ) ⟼ : =
```

Отложены как внутренние знаки:

```text
≡ ♂ ♀ ↑ { } ¬ ↛
```

Только в метаязыке используются:

```text
∧ ⇔ ⇒ ≠ →
```

Остенсивные записи `♂e` / `b♀` остаются допустимой теоретической метанотацией самозамыкания, но не являются текущими токенами F1 или автоматически исполняемыми операторами.

## 3. Самовведение знаков

Внутренние знаки получают значения не через соглашение анализатора языка реализации, а через замкнутую асеть аксиом.

```text
m∞ = m∞ ⟼ m∞

m[ = m[ ⟼ m∞
m] = m∞ ⟼ m]
m1 = m[ ⟼ m]
m0 = m] ⟼ m[

m( = m( ⟼ m∞
m) = m∞ ⟼ m)
m⟼ = m( ⟼ m)

m: = m∞ ⟼ m⟼
m= = m= ⟼ m=
```

Корневая проекция:

```text
m∞, m=   -> R
m[, m(   -> O
m], m)   -> C
m1, m⟼   -> L
m0       -> U
m:       -> R ⟼ L
```

Совпадение корневой проекции двух знаков не делает их одной записью или одной ролью. Запись знака хранит отдельно носитель и значение:

```text
E_g = c_g ⟼ m_g
```

## 4. Корневой базис

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой четверичный словарь:

```text
[ -> O
] -> C
1 -> L
0 -> U
```

`∞` не является пятым абитом.

## 5. Единственная формальная стрелка

В текущем F1 нет второго формального синонима стрелки.

```text
A ⟼ B
```

предъявляет направленную связевую форму с началом `A` и концом `B`.

Нельзя автоматически читать `⟼` как создание записи, выполнение действия, логическое следование или шаг навигации. Эффект определяется выбранной теорией, правилом и актом.

## 6. Круглые скобки — явный контекст `FORMAL`

`(` и `)` являются отдельными внутренними знаками с собственными уравнениями. Они не являются лишь пунктуацией группировки языка реализации.

Принятый жизненный цикл:

```text
K_parent_before
  -> FORMAL_OPEN(target I)
K_child(parent=K_parent_before,current=initial)
  -> child Acts
K_child_final
  -> FORMAL_CLOSE(result)
K_parent_before
  -> PARENT_CONTINUE(result)
K_parent_after
```

Лексическая вложенность принадлежит `K.parent`, временной порядок — структуре `Run`/`Act`. Эти две оси не смешиваются.

## 7. Текущее значение `FORMAL` хранится через `ExactSequence`

Обычная левая свёртка не может быть универсальным носителем последовательности, если допустимо значение `R`:

```text
[]   -> R
[R]  -> R
```

Поэтому используется корнебезопасный носитель:

```text
Seq([]) = R
Cell(prev,value) = start-self-closed(prev ⟼ value)
Seq(xs + [x]) = Cell(Seq(xs), x)
```

Следовательно:

```text
Seq([]) != Seq([R])
```

при этом второй `R` не создаётся: позиция выражается структурой носителя.

## 8. Квадратные скобки — контекст `Q`

В четверичном контексте:

```text
[ ... ]
```

открывает и закрывает явный вложенный контекст `Q`.

Каждый новый контекст `Q` начинается относительно `R`:

```text
des(ε) = R
des([]) = R
```

Пустая группа допустима.

## 9. Состояние `Q` структурно

Скрытый флаг `started:boolean` не является смысловым основанием.

```text
QEmpty = R
QNonEmpty(inner) = start-self-closed(inner)
```

Это различает пустое состояние и непустое состояние, первым значением которого является `R`, без второго экземпляра корня и без скрытого булева поля.

## 10. Возврат между `Q` и `FORMAL`

Закрытие дочернего `Q` и продолжение родительского `FORMAL` — разные переходы:

```text
Q_CLOSE
!=
PARENT_CONTINUE
```

Закрытие дочернего контекста возвращает значение, а отдельное продолжение родителя добавляет его в прежний `ExactSequence`.

Особенно важно, что:

```text
[] -> R
```

и возвращаемый `R` сохраняется как явная позиция.

## 11. Группировка связевой формы

Каноническая формальная связь записывается явно:

```text
(A ⟼ B)
```

Вложенные формы различаются:

```text
(A ⟼ (B ⟼ C))
((A ⟼ B) ⟼ C)
```

Не вводится неявная ассоциативность или приоритет, который сам выбирает одну из группировок.

Запись:

```text
A ⟼ B ⟼ C
```

не является канонической формой основания без отдельно выбранного производного правила разбора.

## 12. Пустой `FORMAL`

Минимальный F1 не допускает пустую формулу:

```text
()
```

как автоматически осмысленную конструкцию. Группировка одной формы может быть допущена отдельным структурным правилом.

## 13. Знак `:`

```text
m: = m∞ ⟼ m⟼
```

Формальный `:` разрешается через структурный путь правила и допуска теорией.

Он не означает автоматически классическое равенство, глобальное присваивание, текстовую подстановку по всей асети или вызов функции среды реализации.

## 14. Знак `=`

```text
m= = m= ⟼ m=
```

В МТС v0.9 формальное `=` использует локальное для контекста свидетельство представителя.

Внешняя метанотация:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Это не заменяет фундаментальное тождество связи по полюсам и не вводит автоматически глобальное транзитивное замыкание, подстановку или конгруэнтность.

## 15. Структурное правило

Правило является связевыми данными:

```text
DR = DR ⟼ RoleSequence
Rule = DR ⟼ Body
T ⟼ Rule
```

Акт связывает объявленную роль со значением структурно.

Проверка требует:

- ровно одно связывание на каждую объявленную роль;
- отсутствие необъявленных связываний;
- точное свидетельство исходного контекста;
- допуск выбранного правила в `T`;
- отсутствие записи в память при проверке.

Идентификатор функции обратного вызова, перечисление вида правила или поле типа среды реализации не являются смысловым основанием.

## 16. Данные правила не исполняются сами

```text
существование Rule
!= исполнение Rule
```

Для перехода состояния нужен явный акт, контекст и выбранный путь интерпретатора. То же относится к конечным функциям-данным и прикладным отношениям.

## 17. Интерпретатор и контекст

```text
I = D ⟼ (G ⟼ T)
```

Контекст:

```text
P = parent ⟼ current
K = K ⟼ P
I ⟼ K
```

`current(K)` здесь — внешняя метанотация чтения структуры `K`, а не принятый внутренний знак `↑`.

## 18. Исходная строка

Формальный источник переносится как точное строковое содержимое.

Для каждого байта `p`:

```text
Rep_SQ(byte p) = [bbbbbbbb]
Byte(p) := Denote_Q([p])
```

Внутри скобок ровно восемь бит, старший бит первым. Один физический байт соответствует одному четверичному конверту.

## 19. Словарь байтов структурен

Все 256 значений `Byte(p)` выводятся из структуры `Q`, а не вводятся как 256 непрозрачных технических идентификаторов.

Повтор байта в строке повторяет одну смысловую связь байта через разные позиции `ExactSequence`.

Некорректная последовательность UTF-8 может быть допустима на уровне точных байтов и отклоняться отдельным строгим текстовым слоем.

## 20. Знак источника и действие интерпретатора различаются

Например физический знак `[` имеет байтовый носитель:

```text
[01011011]
```

Это не автоматически действие открытия `Q`.

Нужен явный выбранный контекст:

```text
один носитель + строковое чтение
!=
тот же носитель + четверичное структурное чтение
```

## 21. `♂` и `♀` остаются теоретической метанотацией

Полезно писать:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
♂♀ = ∞
```

Но `♂` и `♀` находятся в отложенном реестре внутренних знаков F1 v0.9. Нельзя создавать возможность анализатора только потому, что эти знаки удобны в теоретическом изложении.

## 22. Остальные отложенные знаки

```text
≡ ↑ { } ¬ ↛
```

не являются частью минимальной текущей системы самовведения. Их принятие потребует отдельной задачи и, при наблюдаемом машинном изменении, нового жизненного цикла кандидата и выпуска.

## 23. Прямая дейктика — отдельный производный слой

Текущая реализация прямой дейктики на `TypeScript` хранит:

```text
path
up
pole
```

как свидетельство вхождения и навигации. Это специализированное корневое представление свидетельства, а не текущий синтаксис F1 и не общая теория навигации.

```text
координата пути
!= тождество смысловой связи
```

Одна смысловая подасеть может встречаться в нескольких структурных позициях без смыслового копирования.

## 24. Обратное отношение навигации не является знаком F1

В производной теории навигации:

```text
S^op(y,x) iff S(x,y)
[ S1,...,Sn ]^op = [ Sn^op,...,S1^op ]
```

Но обратное отношение навигации отличается от рекурсивной реверсии `J`, перестановки полюсов `P`, несвязи `U` и логического отрицания.

## 25. Формальная нотация не определяет материализацию

```text
разобрать / разрешить / проверить / воспроизвести
!=
материализовать / записать
```

И:

```text
не найдено != не существует
```

Закрытие контекста, проверка правила и проверка равенства не имеют права создавать отсутствующее свидетельство лишь потому, что оно не найдено.

## 26. Смысловая связь и вхождение

F2/F3 дают:

```text
одинаковая рекурсивно заземлённая форма
=> одна смысловая связь
```

Поэтому смысловая связь не тождественна вхождению в источник, позиции последовательности, вхождению акта, координате пути, технической ссылке или строке хранения.

Если множественность существенна, она выражается явной структурой вхождений, происхождения и истории.

## 27. Краткая памятка

```text
внутренние знаки:
  ∞ [ ] 1 0 ( ) ⟼ : =

отложены:
  ≡ ♂ ♀ ↑ { } ¬ ↛

только метаязык:
  ∧ ⇔ ⇒ ≠ →

Q:
  [ ... ]
  пустое значение -> R
  состояние структурно

FORMAL:
  ( ... )
  текущее значение через ExactSequence
  явный допуск структурных правил
  нет скрытого приоритета

STRING:
  точные байты
  один [8 bits] на байт

тождество:
  смысловая связь != вхождение / путь / технический id

эффекты:
  чтение / replay != запись / materialize
```

## Главный принцип

> Формальная нотация МТС v0.9 является частью связевой структуры и самовведения. Знаки, переходы контекстов и носители не получают смысл из соглашений анализатора языка реализации; реализация обязана соответствовать принятой теории, контракту и корпусу соответствия.
