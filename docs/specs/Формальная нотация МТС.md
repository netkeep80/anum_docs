Статус: **актуальная Foundation v2 candidate specification**.

> Следующая версия МТС ещё не принята. Этот документ описывает текущую нотацию source/evidence/resolution/replay. Historical parser/typed-AST/`ContextFrame` mechanisms v0.2–v0.5 остаются воспроизводимыми, но не определяют Foundation-v2 semantics.

# 1. Нотация МТС должна показывать форму

Главные остенсивные знаки Foundation v2:

```text
∞
♂
♀
⟼
```

Они нужны не для украшения формул. Их расположение делает структуру relation видимой непосредственно.

Для начала `b` и конца `e`:

```text
∞        полностью самозамкнутая форма;
♂e       начало самозамкнуто, конец e различён;
b♀       начало b различено, конец самозамкнут;
b ⟼ e    оба полюса различены.
```

Структурные equations:

```text
R = R ⟼ R      # ∞
S = S ⟼ e      # ♂e
E = b ⟼ E      # b♀
X = b ⟼ e      # complete
```

Эта таблица — исходная семантическая ориентация документа.

---

# 2. `∞` — акорень

```text
∞ = ∞ ⟼ ∞
```

`∞` обозначает distinguished fully-self-closed root occurrence.

Форма `∞` одновременно:

- остенсивно показывает полное самозамыкание;
- является корневой точкой bootstrap-а;
- допускает фундаментальное чтение «смысл смысла — связь смыслов».

Но нельзя выводить:

```text
X = X ⟼ X  ⇒  X = ∞
```

потому что exact occurrence identity сильнее structural shape.

---

# 3. `♂e` — самозамкнутое начало

Foundation-v2 orientation:

```text
♂e
```

означает structural form:

```text
S = S ⟼ e
```

Конец `e` уже различён. Начало relation остаётся замкнутым на саму relation `S`.

Знак `♂` находится **слева**, на месте самозамкнутого начала.

Это не primitive function:

```text
♂(e) -> start(e)
```

и не opcode.

`♂e` — форма relation.

---

# 4. `b♀` — самозамкнутый конец

Foundation-v2 orientation:

```text
b♀
```

означает:

```text
E = b ⟼ E
```

Начало `b` уже различено. Конец relation замыкается на exact occurrence `E`.

Знак `♀` находится **справа**, на месте самозамкнутого конца.

Это не primitive `getEnd` и не «команда закрыть скобку».

---

# 5. Complete relation `b ⟼ e`

Когда оба полюса различены:

```text
b ⟼ e
```

соответствует:

```text
X = b ⟼ e
```

Сам знак `⟼` не должен трактоваться только как constructor.

В explicit resolution act complete relation может:

- быть результатом построения;
- быть проверяемым candidate;
- участвовать в associative search;
- предоставлять уже различённые poles;
- быть ordinary payload другой relation.

Форма остаётся одной.

---

# 6. Ромб остенсивных форм

```text
              b ⟼ e
             /     \
           ♂e       b♀
             \     /
                ∞
```

Ромб показывает **степень предъявленности внешних полюсов**, а не host state enum.

При binding:

```text
♂e + b  → b ⟼ e
b♀ + e  → b ⟼ e
```

Обе partial relations остаются immutable exact occurrences; resolution может выбрать или materialize отдельный complete result.

---

# 7. Остенсивная форма не равна exact occurrence

В одной network могут существовать:

```text
S1 = S1 ⟼ e
S2 = S2 ⟼ e
```

Обе имеют ostensive form:

```text
♂e
```

но:

```text
S1 ≠ S2
```

Поэтому запись `♂e` может использоваться как structural pattern, тогда как trusted act/evidence обязан указывать exact occurrence.

Аналогично для `b♀` и complete `b⟼e`.

---

# 8. Остенсивная форма не является opcode

Permanent Foundation-v2 boundary:

```text
form is declarative
execution = directional resolution under explicit bindings
```

Нельзя определять:

```text
♂ = CONSTRUCT_START
♂ = DESTRUCT_START
♀ = CONSTRUCT_END
♀ = DESTRUCT_END
⟼ = CREATE_LINK
```

как intrinsic semantics glyph-а.

Операционные режимы:

```text
construct
resolve
project/read distinguished pole
check
search
```

принадлежат **акту интерпретации**, а не второму значению знака.

---

# 9. Корневой словарь `∞ [ ] 1 0`

Foundation-v2 root kernel:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Root vocabulary:

```text
∞ → R
[ → O
] → C
1 → L
0 → U
```

Остенсивно:

```text
[ → O = O ⟼ R ≡ ♂∞
] → C = R ⟼ C ≡ ∞♀
```

Это **семантическое соответствие формы**, а не равенство Unicode glyphs.

```text
`[` source glyph != `♂` source glyph
`]` source glyph != `♀` source glyph
```

Root abits принадлежат Anum bootstrap; formal glyphs становятся доступны позже через string/dictionary layer.

---

# 10. Historical `♀F / F♂` — другой слой

Historical accepted v0.2 formal notation использовала projection-oriented forms:

```text
♀F
F♂
```

для historical StartProjection/EndProjection semantics.

Эти contracts остаются воспроизводимыми.

Но Foundation v2 **не переносит** эту ориентацию в ostensive self-closure semantics.

Новая foundation фиксирует:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

Поэтому в текущих Foundation-v2 формулах нельзя читать `♂/♀` как старые raw projection operators.

---

# 11. Source glyph не является semantic form

Несмотря на фундаментальность `∞ / ♂ / ♀ / ⟼` для человеческой нотации, их UTF-8 bytes не являются онтологией.

Правильная цепочка:

```text
raw UTF-8 bytes
        ↓
canonical byte-link carrier
        ↓
canonical astring content C
        ↓
exact source occurrence S
        ↓
selected exact segmentation
        ↓
scoped dictionary D
        ↓
explicit G / T admission
        ↓
exact semantic form F
```

То есть:

```text
ostensive notation is semantically meaningful
```

но:

```text
host character identity is not semantic occurrence identity
```

Эти утверждения совместимы.

---

# 12. Canonical astring

Canonical source content строится из byte carriers:

```text
C0     = R
C(n+1) = Cn ⟼ Bn
```

где `Bn` — canonical carrier очередного UTF-8 byte.

Unicode normalization не происходит скрыто.

Два source occurrences с одинаковым content остаются различными:

```text
S1 = S1 ⟼ C
S2 = S2 ⟼ C

S1 ≠ S2
```

Это сохраняет provenance формул, в том числе формул с `♂/♀`.

---

# 13. Segmentation — evidence

Trusted core не обязан иметь один магический tokenizer.

Для source выбираются exact byte slices, и каждый slice разрешается через explicit `D`.

Например:

```text
♂e
```

содержит многобайтный UTF-8 glyph `♂`.

Trusted replay проверяет:

- выбранную byte boundary;
- canonical content знака;
- exact dictionary membership;
- resolved self-closure form.

Он не доверяет host enum `TokenKind.MALE_SIGN` как semantic authority.

---

# 14. Scoped dictionary D

Dictionary topology:

```text
ScopePayload = parentScope ⟼ localHistory
D            = D ⟼ ScopePayload
```

Definition entry:

```text
Entry = sourceContent ⟼ form
```

Exact declaration:

```text
Occurrence = D_before ⟼ Entry
```

History:

```text
H_after = H_before ⟼ Occurrence
D_after = D_after ⟼ (sameParentScope ⟼ H_after)
```

Так source sign `♂` может получать meaning через ordinary relation, а не host switch.

---

# 15. `:` — definition effect

После source resolution символ `:` может обозначать explicit persistent dictionary effect.

```text
sourceContent : form
```

не означает автоматически:

```text
sourceContent = form
host assignment
theorem(form)
```

Trusted replay проверяет уже materialized definition evidence read-only.

---

# 16. Контекст `K` и `↑`

Foundation v2 context:

```text
P = parent ⟼ current
K = K ⟼ P
```

```text
↑ = current(K)
```

`current` может быть exact occurrence любой из форм:

```text
∞
♂e
b♀
b⟼e
```

Это важно: pronoun `↑` указывает не обязательно на completed pair, а на текущую relation resolution state/payload выбранного context.

---

# 17. Relation resolution на ostensive forms

Пусть selected exact form имеет shape:

```text
♂e
```

и current/binding даёт exact `b`.

Executor/search может предложить candidate:

```text
X = b ⟼ e
```

Trusted replay проверяет:

```text
form.start is form itself
form.end is e
binding is b
result.start is b
result.end is e
```

А для:

```text
b♀
```

с binding `e`:

```text
result.start is b
result.end is e
```

Никакого dispatch по glyph `♂`/`♀` trusted core не требует: направление видно в exact relation topology.

---

# 18. `=` — local representative constraint

Foundation-v2 equality:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

```text
Equal_K(a,b)
⇔ rep_K(a) is rep_K(b)
```

Одинаковая ostensive form не создаёт equality.

```text
S1 = S1⟼e
S2 = S2⟼e
```

остаются unequal exact occurrences без explicit representative evidence.

---

# 19. Grammar G и theory T

Admission explicit:

```text
G ⟼ FormSequence
T ⟼ FormSequence
T ⟼ Rule
```

То, что source text выглядит как `♂e`, ещё не даёт права выполнять его в любой theory.

Replay проверяет exact D/G/T memberships.

---

# 20. Actual act A

`I` — interpreter identity/capability.

`A` — конкретный occurred interpretation act.

Act связывает exact evidence:

```text
source
selection
D
G
T
form
K_before
binding
result
K_after
```

Для ostensive partial form это позволяет различить:

```text
саму форму ♂e

и

конкретный акт, в котором она была разрешена с b в b⟼e
```

Это принципиально разные relations.

---

# 21. Read-only replay и materialization

Replay не создаёт result relation.

```text
find / resolve candidate / replay
!=
materialize
```

Если `b⟼e` отсутствует, query `♂e + b` может завершиться отсутствием результата.

Explicit materialization — отдельный effect апамяти.

---

# 22. Ачисла и формальная нотация

Bootstrap direction:

```text
∞ + root kernel
→ [ ] 1 0
→ Anum
→ UTF-8 string Anum
→ source signs `♂ ♀ ⟼ : = ↑ ...`
→ D/T
→ formal interpreter
```

Следовательно formal text может **описать**:

```text
∞ = ∞ ⟼ ∞
```

только после того, как lower bootstrap уже сделал строки и знак `∞` доступными.

Формула не создаёт акорень собственной записью.

---

# 23. Machine/reference notation

В implementation docs допустимо использовать:

```text
Link(start,end)
OccurrenceRef
PersistentOccurrenceId
```

Но всегда должно быть понятно, какую MTS form они несут.

Canonical correspondence:

```text
MTS ostensive       structural              implementation
∞               ↔  R = R⟼R             ↔ Link(R,R)
♂e              ↔  S = S⟼e             ↔ Link(S,e)
b♀              ↔  E = b⟼E             ↔ Link(b,E)
b⟼e             ↔  X = b⟼e             ↔ Link(b,e)
```

Machine vocabulary находится справа, а не заменяет левую колонку.

---

# 24. Краткая памятка

```text
∞   акорень / fully self-closed distinguished form
♂e  self-closed start, distinguished end e
b♀  distinguished start b, self-closed end
b⟼e complete relation
↑   current exact relation from explicit K
:   explicit persistent dictionary effect after resolution
=   local representative constraint after resolution
```

Не путать:

```text
Foundation v2 ostensive:   ♂e / b♀
historical v0.2 projection: ♀F / F♂
```

---

## Главный принцип нотации

> **Формальная нотация МТС должна по возможности предъявлять структуру самой формой знака, а не требовать внешнего type annotation для понимания того, что перед нами.**

Именно поэтому `∞`, `♂`, `♀` и `⟼` являются первым слоем чтения, а tokenizer/AST/API — только последующими средствами реализации и replay.
