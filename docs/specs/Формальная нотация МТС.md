# Формальная нотация МТС

Этот документ задаёт текущее принятое предметное определение формальной нотации МТС v0.12. Исторические версии сохраняются в Git и не образуют слой, который требуется накладывать на текущий текст.

Формальная нотация является частью связевой структуры. Видимый знак, его точный носитель, выбранный контекст интерпретации, смысловой денотат и эффект исполнения — разные отношения.

Связанные нормативные поверхности:

- [Система аксиом МТС](../theory/Система%20аксиом%20МТС.md) — корневой базис, тождество Связи, роли и граница чтение/изменение;
- [Основания МТС](../theory/Основания%20МТС.md) — объяснение фундаментальных положений;
- [Ачисла и сериализация](Ачисла%20и%20сериализация.md) — точные STRING/Q-носители, байты и адресная материализация;
- [Апамять и управление сетью связей](Апамять%20и%20управление%20сетью%20связей.md) — состояния чтения и граница конкретной памяти;
- [CONTRIBUTING](../CONTRIBUTING.md) — процесс проверки и принятия изменений.

## 1. Слои формальной записи

Нормативно различаются:

```text
физический источник / знак
точный носитель
выбранный интерпретатор
структурный контекст
смысловой денотат
акт исполнения
эффект записи
```

Совпадение формы на одном уровне не даёт полномочия на другом.

```text
представление != интерпретация
носитель != денотат
Rule data != Rule execution
read/replay != write/materialize
```

Точный носитель сам по себе не выбирает действие интерпретатора; эта граница также зафиксирована в [спецификации ачисел](Ачисла%20и%20сериализация.md#mts-law-representationNotInterpretation). <!-- ссылка:mts-law-representationNotInterpretation -->

## 2. Минимальный внутренний алфавит F1

Текущий принятый внутренний набор содержит одиннадцать знаков:

```text
∞ [ ] 1 0 ( ) ⟼ : = .
```

Отложены как внутренние знаки:

```text
≡ ♂ ♀ ↑ { } ¬ ↛
```

Только метаязык использует:

```text
∧ ⇔ ⇒ ≠ →
```

Знак `↑` является вытесненным историческим исследовательским знаком; текущая контекстная нотация использует точку `.`.

Остенсивные записи `♂e` и `b♀` допустимы как теоретическая метанотация самозамыкания, но не являются автоматически исполняемыми операторами F1.

Внутренние знаки получают значения структурно, а не соглашением host-парсера:

```text
m∞ = m∞ ⟼ m∞

m[ = m[ ⟼ m∞
m] = m∞ ⟼ m]
m1 = m[ ⟼ m]
m0 = m] ⟼ m[

m( = m( ⟼ m∞
m) = m∞ ⟼ m)
m⟼ = m( ⟼ m)

m: = m∞ ⟼ m⟼
m= = m= ⟼ m=
m. = m⟼ ⟼ m∞
```

Корневая проекция этих знаков не делает разные знаки одной ролью:

```text
m∞, m=   -> R
m[, m(   -> O
m], m)   -> C
m1, m⟼   -> L
m0       -> U
m:       -> R ⟼ L
m.       -> L ⟼ R
```

Запись знака сохраняет различие носителя и значения:

```text
E_g = c_g ⟼ m_g
```

Корневые уравнения `R/O/C/L/U` принадлежат системе аксиом и здесь не переопределяются.

## 3. Явные интерпретаторы

<a id="mts-law-interpreterSeparation"></a> <!-- нормативный владелец -->
В v0.12 `I_STRING`, `I_FORMAL` и `I_Q` являются различными явными смысловыми контекстами. Режим анализатора среды исполнения, ближайший стековый кадр или форма входных данных не имеют самостоятельного смыслового полномочия.

Текущая граница:

```text
FORMAL [...] -> I_STRING
Q [...]      -> I_Q
FORMAL (...) -> I_FORMAL
()           -> ошибка empty-formal-context
```

Одинаковые физические скобки поэтому не означают один универсальный режим.

Печатный знак источника, строковый символ, четверичный абит и формальная роль не отождествляются только из-за одинакового написания.

## 4. Квадратный контекст FORMAL

<a id="mts-law-formalSquareBracketStringChild"></a> <!-- нормативный владелец -->
`FORMAL [...]` открывает дочерний `I_STRING`, а не `I_Q`.

Дочерний контекст начинается от `R`, вычисляет ровно одно значение-Связь, возвращает его родителю, после чего родитель продолжает собственный переход.

```text
FORMAL parent
  -> OPEN child I_STRING
  -> child result: exactly one Link
  -> RETURN
  -> parent continue
```

Структура точного строкового носителя определяется [спецификацией ачисел](Ачисла%20и%20сериализация.md#mts-law-stringNestedAnum). <!-- ссылка:mts-law-stringNestedAnum -->

Сам факт наличия печатного `[` не является полномочием открыть `I_STRING`. Целевой интерпретатор должен быть обоснован выбранным смысловым свидетельством.

## 5. Круглый контекст FORMAL

<a id="mts-law-formalParentheses"></a> <!-- нормативный владелец -->
`FORMAL (...)` открывает явный дочерний `I_FORMAL`.

```text
K_parent_before
  -> FORMAL_OPEN(I_FORMAL)
K_child
  -> child Acts
  -> FORMAL_CLOSE(result)
K_parent_before
  -> PARENT_CONTINUE(result)
K_parent_after
```

Результат дочернего `FORMAL`-контекста — ровно одна Связь/значение. Пустой `FORMAL`-контекст:

```text
()
```

недопустим и даёт `empty-formal-context`.

Лексическая вложенность и временной порядок акта не подменяют друг друга: структура родительства принадлежит контекстам, а ход исполнения — выбранным актам.

## 6. Явный структурный контекст K и точка

Контекст можно представлять структурно:

```text
P = parent ⟼ current
K = K ⟼ P
I ⟼ K
```

`current(K)` — внешняя метанотация чтения структуры `K`; она не является смыслом точки и не создаёт неявное изменяемое текущее значение.

<a id="mts-law-explicitKContext"></a> <!-- нормативный владелец -->
Контекстное вхождение `.` разрешается только через **явно выбранное структурное свидетельство K**.

Не являются полномочием выбора K:

- ближайший лексический кадр;
- стек анализатора среды исполнения;
- изменяемое текущее значение среды исполнения;
- неявный переход к родителю;
- само открытие дочернего контекста;
- порядок хранения или техническая ссылка.

Знак `:` может участвовать в структурном предъявлении области, но запись `A:E` сама по себе не означает «выбрать ближайший A». Любое употребление точки требует уже выбранного структурного K.

```text
m: -> R ⟼ L
m. -> L ⟼ R
```

Противоположная ориентация значений `:` и `.` не превращает точку в автоматическую операцию инверсии.

Свободная `.` без явно выбранного K не получает скрытого значения.

## 7. Связевая форма, стрелка и группировка

В F1 используется одна формальная стрелка:

```text
A ⟼ B
```

Она предъявляет направленную связевую форму с началом `A` и концом `B`. Нельзя автоматически читать её как:

- запись в память;
- вызов функции;
- логическое следование;
- присваивание;
- шаг навигации.

Для уже разрешённых полюсов производная запись:

```text
A[B] -> A ⟼ B
```

может описывать структурный денотат, но не является скрытой командой материализации.

<a id="mts-law-associationBoundary"></a> <!-- нормативный владелец -->
Левоассоциированная топология Связи, общее плоское структурное чтение и FORMAL-исполнение остаются разными уровнями.

Канонические группировки записываются явно:

```text
(A ⟼ (B ⟼ C))
((A ⟼ B) ⟼ C)
```

Незаполненная запись:

```text
A ⟼ B ⟼ C
```

не получает скрытого приоритета без отдельно выбранного производного правила разбора.

Структурная унификация может читать полюса уже существующей Связи без записи:

```text
template: BeginRole ⟼ EndRole
claimed:  X = A ⟼ B

unify
-> BeginRole = A
-> EndRole   = B
```

Чтение начала/конца не даёт полномочия на `ensure` или иную материализацию.

## 8. Исходный текст и полномочие Use

Формальный исходный текст переносится как точное `StringAnum_v012`. Его байтовая и UTF-8-граница принадлежит [спецификации ачисел](Ачисла%20и%20сериализация.md#mts-law-v012StringByteIdentity). <!-- ссылка:mts-law-v012StringByteIdentity -->

Вхождение исходного текста и его разрешённое значение различаются.

<a id="mts-law-sourceUseAuthority"></a> <!-- нормативный владелец -->
Смысловое употребление точного source допустимо только относительно **независимо выбранного** `V012SourceAuthority`:

```text
exact Dictionary identity
+ exact Grammar membership
+ exact Theory membership
```

`Dictionary`, `Grammar` и `Theory` фиксируются до проверки кандидата. Сырая форма членства, совпадение структуры или интерпретация анализатора среды исполнения не дают полномочия.

```text
replayV012SelectedSourceEvidence
!= semantic authority
```

Альтернативный хорошо сформированный Use, не совпадающий с независимо выбранным свидетельством, отклоняется.

Проверка полномочия источника выполняется только для чтения.

## 9. Полномочие результата FORMAL

Структурное правило остаётся связевыми данными:

```text
DR = DR ⟼ RoleSequence
Rule = DR ⟼ Body
T ⟼ Rule
```

Наличие таких данных не означает их исполнение:

```text
существование Rule
!= исполнение Rule
```

Для исполнения нужны явный акт, выбранный контекст, фиксированная теория и допущенное правило.

<a id="mts-law-formalResultAuthority"></a> <!-- нормативный владелец -->
Сквозное source-to-result свидетельство допустимо только если совместно проверены:

1. точный source;
2. независимо выбранные `Dictionary` / `Grammar` / `Theory`;
3. фиксированная Theory;
4. конечный **выбранный** набор `Act attachments`;
5. `Rule`, допущенный этой же `Theory`;
6. совпадение `source-selected Use` с `Rule-role binding`;
7. заявленный `grounded result`.

Композитная проверка:

```text
replayV012SourceResultEvidence
```

не позволяет кандидату самодопустить собственное правило.

Поздние или невыбранные `ambient attachments` не получают полномочия и не меняют результат уже выбранного свидетельства.

Для принятого `FORMAL [` цепочка выглядит так:

```text
exact source "["
  -> independently selected Dictionary / Grammar / Theory
  -> selected Use
  -> Rule admitted by fixed Theory
  -> grounded Rule body: selectedUse ⟼ I_STRING
  -> exact FORMAL K evidence
  -> OPEN child under grounded I_STRING
```

Низкоуровневая операция `openFormalSquareBracketContext(...)` является техническим исполнителем: она исполняет уже выбранную цель, но сама не доказывает, почему выбран именно этот интерпретатор.

До успешной проверки полномочий дочерний контекст не материализуется. Ошибка даёт ноль записей со стороны этой операции.

## 10. Знак = и локальное контекстное равенство

```text
m= = m= ⟼ m=
m= -> R
```

Формальное `=` выражает локальное для явно выбранного контекста свидетельство представителя, а не фундаментальное тождество Связи.

На метауровне:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
Binding != K
```

Одношаговое локальное разрешение можно описать:

```text
Eq_K(X,Y)
iff
localRepresentative(K,X) = localRepresentative(K,Y)
```

Если для одного `(K,X)` предъявлены различимые представители, evidence конфликтно. Нельзя выбирать «первый», «последний» или иной вариант по истории, порядку хранения или техническому идентификатору.

Конфликт не означает `Eq_K=false`; он означает отсутствие однозначного корректного свидетельства.

Необходимо различать:

```text
фундаментальное тождество Связи по полюсам
!= контекстное Eq_K
!= физическое равенство технических ссылок
```

`=` не является присваиванием, глобальной подстановкой, транзитивным замыканием или автоматической конгруэнтностью.

Отдельный `≡` в текущем F1 не требуется и остаётся отложенным.

## 11. Эффекты и материализация

Знаки `:`, `=`, `.`, скобки и сама форма Rule не имеют скрытого права записи.

```text
разобрать / разрешить / проверить / воспроизвести
!=
материализовать / записать
```

Историческое имя `replayColonEffect` не определяет смысл `:`; совместимое более точное имя `replayDefinitionEffect` описывает проверку уже существующего свидетельства эффекта. Материализация такого эффекта остаётся отдельной операцией.

Общая граница чтение/изменение принадлежит системе аксиом; FORMAL использует её, но не переопределяет.

## 12. Производные навигационные слои

Прямая дейктика и производная навигация могут хранить `path`, `up`, `pole` как свидетельства вхождения. Это не текущий синтаксис F1 и не тождество смысловой Связи.

```text
координата пути
!= тождество Связи
```

Обратное отношение навигации:

```text
S^op(y,x) iff S(x,y)
[ S1,...,Sn ]^op = [ Sn^op,...,S1^op ]
```

не является отдельным знаком F1 и отличается от рекурсивной реверсии, перестановки полюсов, несвязи и логического отрицания.

Эти производные слои не меняют минимальную формальную основу v0.12.

## Кандидат v0.13: относительные формы и четверичное заземление

Следующие владельцы относятся к непринятому кандидату v0.13. Они фиксируют уже доказанную исследовательскую семантику, но сами по себе не переключают принятую текущую версию с v0.12.

<a id="mts-law-L2"></a> <!-- нормативный владелец -->
### L2. Форма Связи и результат исполнения различаются

Для `S = a ⟼ b` относительные формы являются самостоятельными Связями:

```text
P = P ⟼ S
Q = S ⟼ Q
D = P ⟼ Q
I = Q ⟼ P
```

а их результаты:

```text
P ⇓ a
Q ⇓ b
D ⇓ S
I ⇓ -S = b ⟼ a
```

Поэтому тождество формы не тождественно тождеству результата. Совпадение результатов не разрешает схлопывать различные формы.

<a id="mts-law-L3"></a> <!-- нормативный владелец -->
### L3. Относительная навигация принадлежит явному контексту Связи

Для выбранной целой Связи `S` операция начала читает `start(S)` и открывает позицию начала, а операция конца читает `end(S)` и открывает позицию конца.

Внутри открытой позиции:

```text
та же сторона      -> более глубокий контекст Связи
противоположная    -> один объемлющий контекст Связи
```

Полномочие такого перехода несёт явная структурная связь контекста. Стек анализатора среды исполнения и неявное изменяемое «текущее значение» полномочием не являются.

<a id="mts-law-L12"></a> <!-- нормативный владелец -->
### L12. Смысл четверичных знаков задаётся FORMAL-полномочием

Физические знаки `8`, `9`, `6`, `1` не получают смысл класса из печатного совпадения или ветвления программы.

Нормативный путь:

```text
точный физический источник
-> точный STRING-источник
-> выбранный Use словаря
-> членство Grammar
-> фиксированная Theory
-> допущенный FORMAL StructuralRule
-> ROOT / START / END / PAIR
```

Другой допустимый Rule той же Theory не может быть подставлен вместо правила, связанного с данным точным источником. Одинаковое начертание в разных ролях не создаёт смыслового тождества.

## 13. Историческая граница

В v0.10/v0.11 существовало описание квадратного FORMAL-контекста как перехода к `Q`. Для текущей v0.12 это **историческая граница**, а не применяемая норма.

Текущая граница однозначна:

```text
FORMAL [...] -> I_STRING
Q [...]      -> I_Q
FORMAL (...) -> I_FORMAL
```

Старые формулировки `nearest A:E`, `ambient current`, `parser-stack authority` и неявное открытие `I_Q` из `FORMAL` не применяются к текущей версии.

Отложенные знаки:

```text
≡ ♂ ♀ ↑ { } ¬ ↛
```

также не становятся исполняемыми только потому, что встречаются в исторической или теоретической записи.

Историческое происхождение этих решений доступно через Git; процесс принятия будущих изменений описан в [CONTRIBUTING](../CONTRIBUTING.md).

## Итог

Текущая FORMAL-граница v0.12:

- F1 содержит `∞ [ ] 1 0 ( ) ⟼ : = .`;
- смысл знака не определяется анализатором среды исполнения;
- `FORMAL [...]` открывает `I_STRING`;
- `Q [...]` остаётся `I_Q`;
- `FORMAL (...)` открывает `I_FORMAL`, а `()` недопустим;
- точка разрешается только через явно выбранное структурное `K`;
- source переносится как точное `StringAnum_v012`;
- `Dictionary`, `Grammar` и `Theory` выбираются независимо до кандидата;
- `Rule` должен быть допущен фиксированной `Theory`;
- `source-selected Use` должен совпадать с `Rule-role binding`;
- только выбранные конечные `Act attachments` участвуют в результате проверки;
- поздние `ambient attachments` не получают полномочия;
- наличие Rule не означает его исполнение;
- плоское чтение, топология Связи и `FORMAL execution` различаются;
- чтение, replay и проверка не дают скрытого права материализации.
