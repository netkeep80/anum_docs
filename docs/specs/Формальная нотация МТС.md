# Формальная нотация МТС

Статус: актуальное, нормативное.

Уровень: **L2 — формальный язык**.

## Назначение

Формальная нотация МТС записывает формы, определения и суждения, чья L1-денотация задаётся [Reference model МТС v0.1](Reference%20model%20МТС%20v0.1.md).

Формальная нотация не вводит внешний источник смысла и не является форматом хранения апамяти.

## Источник формул

Текущая машинная поверхность формул находится в [корневом fixture](../../tests/mtc_formulas.mtc). Чтение принятых аксиом/определений дано в [Системе аксиом МТС](../theory/Система%20аксиом%20МТС.md).

Нахождение строки в fixture не определяет автоматически её логический статус. Статусы `definition`, `derived`, `conformance` и `experimental` различаются согласно reference model.

## Граница L2 ↔ L3

Совпадение видимого знака не означает совпадения объекта разных уровней.

```text
L2: [...]  — квадратная формальная/ачисловая форма в языке МТС
L3: [ ]    — два glyph базового четверичного алфавита абитов
```

Любое тождество или проекция между ними должно задаваться явным правилом L3. Рабочая гипотеза issue #61 не считается частью L2 только потому, что использует те же квадратные знаки.

## Скобочные нотации

```text
(...) — круглая формальная нотация
[...] — квадратная форма L2
{...} — пучковая нотация
```

```text
[] — минимальная завершённая форма одной связи
() — минимальная формальная форма смысла
{} — пустой пучок связей
```

Три пустые формы различимы:

```text
[] != ()
() != {}
{} != []
```

Скобки не взаимозаменяемы. В `([)` и `(])` квадратный знак является буквальным glyph/абитом внутри круглой формы. В `[1]` и `[0]` квадратные скобки являются границами квадратной формы.

## Связь как оператор и как формальная форма смысла

Нужно различать два L2-вхождения одного видимого glyph:

```text
A ⟼ B
```

— инфиксный бинарный конструктор формы связи. Его L1-денотация:

```text
Link(A, B)
```

А:

```text
(⟼)
```

— круглая формальная форма **смысла связи**, введённая корневой системой.

Поэтому нельзя подменять AST узла `A ⟼ B` литералом `(⟼)` или наоборот только из-за общего glyph.

Аналогично `(↛)` является формальной формой смысла несвязи. Несвязь не существует в натуре; её смысл выражается связью.

## Полюса формы

Полюса записываются в актуальной ориентации:

```text
♀F — начало формы, prefix
F♂ — конец формы, postfix
```

Reference model v0.1 задаёт их циклическое чтение:

```text
♀F = Link(♀F, F)
F♂ = Link(F, F♂)
```

Старая ориентация `F♀` и `♂F` не используется в активной нотации.

## Основные сигнатуры

| Знак | Вход | Результат | Ассоциативность |
|---|---|---|---|
| `:` | `Form × Form` | `Definition` | справа |
| `=` | `Form × Form` | `Judgment` | нет |
| `!=` | `Form × Form` | `Judgment` | нет |
| `⟼` | `Form × Form` | `Form` | слева |
| `¬` | `Form` | `Form` | prefix |
| `♀` | `Form` | `Form` | prefix |
| `♂` | `Form` | `Form` | postfix |
| `(...)` | `Form` | `Form` | container |
| `[...]` | `Form` | `Form` | container |
| `{...}` | `Form*` | `Bundle` | container |

Численные приоритеты являются машинным контрактом `core/reference_model.py` и используются будущим typed parser.

## Локальный контекст определения

Форма:

```text
A : F
```

вводит различие `A` через локальную форму `F`.

Это L2-definition, а не L4-команда изменения памяти.

Повторные видимые знаки являются разными позиционными вхождениями одной локально заданной формы. Они связаны локальным контекстом определения, но не являются глобальной текстовой переменной.

```text
∞ : [] = [] ⟼ []
(=) : {♀[] = ♀[], []♂ = []♂}
```

Будущий typed AST обязан хранить occurrence identity и контекст, а не восстанавливать их по совпадению исходных строк.

## Роли вхождений

Видимый glyph не равен AST-вхождению glyph.

| Роль | Пример | Чтение |
|---|---|---|
| `container-boundary` | `[1]`, `{[]}`, `(A)` | граница контейнера |
| `literal-abit` | `([)`, `(])` | буквальный квадратный glyph внутри круглой формы |
| `one-link-form` | `[]` | форма одной связи |
| `link-pole-form` | `♀[]`, `[]♂` | начало или конец формы связи |
| `abit-form` | `[1]`, `[0]` | квадратная форма абита |
| `formal-form` | `(⟼)`, `(↛)` | формальная форма смысла |
| `link-constructor` | `A ⟼ B` | бинарная форма связи |
| `empty-formal-form` | `()` | минимальная формальная форма смысла |
| `grouped-form` | `(A)` | группировка уже заданной формы |
| `bundle-form` | `{}`, `{[]}` | форма пучка связей |

Поэтому `([)` нельзя читать как незакрытый квадратный контейнер, `[1]` — как список, `{}` — как форму одной связи, а `A ⟼ B` — как простой текстовый маркер оператора.

## Пучки

Пучок удерживает несколько форм как одну пучковую форму. Текущий fixture фиксирует экстенсиональные свойства:

```text
{} != []
{[]} != []
{[], []} = {[]}
{[], [][]} = {[][], []}
```

Порядок элементов несущественен, повтор не создаёт новый элемент пучка.

Пучковое раскрытие в текущем fixture является описательной формой. Оно не является скрытой L4-командой создания или удаления связей.

## Требования к front-end

Reader/parser L2 должен:

- сохранять source span;
- различать роли одинаковых glyph;
- строить typed AST до семантической оценки;
- применять приоритеты и ассоциативность reference model;
- не смешивать L2 square forms с L3 raw abits;
- не назначать смысл по `str.replace`, regex или совпадению текста.

Текущий `core/mtc_reader.py` остаётся техническим reader до появления typed front-end; он не является полной грамматикой или semantic interpreter.
