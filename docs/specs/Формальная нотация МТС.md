# Формальная нотация МТС

Этот документ описывает текущую принятую формальную нотацию **МТС v0.10**. Нормативная теория задаёт смысл, принятый контракт и корпус соответствия фиксируют переносимую машинную границу, а пакет `@mts/core` на `TypeScript` реализует её. МТС v0.9 остаётся предыдущей неизменяемой парой свидетельств.

Связанные документы:

- [Основания МТС](../theory/Основания%20МТС.md)
- [Система аксиом МТС](../theory/Система%20аксиом%20МТС.md)
- [Ачисла и сериализация](Ачисла%20и%20сериализация.md)
- [Апамять и управление сетью связей](Апамять%20и%20управление%20сетью%20связей.md)

## 1. Слои нельзя смешивать

В МТС v0.10 различаются:

```text
физический источник / знак
носитель представления
выбранный контекст интерпретации
смысловой денотат
```

Поэтому один и тот же видимый знак может участвовать на разных уровнях, но его смысл не выбирается эвристикой по форме входных данных.

```text
представление ≠ интерпретация
носитель ≠ денотат
вхождение в источник ≠ тождество смысловой связи
```

## 2. Минимальный внутренний алфавит F1

Принятый F1 v0.10 содержит ровно одиннадцать внутренних знаков:

```text
∞ [ ] 1 0 ( ) ⟼ : = .
```

Отложены как внутренние знаки:

```text
≡ ♂ ♀ ↑ { } ¬ ↛
```

`↑` дополнительно является вытесненным историческим исследовательским знаком: активная контекстная нотация v0.10 использует связанную точку `.`.

Только в метаязыке используются:

```text
∧ ⇔ ⇒ ≠ →
```

Остенсивные записи `♂e` / `b♀` остаются допустимой теоретической метанотацией самозамыкания, но не являются текущими токенами F1 или автоматически исполняемыми операторами.

## 3. Самовведение знаков

Внутренние знаки получают значения не через соглашение анализатора языка реализации, а через замкнутую асеть аксиом.

```text
m∞ = m∞ ⟼ m∞

m[ = m[ ⟼ m∞
m] = m∞ ⟼ m]
m1 = m[ ⟼ m]
m0 = m] ⟼ m[

m( = m( ⟼ m∞
m) = m∞ ⟼ m)
m⟼ = m( ⟼ m)

m: = m∞ ⟼ m⟼
m= = m= ⟼ m=
m. = m⟼ ⟼ m∞
```

Корневая проекция:

```text
m∞, m=   -> R
m[, m(   -> O
m], m)   -> C
m1, m⟼   -> L
m0       -> U
m:       -> R ⟼ L
m.       -> L ⟼ R
```

Совпадение корневой проекции двух знаков не делает их одной записью или одной ролью. Запись знака хранит отдельно носитель и значение:

```text
E_g = c_g ⟼ m_g
```

## 4. Корневой базис

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой четверичный словарь:

```text
[ -> O
] -> C
1 -> L
0 -> U
```

`∞` не является пятым абитом.

## 5. Единственная формальная стрелка

В текущем F1 нет второго формального синонима стрелки.

```text
A ⟼ B
```

предъявляет направленную связевую форму с началом `A` и концом `B`.

Нельзя автоматически читать `⟼` как создание записи, выполнение действия, логическое следование или шаг навигации. Эффект определяется выбранной теорией, правилом и актом.

### Производные WRITE и READ

Для уже разрешённых полюсов квадратный контекст даёт производный шаблон конструкции:

```text
A[B] -> A ⟼ B
```

Это структурный WRITE денотата, а не скрытая команда материализации.

Обратное направление в v0.10 выражается без новых знаков Begin/End: один бинарный структурный шаблон с двумя role Links читается через read-only structural unification:

```text
template: BeginRole ⟼ EndRole
claimed:  X = A ⟼ B

unify
-> BeginRole = A
-> EndRole   = B
```

Поэтому:

```text
readBegin(A ⟼ B) = A
readEnd(A ⟼ B)   = B
construct(readBegin(X), readEnd(X)) = X
```

Последнее равенство следует из тождества связи по упорядоченным полюсам, а не из номера runtime handle. READ не вызывает `find`, `ensure` или материализацию и корректно возвращает самоссылочный полюс целиком для `R=R⟼R`, `S=S⟼E` и `T=B⟼T`.

## 6. Круглые скобки — явный контекст `FORMAL`

`(` и `)` являются отдельными внутренними знаками с собственными уравнениями. Они не являются лишь пунктуацией группировки языка реализации.

Принятый жизненный цикл:

```text
K_parent_before
  -> FORMAL_OPEN(target I)
K_child(parent=K_parent_before,current=initial)
  -> child Acts
K_child_final
  -> FORMAL_CLOSE(result)
K_parent_before
  -> PARENT_CONTINUE(result)
K_parent_after
```

Лексическая вложенность принадлежит `K.parent`, временной порядок — структуре `Run`/`Act`. Эти две оси не смешиваются.

## 7. Текущее значение `FORMAL` хранится через `ExactSequence`

Обычная левая свёртка не может быть универсальным носителем последовательности, если допустимо значение `R`:

```text
[]   -> R
[R]  -> R
```

Поэтому используется корнебезопасный носитель:

```text
Seq([]) = R
Cell(prev,value) = start-self-closed(prev ⟼ value)
Seq(xs + [x]) = Cell(Seq(xs), x)
```

Следовательно:

```text
Seq([]) != Seq([R])
```

при этом второй `R` не создаётся: позиция выражается структурой носителя.

## 8. Квадратные скобки — контекст `Q`

В четверичном контексте:

```text
[ ... ]
```

открывает и закрывает явный вложенный контекст `Q`.

Каждый новый контекст `Q` начинается относительно `R`:

```text
des(ε) = R
des([]) = R
```

Пустая группа допустима.

## 9. Состояние `Q` структурно

Скрытый флаг `started:boolean` не является смысловым основанием.

```text
QEmpty = R
QNonEmpty(inner) = start-self-closed(inner)
```

Это различает пустое состояние и непустое состояние, первым значением которого является `R`, без второго экземпляра корня и без скрытого булева поля.

## 10. Возврат между `Q` и `FORMAL`

Закрытие дочернего `Q` и продолжение родительского `FORMAL` — разные переходы:

```text
Q_CLOSE
!=
PARENT_CONTINUE
```

Закрытие дочернего контекста возвращает значение, а отдельное продолжение родителя добавляет его в прежний `ExactSequence`.

Особенно важно, что:

```text
[] -> R
```

и возвращаемый `R` сохраняется как явная позиция.

## 11. Группировка связевой формы

Каноническая формальная связь записывается явно:

```text
(A ⟼ B)
```

Вложенные формы различаются:

```text
(A ⟼ (B ⟼ C))
((A ⟼ B) ⟼ C)
```

Не вводится неявная ассоциативность или приоритет, который сам выбирает одну из группировок.

Запись:

```text
A ⟼ B ⟼ C
```

не является канонической формой основания без отдельно выбранного производного правила разбора.

## 12. Пустой `FORMAL`

Минимальный F1 не допускает пустую формулу:

```text
()
```

как автоматически осмысленную конструкцию. Группировка одной формы может быть допущена отдельным структурным правилом.

## 13. Знак `:` и контекст `A:E`

```text
m: = m∞ ⟼ m⟼
```

Его значение выражает переход от внешнего единства к внутренней ориентированной дуальности:

```text
m: -> R ⟼ L
```

В МТС v0.10 принята контекстная форма:

```text
A : E
```

Она открывает внутреннюю область связи `A`. Свободная точка внутри `E` связывается с ближайшим таким `A`:

```text
resolve_A(.) = A
```

Формальный `:` не означает автоматически классическое равенство, глобальное присваивание, текстовую подстановку по всей асети, dictionary write или вызов функции среды реализации.

Исторический публичный `replayColonEffect` не задаёт смысл `:`: он только читает и проверяет уже существующее свидетельство dictionary-definition effect. Для этой же функции существует более точное совместимое имя:

```text
replayDefinitionEffect === replayColonEffect
```

Материализация definition effect выполняется отдельно и не следует из присутствия glyph `:` или формы `A:E`.

## 14. Знак `.`

```text
m. = m⟼ ⟼ m∞
```

и:

```text
m. = Inv(m:)
```

То есть `:` и `.` имеют противоположную ориентацию по полюсам своих значений:

```text
m: -> R ⟼ L
m. -> L ⟼ R
```

Но contextual occurrence `.` — не «операция инверсии». В области:

```text
A : E
```

она обозначает связанную текущую связь `A` как целое.

Канонические формы:

```text
∞ : . ⟼ . -> ∞ = ∞ ⟼ ∞
O : . ⟼ ∞ -> O = O ⟼ R
C : ∞ ⟼ . -> C = R ⟼ C
```

Свободная `.` вне явного binder не получает ambient значение. Точка не является `current(K)`, переходом к родителю, READ begin/end, поиском или обращением к хранилищу.

## 15. Знак `=`

```text
m= = m= ⟼ m=
```

с корневой проекцией:

```text
m= -> R
```

В МТС v0.10 формальное `=` использует локальное для явного контекста свидетельство представителя.

Внешняя метанотация:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Точный производный judgment:

```text
Eq_K(X,Y)
iff
localRepresentative(K,X) = localRepresentative(K,Y)
```

Разрешение локально выбранному `K` и одношагово. Binding родительского контекста не наследуется дочерним автоматически, а цепочка:

```text
X -> Y
Y -> Z
```

не означает автоматическое разрешение `X -> Z`.

Поэтому нужно строго различать:

```text
фундаментальное тождество смысловой Link по полюсам
!= контекстное равенство ссылок Eq_K
!= физическое равенство runtime handles
```

`=` не является присваиванием, dictionary write, глобальным quotient, транзитивным замыканием, глобальной подстановкой или конгруэнтностью.

Отдельный знак `≡` в текущем F1 не требуется: фундаментальное тождество уже задаётся А6/F3, а контекстное равенство ссылок — `=`. `≡` остаётся отложенным до появления независимой обязанности.

## 16. Структурное правило

Правило является связевыми данными:

```text
DR = DR ⟼ RoleSequence
Rule = DR ⟼ Body
T ⟼ Rule
```

Акт связывает объявленную роль со значением структурно.

Проверка требует:

- ровно одно связывание на каждую объявленную роль;
- отсутствие необъявленных связываний;
- точное свидетельство исходного контекста;
- допуск выбранного правила в `T`;
- отсутствие записи в память при проверке.

Идентификатор функции обратного вызова, перечисление вида правила или поле типа среды реализации не являются смысловым основанием.

## 17. Данные правила не исполняются сами

```text
существование Rule
!= исполнение Rule
```

Для перехода состояния нужен явный акт, контекст и выбранный путь интерпретатора. То же относится к конечным функциям-данным и прикладным отношениям.

## 18. Интерпретатор и контекст

```text
I = D ⟼ (G ⟼ T)
```

Контекст среды исполнения:

```text
P = parent ⟼ current
K = K ⟼ P
I ⟼ K
```

`current(K)` здесь — внешняя метанотация чтения структуры `K`. Она не является смыслом точки `.` и не подменяет связанную область `A:E`.

## 19. Исходная строка

Формальный источник переносится как точное строковое содержимое.

Для каждого байта `p`:

```text
Rep_SQ(byte p) = [bbbbbbbb]
Byte(p) := Denote_Q([p])
```

Внутри скобок ровно восемь бит, старший бит первым. Один физический байт соответствует одному четверичному конверту.

## 20. Словарь байтов структурен

Все 256 значений `Byte(p)` выводятся из структуры `Q`, а не вводятся как 256 непрозрачных технических идентификаторов.

Повтор байта в строке повторяет одну смысловую связь байта через разные позиции `ExactSequence`.

Некорректная последовательность UTF-8 может быть допустима на уровне точных байтов и отклоняться отдельным строгим текстовым слоем.

## 21. Знак источника и действие интерпретатора различаются

Например физический знак `[` имеет байтовый носитель:

```text
[01011011]
```

Это не автоматически действие открытия `Q`.

Нужен явный выбранный контекст:

```text
один носитель + строковое чтение
!=
тот же носитель + четверичное структурное чтение
```

Тот же принцип относится к `:` и `=`: наличие знака или его Entry не является автоматическим выполнением definition/equality effect.

## 22. `♂` и `♀` остаются теоретической метанотацией

Полезно писать:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
♂♀ = ∞
```

Но `♂` и `♀` находятся в отложенном реестре внутренних знаков F1 v0.10. Нельзя создавать возможность анализатора только потому, что эти знаки удобны в теоретическом изложении.

## 23. Остальные отложенные знаки

```text
≡ ↑ { } ¬ ↛
```

не являются частью минимальной текущей системы самовведения.

Для текущего состояния:

```text
≡  -> отложен; независимая роль не доказана после разделения А6/F3 и Eq_K
↑  -> вытеснен точкой `.` из активной контекстной нотации
```

Их возможное будущее принятие потребует отдельного фальсифицируемого основания и, при наблюдаемом машинном изменении, отдельного жизненного цикла кандидата и выпуска.

## 24. Прямая дейктика — отдельный производный слой

Текущая реализация прямой дейктики на `TypeScript` хранит:

```text
path
up
pole
```

как свидетельство вхождения и навигации. Это специализированное корневое представление свидетельства, а не текущий синтаксис F1 и не общая теория навигации.

```text
координата пути
!= тождество смысловой связи
```

Одна смысловая подасеть может встречаться в нескольких структурных позициях без смыслового копирования.

## 25. Обратное отношение навигации не является знаком F1

В производной теории навигации:

```text
S^op(y,x) iff S(x,y)
[ S1,...,Sn ]^op = [ Sn^op,...,S1^op ]
```

Но обратное отношение навигации отличается от рекурсивной реверсии `J`, перестановки полюсов `Inv`, несвязи `U` и логического отрицания.

## 26. Формальная нотация не определяет материализацию

```text
разобрать / разрешить / проверить / воспроизвести
!=
материализовать / записать
```

И:

```text
не найдено != не существует
```

Закрытие контекста, structural READ, проверка правила и проверка равенства не имеют права создавать отсутствующее свидетельство лишь потому, что оно не найдено.

## 27. Смысловая связь и вхождение

F2/F3 дают:

```text
одинаковая рекурсивно заземлённая форма
=> одна смысловая связь
```

Поэтому смысловая связь не тождественна вхождению в источник, позиции последовательности, вхождению акта, координате пути, технической ссылке или строке хранения.

Если множественность существенна, она выражается явной структурой вхождений, происхождения и истории.

## 28. Краткая памятка

```text
внутренние знаки:
  ∞ [ ] 1 0 ( ) ⟼ : = .

отложены:
  ≡ ♂ ♀ ↑ { } ¬ ↛

только метаязык:
  ∧ ⇔ ⇒ ≠ →

Q:
  [ ... ]
  пустое значение -> R
  состояние структурно
  A[B] -> A ⟼ B как derived WRITE

FORMAL:
  ( ... )
  текущее значение через ExactSequence
  явный допуск структурных правил
  нет скрытого приоритета

контекстная дуальность:
  A:E
  nearest `.` -> A
  free `.` запрещена

READ:
  BeginRole ⟼ EndRole + X
  -> read-only structural unification
  -> begin/end без новых glyphs

равенство:
  А6/F3 identity != Eq_K != runtime handle equality
  Eq_K локально K и one-hop

эффект определения:
  `:` сам по себе не пишет словарь
  replayDefinitionEffect проверяет уже существующее evidence

STRING:
  точные байты
  один [8 bits] на байт

тождество:
  смысловая связь != вхождение / путь / технический id

эффекты:
  чтение / replay != запись / materialize
```

## Главный принцип

> Формальная нотация МТС v0.10 является частью связевой структуры и самовведения. Знаки, переходы контекстов и носители не получают смысл из соглашений анализатора языка реализации; реализация обязана соответствовать принятой теории, контракту и корпусу соответствия.
