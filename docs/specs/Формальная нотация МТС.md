# Формальная нотация МТС
<!-- версия документа МТС; mts-doc-version: v0.14 -->
> **Версия МТС: v0.14**

FORMAL — слой **символьной метанотации и явной интерпретации** над уже существующей Link-структурой и sequence carriers. Он не владеет онтологией Link и не определяет внутреннюю семантику Anum/Q.

## 1. Где находится FORMAL

Полная цепочка слоёв:

```text
Link
  ↓
recursive structure 8/9/6/1
  ↓
Anum / ExactSequence / Q
  ↓
STRING / UTF-8
  ↓
names / Dictionary / Grammar / Theory / FORMAL
```

FORMAL принадлежит последнему слою. Он задаёт, **как символы и роли интерпретируются**, но не создаёт второй тип сущности.

<a id="mts-law-interpreterSeparation"></a> <!-- исторический стабильный якорь -->

## 2. Интерпретационный authority всегда явен

Минимальная схема:

```text
exact source
    ↓
selected Dictionary Use
    ↓
Grammar
    ↓
fixed Theory
    ↓
admitted StructuralRule
    ↓
FORMAL result
```

Хорошо сформированный текст не может сам назначить себе Dictionary, Grammar или Theory.

Остенсивные синонимы:

```text
∞  = ROOT  = 8
♂  = START = 9
♀  = END   = 6
⟼  = PAIR  = 1
```

Грамматические формы:

```text
∞
♂S
S♀
A ⟼ B
```

У `PAIR` нет неявной ассоциативности. Неоднозначные негруппированные выражения должны отвергаться или получать группировку от явной Grammar.

Важно: `START/END` здесь — **локальные ориентированные роли Context**, а не абсолютные глобальные стороны Foundation.

## 4. FORMAL не заменяет recursive alphabet

Символы `∞/♂/♀/⟼` — удобная формальная запись структурных аспектов. Рекурсивный алфавит `8/9/6/1` — structural representation.

Это два представления одной нижележащей Link-структуры, но не одно и то же:

```text
recursive alphabet -> compact structural representation
ostensive glyphs   -> formal source notation
```

<a id="mts-law-formalSquareBracketStringChild"></a> <!-- исторический стабильный якорь -->

Квадратный source-context принадлежит строковому/sequence интерпретатору, а не автоматически FORMAL.

<a id="mts-law-formalParentheses"></a> <!-- исторический стабильный якорь -->

Круглый FORMAL-context обозначает вложенную формальную композицию только через явно выбранную Grammar.

## 5. Context

<a id="mts-law-explicitKContext"></a> <!-- исторический стабильный якорь -->

Context выражается Links и не заменяется скрытым runtime state.

Удобная форма текущего payload:

```text
Payload = parent ⟼ current
```

Ориентационная роль Context выводится отдельно через A4′. Поэтому техническое чтение полюсов и семантический `START_K/END_K` — разные уровни.

## 6. Форма и результат исполнения различаются

<a id="mts-law-L2"></a> <!-- исторический стабильный якорь -->

Структурное выражение — это не его результат.

Например:

```text
S = a ⟼ b
```

задаёт форму Link, но не утверждает, что конкретная Theory обязана исполнить её как переход или получить заранее заданный результат.

## 7. Относительная навигация

<a id="mts-law-L3"></a> <!-- исторический стабильный якорь -->

Навигация по структуре должна быть привязана к явной рамке/Context. В зеркальном Context роли полюсов транспортируются через `J`.

Следовательно, вызов технического `.start/.end` может быть способом доступа реализации, но не становится сам по себе семантическим доказательством `START_K/END_K`.

## 8. Dictionary

`Dictionary` связывает имена с уже различёнными структурными ролями/Links.

Имена — не Link identity. Переименование символа не меняет саму Link-структуру.

Один и тот же Link может иметь разные допустимые имена в разных Dictionary, если выбор Dictionary явен.

## 9. Grammar

`Grammar` определяет допустимую композицию source forms.

Она отвечает, например, за:

- группировку;
- допустимость вложенности;
- связь символических операторов с структурными ролями;
- отклонение неоднозначных форм.

Grammar не получает права материализовать Links только из факта синтаксической корректности.

## 10. Theory и StructuralRule

Удобная структурная схема:

```text
Interpreter = Dictionary ⟼ (Grammar ⟼ Theory)
```

Rule:

```text
RoleDictionary = START(RoleSequence)
Rule           = RoleDictionary ⟼ Body
Admission      = Theory ⟼ Rule
```

Только Links, явно перечисленные в `RoleDictionary`, играют роль переменных. Остальная структура шаблона остаётся заземлённой.

## 11. Полномочие источника

<a id="mts-law-sourceUseAuthority"></a> <!-- исторический стабильный якорь -->

FORMAL source получает смысл не потому, что «похож на правило», а через цепочку:

```text
exact source
+ selected Dictionary Use
+ Grammar
+ fixed Theory
+ admitted rule
```

Ambient-похожесть, имя файла, host-object или порядок регистрации не дают семантического authority.

## 12. Полномочие результата

<a id="mts-law-formalResultAuthority"></a> <!-- исторический стабильный якорь -->

FORMAL result допускается только после валидного source/use/theory path. Результат не может сам себя легитимировать.

Чтение и materialization остаются разделены: parser/interpreter может распознать выражение без скрытой записи новых Links.

## 13. Ассоциативность и группировка

<a id="mts-law-associationBoundary"></a> <!-- исторический стабильный якорь -->

Запись:

```text
A ⟼ B ⟼ C
```

не имеет универсальной неявной ассоциативности FORMAL.

Допустимы только:

```text
(A ⟼ B) ⟼ C
A ⟼ (B ⟼ C)
```

или иная группировка, если она однозначно задана Grammar.

## 14. Инверсия J и FORMAL

`J` действует на Link-структуру. FORMAL может быть эквивариантен этому действию только при согласованном переносе:

- Context orientation;
- Dictionary roles;
- Grammar conventions;
- Theory admissions;
- StructuralRule bodies.

Это не означает, что текущая Dictionary буквально остаётся той же самой при зеркальном переходе. Authority должен быть транспортирован согласованно.

## 15. Отношение к Anum/Q

FORMAL не переопределяет:

- `Anum`;
- `ExactSequence`;
- Q14/Q13;
- byte identity STRING.

Он может **использовать** эти carriers как source, но их внутренняя идентичность принадлежит [«Ачислам и сериализации»](Ачисла%20и%20сериализация.md).

## 16. Что FORMAL не утверждает

FORMAL не означает, что:

- символ сам по себе является Link;
- любой parseable source допустим текущей Theory;
- Grammar может скрыто выбрать Context orientation;
- parser имеет право записи;
- один glyph обязан иметь один смысл во всех слоях;
- физический ISA обязан совпадать с `∞/♂/♀/⟼`.

## Итог

```text
source
  ↓
Dictionary Use
  ↓
Grammar
  ↓
Theory
  ↓
admitted StructuralRule
  ↓
FORMAL composition
  ↓
explicit result authority
```

FORMAL v0.14 — это **явно авторизованная символьная проекция** Link-семантики, а не самостоятельная онтология и не скрытый runtime.
