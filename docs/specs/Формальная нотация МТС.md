# Формальная нотация МТС

Этот документ описывает текущую формальную нотацию принятого основания MTS v0.7. Будущие расширения нотации и семантики требуют отдельных решений о принятии.

Связанные документы:

- [Основания МТС](../theory/Основания%20МТС.md)
- [Система аксиом МТС](../theory/Система%20аксиом%20МТС.md)
- [Ачисла и сериализация](Ачисла%20и%20сериализация.md)
- [Апамять и управление сетью связей](Апамять%20и%20управление%20сетью%20связей.md)

## 1. Остенсивная запись первична

Главные знаки:

```text
∞
♂
♀
⟼
```

Для начала `b` и конца `e`:

```text
∞        оба полюса самозамкнуты
♂e       начало самозамкнуто, конец e различён
b♀       начало b различено, конец самозамкнут
b ⟼ e    оба полюса различены
```

Структурно:

```text
R = R ⟼ R
S = S ⟼ e
E = b ⟼ E
X = b ⟼ e
```

Остенсивная форма предшествует программному представлению.

## 2. Единственный акорень

```text
∞ = ∞ ⟼ ∞
```

Полностью самозамкнутая связь единственна:

```text
X = X ⟼ X
=>
X = ∞
```

Нельзя различить две такие формы только по внешним техническим адресам. Сам адрес не является знаком МТС и не создаёт смысловой полюс.

## 3. Самозамыкание начала и конца

Форма:

```text
♂e = S = S ⟼ e
```

показывает самозамкнутое начало и уже различённый конец `e`.

Форма:

```text
b♀ = E = b ⟼ E
```

показывает уже различённое начало `b` и самозамкнутый конец.

`♂` и `♀` **не являются встроенными командами получения полюсов**. Они показывают способ структурного различения связи.

Для уже различённого `e` форма `♂e` единственна. Для уже различённого `b` форма `b♀` единственна.

### Замкнутый шаблон `♂♀`

Запись:

```text
♂♀
```

не означает `♂(♀)` и не делает `♂`/`♀` самостоятельными значениями. Она обозначает предельный остенсивный случай, в котором левое и правое самозамыкание замкнуты друг через друга без внешнего уже различённого полюса.

Если временно обозначить соответствующие связи через `y` и `x`, шаблон раскрывается как:

```text
y = y ⟼ x
x = y ⟼ x
```

По тождеству связи `x=y`, после чего остаётся полное самозамыкание:

```text
x = x ⟼ x
```

Следовательно:

```text
♂♀ = ∞
```

Это именно **схлопывание однополюсного шаблона в полностью самозамкнутую форму**, а не утверждение `♂∞ = ∞` или `∞♀ = ∞`: корневые `♂∞ = O` и `∞♀ = C` остаются различёнными, потому что в них `∞` является уже внешне различённым полюсом относительно `O` или `C`.

## 4. Полная связь

```text
b ⟼ e
```

обозначает связь двух уже структурно различённых полюсов.

Сам знак `⟼` не означает скрытую команду создания. В конкретном акте связь может быть:

- уже существующим значением;
- искомой связью;
- проверяемым результатом;
- явно материализуемой записью;
- полюсом другой связи.

## 5. Источник различимости

Тождество по полюсам имеет смысл только после того, как сами полюса различены.

Первичный источник различимости:

```text
самозамыкание начала/конца
```

Дальнейший источник:

```text
связанность с уже различёнными корневыми связями
```

Корневая цепочка:

```text
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

То есть:

- `R` различён полным самозамыканием;
- `O` — формой `♂R`;
- `C` — формой `R♀`;
- `L` и `U` — упорядоченными парами уже различённых `O/C`.

## 6. Тождество связи

Фундаментальное тождество:

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Следовательно:

```text
P1 = A ⟼ B
P2 = A ⟼ B
=> P1 = P2
```

Здесь `A=B` и подобные сравнения относятся к уже структурно различённым связям, а не к совпадению или несовпадению адресов памяти.

Для самозамкнутых форм нельзя сначала объявить два технических `ref` различными, а затем использовать это как доказательство различия их собственных полюсов.

## 7. Четыре конструктивные формы

Удобный машинно-независимый контракт:

```text
∞
♂e
b♀
b⟼e
```

Он задаёт четыре способа предъявить одну бинарную сущность — связь.

Несамозамкнутые полюса должны быть уже различены. Поэтому различение распространяется от акорня наружу, а не возникает из заранее выданного множества номеров.

## 8. Петля и полное самозамыкание

Петля над `a`:

```text
Loop(a) = a ⟼ a
```

означает связь с одинаковыми внешними полюсами `a`.

Обычно:

```text
Loop(a) ≠ a
```

Полное самозамыкание — другой случай:

```text
a = a ⟼ a
```

Тогда сама связь совпала со своими полюсами, поэтому:

```text
a = ∞
```

Это различие обязательно сохранять в формулах и коде.

### Конечная итерация как производная метанотация

Для описания конечного повторения допустима внешняя запись:

```text
a¹ = a
aⁿ⁺¹ = aⁿ ⟼ a,  n >= 1
```

Она разворачивается левоассоциативно:

```text
a² = a ⟼ a
a³ = (a ⟼ a) ⟼ a
a⁴ = ((a ⟼ a) ⟼ a) ⟼ a
```

Знак `^`/верхний индекс **не добавляется в нормативный синтаксис МТС v0.7**. Это сокращение метаязыка для конечного числа уже определённых шагов `⟼`; конкретная связевая форма полностью задаётся после раскрытия сокращения.

В частности:

```text
a² = Loop(a)
Rⁿ = R,  n >= 1
```

`a⁰` и `a^∞` этой договорённостью не определяются. Натуральный ряд нельзя считать уже выведенным только потому, что метаязык использует конечный индекс `n`; внутреннее основание successor исследуется отдельно.

## 9. Корневой словарь

Пятисвязное ядро:

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой четверичный словарь:

```text
[ → O
] → C
1 → L
0 → U
```

Первые различения:

```text
[ → O = O ⟼ R ≡ ♂∞
] → C = R ⟼ C ≡ ∞♀
```

Акорень `∞` не является пятым абитом.

## 10. Историческая запись проекций

Исторические формы:

```text
♀F
F♂
```

относятся к старой проекционной семантике.

Текущая остенсивная ориентация:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

Историческая запись не определяет текущий смысл `♂/♀`.

## 11. Исходная запись не является смыслом

Знак в файле ещё не является самой связью.

Рабочая цепочка:

```text
байты
→ связевое представление источника
→ позиция / история употребления
→ словарь D
→ форма F
→ допуск G/T
```

Если два чтения приводят к одной структурной форме, результат остаётся одной связью. Различие актов хранится историей, а не вторым экземпляром результата.

## 12. Строка и последовательность

Каноническое содержимое может строиться как последовательность:

```text
C0     = R
C(n+1) = Cn ⟼ Bn
```

Повтор одной и той же связи в нескольких позициях не создаёт её копии.

Например:

```text
1110
```

использует:

```text
[L, L, L, U]
```

## 13. Контекст K и знак `↑`

Контекст:

```text
P = parent ⟼ current
K = K ⟼ P
```

Тогда:

```text
↑ = current(K)
```

`↑` относится к текущей связи из явно предъявленного `K`, а не к скрытому глобальному состоянию.

Для одного и того же уже различённого `P` форма `K = K ⟼ P` канонически одна. Различие моментов использования должно храниться отдельной историей актов.

## 14. Словарь и определения

Состояние словаря может иметь форму:

```text
ScopePayload = parentScope ⟼ localHistory
D            = D ⟼ ScopePayload
```

Определение:

```text
Entry = sourceContent ⟼ form
```

Если требуемая связь уже существует, повторное получение не создаёт копию.

## 15. Знак `:`

После разрешения исходной записи `:` обозначает явное изменение словаря.

Он не означает автоматически:

```text
равенство
доказанность
глобальную подстановку
```

Проверка уже выполненного изменения должна оставаться чтением.

## 16. Локальное равенство

Дополнительное контекстное отношение представителей может использовать:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

```text
Equal_K(a,b)
⇔ rep_K(a) = rep_K(b)
```

Оно не переопределяет фундаментальное тождество самой связи.

## 17. Грамматика и теория

Допуск задаётся явно:

```text
G ⟼ FormSequence
T ⟼ FormSequence
T ⟼ Rule
```

Нахождение формы в словаре ещё не означает её допустимость во всякой теории.

## 18. Акт интерпретации

Следует различать:

```text
I — интерпретатор
A — конкретный акт
R — результат
```

Разные акты могут иметь один и тот же результат. Это не создаёт нескольких экземпляров результирующей связи.

## 19. Проверка отделена от материализации

Ключевой инвариант:

```text
поиск / разрешение / проверка
              ≠
материализация
```

```text
не найдено ≠ не существует
```

Явная материализация должна переиспользовать уже существующую связь той же структурно различённой пары.

## 20. Ачисла

Уровни возникновения:

```text
акорень ∞
→ корневые [ ] 1 0
→ ачисла
→ строки
→ формальная нотация
```

Каждый новый контекст десериализации начинается от акорня:

```text
des(ε)  = R
des([]) = R
```

Пустая группа допустима и не требует пятого абита.

## 21. Машинное представление

Технический слой может хранить:

```text
Link(start,end)
slot
address
```

Но `slot/address` не являются третьим полюсом и не создают смысловое тождество.

Более точный конструктивный интерфейс текущего основания:

```text
ensureRoot()
ensureStartSelfClosed(e)
ensureEndSelfClosed(b)
ensureLink(b,e)
```

где `b/e` уже структурно различены.

## 22. Корневая прямая дейктика v0.6

Принятая в МТС v0.7 поверхность `mts-direct-deixis/v0.6` читает уже предъявленный корневой носитель. Полное типизированное синтаксическое дерево, написание операторов, позиция в исходной записи и технический идентификатор исполнения не являются смысловыми входами этой операции.

Минимальная предъявляемая структура:

```text
NODE(children...)  — упорядоченные структурные дочерние значения
OPAQUE              — лист без прямой дейктики
PRONOUN(up,pole)    — явный выбор полюса с числом подъёмов к родителю
```

Все три формы строятся из обычных канонических связей. Упорядоченные `children` и метаданные `PRONOUN` представлены конечными R-корневыми последовательностями.

Для канонического корневого словаря используются структурные роли:

```text
START = O = O ⟼ R       ≡ ◁
END   = C = R ⟼ C       ≡ ▷
NODE  = L = O ⟼ C
OPAQUE_TAG = U = C ⟼ O
PRONOUN_TAG = L ⟼ U
POP         = U ⟼ L
```

`POP` здесь — имя одного шага подъёма в метаданных местоимения, а не новый фундаментальный оператор МТС. Поэтому:

```text
PRONOUN(n, START) = PRONOUN_TAG ⟼ Seq(POP × n, START)
PRONOUN(n, END)   = PRONOUN_TAG ⟼ Seq(POP × n, END)
```

где `Seq(...)` — уже определённая конечная R-корневая последовательность. `OPAQUE` предъявляется как общий лист `OPAQUE_TAG ⟼ R`, а `NODE(children...)` — как `NODE ⟼ Seq(children...)`.

Результат прямой дейктики состоит из троек употребления:

```text
(ROOTED_PATH, up, pole)
```

```text
ROOTED_PATH = (i0, i1, ..., ik)
```

`ROOTED_PATH` — координата проверяющего обхода, полученная из индексов в упорядоченных дочерних позициях. Она **не является смысловым тождеством связи**. Если одна и та же смысловая подасеть использована в двух позициях, остаётся одна смысловая связь, но возникают две разные координаты употребления.

Следовательно:

```text
одна смысловая подасеть
+ две дочерние позиции
=> две ROOTED_PATH
!= две смысловые связи подасети
```

Группировка остаётся видимой в пути именно как структура вложенных дочерних позиций. `up` равен числу последовательных `POP`, а `pole` принимает только `START/◁` или `END/▷`.

Прямая дейктика является операцией чтения:

```text
analyze / replay
!= ensure / materialize
```

Она не должна менять апамять. Положительный результат сам по себе не доказывает `ContextSensitive`, а отсутствие дейктических употреблений не доказывает `ContextInvariant`.

## 23. Проверка формы как суждение чтения

Для уже предъявленной смысловой связи `X` и уже структурно различённых полюсов `A`, `B` вводится суждение:

```text
Shape(X; A,B)
⇔
start(X)=A ∧ end(X)=B
```

В канонической сети это эквивалентно предъявленной форме:

```text
Shape(X; A,B)
⇔
X = A ⟼ B
```

Эквивалентность использует принятое тождество связи по упорядоченной паре полюсов. Она **не** означает вызов `ensure(A,B)` и не разрешает создавать отсутствующую физическую запись во время проверки.

Для остенсивных частных случаев:

```text
StartSelf(X; e) ⇔ start(X)=X ∧ end(X)=e
EndSelf(X; b)   ⇔ start(X)=b ∧ end(X)=X
FullSelf(X)     ⇔ start(X)=X ∧ end(X)=X
```

Из единственности полного самозамыкания:

```text
FullSelf(X) => X=R=∞
```

Корневые проверочные формы:

```text
FullSelf(R)
StartSelf(O; R)
EndSelf(C; R)
Shape(L; O,C)
Shape(U; C,O)
```

Неверный ожидаемый полюс даёт ложный результат и не изменяет сеть.

Техническая ссылка реализации допустима здесь только как локальная координата доступа **после** того, как `LinkNetwork` уже установила укоренённую структурную различимость. Чужая или поддельная ссылка должна быть отвергнута; сама по себе разница адресов не является семантической посылкой.

Если пары `A ⟼ B` физически нет в выбранной апамяти, то:

```text
find(A,B) = not found
```

не превращается ни в доказательство структурной невозможности, ни в скрытую материализацию. Поэтому сохраняется более сильная граница:

```text
не найдено ≠ не существует
find ≠ ensure
проверить ≠ материализовать
```

Если нужно различать два акта проверки одной связи, различие должно находиться в связевой структуре самих актов — например, в ролях фактического и ожидаемого полюсов и в истории. Копия проверяемой связи для этого не создаётся.

Исполняемые положительные и отрицательные проверочные векторы находятся в существующем `tests/test_mts_rooted_link_network.py`. Эталонные функции проверки определены только внутри теста и используют `LinkNetwork.link()` без конструктора и `ensure`, поэтому исследовательское суждение не расширяет принятую поверхность исполнения версии 0.7.

## Краткая памятка

```text
∞      единственная полностью самозамкнутая связь
♂e     самозамкнутое начало, различённый конец e
b♀     различённое начало b, самозамкнутый конец
♂♀     замкнутый взаимный шаблон; схлопывается в ∞
b ⟼ e  связь двух различённых полюсов
aⁿ     внешняя derived-метанотация конечной левой итерации, n>=1
↑      текущая связь из явного K
:      явное изменение словаря после разрешения записи
```

## Главный принцип

> Формальная нотация МТС должна показывать не только полюса связи, но и источник их различимости: самозамыкание и связанность с уже различённой корневой структурой.
