# Формальная нотация МТС

Статус: **актуальная Foundation v2 candidate specification**.

> Следующая версия МТС ещё не принята. Этот документ описывает текущую целевую семантику source/evidence/replay. Старые parser/typed-AST/`ContextFrame` механизмы остаются частью accepted-линии v0.2–v0.5 до explicit cutover, но больше не считаются целевой семантической моделью.

# 1. Нотация не является онтологией

Запись:

```text
A ⟼ B
```

является source-представлением отношения, а не отдельным видом сущности.

В онтологии существует exact occurrence связи:

```text
L = A ⟼ B
```

Но символ `⟼`, token для него и AST-node, созданный parser-ом, — разные уровни.

Foundation v2 запрещает неявное отождествление:

```text
text spelling
=
host token
=
AST class
=
semantic occurrence
```

Эти равенства неверны без explicit evidence.

---

# 2. Каноническая source-цепочка

Текущий front-end строится как проверяемая цепочка:

```text
raw UTF-8 bytes
        ↓
canonical byte-link carrier
        ↓
canonical astring content C
        ↓
exact source occurrence S
        ↓
selected exact segmentation
        ↓
scoped dictionary D resolution
        ↓
explicit G / T admission
        ↓
exact semantic form(s)
```

Source occurrence отделён от content:

```text
S = S ⟼ C
```

Два источника с одинаковым `C` могут оставаться двумя разными exact occurrences `S1` и `S2`.

Это необходимо для provenance.

---

# 3. Canonical astring

Canonical astring content строится из канонических byte carriers и не требует host Unicode string как semantic identity.

Концептуально:

```text
C0     = R
C(n+1) = Cn ⟼ Bn
```

где `Bn` — canonical carrier очередного byte.

UTF-8 используется как транспортное представление source. Unicode normalization не должна происходить скрыто: если нормализация нужна языку, она должна стать explicit правилом или preprocessing contract.

Следовательно:

```text
одинаковый отображаемый текст
```

не обязан означать:

```text
одинаковую последовательность source bytes
```

и тем более не означает автоматически один semantic occurrence.

---

# 4. Segmentation является evidence

Trusted core не обязан иметь один встроенный tokenizer.

Для source выбирается exact segmentation:

```text
slice_0 = bytes[i0:j0]
slice_1 = bytes[i1:j1]
...
```

и для каждого slice предъявляется разрешение через `D`.

Например строка:

```text
a⟼b
```

содержит многобайтный UTF-8 символ `⟼`, но trusted replay проверяет выбранные byte boundaries и dictionary evidence, а не доверяет host `TokenKind.ARROW`.

Если source допускает несколько segmentation candidates, поиск может предложить любой из них. Trusted layer проверяет только предъявленный candidate.

Поэтому longest-match не является аксиомой МТС.

---

# 5. Scoped dictionary D

Лексическое/семантическое разрешение source задаётся explicit persistent dictionary state.

Текущая topology:

```text
ScopePayload = parentScope ⟼ localHistory
D            = D ⟼ ScopePayload
```

Definition entry:

```text
Entry = sourceContent ⟼ form
```

Exact occurrence определения:

```text
Occurrence = D_before ⟼ Entry
```

История после определения:

```text
H_after = H_before ⟼ Occurrence
```

Новый scope snapshot:

```text
D_after = D_after ⟼ (sameParentScope ⟼ H_after)
```

`D_before` сохраняется.

Это persistent semantics, а не mutable global hash map.

---

# 6. `:` — explicit definition effect

В Foundation v2 candidate символ `:` обозначает persistent dictionary effect только после разрешения его формы через текущие `D/G/T`.

Концептуально:

```text
sourceContent : form
```

создаёт новый exact definition occurrence и новый `D_after`.

Важно:

```text
:` ≠ `=`
:` ≠ host assignment
:` ≠ theorem assertion
```

Trusted replay `:` проверяет уже materialized effect read-only; создание actual links относится к executor/materialization boundary.

---

# 7. Контекст K и `↑`

Целевая Foundation-v2 модель контекста не использует скрытый `ContextFrame(start,end,parent)` как semantic primitive.

Контекст хранится explicit сетью:

```text
P = parent ⟼ current
K = K ⟼ P
```

В текущей candidate-семантике:

```text
↑
```

означает обращение к exact `current`, разрешённому из предъявленного `K`.

Это не глобальная переменная и не ambient stack lookup.

Переход:

```text
K_before → K_after
```

должен быть предъявлен в actual act.

---

# 8. Формы связи и structural resolution

Самозамыкание одного полюса может служить структурной формой:

```text
F = F ⟼ X
```

или:

```text
F = X ⟼ F
```

Однако сама shape не является opcode.

Operational direction возникает только при selected form + explicit binding/context evidence.

Например при binding `B`:

```text
F = F ⟼ X
```

может быть проверено как результат:

```text
B ⟼ X
```

а форма:

```text
F = X ⟼ F
```

как:

```text
X ⟼ B
```

Но trusted replay принимает только exact result occurrence с нужными полюсами; он не создаёт result автоматически.

---

# 9. `=` — local representative equality

Foundation v2 не использует `=` как глобальный textual rewrite.

Local representative evidence:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Сравнение:

```text
Equal_K(a,b)
⇔ rep_K(a) is rep_K(b)
```

Если для `x` нет local binding:

```text
rep_K(x) = x
```

Только один exact hop.

Не выполняются автоматически:

```text
a=b, b=c ⇒ a=c
substitution into arbitrary links
congruence
recursive decomposition
shape equality
```

---

# 10. Теория T и grammar G

Foundation v2 требует explicit admission evidence.

Примеры:

```text
G ⟼ FormSequence
T ⟼ FormSequence
T ⟼ Rule
```

`G` и `T` являются exact occurrences.

Один source artifact, разрешённый под `T1`, нельзя незаметно использовать как доказательство под exact-другой `T2`, даже если обе теории содержат внешне одинаковые правила.

---

# 11. Actual act A

Конкретная интерпретация фиксируется actual act occurrence `A`.

Его поля адресуются explicit role occurrences и сами представлены связями.

Для relation resolution акт может включать:

```text
source
source-selection
form-sequence
dictionary
grammar
theory
form
before-context
binding
result
after-context
```

Смысл не зависит от Python dataclass names: dataclasses являются checker handles. Semantic identity находится в exact link occurrences.

---

# 12. Run

Многошаговая последовательность фиксируется exact chain:

```text
Run_0     = R
Run_(i+1) = Run_i ⟼ A_i
```

Host tuple/list допускается как API handle, но trusted replay реконструирует и проверяет link chain.

Continuity:

```text
A_i.after is A_(i+1).before
```

Shape-equivalent, но exact-другой `K` не удовлетворяет continuity.

---

# 13. Proof-rule notation

Логическое правило не встроено в glyph `=` или `⟼`.

Оно должно быть exact occurrence `Rule` и иметь admission:

```text
T ⟼ Rule
```

Первый executable proof candidate:

```text
premise:
    Equal_K(L,R) = true

L = ls ⟼ le
R = rs ⟼ re

conclusions:
    C_start = ls ⟼ rs
    C_end   = le ⟼ re
```

Это one-step decomposition.

`C_start` и `C_end` — exact claims/evidence; они не становятся local representative bindings без отдельного explicit effect.

Подробнее: [Foundation v2 Proof replay](Foundation%20v2%20Proof%20replay.md).

---

# 14. Integrated proof source

Первый end-to-end candidate уже связывает source spelling с exact proof rule:

```text
source `decompose`
→ C / S
→ selected segmentation
→ scoped D
→ exact Rule
→ G/T admission
→ true equality A_eq
→ exact T ⟼ Rule
→ A_rule
→ Run[A_eq, A_rule]
→ trusted replay
```

Integrated checker не ищет доказательство. Он проверяет, что все слои ссылаются на те же exact `Rule`, `T`, `K` и actual acts.

---

# 15. Read-only и effect boundary

Для любой нотации действует инвариант:

```text
разрешить форму
проверить act
проверить proof
```

не означает:

```text
создать отсутствующую связь
изменить D/K
сохранить новый факт
```

Materialization должна быть explicit.

Это особенно важно для апамяти: parser/interpreter не получает скрытого write-access только потому, что умеет описать желаемую связь.

---

# 16. Ачисловая нотация — отдельный слой

Абиты:

```text
[ ] 0 1
```

относятся к протоколу ачисел и не должны автоматически смешиваться с source glyphs Foundation v2.

Рекурсивная ачисловая grammar и historical boundary projection сохранены в:

- [Ачисла и сериализация](Ачисла%20и%20сериализация.md)
- [Протокол абитов ачисел](Протокол%20абитов%20ачисел.md)

Следующий gate #242 должен определить executable связь:

```text
Anum sequence
→ explicit materialization plan
→ apamemory exact links
```

без host parser side effects.

# 17. Историческая нотация v0.2–v0.5

Accepted-линия использовала такие конструкции, как:

```text
◁
▷
↑◁
↑▷
[]
♀
♂
ContextFrame
StartProjection
EndProjection
LinkForm
```

и pipeline:

```text
mtc_parser.py
→ mtc_ast.py
→ mtc_interpreter.py
```

Эта линия остаётся воспроизводимой через [Reference model МТС v0.2](Reference%20model%20МТС%20v0.2.md) и versioned contracts.

Но для Foundation v2 действует принцип:

```text
legacy spelling/API
не является semantic authority следующей версии
```

При production cutover historical consumers должны быть либо мигрированы на новый exact-evidence path, либо явно оставлены как historical compatibility surface. Временный двойной semantic core не является конечной архитектурой.

# 18. Текущая исполнимая карта

```text
core/exact_link_network.py
    exact occurrence identity

core/foundation_v2_state.py
    K / scoped D / membership / A helpers

core/foundation_v2_source.py
    C / S / segmentation / D-G-T replay

core/foundation_v2_interpreter.py
    relation / : / = replay

core/foundation_v2_run.py
    exact Run

core/foundation_v2_proof.py
    T-admitted one-step proof rule

core/foundation_v2_checker.py
    integrated source-to-proof replay
```

Host API этих модулей ещё может меняться до acceptance. Их semantic invariants должны сохраняться.

# 19. Нормативное правило чтения candidate-нотации

Пока Foundation v2 не принята, каждую запись следует читать в таком порядке:

```text
1. какой exact source предъявлен?
2. как он сегментирован?
3. каким D разрешён?
4. какой G/T допускает форму?
5. какой exact K выбран?
6. какой actual act предъявлен?
7. является ли действие read-only или effect?
8. если есть вывод — какой T-admitted Rule его разрешает?
9. можно ли replay-ить всё без догадок и мутации?
```

Если ответ на один из этих вопросов скрыт в host-коде, это признак незавершённой формализации.
