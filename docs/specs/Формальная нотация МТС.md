# Формальная нотация МТС
<!-- версия документа МТС; mts-doc-version: v0.13 -->
> **Версия МТС: v0.13**

Этот документ задаёт текущую формальную нотацию МТС v0.13: интерпретационные контексты, `FORMAL`-композицию, явный `Context`, относительные формы и полномочия `Dictionary / Grammar / Theory / Rule`.

Документ является нормативным владельцем законов `L2`, `L3` и `L12`.

Связанные владельцы:

- [Система аксиом МТС](../theory/Система%20аксиом%20МТС.md) — онтология Связи, корневой базис и фундаментальные производные результаты;
- [Основания МТС](../theory/Основания%20МТС.md) — объяснение структурного фундамента, хиральности и рекурсивной инверсии;
- [Ачисла и сериализация](Ачисла%20и%20сериализация.md) — структурный носитель `8/9/6/1`, `STRING`, точные байты и перенос;
- [Апамять и управление сетью связей](Апамять%20и%20управление%20сетью%20связей.md) — чтение, материализация, `Scope` и исполнение.

## 1. Формальная запись всегда многослойна

Нормативно различаются:

```text
физический источник
-> точный STRING-источник
-> выбранное употребление Dictionary
-> Grammar
-> фиксированная Theory
-> допущенный StructuralRule
-> структурный смысл
-> действие / материализация
```

Совпадение формы на одном уровне не создаёт полномочие на другом:

```text
представление != интерпретация
носитель != денотат
Rule как данные != исполнение Rule
чтение / replay != запись / materialize
одинаковый печатный знак != одинаковая смысловая роль
```

Точный источник и его носитель описаны в [спецификации ачисел](Ачисла%20и%20сериализация.md#mts-law-stringByteIdentity).

## 2. Явные интерпретационные контексты

<a id="mts-law-interpreterSeparation"></a> <!-- служебный якорь -->

В МТС v0.13 используются три различные явные интерпретационные роли:

```text
I_STRING
I_FORMAL
I_Q
```

Они не являются скрытыми режимами лексера или анализатора. Выбранный интерпретатор является частью явного смыслового свидетельства.

Текущие правила вложения:

```text
FORMAL [...] -> I_STRING
Q [...]      -> I_Q
FORMAL (...) -> I_FORMAL
()           -> empty-formal-context
```

Одинаковое начертание `[`, `]`, `1` или `0` в разных интерпретационных ролях не означает тождество их смыслов.

<a id="mts-law-formalSquareBracketStringChild"></a> <!-- служебный якорь -->

Для `FORMAL [...]` дочерний контекст:

```text
начинается от R
исполняется как I_STRING
возвращает ровно одну Связь
передаёт результат родителю
после чего родитель продолжает исполнение
```

<a id="mts-law-formalParentheses"></a> <!-- служебный якорь -->

Для `FORMAL (...)` дочерний `I_FORMAL` также возвращает ровно одну Связь. Пустой круглый контекст недопустим.

## 3. Внутренняя нотация и структурный квартет — разные роли

Текущий внутренний набор `F1`:

```text
∞ [ ] 1 0 ( ) ⟼ : = .
```

Он не является структурным алфавитом ачисла.

Канонический структурный квартет МТС v0.13:

```text
8 = ROOT
9 = START
6 = END
1 = PAIR
```

одновременно играет четыре согласованные роли:

```text
локальный аспект Связи
локальная форма Связи
структурный абит ачисла
корневой FORMAL-оператор
```

Одинаковый символ `1` в `F1/Q` и в структурном квартете не даёт права отождествлять роли.

## 4. Композиция `FORMAL`: `ROOT / START / END / PAIR`

<a id="mts-law-L12"></a> <!-- нормативный владелец -->
<!-- mts:req:L12:begin -->
> **Скомпилированное требование `L12`.** Вид: `semantic-law`; классификация: `notation/formal/structural-grounding`.
>
> Машинный источник: `contracts/mts-contract-v0.13.json#/requiredSemanticLaws/L12`.
<!-- mts:req:L12:end -->

### L12. Структурный смысл задаётся FORMAL-полномочием

Физические знаки `8`, `9`, `6`, `1` не получают смысл класса из своего начертания и не выбираются ветвлением программы среды исполнения.

Нормативный путь:

```text
точный физический источник
-> точный STRING-источник
-> выбранное употребление Dictionary
-> членство Grammar
-> фиксированная Theory
-> допущенный FORMAL StructuralRule
-> ROOT / START / END / PAIR
```

После того как смысл оператора уже доказан этим путём, физический знак проверяется как его каноническая запись.

Обобщённая композиция:

```text
Eval(8)       = R
Eval(9 a)     = START(Eval(a))
Eval(6 a)     = END(Eval(a))
Eval(1 a b)   = PAIR(Eval(a), Eval(b))
```

Она одна и та же для произвольной вложенности; специальных случаев для конкретных термов нет.

Корневые примеры:

```text
8      -> R
98     -> O = START(R)
68     -> C = END(R)
19868  -> L = PAIR(O,C)
16898  -> U = PAIR(C,O)
```

Поэтому необходимо различать:

```text
9  != O
98  = O

6  != C
68  = C

1  != L
19868 = L
```

`U=16898` не является пятым аспектом, пятым абитом или пятым FORMAL-оператором.

## 5. Явный Context

Текущий структурный контекст задаётся обычными Связями:

```text
Payload = parent ⟼ current
K       = START(Payload)
```

То есть:

```text
Context(parent,current)
=
START(parent ⟼ current)
```

`ROOT` не является альтернативной записью пустого `Context`.

<a id="mts-law-explicitKContext"></a> <!-- служебный якорь -->

Контекстное употребление `.` разрешается только через явно выбранный структурный `K`.

Не являются смысловым полномочием выбора контекста:

- стек анализатора;
- ближайшая лексическая рамка;
- изменяемое текущее значение среды исполнения;
- порядок хранения;
- технический handle;
- сам факт открытия дочернего интерпретатора.

Структура родительства и временной порядок исполнения — разные отношения.

## 6. Относительные формы

<a id="mts-law-L2"></a> <!-- нормативный владелец -->
<!-- mts:req:L2:begin -->
> **Скомпилированное требование `L2`.** Вид: `semantic-law`; классификация: `notation/formal/result-identity`.
>
> Машинный источник: `contracts/mts-contract-v0.13.json#/requiredSemanticLaws/L2`.
<!-- mts:req:L2:end -->

### L2. Форма Связи и результат её относительного исполнения различаются

Для:

```text
S = a ⟼ b
```

определены четыре самостоятельные Связи:

```text
P = P ⟼ S
Q = S ⟼ Q
D = P ⟼ Q
I = Q ⟼ P
```

Их результаты:

```text
P ⇓ a
Q ⇓ b
D ⇓ S
I ⇓ -S = b ⟼ a
```

Следовательно:

```text
тождество формы
!=
тождество результата
```

Совпавший результат не разрешает схлопывать разные относительные формы.

## 7. Относительная навигация

<a id="mts-law-L3"></a> <!-- нормативный владелец -->
<!-- mts:req:L3:begin -->
> **Скомпилированное требование `L3`.** Вид: `semantic-law`; классификация: `notation/formal/context-authority`.
>
> Машинный источник: `contracts/mts-contract-v0.13.json#/requiredSemanticLaws/L3`.
<!-- mts:req:L3:end -->

### L3. Навигация по полюсам принадлежит явному контексту Связи

Для выбранной целой Связи `S`:

```text
START-операция -> прочитать start(S) и открыть START-позицию
END-операция   -> прочитать end(S) и открыть END-позицию
```

Внутри открытой позиции:

```text
та же сторона
-> открыть более глубокий контекст Связи

противоположная сторона
-> вернуться на один объемлющий контекст Связи
```

Полномочие перехода несёт явная связевая структура контекста. Стек анализатора и неявное изменяемое «текущее значение» полномочием не являются.

## 8. Структурное правило и теория

Структурный интерпретатор задаётся тремя явно выбранными Связями:

```text
Interpreter = Dictionary ⟼ (Grammar ⟼ Theory)
```

Словарь ролей имеет форму:

```text
RoleSequence   = ExactSequence(role...)
RoleDictionary = START(RoleSequence)
```

Роль в `RoleDictionary` может встречаться только один раз.

Правило:

```text
Rule = RoleDictionary ⟼ Body
```

Допуск правила теорией:

```text
Admission = Theory ⟼ Rule
```

Критическая граница:

```text
Rule существует
!=
Rule допущено выбранной Theory
```

При сопоставлении только Связи, явно перечисленные в `RoleDictionary`, являются переменными ролями. Остальные части шаблона — заземлённые структурные константы.

Ни имя функции среды исполнения, ни `opcode`, ни имя поля объекта не участвуют в смысловом тождестве Rule.

## 9. Полномочие источника

<a id="mts-law-sourceUseAuthority"></a> <!-- служебный якорь -->

Формальный исходный текст переносится как точное строковое ачисло `STRING`.

Смысловое употребление источника допустимо только при совместном совпадении заранее выбранных:

```text
exact source
Dictionary Use
Grammar
fixed Theory
```

Кандидат не может назначить себе `Dictionary`, `Grammar` или `Theory` только потому, что его структура хорошо сформирована.

Проверка источника является чтением и сама по себе не даёт права материализовать семантический результат.

## 10. Полномочие результата FORMAL

<a id="mts-law-formalResultAuthority"></a> <!-- служебный якорь -->

Сквозной FORMAL-результат требует совместно:

1. точный источник;
2. выбранное употребление `Dictionary`;
3. соответствующее `Grammar`;
4. заранее фиксированную `Theory`;
5. `StructuralRule`, допущенное этой `Theory`;
6. точные связывания всех объявленных ролей;
7. отсутствие необъявленных или неоднозначных связываний;
8. совпадение заявленного заземлённого тела Rule;
9. явный ожидаемый контекст после акта.

Поздно появившиеся или невыбранные окружающие Связи не получают полномочия менять уже выбранное свидетельство.

Проверка Rule выполняется только для чтения:

```text
replay Rule
!=
materialize Rule result
```

## 11. Стрелка, группировка и локальное равенство

В формальной нотации используется одна стрелка:

```text
A ⟼ B
```

Она предъявляет Связь с началом `A` и концом `B`.

Сама стрелка не означает автоматически:

- запись в память;
- вызов функции;
- логическое следование;
- присваивание;
- переход состояния.

<a id="mts-law-associationBoundary"></a> <!-- служебный якорь -->

Плоское чтение, конкретная топология Связи и исполнение `FORMAL` — разные уровни. Неоднозначная запись должна получать группировку от явно выбранного правила `Grammar`, а не от скрытого приоритета среды исполнения.

Формальное `=` выражает локальное свидетельство представителя в явно выбранном контексте:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Оно не переопределяет фундаментальное тождество Связи по полюсам и не является присваиванием, глобальной подстановкой или автоматической конгруэнтностью.

## 12. Чтение и материализация

`FORMAL`, `Rule`, `Context`, `:`, `=`, `.` и сами структурные операторы не имеют скрытого права записи.

```text
разобрать
прочитать
разрешить
сопоставить
проверить
воспроизвести
!=
создать
изменить
материализовать
```

Семантическая запись `START/END/PAIR` требует отдельного полного полномочия:

```text
exact source
+ selected Dictionary Use
+ Grammar
+ fixed Theory
+ admitted StructuralRule
+ validated construction request
```

Неуспешная авторизация должна завершиться до записи семантической цели.

## 13. Рекурсивная инверсия FORMAL

**Статус: производный результат о принятой v0.13, а не новый закон принятого контракта.**

Для структурного FORMAL-выражения определена рекурсивная инверсия операторов:

```text
Jq(8)       = 8
Jq(9 a)     = 6 Jq(a)
Jq(6 a)     = 9 Jq(a)
Jq(1 a b)   = 1 Jq(b) Jq(a)
```

Обобщённый FORMAL-композитор эквивариантен:

```text
Eval(Jq(q)) = J(Eval(q))
```

То есть сама рекурсивная композиция `ROOT/START/END/PAIR` не выбирает абсолютную сторону.

Но текущие соглашения более высокого уровня ориентированы.

Для `Context`:

```text
K = START(parent ⟼ current)

J(K)
=
END(J(current) ⟼ J(parent))
```

Полученная `END`-форма является точным двойственным контекстом, но не принимается тем же текущим правилом чтения `Context`, которое требует `START`.

Аналогично `RoleDictionary = START(RoleSequence)`, допуск `Theory ⟼ Rule` и связанные с ними полномочия переходят под `J` в согласованные зеркальные формы, а не остаются теми же фиксированными текущими конвенциями.

Поэтому:

```text
FORMAL composition:
  J-эквивариантна

fixed current Context/Theory authority:
  не является J-инвариантной
  имеет точную двойственную форму
```

Именно это даёт итоговый производный результат:

```text
NO_AUTOMORPHISM    = false
FULL_AUTOMORPHISM  = false
THEORY_DUALIZATION = true
```

Результат доказан только в принятой v0.13 области конечного ROOT-заземления с разрешёнными прямыми самовхождениями `ROOT/START/END`; нефундированные циклы зависимостей между разными узлами сюда не добавляются.

Машиночитаемая проверка результата: [аудит дуализации](../../theorems/v0.13/inversion/dualization-audit.json).

## 14. Что FORMAL не утверждает

Из текущей спецификации не следуют:

```text
одинаковый glyph -> одинаковая роль
Rule существует -> Rule исполняется
FORMAL replay -> materialization
Context -> скрытый runtime current
J-эквивариантность Eval -> FULL_AUTOMORPHISM
START/END duality -> START = END
```

Также обязательное внешнее начертание относительных форм не фиксируется этой версией: нормативна их связевая структура, а не единственная печатная поверхность.

## Итог

Текущая FORMAL-семантика v0.13 строится так:

```text
точный источник
-> явный интерпретационный контекст
-> Dictionary / Grammar / fixed Theory
-> admitted StructuralRule
-> структурный смысл
-> явный Context
-> отдельное полномочие исполнения или материализации
```

Четыре структурных оператора `8/9/6/1` образуют один рекурсивный композитор `ROOT/START/END/PAIR`. Сам композитор совместим с рекурсивной инверсией, а текущие контекстные и теоретические соглашения выбирают одну из двух двойственных ориентаций.
