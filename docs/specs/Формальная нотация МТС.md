# Формальная нотация МТС

Этот документ описывает текущую принятую формальную нотацию **MTS v0.9**. Нормативная теория задаёт смысл, accepted contract/conformance фиксирует переносимую машинную границу, а TypeScript `@mts/core` реализует её. Ни runtime, ни parser convention не являются самостоятельным источником теории.

## 1. Три слоя нельзя смешивать

В MTS v0.9 явно различаются:

```text
physical source / glyph
representation carrier
selected interpretation context
semantic denotation
```

Поэтому один и тот же видимый знак может участвовать на разных уровнях, но его смысл не выбирается эвристикой по payload shape.

Критическая граница:

```text
representation != interpretation
carrier != denotation
source occurrence != semantic Link identity
```

## 2. Минимальный внутренний F1-алфавит

Accepted F1 v0.9 содержит ровно десять внутренних знаков:

```text
∞ [ ] 1 0 ( ) ⟼ : =
```

Отложены как внутренние знаки:

```text
≡ ♂ ♀ ↑ { } ¬ ↛
```

Только в метаязыке описания и доказательства используются:

```text
∧ ⇔ ⇒ ≠ →
```

Это означает, например, что остенсивные записи `♂e` / `b♀` остаются допустимой теоретической метанотацией самозамыкания, но не являются current F1 parser tokens или автоматически исполняемыми операторами.

## 3. Самовведение знаков

Внутренние знаки F1 получают значения не через host lexer convention, а через собственную замкнутую axiom-aset.

Смысловые Links знаков удовлетворяют:

```text
m∞ = m∞ ⟼ m∞

m[ = m[ ⟼ m∞
m] = m∞ ⟼ m]
m1 = m[ ⟼ m]
m0 = m] ⟼ m[

m( = m( ⟼ m∞
m) = m∞ ⟼ m)
m⟼ = m( ⟼ m)

m: = m∞ ⟼ m⟼
m= = m= ⟼ m=
```

Root projection:

```text
m∞, m=   -> R
m[, m(   -> O
m], m)   -> C
m1, m⟼   -> L
m0       -> U
m:       -> R ⟼ L
```

Совпадение root projection двух знаков не делает их одной записью или одной ролью. Entry знака хранит отдельно carrier и meaning:

```text
E_g = c_g ⟼ m_g
```

## 4. Корневой базис

```text
R = ∞
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Корневой четверичный словарь:

```text
[ -> O
] -> C
1 -> L
0 -> U
```

`∞` не является пятым абитом.

## 5. `⟼` — единственная FORMAL-стрелка

В текущем F1 нет второго формального arrow synonym.

```text
A ⟼ B
```

предъявляет направленную связевую форму с началом `A` и концом `B`.

Нельзя автоматически читать `⟼` как:

```text
создать запись в памяти
выполнить действие
логическое следование
navigation step
```

Конкретный эффект определяется выбранной теорией, Rule и Act/context.

## 6. `()` — явный FORMAL context

`(` и `)` являются отдельными внутренними знаками с собственными equations. Они не являются просто host grouping punctuation.

Accepted lifecycle:

```text
K_parent_before
  -> FORMAL_OPEN(target I)
K_child(parent=K_parent_before,current=initial)
  -> child Acts
K_child_final
  -> FORMAL_CLOSE(result)
K_parent_before
  -> PARENT_CONTINUE(result)
K_parent_after
```

Лексическая вложенность принадлежит `K.parent`.

Временной порядок принадлежит `Run/Act`.

Эти две структуры не смешиваются.

## 7. FORMAL current хранится как ExactSequence

Обычная левая свёртка не может быть универсальным carrier последовательности, потому что допускает схлопывание root-позиций:

```text
[]   -> R
[R]  -> R              # неприемлемо как identity последовательности
```

Поэтому для F1-критичных последовательностей используется root-safe carrier:

```text
Seq([]) = R
Cell(prev,value) = start-self-closed(prev ⟼ value)
Seq(xs + [x]) = Cell(Seq(xs), x)
```

Следовательно:

```text
Seq([]) != Seq([R])
```

при этом второй semantic `R` не создаётся: позиция выражается структурой carrier.

`ExactSequence` используется для FORMAL current, RoleSequence и других мест, где `R` допустим как явное значение позиции.

## 8. `[]` — Q context, а не host bracket pair

В QUATERNARY/Q context:

```text
[ ... ]
```

открывает и закрывает явный вложенный Q context.

Каждый новый Q context стартует относительно `R`.

Поэтому:

```text
des(ε) = R
des([]) = R
```

Пустая Q-группа допустима.

## 9. QState структурен

Accepted v0.9 не использует hidden `started:boolean` как semantic authority.

Структурная модель:

```text
QEmpty = R
QNonEmpty(inner) = start-self-closed(inner)
```

Это различает:

```text
пустой Q state
```

и:

```text
непустой Q state, первым значением которого является R
```

без host-only флага и без второго root instance.

## 10. Вложенное Q/FORMAL re-entry

FORMAL может явно открыть Q child, а его результат затем возвращается в прежний FORMAL parent.

Ключевая граница:

```text
Q_CLOSE
!=
PARENT_CONTINUE
```

Закрытие child не мутирует lexical parent скрыто. Parent continuation является отдельным структурным переходом.

Особенно важно:

```text
[] -> R
```

и возвращаемый `R` должен сохраняться как **явная позиция** FORMAL ExactSequence, а не исчезать из-за root-fold collapse.

Обязательные различимые примеры:

```text
[]
[[]]
([[]])
```

## 11. Группировка relation-form

Canonical FORMAL relation записывается явно:

```text
(A ⟼ B)
```

Вложенная группировка сохраняет структуру:

```text
(A ⟼ (B ⟼ C))
((A ⟼ B) ⟼ C)
```

Эти формы не считаются одинаковыми по implicit associativity.

Bare form:

```text
A ⟼ B ⟼ C
```

не является foundation-canonical и отвергается, если отдельный derived elaborator не выбран явно.

MTS v0.9 не вводит precedence primitive для скрытого выбора одной из группировок.

## 12. Пустой FORMAL context

Минимальный F1 не допускает пустой FORMAL:

```text
()
```

как автоматически осмысленную формулу.

One-form grouping может быть допущена явным structural Rule, но это не превращает `()` в host syntax shortcut.

## 13. `:` — структурное правило, а не присваивание языка реализации

Sign meaning:

```text
m: = m∞ ⟼ m⟼
```

FORMAL `:` разрешается через structural Rule/admission path.

Он не означает автоматически:

```text
классическое равенство
глобальное присваивание
textual rewrite всей сети
execution callback
```

Словарь/теория/context должны быть предъявлены явно.

## 14. `=` — контекстно-локальное формальное равенство

Sign meaning:

```text
m= = m= ⟼ m=
```

В MTS v0.9 `=` использует context-local representative evidence.

Внешняя метанотация такого свидетельства может быть записана:

```text
Pair    = member ⟼ representative
Binding = K ⟼ Pair
```

Это **не** заменяет фундаментальное semantic identity Link по полюсам.

Из FORMAL `=` не следуют автоматически:

```text
global transitive closure
глобальная substitution
congruence всех конструкций
переписывание всей асети
```

## 15. Structural Rule

Rule сам является структурными Link-data:

```text
DR = DR ⟼ RoleSequence
Rule = DR ⟼ Body
T ⟼ Rule
```

Act связывает declared role с value структурно.

Accepted replay требует:

- ровно одно binding на каждую declared role;
- отсутствие undeclared bindings;
- exact before/context evidence;
- выбранный Rule действительно admitted в `T`;
- read-only verification.

Host callback identity, enum `RuleKind` или property `type` не являются semantic authority.

## 16. Rule-data не исполняются сами

Критическая граница:

```text
Rule existence
!= execution
```

Для state transition требуется явный Act/context и выбранный interpreter/rule path.

То же относится к finite functions-as-data и application relations: наличие relation/function data никогда автоматически не вызывает действие.

## 17. Interpreter и context

Accepted structural interpreter:

```text
I = D ⟼ (G ⟼ T)
```

Context:

```text
P = parent ⟼ current
K = K ⟼ P
I ⟼ K
```

`current(K)` в этом документе — метанотация чтения структуры `K`, а не принятый внутренний знак `↑`.

Один и тот же semantic `K` может встречаться в разных occurrence/history structures без создания semantic copies.

## 18. STRING source и FORMAL source

FORMAL source является exact STRING content.

Строковое содержимое хранится как точная конечная последовательность bytes. Никакая Unicode normalization не происходит скрыто.

Для каждого byte `p`:

```text
Rep_SQ(byte p) = [bbbbbbbb]
Byte(p) := Denote_Q([p])
```

где внутри brackets ровно восемь bits, MSB-first.

Один physical byte — один Q envelope.

Например UTF-8 символ из нескольких bytes даёт несколько byte envelopes, а не один host-code-point envelope.

## 19. Byte vocabulary структурна

256 `Byte(p)` выводятся из Q structure, а не вводятся 256 opaque runtime IDs.

Следовательно:

```text
runtime byte id
!= semantic byte identity
```

Repeated byte в строке повторяет одну semantic Byte-link через разные позиции ExactSequence.

Malformed UTF-8 bytes допустимы на exact byte-carrier уровне; strict UTF-8 interpretation — отдельный слой и может отклонить их.

## 20. Source glyph и semantic sign различаются

Например carrier физического glyph `[`:

```text
[01011011]
```

не является автоматически raw Q delimiter-use знака `[`.

Нужен explicit selected context.

Поэтому:

```text
source glyph '['
!= Q OPEN act
!= root semantic O
```

между слоями существуют явные representation/interpretation relations.

## 21. Ostensive `♂/♀` — theory notation, не F1 tokens

Теоретически по-прежнему полезно писать:

```text
♂e = S = S ⟼ e
b♀ = E = b ⟼ E
```

и:

```text
♂♀ = ∞
```

Но в accepted F1 v0.9 `♂` и `♀` находятся в deferred registry.

Нельзя строить parser/runtime feature только потому, что эти знаки удобны в теоретическом изложении.

## 22. `≡`, `↑`, `{}`, `¬`, `↛` также deferred

Эти знаки не являются частью минимальной current F1 self-introducing system.

Если будущая теория захочет принять один из них, потребуется отдельный owner issue и при observable machine delta — новый candidate/contract/conformance/acceptance lifecycle.

## 23. Direct Deixis — отдельный derived/read-only слой

Текущий TypeScript Direct Deixis может хранить:

```text
path
up
pole
```

как occurrence/navigation evidence.

Это специализированное rooted evidence representation, а не текущий F1 syntax и не generic navigation foundation.

Особенно:

```text
path coordinate
!= semantic Link identity
```

Одна semantic subtree может встречаться в нескольких structural positions и иметь несколько path coordinates без semantic cloning.

## 24. Navigation converse не является знаком F1

В derived navigation theory:

```text
S^op(y,x) iff S(x,y)
```

и:

```text
[S1,...,Sn]^op = [Sn^op,...,S1^op]
```

Но navigation converse отличается от:

```text
recursive reversal J
pole swap P
U
logical negation
```

и не добавляется как hidden FORMAL opcode.

## 25. Формальная нотация не определяет materialization

Общий read/effect invariant:

```text
parse / decode / resolve / verify / replay
!=
materialize / write
```

И:

```text
not found != does not exist
```

Ни закрытие context, ни проверка Rule, ни equality replay не имеют права создавать отсутствующую semantic evidence запись лишь потому, что её не нашли.

## 26. Semantic identity и occurrence

В F2/F3:

```text
same recursively grounded form
=> same semantic Link
```

Поэтому:

```text
semantic Link
!= source occurrence
!= sequence position
!= Act occurrence
!= path coordinate
!= runtime handle
!= storage row
```

Если multiplicity существенна, она выражается explicit occurrence/provenance/history structure.

## 27. Краткая памятка current F1

```text
internal signs:
  ∞ [ ] 1 0 ( ) ⟼ : =

deferred:
  ≡ ♂ ♀ ↑ { } ¬ ↛

meta-only:
  ∧ ⇔ ⇒ ≠ →

Q:
  [ ... ]
  empty -> R
  state structural, no hidden started flag

FORMAL:
  ( ... )
  ExactSequence current
  explicit structural Rule admission
  no implicit precedence

STRING:
  exact bytes
  one [8 bits] Q envelope per byte

identity:
  semantic Link != occurrence/path/id

effects:
  read/replay != materialize/write
```

## Главный принцип

> Формальная нотация MTS v0.9 является частью самой связевой структуры и самовведения. Знаки, context transitions и carriers не получают смысл от host parser по соглашению; machine implementation обязана соответствовать принятой theory/contract/conformance границе.
