# Асеть доказательства МТС

Статус: архитектурная спецификация исчисления доказательств.
Связанные задачи: #999, #1019, #1040, #1050, #1057. Исполнимое основание: #1038 / #1039.
Принятая семантика МТС остаётся `v0.11`. Активного смыслового кандидата нет.

Эта спецификация не меняет принятый контракт. Она фиксирует архитектурную границу доказательств перед следующим исполнимым этапом.

## 1. Главный закон

Доказательство в МТС является асетью:

```text
ДОКАЗАТЕЛЬСТВО = АСЕТЬ СВЯЗЕЙ
```

Массивы, индексы, объекты языка реализации, графы, JSON и текст могут быть только проекциями этой асети.

```text
асеть доказательства          <- авторитет
        |
        +-> массив / индекс    <- обход
        +-> граф               <- визуализация
        +-> JSON               <- перенос
        +-> нотация            <- текстовая проекция
```

Ни одна проекция не получает самостоятельного доказательного авторитета.

### 1.1. В МТС нет встроенных сортов математических сущностей

На фундаментальном уровне МТС не вводит различий:

```text
тип / терм
множество / элемент
категория / объект / морфизм
утверждение / правило / доказательство
```

Есть только связи и асети связей. Связь может иметь любой из этих смыслов, если такой смысл задаётся её отношениями с другими связями.

Одна и та же связь может одновременно участвовать в разных интерпретациях: быть элементом некоторого множества, термом некоторого типа, объектом некоторой категории и частью доказательства.

Поэтому обозначения `Theory`, `DR`, `Claim`, `Role`, `Proof`, `I/H/A/O/P` в этой спецификации являются только мнемоническими именами ролей связей или асетей в рассматриваемой топологии. Они не вводят в МТС классы, типы или сорта сущностей.

Никакой объект, перечисление, тег или поле языка реализации не может сообщить связи такой математический смысл или доказательный авторитет. Смысл должен восстанавливаться из самой асети и её отношений.

## 2. Доказательство и история его построения

Специализация, перенос между областями ролей и композиция являются способами построения или преобразования асети, а не обязательными типами доказательных узлов.

Неверно вводить авторитетную иерархию:

```text
PrimitiveProof
SpecializedProof
CrossScopeProof
ClosureProof
```

Правильная схема:

```text
исходная асеть
+ структурное преобразование
        ↓
новая асеть
        ↓
независимая доверенная проверка
```

История построения может сохраняться для происхождения и диагностики, но не становится доказательством.

## 3. Уже подтверждённые свойства

#1038 / #1039 исполнимо подтвердили:

1. Один доказанный Link может использоваться в нескольких позициях зависимостей без создания копий.
2. `DerivedDR -> Theory` само по себе не даёт производному правилу примитивного авторитета.
3. Производное доказательство может нести полный исходный proof-Aset и расширяться без `Theory -> DerivedDR`.
4. Повторное использование одного вхождения совместимо с такой композицией.
5. Реальный L0 уже полностью представим как асеть МТС в исторической арифметической модели, в которой проводилось это исследование.

Для исторического L0:

```text
Nat0(A)
-------
Add(U,A,A)
```

была получена классификация:

```text
representation = SUPPORTED
trusted proof-Aset replay = GAP
```

Эта классификация сохраняется как происхождение proof-calculus работ, но после Nat re-foundation #1052 и программы #1057 она не является текущим математическим статусом нового Nat carrier.

## 4. Кандидатная конечная нормальная форма

Следующая форма является кандидатом для отдельной проверки на опровержение. Она ещё не считается подтверждённой целиком для всех будущих форм доказательства.

### 4.1. Тождество производного доказательства

```text
I = TargetDR -> Theory
```

`I` выбирает целевое производное правило и Теорию, но не разрешает правило как примитивное.

Примитивное разрешение имеет форму:

```text
Theory -> PrimitiveDR
```

### 4.2. Внешняя посылка

```text
H = Claim -> I
```

### 4.3. Применение примитивного правила

```text
A = PrimitiveDR -> ExactSequence(dependencies)
```

Последовательность зависимостей содержит ссылки на внешние посылки или доказанные вхождения. Одна ссылка может встречаться несколько раз.

### 4.4. Доказанное вхождение

```text
O = Claim -> A
```

`Claim` — фактически доказанная связь, а не обязательно буквальное тело исходного общего правила.

### 4.5. Корень

```text
P = I -> TargetOccurrence
```

Принадлежность асети определяется достижимостью от `P` по доказательным зависимостям.
Посторонние Links общей памяти не входят в доказательство и не получают авторитета.
Если переносная проекция содержит отдельный список членов асети, этот список должен совпадать с достижимым замыканием, но остаётся только проекцией.

### 4.6. Коллизии и отсутствие скрытых типов

`H`, `A`, `O`, `I`, `P` являются обычными связями МТС. Их имена не являются типами и не дают права различать их средствами языка реализации.

Проверка обязана устанавливать, можно ли однозначно восстановить их смысл только из топологии связей.
Если форма неоднозначна, её следует усилить дополнительными связями МТС, а не скрытой меткой или host-классом.

## 5. Один шаг доказательства как система ограничений

Общее правило сложения:

```text
Add(A,B,C)
S0(B,B1)
S0(C,C1)
------------
Add(A,B1,C1)
```

в историческом L0 использовалось как:

```text
Add(U,N,N)
S0(N,N1)
S0(N,N1)
-------------
Add(U,N1,N1)
```

Поэтому примитивный шаг должен проверяться не сравнением фактического результата с телом общего правила, а существованием одной согласованной структурной подстановки:

```text
source conclusion -> actual conclusion
source premise 1  -> actual premise 1
source premise 2  -> actual premise 2
...
```

Одна и та же подстановка действует на заключение и на все позиции посылок.
Для каждой исходной роли должно получиться ровно одно значение.
Повторное появление роли обязано давать то же значение.
Противоречие или неполная подстановка приводят к отказу.

Это необходимо, потому что часть ролей может встречаться только в посылках и не определяться одним заключением.

## 6. Первая достаточная граница подстановки

Для уже исследованного generic proof-calculus корпуса достаточно:

```text
роль источника -> роль цели
роль источника -> точная заземлённая связь
```

Исторический арифметический пример давал отображение:

```text
A  -> U
B  -> N
C  -> N
B1 -> N1
C1 -> N1
```

Неинъективная подстановка допустима: разные исходные роли могут отображаться в одну целевую роль, если Теория не содержит явного запрета.

Произвольные составные выражения с несколькими целевыми ролями как значение одной исходной роли в первый этап не входят.

## 7. Защита от захвата роли

Роль существует только потому, что она явно объявлена ролью выбранного словаря.

При преобразовании сохраняется разделение:

```text
объявленная роль источника -> разрешённая подстановка
заземлённая часть источника -> точное тождество
```

Заземлённая связь не должна внезапно интерпретироваться как роль целевой области только из-за совпадения тождества.
Такой захват приводит к отказу.

## 8. Нормализация конечных преобразований

Для конечной специализации, межобластного переноса и композиции действует закон:

```text
исходная асеть доказательства
+ преобразование
        ↓
недоверенно построенная новая асеть доказательства
        ↓
независимая доверенная проверка
```

Успех преобразователя не является доказательством.
После нормализации проверяющий механизм не должен требовать метку способа построения.

Примитивный авторитет остаётся только таким:

```text
Theory -> Rule
Theory -> DR
```

Запрещено превращать успешно проверенный `DerivedDR` в новую примитивную связь `Theory -> DerivedDR`.
Точная ревизия Теории должна оставаться неизменной.

## 9. Индукция и наименьшее замыкание

Не каждое доказательное основание можно конечным образом развернуть в обычную цепочку.

Структурная индукция имеет форму:

```text
P(U)
P(N) -> P(N1)
---------------
Nat0(N) -> P(N)
```

Нельзя материализовать бесконечное семейство `P(U), P(S(U)), P(S(S(U))), ...`.

Поэтому неприводимое основание индукции или наименьшего замыкания само должно быть явной асетью доказательного авторитета:

```text
асеть основания замыкания
+ асеть базы
+ асеть шага
+ структурные отображения
        ↓
асеть итогового доказательства
```

Это не разрешает специальный доверенный объект или команду «индукция» в языке реализации. Авторитет по-прежнему выражен связями МТС.

## 10. Требования к доверенной проверке

Доверенная проверка должна:

1. начинаться от явного корня асети;
2. восстанавливать целевой `TargetDR` и точную Теорию;
3. определять доказательное замыкание достижимостью от корня;
4. читать зависимости из связей МТС;
5. восстанавливать смысл доказательных связей по топологии, а не по host-типам;
6. разрешать повторные ссылки на одно доказанное вхождение;
7. проверять точное разрешение каждого примитивного правила в Теории;
8. находить одну согласованную подстановку по заключению и всем посылкам шага;
9. сохранять точное тождество заземлённых частей;
10. отвергать захват ролей и противоречивую подстановку;
11. отвергать циклические доказательные зависимости;
12. отвергать самопринятие производного правила;
13. оставаться только читающей;
14. сохранять точную ревизию Теории;
15. принимать внешнее `H = Claim -> I` как посылку только тогда, когда `Claim` является точной объявленной посылкой `TargetDR`;
16. разрешать объявленной посылке внешнего контекста оставаться недостижимой и неиспользованной.

Посторонние связи общей памяти не являются ошибкой: они просто не принадлежат достижимой асети доказательства.

### 10.1. Ослабление внешнего целевого контекста

`TargetDR` задаёт объявленный внешний контекст:

```text
DeclaredPremises = ExactSequence(TargetDR premises)
```

Фактическая доказательная поддержка определяется только внешними `H`, достижимыми от корня `P` по зависимостям асети:

```text
UsedPremises = reachable declared H claims
```

Действует общий закон:

```text
UsedPremises ⊆ DeclaredPremises
```

Поэтому объявленная внешняя посылка может не использоваться. Это обычное ослабление контекста и не требует искусственно добавлять её в доказательство.

Обратное запрещено: любое достижимое внешнее `H`, чья `Claim` не входит точно в `DeclaredPremises`, должно быть отвергнуто. Ослабление не расширяет внешний контекст.

Диагностика доверенного replay различает:

```text
declaredAssumptionCount
usedAssumptionCount
```

и не сводит их к одному неоднозначному счётчику.

Это ослабление относится только к внешнему контексту `TargetDR`. Для каждого примитивного применения остаются строгими:

```text
точное число premise slots
все premise slots обязательны
точный порядок и кратность
одна полная подстановка по всему DR
все Roles связаны
заземлённые поддеревья совпадают точно
```

## 11. Обязательная отрицательная проверка

Исполнимый корпус должен отвергать:

```text
DerivedDR -> Theory без доказательной асети
поддельное Theory -> DerivedDR
достижимую внешнюю посылку, не объявленную TargetDR
отсутствующую или лишнюю зависимость примитивного шага
неверное число позиций посылок
частичную или противоречивую подстановку
захват заземлённой связи ролью цели
неразрешённый примитивный DR
чужую Theory
цикл зависимостей
подмену Claim
подмену последовательности зависимостей
запись в память во время проверки
неоднозначную коллизию H/A/O/I/P
подмену смысла связи через host-tag / host-type
```

Обязательные положительные случаи:

```text
одно доказанное вхождение используется двумя позициями одного правила
объявленная внешняя посылка остаётся неиспользованной
```

## 12. Связь с программой Nat × Proof Calculus

Текущее состояние старой арифметической лестницы после #1052 / #1057:

```text
N2a = COMPLETE
N2b = COMPLETE
generic role morphisms = PRESERVED
cross-scope proof reuse = PRESERVED
IND-related generic machinery = PRESERVED

L0   = PAUSED
L1   = PAUSED
COMM = PAUSED
```

Исторические результаты L0 остаются исследовательским происхождением и regression evidence, но старый `Nat0={U}∪L-degree` больше не является математической authority для нового Nat carrier.

Текущий #1050 проверяет только общий закон ослабления rooted proof Anet:

```text
UsedPremises ⊆ DeclaredPremises
```

Он не запускает старый L0, не меняет арифметический статус и не создаёт нового semantic candidate. Возврат к арифметике происходит через theorem challenges #1057 после структурного основания Nat #1052.

## 13. Текущий исполнимый корпус

Rooted proof Anet replay должен независимо покрывать generic случаи:

```text
простая цепочка примитивных DR
ветвящееся доказательство
повторное использование одного точного вхождения
TargetDR без Theory -> TargetDR
объявленный, но неиспользованный внешний premise
достижимый необъявленный внешний premise -> REJECT
специализированная асеть без специальной метки
межобластная асеть без специальной метки
```

Ключевые проверки:

```text
одна rho согласуется с conclusion + всеми primitive premise slots
UsedPremises ⊆ DeclaredPremises
H/A/O/I/P различаются только топологией МТС
нет встроенных сортов Claim/Rule/Proof/Theory в host-language
replay read-only
exact Theory unchanged
```

Исторический `derived-l0-left-zero-rerun.test.ts` сохраняется как диагностический материал, но не входит в acceptance #1050. Никакой арифметический статус из generic weakening slice не выводится.

Если сама топология недостаточна, исправляется топология МТС, а не вводится тип доказательства, существующий только в языке реализации.

## 14. Жёсткие запреты

```text
NO host ProofAuthority tagged union
NO PrimitiveProof / SpecializedProof / CrossScopeProof hierarchy
NO host Claim/Rule/Proof/Theory semantic sorts
NO trusted specialization or cross-scope tag
NO trusted induction opcode
NO closureWithSpecializations workaround
NO Nat/Add/S0 trusted opcode
NO importer self-admission
NO Theory mutation during replay
NO fabricated premise use to satisfy target context
NO weakening primitive premise arity/order/multiplicity
NO accepted v0.11 mutation
NO new semantic candidate/version from this work alone
```

## 15. Критерий архитектурной завершённости

Цель достигнута, когда достаточно указать:

```text
корень асети доказательства
точную Теорию
```

и доверенный механизм способен восстановить и проверить весь доказательный авторитет без знания алгоритма, которым асеть была построена, и без встроенного знания о «типах» математических объектов.

```text
всё доказательство выражено связями
смысл доказательных связей выражен связями
```
