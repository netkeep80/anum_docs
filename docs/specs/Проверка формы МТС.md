# Проверка формы МТС

Этот документ фиксирует проверку формы связи без изменения сети поверх уже канонизированной укоренённой сети МТС v0.7.

Связанные основания:

- [Основания МТС](../theory/Основания%20МТС.md);
- [Система аксиом МТС](../theory/Система%20аксиом%20МТС.md);
- [Формальная нотация МТС](Формальная%20нотация%20МТС.md).

## 1. Область действия

Проверка формы применяется к уже предъявленной смысловой связи `X` внутри сети, которая ранее прошла укоренённую каноническую проверку.

Она отвечает на вопрос:

```text
каковы уже существующие полюса X?
```

и не отвечает на вопрос:

```text
следует ли создать связь с такими полюсами?
```

Поэтому обязательна граница:

```text
проверка формы
≠
материализация формы
```

## 2. Основное суждение формы

Для уже различённых `X`, `A`, `B`:

```text
Shape(X; A,B)
⇔
start(X)=A ∧ end(X)=B
```

В канонической сети это эквивалентно утверждению:

```text
X = A ⟼ B
```

потому что одна упорядоченная пара уже различённых полюсов задаёт одну смысловую связь.

Эквивалентность не означает, что проверка должна вызывать `ensure(A,B)`. Если физической записи пары нет, операция чтения не обязана и не имеет права создавать её.

## 3. Остенсивные частные случаи

Самозамкнутое начало:

```text
StartSelf(X; e)
⇔
start(X)=X ∧ end(X)=e
```

Самозамкнутый конец:

```text
EndSelf(X; b)
⇔
start(X)=b ∧ end(X)=X
```

Полное самозамыкание:

```text
FullSelf(X)
⇔
start(X)=X ∧ end(X)=X
```

Из принятого основания следует:

```text
FullSelf(X)
=>
X = R = ∞
```

Поэтому в корректной канонической сети `FullSelf` истинно ровно для акорня.

## 4. Корневые challenge-векторы

Для корневого базиса:

```text
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

обязательны:

```text
FullSelf(R)
StartSelf(O; R)
EndSelf(C; R)
Shape(L; O,C)
Shape(U; C,O)
```

Неверный ожидаемый полюс даёт `false`, а не новую связь.

## 5. Технический handle не является семантической посылкой

Исполняемая реализация получает локальные `LinkRef`, но это не возвращает identity-by-pointer.

Порядок другой:

```text
rooted canonicalization
→ одна смысловая связь на одну форму
→ локальный handle как координата доступа
→ read-only проверка формы
```

То есть сравнение канонических локальных ссылок допустимо только **после** того, как сеть уже установила структурную различимость и единственность связей.

Сырая физическая запись не может стать смысловым различием только потому, что у неё другой адрес или номер слота.

Чужие и поддельные handle должны отвергаться на границе доступа.

## 6. Проверка отсутствующей пары

Пусть `A` и `B` уже различены, но физической записи `A ⟼ B` нет.

Тогда:

```text
find(A,B) = not found
```

не означает:

```text
A ⟼ B структурно невозможна
```

и не должно приводить к:

```text
materialize(A,B)
```

Проверка неверного ожидания:

```text
Shape(X; A,B) = false
```

также не меняет апамять.

Это частный случай общего принципа:

```text
не найдено ≠ не существует
find ≠ ensure
verify ≠ materialize
```

## 7. Акт проверки и проверяемая связь

Если необходимо хранить происхождение проверки, различаются:

```text
проверяемая связь X
ожидаемое начало A
ожидаемый конец B
результат проверки
сам акт проверки
```

Роли вида:

```text
actual-start
expected-start
actual-end
expected-end
```

принадлежат структуре акта проверки и не добавляют полей к самой связи `X`.

Два разных акта могут проверить одну и ту же `X` и получить один и тот же результат. Различие актов, если оно существенно, должно находиться в их связевой истории, а не в копиях `X`.

## 8. Исполняемая эталонная проверка

Эталонная реализация находится в:

```text
core/rooted_shape_judgment.py
```

Она содержит четыре чистые операции:

```text
shape(network, X, A, B)
start_self(network, X, e)
end_self(network, X, b)
full_self(network, X)
```

Все они только читают `LinkNetwork`.

Внутри них отсутствуют:

```text
LinkNetworkBuilder
ensure
reserve
define
```

Поэтому проверка формы не имеет собственного пути материализации.

## 9. Инвариант

```text
rooted distinction
→ canonical semantic identity
→ presented X
→ read-only pole observation
→ true / false
```

а не:

```text
runtime ID
→ предполагаемое различие
→ скрытое создание пары
→ объявление формы истинной
```

Именно эта граница делает `Shape` совместимым с пересмотром семантики #343.
