# Пучки значений МТС v0.2

> **Статус:** нормативная спецификация accepted `mts-value-bundle/v0.2`.
>
> Теоретический смысл изложен в [«Пучки связей МТС»](../theory/Пучки%20связей%20МТС.md). Machine-readable source of truth: `contracts/mts-value-bundle-v0.2.json` и `contracts/mts-value-bundle-conformance-v0.2.json`.

## 1. Область версии

v0.2 принимает только **плоский** `ValueBundle`.

Принято:

- статическое различение `ConstraintBundle` / `ValueBundle` для одного surface `{...}`;
- независимое разрешение каждого source occurrence;
- extensional equality по множеству уже разрешённых link identities;
- отсутствие singleton coercion между `ValueBundle` и одиночным Link value;
- read-only expansion/query через juxtaposition с минимум одним bundle operand;
- пустой bundle как wildcard только в endpoint position expansion-а.

Не принято:

- вложенный `ValueBundle`;
- непустой bundle-valued RHS `:`;
- lifting `⟼`, `♀`, `♂`, `¬` на bundle;
- bundle как explicit pole `LinkForm`;
- implicit `realize`/`delete`;
- synthetic value для отсутствующей связи.

## 2. Surface и статическая elaboration

Surface parser сохраняет фигурную форму и source occurrences. Семантическая роль выбирается **до interpretation**.

```text
CurlySyntax
  ├─ ConstraintBundle
  └─ ValueBundle
```

Runtime inspection памяти не участвует в выборе роли.

### 2.1 Evidence

Для непустого bundle:

- direct Judgment items дают constraint evidence;
- direct non-bundle Form items дают value evidence;
- смесь evidence → `mixed-bundle-role-evidence`.

### 2.2 Пустой `{}`

Пустой bundle не содержит внутреннего evidence, поэтому его роль задаётся статическим parent/entry context.

| Контекст | Роль |
|---|---|
| constraint entry | `ConstraintBundle` |
| operand `=` / `!=` | `ValueBundle` |
| endpoint bundle-expansion | `ValueBundle` |
| RHS `x : {}` | `ConstraintBundle` |
| без достаточного статического контекста | `ambiguous-empty-bundle-role` |

### 2.3 Operator domains

| Позиция | v0.2 |
|---|---|
| `ConstraintBundle` at constraint entry | accepted |
| flat `ValueBundle` at value/equality position | accepted |
| sequence with >=1 `ValueBundle` | expansion query |
| `ValueBundle` as explicit `⟼` pole | rejected/deferred |
| `♀ValueBundle`, `ValueBundle♂`, `¬ValueBundle` | rejected/deferred |
| `name : {a,b}` | rejected/deferred |
| nested `{{a,b}}` as value | rejected/deferred |

## 3. Runtime value model

Семантические значения tagged:

```text
LinkValue(link)
BundleValue({link₁, link₂, ...})
```

Между ними нет singleton coercion:

```text
{a} != a
```

даже если `a` разрешилось в единственную связь.

## 4. Resolution и provenance

Каждый direct item плоского `ValueBundle` разрешается независимо.

Для source:

```text
{[], []}
```

две occurrences имеют разные structural paths. Их нельзя объединить до resolution.

Observable stages:

```text
source occurrences
      ↓ independent resolution
ordered occurrence → resolved identity trace
      ↓ extensional projection
unique resolved identity set
```

Именно последний набор является semantic identity `BundleValue`.

Порядок и число повторных source occurrences сохраняются для provenance/trace, но после resolution не входят в extensional equality.

## 5. Equality

Для двух `BundleValue`:

```text
equal(left, right) ⇔ resolvedSet(left) = resolvedSet(right)
```

Следствия:

```text
{a,b} = {b,a}
{a,a} = {a}
```

только после разрешения соответствующих occurrences.

Для anonymous forms:

```text
{[],[]} = {[]}
```

не является source-level тождеством. Результат зависит от bindings отдельных occurrences.

Cross-kind comparison:

```text
LinkValue(x) != BundleValue({x})
```

## 6. Expansion/query

Если `Sequence` содержит ровно два endpoint expression и хотя бы один endpoint статически elaborated как `ValueBundle`, последовательность трактуется как bundle expansion query.

Endpoint domain:

- scalar form → singleton resolved identity;
- non-empty bundle → resolved identity set;
- empty bundle → wildcard/unconstrained endpoint **только в expansion position**.

### 6.1 Семантика

```text
a{b,c}
```

выбирает существующие links `(a,b)` и `(a,c)`, если они существуют.

```text
{a,b}c
```

выбирает существующие `(a,c)` и `(b,c)`.

```text
{a,b}{c,d}
```

выбирает существующие ordered pairs из декартова произведения endpoint domains.

### 6.2 Wildcard

```text
a{}   → existing outgoing from a
{}b   → existing incoming to b
{}{}  → all existing links in selected read-only memory view
```

### 6.3 Отсутствующие pairs

Если exact pair отсутствует, он пропускается:

```text
missing pair → no result element
```

Никакого implicit realization.

## 7. Effects

Accepted invariant:

```text
bundle interpretation may read memory
bundle interpretation may not realize
bundle interpretation may not delete
```

Expansion — query, не команда.

## 8. Canonical reference core

Единственный reference implementation:

```text
core/mtc_value_bundle.py
```

Основные операции:

```text
elaborate_bundles
 evaluate_flat_value_bundle
 values_equal
 expand_bundle_query
```

`ConstraintBundle` execution остаётся существующим `interpret_constraints()`; роли различаются статически и не образуют compatibility implementations одного поведения.

## 9. Conformance

Normative corpus:

```text
contracts/mts-value-bundle-conformance-v0.2.json
```

Он фиксирует:

- role elaboration;
- static rejections;
- extensional equality после resolution;
- occurrence-local `[]` cases;
- cross-kind comparison;
- read-only expansion;
- no-realize veto.

Challenge/decision artifacts остаются доказательной историей принятого решения, но не альтернативными runtime implementations.

## 10. Root regression

Десять корневых определений МТС не меняются. Bundle-формы внутри `∞` и `(=)` elaborated только как `ConstraintBundle`.

Это обязательный acceptance gate v0.2.
