# Пучки значений МТС

Этот документ — каноническое описание сохранённой производной поверхности:

```text
mts-value-bundle/v0.3
```

Версия поверхности пучков **не является номером глобального выпуска МТС**. Текущий выпуск МТС определяется указателями и генерируемым блоком в [README](../../README.md).

Имя файла `Пучки значений МТС v0.2.md` сохранено как исторически стабильный путь. Поверхность v0.3 возникла из v0.2 через укоренённую миграцию без изменения наблюдаемой семантики результата.

Пучок остаётся производным структурным слоем над обычными Связями и не вводит новый вид первичной сущности.

## 1. Фигурные скобки — метанотация поверхности

Нужно различать:

```text
принятая семантика ValueBundle
!=
принятые внутренние знаки { и }
```

Текущая формальная основа F1 описана в [спецификации формальной нотации](Формальная%20нотация%20МТС.md). Фигурные знаки не входят в принятый внутренний набор и остаются отложенными.

Поэтому записи:

```text
{a,b}
{}
a{b,c}
{a,b}c
```

являются удобной **метанотацией** уже определённой пучковой поверхности. Они не доказывают самовведение `{` и `}` как операторов МТС.

Если фигурные знаки когда-либо будут предложены именно как внутренние FORMAL-знаки, это будет отдельное смысловое изменение со своим обоснованием и принятием.

## 3. Назначение и роли

Пучок применяется, когда производная операция работает с совокупностью уже разрешённых Связей.

Сохраняются две статические роли:

```text
ConstraintBundle
ValueBundle
```

Роль определяется структурным свидетельством до интерпретации значений и не выводится из случайного текущего содержимого апамяти.

Пустая пучковая форма сама по себе роль не определяет. В метанотации `{}` сохраняется историческое распределение ролей:

| Позиция | Роль |
|---|---|
| вход условий | пучок условий |
| операнд `=` или `!=` | пучок значений |
| полюс раскрытия | пучок значений |
| правая часть `x : {}` | пучок условий |
| недостаточный контекст | ошибка неоднозначности |

Как самостоятельное значение `{}` обозначает пустой пучок. Значение «нет ограничения» возникает только в полюсе раскрытия.

## 4. Укоренённый вход v0.3

Историческая v0.2 принимала типизированное синтаксическое представление. В v0.3 смысловой вход заменён явным укоренённым структурным свидетельством.

Понятийно:

```text
kind-tag ⟼ rooted(children...)
```

Отсюда следуют ограничения:

- адрес синтаксического объекта не является смыслом;
- техническая ссылка среды исполнения не является смыслом;
- путь обхода не является тождеством Связи;
- повтор одной смысловой Связи в нескольких позициях допустим;
- некорректный циклический носитель отклоняется.

Путь — только координата происхождения и проверки.

## 5. Разрешение вхождений

Каждое исходное вхождение разрешается отдельно **до** построения экстенсионального значения пучка.

Свидетельство разрешённого вхождения имеет форму:

```text
(path, canonicalLink)
```

где `path` — координата происхождения, а `canonicalLink` — уже различённая смысловая Связь.

Правильная последовательность:

```text
вхождение
-> проверить и разрешить
-> получить каноническую Связь
-> затем выполнить экстенсиональную дедупликацию
```

Два разных пути могут указывать на одну смысловую Связь. Это не создаёт вторую Связь.

## 6. Экстенсиональное равенство

После разрешения пучок рассматривается как множество различных канонических Связей.

В метанотации:

```text
{a,b} = {b,a}
{a,a} = {a}
```

Происхождение сохраняется отдельно и не входит в экстенсиональное равенство.

Текущая инженерная модель различает:

```text
BundleValue.links
BundleValue.occurrences
```

Первое задаёт экстенсиональное значение, второе — свидетельства происхождения.

## 7. Пучок не равен одиночной Связи

Автоматическое приведение:

```text
{a} = a
```

не принимается.

Одноэлементный пучок остаётся пучком. Инженерная реализация различает:

```text
LinkValue
BundleValue
```

Это различие уровня производного значения не создаёт новый тип примитивной Связи.

## 8. Раскрытие пучка

Если хотя бы один полюс запроса является пучком значений, выполняется чтение уже существующих Связей.

Метанотация:

```text
a{b,c}       -> существующие a⟼b и a⟼c
{a,b}c       -> существующие a⟼c и b⟼c
{a,b}{c,d}   -> существующие пары декартова произведения
```

Пустой пучок означает отсутствие ограничения **только в позиции раскрытия**:

```text
a{}   -> все существующие исходящие Связи из a
{}b   -> все существующие входящие Связи в b
{}{}  -> все существующие Связи выбранной памяти
```

Вне раскрытия `{}` не является универсальным знаком «любая Связь».

Это производный слой чтения и не превращает глобальное перечисление памяти в фундаментальную семантику F1.

## 9. Поиск не материализует

Раскрытие использует только уже существующие Связи.

Если подходящей пары нет, она отсутствует в результате.

Запрещён переход:

```text
не найдено
-> создать Связь
```

Следовательно:

```text
раскрытие != материализация
раскрытие != удаление
```

Это применение общей границы апамяти «чтение != изменение», описанной в [спецификации апамяти](Апамять%20и%20управление%20сетью%20связей.md).

## 10. Что миграция v0.2 → v0.3 не добавила

Укоренённая миграция не приняла автоматически:

- вложенные пучки значений;
- непустой пучок значений в правой части `:`;
- новый примитивный тип полюса для пучка;
- автоматическое распространение произвольных операций на пучок;
- неявное создание отсутствующих Связей;
- удаление через пустой пучок;
- синтетические значения для отсутствующих пар;
- глобальное переписывание по равенству пучков;
- приведение одноэлементного пучка к одиночной Связи;
- внутренние F1-знаки `{` и `}` только из факта существования ValueBundle.

Такие расширения требуют отдельного смыслового решения.

## 11. Граница с тождеством Связи

Пучки не являются исключением из фундаментального тождества Связи по различённым упорядоченным полюсам, определённого [Системой аксиом МТС](../theory/Система%20аксиом%20МТС.md).

Нужно различать:

```text
множественность исходных вхождений
сведения об их происхождении
тождество разрешённой Связи
экстенсиональное тождество пучка
пустой пучок как отсутствие ограничения поиска
поиск и явную материализацию
метанотацию {...}
внутренний F1-знак
```

Позиция, путь, слот, адрес хранения или видимый знак не создают вторую смысловую Связь.

## 12. Сохранённая граница v0.2

Укоренённая миграция сохраняет наблюдаемое поведение v0.2:

- статические роли пучковых форм;
- коды статических отказов;
- разрешение каждого вхождения до дедупликации;
- экстенсиональное членство;
- различие одиночной Связи и одноэлементного пучка;
- пустой пучок как отсутствие ограничения в раскрытии;
- отсутствие синтетической пары при неудачном поиске;
- отказ для чужого или некорректного свидетельства;
- отсутствие второй смысловой Связи при совместном использовании одной формы.

Поэтому `mts-value-bundle/v0.3` — сохранённая производная поверхность над укоренённым основанием, а не новая математика пучков.
