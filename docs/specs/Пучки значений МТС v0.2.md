# Пучки значений МТС

Этот документ описывает принятую в MTS v0.7 поверхность `mts-value-bundle/v0.3` и является её каноническим текстовым описанием в репозитории.

Имя файла сохранено как стабильный исторический путь. Версия 0.3 получена укоренённой миграцией версии 0.2: наблюдаемое поведение сохранено, но типизированное синтаксическое дерево больше не является семантическим авторитетом.

Машинные источники истины:

```text
contracts/mts-contract-v0.7.json#surfaces.valueBundle
contracts/mts-conformance-v0.7.json#corpora.valueBundle
core/foundation_v2_value_bundle.py
cutover/value-bundle-rooted-migration-decision-v0.1.json
```

## 1. Назначение и роли

Пучок используется, когда требуется работать не с одной связью, а с совокупностью уже разрешённых связей.

Сохраняются две статические роли фигурной формы:

```text
ConstraintBundle
ValueBundle
```

Роль определяется до интерпретации значений и не выводится из текущего содержимого апамяти.

Пустая форма `{}` сама не определяет роль. Сохраняются правила версии 0.2:

| Позиция | Роль |
|---|---|
| вход условий | пучок условий |
| операнд `=` или `!=` | пучок значений |
| полюс раскрытия | пучок значений |
| правая часть `x : {}` | пучок условий |
| недостаточный контекст | ошибка неоднозначности |

Как самостоятельное значение `{}` является пустым пучком. Значение «нет ограничения» возникает только в полюсе раскрытия.

## 2. Укоренённый вход версии 0.3

Историческая версия 0.2 принимала типизированное синтаксическое представление. Версия 0.3 проверяет явный укоренённый носитель структуры.

Понятийно:

```text
kind-tag ⟼ rooted(children...)
```

Из этого следуют ограничения:

- адрес синтаксического объекта не является смыслом;
- техническая ссылка времени исполнения не является смыслом;
- путь обхода не является тождеством связи;
- повтор одной смысловой связи в нескольких позициях допустим;
- некорректный циклический носитель отвергается.

Путь используется только как координата происхождения и проверки.

## 3. Разрешение вхождений

Каждое исходное вхождение разрешается отдельно до построения экстенсионального значения пучка.

Свидетельство разрешённого вхождения имеет форму:

```text
(path, canonicalLink)
```

где `path` — координата происхождения, а `canonicalLink` — уже различённая смысловая связь.

Правильный порядок:

```text
вхождение
→ проверить и разрешить
→ получить каноническую связь
→ затем выполнить экстенсиональную дедупликацию
```

Два разных пути могут указывать на одну смысловую связь. Это не создаёт вторую связь.

## 4. Экстенсиональное равенство

После разрешения пучок является множеством различных канонических связей:

```text
{a,b} = {b,a}
{a,a} = {a}
```

Происхождение сохраняется отдельно и не входит в экстенсиональное равенство.

Эталонная модель различает:

```text
BundleValue.links
BundleValue.occurrences
```

Первое поле задаёт смысловое множество, второе — свидетельства происхождения.

## 5. Пучок не равен одиночной связи

Автоматическое приведение:

```text
{a} = a
```

не принимается.

Одноэлементный пучок остаётся пучком. В эталонной реализации различаются:

```text
LinkValue
BundleValue
```

Это различие относится к уровню значения и не вводит новый вид примитивной связи.

## 6. Раскрытие пучка

Если хотя бы один полюс запроса является пучком значений, выполняется чтение уже существующих связей.

```text
a{b,c}       → существующие a⟼b и a⟼c
{a,b}c       → существующие a⟼c и b⟼c
{a,b}{c,d}   → существующие пары декартова произведения
```

Версия 0.3 использует общий читающий поиск Foundation-v2. Собственный путь скрытой материализации не вводится.

Только в позиции раскрытия пустой пучок означает отсутствие ограничения:

```text
a{}   → все существующие исходящие связи из a
{}b   → все существующие входящие связи в b
{}{}  → все существующие связи выбранной памяти
```

Вне раскрытия пустой пучок не является универсальным знаком «любая связь».

## 7. Поиск не материализует

Если подходящей пары нет, она просто отсутствует в результате.

Запрещён скрытый переход:

```text
не найдено
→ создать связь
```

Поэтому:

```text
раскрытие ≠ материализация
раскрытие ≠ удаление
```

Это частный случай общей границы апамяти:

```text
поиск / чтение / проверка
≠
явное изменение
```

## 8. Что миграция 0.2 → 0.3 не добавляет

Не становятся автоматически принятой семантикой:

- вложенные пучки значений;
- непустой пучок значений в правой части `:`;
- новый примитивный тип полюса для пучка;
- автоматическое распространение операций на пучок;
- неявное создание отсутствующих связей;
- удаление через пустой пучок;
- синтетические значения для отсутствующих пар;
- глобальное переписывание по равенству пучков;
- приведение одноэлементного пучка к одиночной связи.

Такие расширения требуют отдельных решений.

## 9. Граница с тождеством связи

Пучки не являются исключением из фундаментальной аксиомы MTS v0.7:

```text
(A ⟼ B) = (C ⟼ D)
⇔
A = C ∧ B = D
```

Нужно различать:

```text
множественность исходных вхождений
сведения об их происхождении
тождество разрешённой связи
экстенсиональное тождество пучка
пустой пучок как отсутствие ограничения поиска
поиск и явную материализацию
```

Позиция, путь, слот или адрес хранения не создают вторую смысловую связь.

## 10. Что сохранено от версии 0.2

Решение об укоренённой миграции сохраняет наблюдаемое поведение:

- статические роли фигурных форм;
- коды статических отказов;
- разрешение каждого вхождения до дедупликации;
- экстенсиональное членство пучка;
- различие одиночной связи и одноэлементного пучка;
- пустой пучок как отсутствие ограничения в раскрытии;
- отсутствие синтетической пары при неудачном поиске;
- отказ для чужого или некорректного свидетельства;
- отсутствие второй смысловой связи при совместном использовании одной формы.

Таким образом `mts-value-bundle/v0.3` — не новая математика пучков, а перенос сохранённой семантики на укоренённое основание MTS v0.7.

## Итог

```text
роль определяется явной структурой
path — только координата происхождения и проверки
тождество разрешённой связи — по полюсам
членство пучка — экстенсиональное
происхождение хранится отдельно
{a} != a
пустой полюс раскрытия = отсутствие ограничения
query != materialize
missing pair != synthetic value
```

Историческая версия 0.2 остаётся источником сохранённых наблюдаемых правил; текущая принятая машинная поверхность — `mts-value-bundle/v0.3`.
