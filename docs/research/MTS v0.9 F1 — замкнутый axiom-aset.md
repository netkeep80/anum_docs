# МТС v0.9 F1 — замкнутая асеть аксиом

Статус: **кандидатный артефакт оснований** для #594.

Этот документ не изменяет принятую МТС v0.8 и не доказывает теоремы #582/#583. Его задача — собрать в одной форме завершённые решения #595/#596/#599/#601/#602/#597 и показать минимальную замкнутую систему самовведения знаков F1.

## 1. Граница F1

Внутренний минимальный алфавит состоит ровно из десяти знаков:

```text
∞ [ ] 1 0 ( ) ⟼ : =
```

Не входят в минимальный F1:

```text
≡              DEFER / META-ONLY
♂ ♀            DEFER-DERIVED
↑              DEFER-DERIVED
{ }            DEFER-DERIVED
¬ ↛            DEFER-DERIVED
∧ ⇔ ⇒ ≠ →      META-ONLY
```

Служебные записи вроде `->`, `!=`, `INF` также не являются знаками оснований.

`R/O/C/L/U` — мета- и машинные имена связей, а не второй физический алфавит.

## 2. Четыре различаемых слоя

Для каждого внутреннего знака `g` различаются:

```text
physical glyph g
canonical exact source carrier c_g
sign/dictionary Entry E_g
semantic meaning Link m_g
```

Иначе говоря, отдельно существуют:

1. физический знак;
2. его точный исходный носитель `c_g`;
3. словарная запись `E_g`;
4. смысловая связь `m_g`.

Конкретное употребление дополнительно задаётся явным контекстом `I/K/Rule`.

Канонический исходный носитель строится так:

```text
UTF-8 bytes(g)
-> Rep_SQ: один [bbbbbbbb] на каждый byte, MSB-first
-> ExactSequence<Byte(p)>
= c_g
```

Затем собственная связь знака имеет форму:

```text
E_g := c_g ⟼ m_g
```

Здесь `:=` — только метазапись этого документа. Внутри асети аксиом отдельного оператора `:=` нет.

Одинаковый смысл не означает одинаковый знак:

```text
m∞ и m=    ожидаемо один R
E∞ и E=    разные связи из-за разных c_g

m[ и m(    ожидаемо один O
E[ и E(    разные связи

m] и m)    ожидаемо один C
E] и E)    разные связи

m1 и m⟼    ожидаемо один L
E1 и E⟼    разные связи
```

## 3. Внутренняя форма аксиомы без внешнего равенства

Строки вида

```text
m∞ = m∞ ⟼ m∞
```

ниже являются лишь удобной метазаписью рекурсивного ограничения на полюса. Знак `=` в такой строке **не** является внутренним знаком `=` МТС и не импортирует классическое равенство.

Само ограничение хранится обычной структурой связей:

```text
poles(m_g) = (m_start, m_end)
E_g       = c_g ⟼ m_g
```

Разрешённая внутренняя форма вводящей аксиомы имеет вид:

```text
Relation_g = ExactSequence(
  m_start,
  E_⟼,
  m_end
)

A_g = ExactSequence(
  c_g,
  E_:,
  Relation_g
)
```

То есть её читаемый смысл:

```text
carrier_g : (m_start ⟼ m_end)
```

Результат внутреннего отношения:

```text
m_start ⟼ m_end -> m_g
c_g ⟼ m_g       -> E_g
```

Отдельный объект уравнения не вводится. `A_g` — обычная точная последовательность, `E_g` — обычная связь, а рекурсивное уравнение уже выражено полюсами `m_g`.

## 4. Десять одновременных ограничений

Мета-проекция системы:

```text
m∞ = m∞ ⟼ m∞

m[ = m[ ⟼ m∞
m] = m∞ ⟼ m]
m1 = m[ ⟼ m]
m0 = m] ⟼ m[

m( = m( ⟼ m∞
m) = m∞ ⟼ m)
m⟼ = m( ⟼ m)

m: = m∞ ⟼ m⟼
m= = m= ⟼ m=
```

Все имена зависимостей справа принадлежат тому же набору из десяти смыслов. Внешний примитив оснований для замыкания не требуется.

Система рассматривается одновременно, а не как программа «сначала определить `∞`, затем `[`, затем остальные знаки».

Особенно важно:

```text
A_: содержит E_: как свой оператор `:`
A_⟼ содержит E_⟼ как свой оператор `⟼`
```

Поэтому `:` и `⟼` участвуют в собственном самовведении. Это взаимное структурное ограничение, а не последовательная загрузка заранее известных токенов.

## 5. Точные носители

| знак | каноническая `Rep_SQ` |
|---|---|
| `∞` | `[11100010][10001000][10011110]` |
| `[` | `[01011011]` |
| `]` | `[01011101]` |
| `1` | `[00110001]` |
| `0` | `[00110000]` |
| `(` | `[00101000]` |
| `)` | `[00101001]` |
| `⟼` | `[11100010][10011111][10111100]` |
| `:` | `[00111010]` |
| `=` | `[00111101]` |

Носитель — представление, а не толкование. Произвольные байты могут оставаться допустимыми на нижнем байтовом уровне, но эти десять физических знаков являются строгими текстовыми значениями `UTF-8`.

## 6. Ожидаемая корневая проекция

Кандидатная система намеренно совместима с текущей машинной проекцией:

```text
m∞ = m=       -> R
m[ = m(       -> O
m] = m)       -> C
m1 = m⟼       -> L
m0             -> U
m:             -> R ⟼ L
```

Эта таблица **не является доказательством** схлопываний.

F1 только предъявляет рекурсивную систему и машинное свидетельство её непротиворечивости с уже существующей проекцией. Внутреннее основание одновременного решения и отсутствия экземплярности принадлежит:

```text
#582 — grounded simultaneous solution
#583 — no-instance / unique-root consequences
```

Нельзя закрывать #583 ссылкой на `Memory.ensure` или на таблицу выше.

## 7. Асеть аксиом как обычная теория

Порядок объявлений нужен как точное представление конфигурации, но не как непрозрачный идентификатор аксиом.

Кандидатная структура:

```text
TheoryDeclSeq = ExactSequence(
  A_∞,
  A_[,
  A_],
  A_1,
  A_0,
  A_(,
  A_),
  A_⟼,
  A_:,
  A_=
)

T_F1 = T_F1 ⟼ TheoryDeclSeq
```

`T_F1` — обычная односторонне самозамкнутая связь с точной последовательностью объявлений. Никаких `AxiomId`, `UUID`, объектов среды выполнения или отдельной тождественности неупорядоченного множества нет.

Перестановка `TheoryDeclSeq` даёт структурно другое представление. Если позже понадобится экстенсиональная эквивалентность теорий независимо от порядка, это должна быть производная теорема, а не тождественность F1.

## 8. Словарь и контексты

Все `E_g` включаются в обычный словарь `D` как канонические записи:

```text
Entry = sourceContent ⟼ form
```

Связи появления и истории словаря не создают новые `E_g` или `m_g`; они только выражают историю объявления и эффекта.

Контекст задаётся структурной конфигурацией:

```text
G_Q      = G_Q      ⟼ ExactSequence(E_[, E_], E_1, E_0)
G_FORMAL = G_FORMAL ⟼ ExactSequence(E_(, E_), E_⟼, E_:, E_=)

I_Q      = D ⟼ (G_Q      ⟼ T_F1)
I_FORMAL = D ⟼ (G_FORMAL ⟼ T_F1)

K = K ⟼ (parent ⟼ current)
I ⟼ K
```

Одинаковая структурная `K` не должна клонироваться только ради названий «Q» и «формальный». Различие употребления выражено через `I ⟼ K` и различную рекурсивную структуру `G`.

Перечисление режима в языке реализации не является смысловым основанием.

## 9. Замкнутый цикл каждого знака

Для каждого `g` действует одна схема:

```text
physical glyph g
-> exact UTF-8 bytes
-> canonical Rep_SQ / ExactSequence carrier c_g
-> dictionary Entry E_g = c_g ⟼ m_g
-> recursive poles of m_g use only meanings of the same F1 registry
-> exact FORMAL axiom A_g uses E_: and E_⟼ from the same registry
-> A_g belongs to TheoryDeclSeq of T_F1
-> T_F1 participates in I_Q / I_FORMAL
-> D in the same I resolves c_g back to m_g
```

Внешний смысловой токен ни на одном шаге не нужен.

Материализация носителей относится к явному пути записи при построении структуры. Последующее разрешение, проверка и воспроизведение обязаны идти без записи.

## 10. Центральные проверки самовведения

### Корень

Внутренняя форма:

```text
A_∞ = [
  c_∞,
  E_:,
  [m∞, E_⟼, m∞]
]
```

В машинной проекции внутреннее отношение имеет форму `R ⟼ R` и возвращает `R`, а внешняя словарная запись имеет форму `c_∞ ⟼ R`.

Краткая человеческая запись:

```text
∞ : (∞ ⟼ ∞)
```

Она читается как представление самосогласованности, а не как внешнее определение корня.

### Двоеточие

```text
A_: = [
  c_:,
  E_:,
  [m∞, E_⟼, m⟼]
]
```

`E_:` уже находится внутри собственного объявления теории. Нет первого «магически заранее определённого» двоеточия.

### Формальная стрелка

```text
A_⟼ = [
  c_⟼,
  E_:,
  [m(, E_⟼, m)]
]
```

`E_⟼` участвует в собственной форме аксиомы тем же одновременным способом.

### Знак равенства

```text
poles(m=) = (m=, m=)
E_=       = c_= ⟼ m=
```

Это самовведение корневого смысла отсутствия различия. Оно **не** определяет формальное употребление `=` через имя функции языка реализации.

Формальное употребление `left = right` остаётся отдельным допущенным правилом с проверкой:

```text
localRepresentative(K,left)
localRepresentative(K,right)
-> no-distinction только если representatives совпали
```

Глобального транзитивного замыкания равенства, присваивания, переписывания или примитива конгруэнтности F1 не вводит.

## 11. Слой правил и употреблений

Замыкание асети аксиом знаков не создаёт второй интерпретатор. Оно опирается на уже зелёные кандидатные свидетельства:

| назначение | исполняемое свидетельство |
|---|---|
| точная последовательность и состояние Q | `ts/test/v09-structural-carriers.test.ts` |
| канонический байтовый носитель | `ts/test/v09-byte-carrier.test.ts` |
| `I/DR/Rule`, `T ⟼ Rule`, общее воспроизведение | `ts/test/v09-structural-rules.test.ts` |
| контексты Q/формальный, `:`, `=`, отношение и закрытие | `ts/test/v09-context-integration.test.ts` |
| дополнительные отрицательные проверки готовности | `ts/test/v09-readiness.test.ts` |
| собранное замыкание F1 | `ts/test/v09-f1-axiom-aset.test.ts` |

Минимальные смысловые роли правил остаются:

```text
Q_OPEN
Q_VALUE
Q_CLOSE
Q_FINALIZE
FORMAL_OPEN
FORMAL_GROUP
FORMAL_LINK
FORMAL_COLON
FORMAL_EQUAL
FORMAL_CLOSE
PARENT_CONTINUE
```

Это роли структурных правил и контекстов, а не `RuleKind`, `opcode` или `callback` как источник смысла.
