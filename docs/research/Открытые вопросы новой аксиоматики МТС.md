## F1. МТС как одновременная система рекурсивных уравнений

### 13. Методологическая граница

Фундамент МТС не определяется через заранее выбранную внешнюю математическую онтологию.

Неверное направление:

```text
носитель
-> граф / узлы
-> эквивалентность
-> факторизация
-> смысловая связь
```

Графы, коалгебры, категории и другие известные конструкции могут использоваться только позже как внешние модели и проверки уже сформулированной МТС.

PR #591/#592 сохраняются как отрицательные проверки, но не как фундамент.

### 14. Корневое начальное самозадание решается как одно целое

Принятая машинная запись:

```text
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O

(A ⟼ B) = (C ⟼ D)
⇔ A = C ∧ B = D
```

должна читаться как взаимно-рекурсивная система уравнений.

Она одновременно связывает понятия:

```text
связь
↔ начало / конец
↔ тождество
↔ различие
↔ рекурсивность
↔ самозамыкание
↔ корневые формы
```

Порядок записи `R`, затем `O/C`, затем `L/U` не означает последовательного онтологического построения.

### 15. Один стрелочный знак формальной связи: `⟼`

Используется только исторический и уже принятый стрелочный знак формальной нотации:

```text
⟼
```

Новый знак `⇝` не вводится.

Причины:

- `⟼` уже используется в нормативной теории, контрактах и реализации TypeScript;
- `⇝` не используется в текущем коде и документации;
- у `⇝` нет отдельного рекурсивно выраженного смысла;
- второй синонимичный стрелочный знак нарушал бы принцип минимальности;
- различие графического написания без различия в системе аксиом не создаёт новый смысловой знак.

При этом нельзя схлопывать в один поверхностный знак:

```text
⟼
1
L
```

Они принадлежат разным контекстам нотации:

```text
⟼ = бинарный оператор/конструктор формальной нотации МТС
1  = знак абита в четверичном ачисле
L  = связь в натуре вокруг акорня, задающая смысл связи/связности
```

Это три разных контекстных знаковых роли, связанные одним корневым смыслом связности. Их различие сообщает, **как именно используется один и тот же смысл**.

### 16. Уровни представления, интерпретации и рекурсивного самовведения

Последнее уточнение #599 задаёт не несколько равноправных физических языков, а стек представлений и интерпретаторов.

Формальная нотация записывается **строковым ачислом**, а строковое ачисло должно иметь ровно одно каноническое представление четверичным ачислом:

```text
FORMAL source
  is a STRING ACHISLO

STRING ACHISLO
  has one canonical QUATERNARY representation

QUATERNARY carrier
  is read only under an explicitly selected interpretation context

ROOT/ASET
  carries the semantic Links to which those readings are related
```

Поэтому нужно различать как минимум три отношения:

```text
представление
интерпретация
смысловой денотат
```

Каноническое представление строки четверичным носителем не означает, что этот носитель имеет только одно возможное чтение. В исследовательской метанотации #602 это можно выразить как:

```text
Rep_SQ(s, q)
```

при требовании функциональности:

```text
Rep_SQ(s, q1) ∧ Rep_SQ(s, q2)
=> q1 = q2
```

но один и тот же физический `q` при разных **явно выбранных** интерпретаторах может давать разные результаты:

```text
q + STRING context       -> строковое ачисло
q + QUATERNARY context   -> структурное четверичное чтение
```

Это сохраняет исторический результат #213: носитель сам по себе не определяет режим интерпретации.

#### 16.1. Рабочий кандидат канонического строкового носителя

#602 отдельно проверяет точную границу `STRING -> QUATERNARY`. Текущий наиболее узкий кандидат, ещё не принятый как нормативная семантика:

```text
StringAchislo(bytes) = canonical byte content C(bytes)

C0 = R
C(n+1) = Cn ⟼ B(byte_n)
```

где один байтовый носитель имеет четверичное написание:

```text
byte b -> [bbbbbbbb]
```

То есть кандидат на каноническое представление:

```text
enc_SQ(C(b0...bn))
  = [bits8(b0)][bits8(b1)]...[bits8(bn)]
```

UTF-8 при этом является отдельным строгим текстовым чтением точных байтов без скрытой нормализации Юникода.

Эта линия восстанавливает полезную часть исследовательских проверок #214/#233, но **не** возвращает старую модель экземпляров исходного текста:

```text
S = S ⟼ C
```

если различие двух `S` выражалось только фактом повторного появления текста. По текущему принципу отсутствия экземплярности одинаковое содержимое задаёт одно каноническое значение, а позиция, история и акт чтения выражаются отдельной структурой.

Текущий конвертер на TypeScript, группирующий все байты UTF-8 одной кодовой точки Юникода внутри одной пары `[...]`, остаётся полезным свидетельством вспомогательной реализации, но не определяет фундамент. #597 должен после решения #602 явно классифицировать его относительно единственного канонического `STRING -> QUATERNARY` представления.

#### 16.2. Порядок декодирования не является порядком происхождения смысла

Для физического предъявления допустим направленный стек:

```text
QUATERNARY carrier
-> STRING reading
-> FORMAL reading
-> axiom/form reading
```

Но из этого нельзя выводить онтологическую лестницу:

```text
Q сначала независимо создаёт смысл S,
S затем независимо создаёт смысл FORMAL,
FORMAL затем создаёт аксиомы
```

Смысловая зависимость остаётся взаимно-рекурсивной:

```text
root/aset
↔ контексты и словари четверичного слоя
↔ строковое представление
↔ формальные знаки
↔ знаки выбора контекста
↔ аксиомы
↔ асеть аксиом
```

Иначе говоря:

```text
transport/decode dependency = layered
semantic-definition dependency = mutual recursion / fixed point
```

Именно это разделение позволяет использовать несколько уровней как механизм «разделения курицы и яйца» в self-bootstrap, не превращая нижний транспортный слой во внешний источник смысла.

#### 16.3. Явный выбор вложенного контекста

Одного режима на уровне файла или среды исполнения недостаточно. Строковое ачисло должно уметь явно содержать значение четверичного слоя, а формальная нотация — явно отличать как минимум:

```text
формальный знак/токен
четверичное ачисло или отдельный абит как literal value
строковое ачисло как literal value
```

Поэтому #601 исследует типизированное цитирование и явный повторный вход в контекст. До введения конкретных знаков используется только метанотация:

```text
Typed(K, x)
```

где `K` — явно выбранный контекст, а `x` — то же самое значение, не получающее нового тождества от позиции в исходном тексте.

Минимальный связевой кандидат:

```text
Typed(K, x) := K ⟼ x
```

с ещё не выбранной окончательно ориентацией. Это не новый вид сущности: `K`, `x` и их связь остаются обычными связями.

Такой носитель контекста необходим уже на пустых значениях:

```text
пустое четверичное ачисло -> R
пустое строковое содержимое -> R
```

Если выбор интерпретатора существует только как исчезающий режим лексического разбора, два чтения становятся неразличимы сразу после возврата `R`. В связевой записи контекст можно сохранить структурно:

```text
Typed(K_Q, R)
!=
Typed(K_S, R)
```

не создавая второго `R`.

Сами `K_Q`, `K_S`, `K_F` здесь только внешние исследовательские имена. Если соответствующие контексты войдут во внутренний язык МТС, #595/#594 должны ввести их как связи/подасети собственными уравнениями, а не как перечисление среды исполнения.

#### 16.4. Поверхностные кавычки пока только кандидат

Для проверки удобства и минимальности #601 рассматривает, но пока **не принимает**, например:

```text
'1'          — четверичный literal: один абит 1
'[0101]'     — literal четверичного ачисла
"1"          — literal строкового ачисла с текстовым знаком 1
"⟼"          — строковый literal, а не формальный оператор ⟼
```

В формальном контексте тогда принципиально различались бы:

```text
1
'1'
"1"
```

Кавычки не могут быть магией внешнего лексического разбора. Если такая поверхностная запись будет выбрана, сами её графические знаки должны кодироваться тем же строковым/четверичным транспортом и получить собственные связи знаков и вводящие уравнения через #595/#594.

У четверичного литерала есть полезный кандидат на простое ограничение: его внутренний алфавит состоит только из `[ ] 1 0`, поэтому одинарная кавычка не требует экранирования внутри четверичного содержимого. Для строкового литерала точное правило вложенности/экранирования ещё должно быть выведено и проверено.

Нельзя смешивать этот будущий поверхностный маркер с уже существующим понятием смыслового цитирования/сегментации, где D/G/T выбирает один носитель как одно смысловое значение. Первое явно выбирает **контекст чтения исходной записи**, второе выбирает **единицу денотации**; их возможное внутреннее совпадение ещё предстоит доказать.

#### 16.5. Контекстно разные предъявления не создают экземпляры смысла

Ключевой пример остаётся:

```text
FORMAL:
  A ⟼ B
  — использование смысла связи как бинарного построения/предъявления связи

QUATERNARY:
  1
  — абитное предъявление корневой связности в четверичном ачисле

ROOT ASET:
  L = O ⟼ C
  — сама корневая связь в натуре, несущая смысл связности
```

Нельзя писать:

```text
⟼ == 1 == L
```

как буквальное тождество поверхностных знаков. Но разные контекстные предъявления не создают три экземпляра `L`: различие должно находиться в рекурсивно выраженной роли/контексте использования.

Для каждого перехода требуется явно установить:

```text
исходный carrier
контекст интерпретации
правило разрешения
результирующую форму/значение
границу чтение/материализация
```

Особенно важно сохранить:

```text
носитель != денотат
описать связь != материализовать связь
повтор source position != новая semantic Link
```

### 17. Самовведение языка

Система аксиом должна сама вводить язык, которым записана.

Обязательные условия:

1. каждая аксиома записана формальной нотацией МТС;
2. каждый внутренний смысловой знак вводится собственной, возможно рекурсивной, аксиомой;
3. каждому такому знаку соответствует связь в асети системы аксиом;
4. сами аксиомы представлены связями или подасетями в той же асети;
5. определения знаков и аксиом замыкаются взаимной рекурсией;
6. контекст нотации является частью формальной роли знака и не должен стираться при интерпретации.

```text
аксиомы
↔ нотации
↔ смысловые знаки
↔ связи знаков
↔ асеть аксиом
↔ аксиомы
```

Это не порядок «сначала язык, потом теория».

### 18. Акорень как смысл

Фундаментальный знак автора:

```text
∞
```

Текущий машинный псевдоним:

```text
R
```

Рабочая фундаментальная форма:

```text
∞ : ∞ ⟼ ∞
```

должна последовательно читаться:

```text
«смысл есть смысл, связанный со смыслом»
```

Полное самозамыкание есть полная рекурсия и первичная смысловая определённость. Поэтому акорень рассматривается как корневой смысл, связь полных рекурсий, связь смыслов и рекурсивно — смысл смысла.

### 19. Связь как переход смыслов

Форма:

```text
A ⟼ B
```

в контексте формальной нотации понимается как использование смысла связи для построения/предъявления конкретной связи: перехода / трансформации / континуума от начального смысла `A` к конечному смыслу `B`.

Смысл производной связи определяется:

- смыслом её начала;
- смыслом её конца;
- связями этих смыслов относительно акорня `∞`;
- всей взаимно-рекурсивной системой аксиом.

Смысл не добавляется к связи внешним словарём.

### 20. Последовательное смысловое чтение аксиом

После введения каждого внутреннего знака собственной аксиомой любая фундаментальная формула должна читаться последовательно через смыслы этих знаков в их нотационном контексте.

Ключевая проверка:

```text
∞ : ∞ ⟼ ∞
```

```text
«смысл есть смысл, связанный со смыслом»
```

Словесная фраза не задаёт значение знаков, а проверяет уже полученную внутреннюю семантику.

### 21. `:`, `=`, `≡` не смешиваются

Рабочие гипотезы:

```text
:   — возможно сопоставление внешней целостности связи
      с внутренней дуальностью начала и конца;

=   — равенство, возможно прежде всего переменных / ссылок на связи;

≡   — отдельное тождество только если после точного введения `:` и `=`
      остаётся самостоятельный смысл.
```

Это не определения. Каждый внутренний знак должен получить собственную аксиому и собственную связь в асети аксиом.

Если для `≡` не обнаружится самостоятельного смысла, знак не нужен.

### 22. Внешний логический метаязык

Знаки:

```text
∧
⇔
⇒
≠
→
```

временно могут использоваться как внешний язык исследования.

Если такой знак становится внутренним знаком МТС, он должен быть введён тем же способом:

```text
знак
-> собственная аксиома
-> связь знака в асети аксиом
```

Необходимые логические конструкции в дальнейшем следует связать с ассоциативной логикой МТС.

### 23. Что такое решение системы

Нужно дать собственное понятие решения, не предполагающее заранее смысловые идентификаторы или готовые объекты.

Минимальные вопросы:

- что связывается знаком в левой части уравнения;
- какова область действия рекурсивной ссылки;
- что означает повтор того же связанного знака справа;
- как трактуется `⟼` внутри взаимной рекурсии;
- как контекстные нотации участвуют в одном решении;
- что означает одновременное выполнение нескольких уравнений;
- когда две системы выражают один смысл с точностью до переименования связанных обозначений.

### 24. Тождество и равенство

Принятый машинный инвариант:

```text
(A ⟼ B) = (C ⟼ D)
⇔ A = C ∧ B = D
```

не следует автоматически читать как внешнюю экстенсиональность готовых упорядоченных пар.

Нужно установить:

```text
аксиома системы?
правило решения?
следствие более минимального рекурсивного принципа?
```

И отдельно определить внутренние роли `:`, `=` и возможного `≡`.

### 25. Переименование не создаёт смыслового различия

```text
R = R ⟼ R
X = X ⟼ X
```

не должны задавать два акорня только из-за разных физических имён.

Кандидат на общий принцип:

> если различие не выражено рекурсивной системой уравнений, оно не может быть импортировано извне.

Это основание для #583 и принципа отсутствия экземплярности смысловых связей.

При этом контекстно разные знаки разных нотаций — это не экземпляры одной смысловой связи: их различие выражает роль использования, а не вторую смысловую связь.

### 26. Частичное самозамыкание и первичное различие

```text
O = O ⟼ R
C = R ⟼ C
```

исследуются как два ориентированных рекурсивных уравнения одной общей системы.

Различие `O/C` находится в стороне самозамыкания, а не в технических идентификаторах.

Это создаёт основу для последующей остенсивной инверсии:

```text
self ⟼ R
↔
R ⟼ self
```

### 27. Единственность акорня и отсутствие экземпляров

Если:

```text
X = X ⟼ X
Y = Y ⟼ Y
```

и система не содержит другого различающего уравнения, внешнее предположение `X != Y` не должно создавать два смысла.

Кандидат на теорему:

> отсутствие рекурсивно выраженного различия означает отсутствие двух смысловых связей.

См. #583.

### 28. Следующий результат F1

1. зафиксировать точную иерархию представлений #599: формальная запись является строковым ачислом, а строковое ачисло имеет каноническое четверичное представление;

## Ограничения F1

- не вводить второй синонимичный стрелочный знак рядом с `⟼`;
- не схлопывать `⟼`, `1`, `L` в один поверхностный знак;
- не считать контекст нотации техническим шумом или исчезающим режимом лексического разбора;
- не иметь два одновременно канонических `STRING -> QUATERNARY` представления;
- не выводить семантику основания из текущего конвертера по кодовым точкам Юникода только потому, что он реализован в TypeScript;
- не считать предложенные `'...'` / `"..."` внутренними знаками до их собственного введения через #595/#594;
- не вводить технический идентификатор или позицию в исходнике как смысловое тождество;
- не использовать граф, сильносвязные компоненты и автоморфизмы как определение смысла;
- не определять связь через внешнюю факторизацию;
- не принимать теорию категорий, коалгебр или множеств за фундамент МТС;
- не подменять одновременную рекурсию последовательным построением: направленным может быть транспорт/декодирование, но не происхождение смысла;
- не менять исполняемое ядро и принятые контракты v0.8 до отдельного решения о семантике.
