# МТС следующего цикла — контекстное основание самозамыкания

Статус: **исследовательский кандидат**, владелец #658, текущий срез #673, родитель #657.

Принятое машинное состояние не меняется:

```text
current  = MTS v0.9
previous = MTS v0.8
runtime  = TypeScript only
```

Документ исследует новую пару знаков `:` / `.`. Он не изменяет принятую аксиоматику, контракт или среду исполнения.

## 1. Исходная геометрия

Связь едина снаружи и ориентированно дуальна внутри.

Рабочая гипотеза:

```text
:  — переход от внешнего единства связи к внутренней дуальности
.  — возврат из внутренней позиции к внешнему единству
```

Это не обычная биекция. Одно целое имеет две ориентированные внутренние позиции, но каждая позиция возвращается к тому же целому:

```text
          начало
         /      \
целое  :          .
         \      /
           конец
```

Точку можно остенсивно понимать как центр связи: из любой внутренней позиции она указывает на одно внешнее единство текущего контекста.

## 2. Контекстная запись

Кандидатная форма:

```text
A : E
```

означает, что `E` рассматривается как внутренняя дуальность связи `A`.

Свободная точка внутри этой области относится к ближайшему связанному `A`:

```text
. -> A
```

Это только правило разрешения связанной контекстной ссылки. Оно не является глобальной текстовой подстановкой.

Удобная метазапись раскрытия:

```text
⟦.⟧A = A
⟦X ⟼ Y⟧A = ⟦X⟧A ⟼ ⟦Y⟧A
```

Вложенный `B : F` создаёт собственную область для точек внутри `F`; после неё действует прежняя область `A`.

## 3. Аксиома полного смысла

Авторская кандидатная запись:

```text
∞ : . ⟼ .
```

Обе точки находятся внутри контекста `∞`, поэтому:

```text
⟦. ⟼ .⟧∞ = ∞ ⟼ ∞
```

и контекстная форма раскрывается в принятую корневую рекурсию:

```text
∞ = ∞ ⟼ ∞
```

В терминах F2 это `ROOT`.

Таким образом полная рекурсия получает простую геометрию: обе стороны внутренней дуальности возвращаются к одному внешнему центру.

## 4. Уникальность полного контекстного замыкания

Рассмотрим общую форму:

```text
A : . ⟼ .
```

Её раскрытие:

```text
A = A ⟼ A
```

По результату #670 полное самозамыкание имеет единственный смысловой класс `ROOT`. Следовательно укоренённое решение требует:

```text
A = R = ∞
```

Поэтому запись с двумя точками не создаёт отдельный корень для каждого имени контекста.

Это важный фальсификатор: если реализация допускает два смыслово различных `A` и `B` с формами `A:.⟼.` и `B:.⟼.`, она нарушает основание #670.

## 5. Односторонние формы

Для начала:

```text
O : . ⟼ ∞
```

раскрытие даёт:

```text
O = O ⟼ R
```

Для конца:

```text
C : ∞ ⟼ .
```

раскрытие даёт:

```text
C = R ⟼ C
```

Это ровно формы `START(ROOT)` и `END(ROOT)` из F2.

Полная и односторонняя рекурсия теперь различаются числом внутренних позиций, возвращённых к текущему целому:

```text
∞ : . ⟼ .   — возвращены обе позиции
O : . ⟼ ∞   — возвращено начало
C : ∞ ⟼ .   — возвращён конец
```

## 6. Общие односторонние формы

Для уже укоренённого `B`:

```text
A : . ⟼ B
```

раскрывается как:

```text
A = A ⟼ B
```

а:

```text
A : B ⟼ .
```

как:

```text
A = B ⟼ A
```

Следовательно точка не является специальным знаком только для акорня. Она выражает положение текущего внешнего единства внутри его собственной дуальности.

Основание самостоятельного смысла таких форм по-прежнему определяется #670: внешний полюс должен быть укоренён.

## 7. Вложенный контекст

Критическая форма:

```text
A : (B : . ⟼ R) ⟼ .
```

имеет две разные области связывания.

Внутренняя точка относится к `B`:

```text
B : . ⟼ R
->
B = B ⟼ R
```

Внешняя точка относится к `A`.

Поэтому вложенность должна быть лексически точной:

```text
внутренняя . = B
внешняя . = A
```

Стек языка реализации может обслуживать такой разбор, но не является источником смысла.

## 8. Свободная точка запрещена

Точка вне явно связанного контекста не должна получать скрытый смысл:

```text
. ⟼ R
```

без окружающего `A : ...` не означает «текущую связь среды исполнения».

Допустимые результаты исследования:

```text
нет связующего контекста -> форма не разрешена
```

или отдельное будущее явное правило. Не допускается ambient-current семантика.

## 9. Принятый смысл знака `:`

В F1 v0.9 знак `:` уже самовведён:

```text
m: = m∞ ⟼ m⟼
```

Корневая проекция:

```text
m∞ -> R
m⟼ -> L
```

поэтому:

```text
m: -> R ⟼ L
```

При этом:

```text
L = O ⟼ C
```

является корневой ориентированной связью между началом и концом.

Следовательно существующий смысл `:` уже имеет направление:

```text
R -> L
единство -> ориентированная дуальность
```

Это сильная совместимость с новой геометрической интерпретацией двоеточия.

Однако из `m: = R⟼L` ещё не следует автоматически правило связывания `A:E`. Значение знака и его контекстная роль — разные уровни.

## 10. Кандидат смысла знака `.`

Если точка выражает обратное направление относительно значения двоеточия, естественно проверить true pole-swap из #661.

Имеем:

```text
m: = m∞ ⟼ m⟼
```

Перестановка его полюсов:

```text
Inv(m:) = m⟼ ⟼ m∞
```

Поэтому минимальный кандидат:

```text
m. = m⟼ ⟼ m∞
```

Корневая проекция:

```text
m. -> L ⟼ R
```

То есть:

```text
m: -> R ⟼ L
m. -> L ⟼ R
```

образуют направленно сопряжённую пару на уровне значений знаков.

## 11. Проверка инволюции пары знаков

True pole-swap является инволюцией по #661. Поэтому из кандидата:

```text
m. = Inv(m:)
```

следует:

```text
Inv(m.) = m:
```

Это не требует рекурсивного зеркалирования внутренних полюсов `R` или `L`.

`L ⟼ R` является обычной укоренённой формой `PAIR(L,R)`. Новый корневой primitive для точки не требуется.

Но новый внутренний глиф `.` всё равно изменил бы внутренний алфавит F1 и потому требует отдельного жизненного цикла принятия.

## 12. Значение знака не равно его роли в контексте

Нужно удерживать два разных утверждения:

```text
m. = L ⟼ R
```

— кандидат значения самого знака;

и:

```text
A : . ⟼ B
->
A = A ⟼ B
```

— кандидат правила разрешения употребления точки в контексте.

Первое не доказывает второе.

Это соответствует уже принятому разделению:

```text
физический знак
значение знака
роль знака в выбранном контексте
смысловой результат
```

## 13. Три описания точки

В контекстной роли точку можно описать тремя способами:

```text
возврат из внутренней позиции к целому
точка центра текущей связи
подстановка связанного целого во внутреннюю позицию
```

В рамках текущей гипотезы это не три операции, а три взгляда на одно разрешение:

```text
Resolve(A, .) = A
```

Слово «подстановка» здесь не означает произвольное переписывание других вхождений. Заменяется только связанная точка в конкретной позиции.

## 14. Граница с READ

READ из #660 движется в другом направлении:

```text
целое -> начало
целое -> конец
```

Точка делает:

```text
внутренняя позиция -> целое
```

Поэтому:

```text
. != readBegin
. != readEnd
```

Двоеточие раскрывает область двух позиций, но само не выбирает один из полюсов для READ.

## 15. Граница с WRITE

#671 доказал производный шаблон:

```text
A[B] -> A ⟼ B
```

Квадратные скобки остаются границами контекста Q.

Пара `:` / `.` решает другую задачу:

```text
:/.  — единство и внутренняя дуальность одной связи
[ ]  — структурный контекст Q и производный WRITE
```

Эти механизмы могут взаимодействовать, но не являются синонимами.

## 16. Граница с исполнением

Разрешение точки:

```text
A : . ⟼ B
```

не является само по себе актом вычисления `A -> B`.

Нужно различать:

```text
связать точку с текущим целым
исполнить сопоставление
изменить состояние контекста
материализовать связь в памяти
```

Закрытые #666/#668 могут использовать точку вместо прежнего research-placeholder `↑` только после принятия этой контекстной роли.

## 17. Судьба `↑`

Прежняя гипотеза использовала:

```text
↑ = текущая контекстная связь как целое
```

Новая запись:

```text
A : . ⟼ B
```

покрывает ту же связанную ссылку и дополнительно объясняет направление «дуальность -> единство».

Если scoped-разрешение точки выдерживает фальсифицирующий корпус, активный кандидат `↑` избыточен:

```text
↑ -> историческая исследовательская нотация
. -> предпочтительный кандидат
```

Это не изменение accepted v0.9: `↑` и так не принят во внутренний F1.

## 18. Фальсифицирующий корпус

Положительные случаи:

```text
∞:.⟼.
O:.⟼∞
C:∞⟼.
A:.⟼B
A:B⟼.
A:(B:.⟼R)⟼.
m: -> R⟼L
m. -> L⟼R
Inv(m:) -> m.
Inv(m.) -> m:
```

Отрицательные случаи:

```text
свободная . вне A:...
. как parent navigation
. как runtime current
. как readBegin/readEnd
. как storage dereference
. как произвольное переписывание
: как equality/assignment
:/. как скрытый push/pop
```

Особый veto:

```text
A:.⟼. при A != R
```

не может дать второй полный корень.

## 19. Классификация результата

На исследовательском уровне:

```text
`:` как единство -> дуальность
  СОВМЕСТИМО с accepted m: = R⟼L

`.` как дуальность -> единство
  ТОЧНО определимо как scoped contextual role

m. = Inv(m:) = L⟼R
  СИЛЬНЫЙ КАНДИДАТ значения нового знака

↑
  ВЫТЕСНЯЕТСЯ новой нотацией на active research line
```

Но принятие внутрь F1 разделяется:

```text
чтение существующего m: как единство->дуальность
  -> возможно только уточнение без наблюдаемой дельты

новая контекстная роль A:E
  -> потенциальная наблюдаемая дельта

новый внутренний знак .
  -> явная дельта внутреннего алфавита
```

Финальную классификацию выполняют #662/#663.

## 20. Итог

Главная кандидатная запись теперь:

```text
∞ : . ⟼ .
```

Она выражает полный смысл без специального знака самоссылки: двоеточие раскрывает единство в дуальность, а обе точки возвращают внутренние позиции к одному центру.

На уровне значений знаков обнаруживается естественная сопряжённость:

```text
m: -> R ⟼ L
m. -> L ⟼ R
```

Это делает `.` более содержательным кандидатом, чем прежний `↑`, но ещё не принимает новый глиф в F1 и не меняет MTS v0.9.
