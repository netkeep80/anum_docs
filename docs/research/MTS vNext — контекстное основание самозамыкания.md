# MTS vNext — контекстное основание самозамыкания

Статус: **research hypothesis**, owner #658, parent roadmap #657.

Accepted machine state не меняется:

```text
current  = MTS v0.9
previous = MTS v0.8
runtime  = TypeScript only
```

Этот документ не является новой принятой аксиоматикой. Его задача — проверить, можно ли заменить специальное метаописание односторонней самоссылки единым явным контекстным механизмом.

## 1. Исходная гипотеза

Связь рассматривается как единство снаружи и как ориентированная дуальность внутри.

Кандидатная запись:

```text
A: E
```

означает: выражение `E` рассматривается в контексте связи `A`.

Внутри этого контекста кандидатный знак

```text
↑
```

обозначает **текущую контекстную связь как целое**.

Это не parent-navigation, не runtime stack frame и не source occurrence.

## 2. Корневой базис как контекстные формы

Проверяемая кандидатная запись:

```text
R: ↑ ⟼ ↑
O: ↑ ⟼ R
C: R ⟼ ↑
L: O ⟼ C
U: C ⟼ O
```

При корректном раскрытии контекстного связывания должны получаться уже известные формы:

```text
R = R ⟼ R
O = O ⟼ R
C = R ⟼ C
L = O ⟼ C
U = C ⟼ O
```

Критически важно: это пока **цель проверки**, а не уже доказанное равенство двух нотаций.

## 3. Что означает самозамыкание в этой гипотезе

Полное самозамыкание:

```text
R: ↑ ⟼ ↑
```

Оба полюса внутренней дуальности указывают на то же внешнее единство — текущую контекстную связь.

Самозамыкание начала:

```text
O: ↑ ⟼ R
```

Начальный полюс внутренней дуальности совпадает с текущей контекстной связью.

Самозамыкание конца:

```text
C: R ⟼ ↑
```

Конечный полюс внутренней дуальности совпадает с текущей контекстной связью.

То есть `SELF_START` / `SELF_END` могут оказаться не фундаментальными конструкциями, а метаописанием двух положений одной и той же контекстной ссылки `↑`.

## 4. Направление «изнутри наружу»

Если мы уже находимся внутри дуальности конкретной связи, переход к связи как целому однозначен:

```text
inner position
    ↓
current contextual whole
```

Кандидат для этого единственного перехода — `↑`.

Здесь нет выбора между началом и концом, потому что `↑` не выбирает внутренний полюс. Он возвращает внешнее единство текущего контекста.

## 5. Направление «снаружи внутрь»

Обратный переход принципиально двузначен:

```text
whole
  ↙  ↘
begin end
```

Поэтому будущие операции доступа к началу и концу не следует смешивать с `↑`.

Гипотеза #660: эти две операции могут оказаться **составными производными структурами**, использующими два возможных односторонних самозамыкания:

```text
↑ ⟼ A
A ⟼ ↑
```

а не новыми необъяснимыми primitives.

## 6. `[` и `]` как частные случаи

Корневые абиты:

```text
[ -> O
] -> C
```

в этой гипотезе являются только специальными смыслами одностороннего самозамыкания относительно `R`:

```text
O: ↑ ⟼ R
C: R ⟼ ↑
```

Но формы

```text
X: ↑ ⟼ A
Y: A ⟼ ↑
```

имеют смысл и для `A != R`.

Следовательно одностороннее самозамыкание — более общий механизм, а `[ ]` — только два корневых элемента уже построенного словаря.

## 7. Первый порождаемый слой

Для каждого уже известного корневого смысла

```text
A ∈ {R,O,C,L,U}
```

естественно исследовать:

```text
↑ ⟼ A
A ⟼ ↑
```

Всего десять контекстных форм.

Две из них уже соответствуют известным:

```text
↑ ⟼ R  -> candidate O-form
R ⟼ ↑  -> candidate C-form
```

Остальные восемь не получают имён заранее. Они должны быть сначала факторизованы по semantic identity и только затем исследованы как возможные новые смыслы. Этим занимается #659.

## 8. `:` как контекстное связывание

Ранее `:` исследовался как возможное сопоставление внешнего единства и внутренней дуальности.

Новая гипотеза уточняет это:

```text
A: E
```

может быть не статическим знаком «A соответствует E», а структурным связыванием:

```text
enter/bind context A
interpret E with current-context = A
```

Но слово `push` здесь только реализационная аналогия. Foundation semantics не должна зависеть от host stack.

Требуется выразить тот же смысл через уже принятую explicit-context discipline:

```text
I
K
Act
Run
```

или доказать, что нынешняя context machinery недостаточна.

## 9. Вложенный контекст

Нужно различать как минимум:

```text
current contextual Link
parent contextual Link
lexical nesting
runtime temporal order
```

Внутри:

```text
A: (B: ↑ ⟼ R) ⟼ ↑
```

внутренний `↑` должен относиться к `B`, а внешний — к `A`.

Если язык потребует отдельного явного доступа к parent context, это другая производная операция. Нельзя перегружать `↑` двумя смыслами.

## 10. Инверсия сюда не импортируется

Этот slice не определяет инверсию.

После вывода Begin/End в #660 инверсия проверяется отдельно в #661 как перестановка полюсов **текущей связи**:

```text
A ⟼ B
↦
B ⟼ A
```

без рекурсивного распространения преобразования внутрь `A` и `B`.

## 11. F2/F3 boundary

Текущие F2-формы:

```text
ROOT
START(F)
END(F)
PAIR(F,G)
```

остаются валидным метаописанием уже полученных grounded recursive forms до тех пор, пока новая гипотеза не доказана.

Research question:

```text
START(F)
END(F)
```

являются ли самостоятельной необходимой foundation machinery или только мета-нормализацией положения `↑` в contextual binder form.

F3 no-instance/identity результат сохраняется как обязательный invariant: разные aliases, runtime objects или source occurrences не создают новые semantic Links.

## 12. Фальсифицирующий корпус

Минимум:

```text
R: ↑ ⟼ ↑
O: ↑ ⟼ R
C: R ⟼ ↑
X: ↑ ⟼ O
Y: O ⟼ ↑
A: B ⟼ C
A: (B: ↑ ⟼ R) ⟼ ↑
```

Проверить:

1. alpha-renaming не меняет смысл;
2. `↑` всегда локален к текущему lexical context;
3. parent/current не смешиваются;
4. runtime/storage identity не участвует;
5. раскрытие R/O/C не использует скрыто старую SELF_START/SELF_END семантику как premise;
6. non-selfreferential `A: B⟼C` остаётся осмысленной contextual form;
7. вложенный контекст не требует hidden host stack как semantic authority.

## 13. Возможные результаты

```text
ACCEPT-CANDIDATE
  `:` + `↑` дают более простое основание самозамыкания

PARTIAL
  механизм работает, но требует отдельного parent/context relation

NO-DELTA-REFORMULATION
  это только более ясная запись уже принятой semantics

OBSERVABLE-DELTA
  меняется внутренний смысл `:` / принимается `↑` / меняется F1 foundation

REJECT
  контекстная форма не может заменить текущую recursive grounding machinery
```

Только `OBSERVABLE-DELTA` может перейти в contract lifecycle #663.
