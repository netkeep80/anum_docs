# План сопряжённого развития натуральных чисел и исчисления доказательств

## Цель

Построить первый переиспользуемый набор теорем Пеано, одновременно развивая математическую структуру натуральных чисел и общий механизм доказательств МТС.

Три вида результата никогда не смешиваются:

```text

PROOF_ANET
REUSE
```

## Ответственность

```text

#999  — исчисление доказательств
#1057 — синхронизация через последовательность теорем
```

Каждая исполняемая теорема получает отдельную ограниченную задачу с собственным описанием допустимого изменения.

Если теорема структурно истинна, но её нельзя доказать текущим аппаратом, изменяется только общий механизм доказательств. Если структурная гипотеза опровергнута, механизм проверки не усиливается ради её сохранения.

## Задача 3 — теорема 3: ноль не является следующим

Владелец: #1059.

Цель структуры:

```text
Nat(N)
-------
N ⟼ L != U
```

### Конечная исполняемая фальсификация

Создать только:

```text
ts/test/nat-peano-zero-not-successor.test.ts
```

Построить конечную выборку:

```text
N0 = U
N(n+1) = Nn ⟼ L
```

Для всех выбранных значений проверить:

```text
Succ(N) != U
start(Succ(N)) = N
end(Succ(N)) = L
```

Индексы цикла являются только метками тестовой выборки.

### Общий структурный вывод

Конечная выборка не является общей теоремой. Нужно отдельно замкнуть вывод на принятой структуре корневого базиса:

```text
U = C ⟼ O
Succ(N) = N ⟼ L
```

Если предположить:

```text
N ⟼ L = U = C ⟼ O
```

то инвариант тождества связи требует:

```text
N = C
L = O
```

Следовательно, общая теорема сводится к структурно установленному различию между `L` и `O`. Это различие должно подтверждаться самой конструкцией корневого базиса, а не именами.

Статус структуры повышается только после общего вывода, а не только после конечного теста.

## Задача 4 — теорема 4: инъективность следующего

Владелец: #1060.

Структурная теорема:

```text
A ⟼ L = B ⟼ L
----------------
A = B
```

Создать только:

```text
ts/test/nat-peano-successor-injective.test.ts
```

Проверить несколько независимых и вложенных связей:

```text
A = B  =>  Succ(A) = Succ(B)
A != B =>  Succ(A) != Succ(B)
start(Succ(A)) = A
end(Succ(A)) = L
```

Общий математический вывод должен ссылаться на инвариант упорядоченных полюсов:

```text
(A ⟼ B) = (C ⟼ D)
iff
A=C and B=D
```

Следовательно:

```text
(A⟼L)=(B⟼L)
=> A=B
```

После полного принятия ожидаемый статус:

```text
STRUCTURE = SUPPORTED
PROOF_ANET = NOT TESTED
REUSE = NOT TESTED
```

## Задача 6 — теорема 5: единственность предыдущего как первая проверка переиспользования

Открывается после принятой асети доказательства теоремы 4.

Теорема:

```text
A ⟼ L = N
B ⟼ L = N
----------------
A = B
```

Доказательство должно:

1. получить равенство двух форм следующего элемента из двух равенств с общим результатом;
2. применить уже доказанную теорему 4;
3. использовать производное доказательное свидетельство через общий механизм раскрытия и повторной проверки;
4. не создавать вторую примитивную аксиому инъективности.

Если теорему 4 можно доказать, но нельзя переиспользовать, исправляется только общий механизм переиспользования и добавляется неарифметический контроль.

Первая волна не считается законченной, пока теорема 5 действительно не использует теорему 4.

## Правило завершения каждого исполняемого среза

Перед каждой записью или сменой состояния перечитываются основная ветка, целевая задача или запрос на слияние и политика репозитория.

Перед слиянием обязательно должны быть успешны полный набор проверок и блокирующая проверка политики; рабочая ветка не должна отставать; запрос должен быть готов к слиянию; вершина должна оставаться неизменной. Слияние выполняется с проверкой точной вершины, после чего заново проверяются основная ветка и её проверки.

Ни один статус математической теоремы не повышается только потому, что код компилируется или конечный тест прошёл. Вид свидетельства должен соответствовать именно структурной истинности, доказуемости или переиспользованию.
